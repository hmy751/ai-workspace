# 코드 작업 지침의 명확성 정리

사용자는 루트 `CODE-QUALITY.md`를 프롬프트 엔지니어링 관점과 전역 `ai-system_instruction-clarity.md` 기준으로 다듬도록 요청했다. 전역 레퍼런스 본문과 shared reference의 연결 규칙을 직접 읽고, 합의한 코드 기준의 목적과 적용 범위를 유지하며 표현과 구성을 수정했다.

## 확인한 해석 위험과 수정

기존 문서는 일반 수정과 구조 변경의 조사·검증 요구가 함께 적혀 있었고, 책임이 여러 개라는 이유만으로 분리하거나 모든 작업에 같은 절차를 적용할 여지가 있었다. 조사할 내용과 답변에 보여 줄 내용도 구별이 부족했다. 이는 문서 검토에서 발견한 위험이며 실제 AI의 새 실행 실패를 관찰한 결과는 아니다.

목적·대상·권한의 한계를 앞에 두고, 국소 수정과 책임·호출 경계 변경을 구별했다. 분석·진단·리뷰는 수정 권한을 추가하지 않으며, 명시적으로 제외한 영역의 변경이 필요하면 선택을 확인하도록 했다. 책임 분리는 변경 이유와 검증 경계가 명확해지는지로 판단하도록 보완했다.

테스트 이동은 기존 보장을 유지하는 것이 기준임을 명시했다. 내부 호출에 묶인 assertion을 그대로 고정하지 않되 결과·실패·부작용 검증은 약화하지 않는다. 같은 fake를 실제로 공유할 때의 예외도 fixture 기준 가까이에 두었다.

영문 LLM 문자열의 번역 규칙은 영어 사용 자체를 요구하지 않는다고 명시했다. 번역은 전달 문자열 밖에 유지하고, JSON처럼 주석을 허용하지 않는 형식에서는 형식이나 schema를 바꾸지 않는 예외를 붙였다.

예시는 적용 범위를 설명하는 용도로 한정했다. 두 AI 도구 지원은 실제 연결 차이의 분리이며 자유로운 조합 선택 기능은 별도 요구라는 뜻을 유지했다. 특정 도구명·언어·파일 수·폴더 구조를 고정하지 않았다.

## 대표 요청에 대한 문서 검토

다음 요청을 각 절에 대입해 요구와 예외가 연결되는지 정적으로 검토했다. 별도 agent 실행이나 실제 코드 수정 실험은 하지 않았다.

- “현황 분석부터”: 필요한 구현과 호출 근거를 조사하고 결과를 설명한다. 문제 발견만으로 코드를 수정하지 않는다.
- “작은 조건식 수정”: 해당 동작과 영향 범위를 확인한다. 전체 코드 재구성이나 전체 테스트를 자동 요구하지 않는다.
- “Maintain만 리팩터링, Recover·Verify는 제외”: 필요한 호출 경계는 확인하되 제외 영역의 별도 개선을 시작하지 않는다. 그 영역 변경 없이는 요청을 완성할 수 없다면 충돌과 영향을 설명한다.
- “두 AI 도구에서 같은 기능 지원”: 공통 계약을 유지하고 실제 연결 차이를 처리한다. 조합 선택 시스템을 자동 추가하지 않는다.
- “테스트 이동·분할”: 기존 검사 기준선과 보장 내용을 확인하고, 이동 뒤 누락·중복과 결과 검증을 확인한 뒤 이전 파일을 정리한다. 새 테스트 도구를 자동 도입하지 않는다.
- “영문 프롬프트 아래 한국어 번역”: 코드 주석으로 번역하고 실제 전달 문자열은 유지한다. 주석 불가 형식에는 번역 필드나 비표준 주석을 넣지 않는다.
- “회귀 한 건 실패”: 변경 전 결과나 재현 근거가 있을 때만 기존 실패로 구분한다. 근거가 없으면 기존 실패라고 단정하지 않고, 전체 통과로 보고하지 않는다.

## 연결과 검증 범위

루트 AGENTS의 적용 대상에 분석·진단을 맞추고, 세부 기준의 중복 설명을 제거했다. `CLAUDE.md → AGENTS.md` symlink와 `CODE-QUALITY.md` 연결, 전역 레퍼런스 파일의 존재를 확인했다. 명확성 기준의 적용 관계는 로컬 지침에 표시했다. 전역 레퍼런스·색인·사용자 지침은 수정하지 않았다.

`git diff --check`는 통과했다. 이번 변경은 문서와 routing 문장에 한정하며 프로덕션 코드·LLM 프롬프트·테스트는 수정하지 않았다. 코드 테스트는 다시 실행하지 않았다. 문서의 해석 가능성을 검토한 결과이며 실제 모델의 준수율이나 수행 신뢰성 개선을 검증한 것으로 주장하지 않는다.
