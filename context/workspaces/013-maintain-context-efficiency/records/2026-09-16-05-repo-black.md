# 기존 작업 커밋과 저장소 공통 Black 적용

사용자는 Maintain만이 아니라 저장소 전체에 Black을 설정하고, 적용 전에 지금까지의 작업을 먼저 커밋하도록 요청했다.

책임·테스트·도구 연결 리팩터링, 가독성 정리, 루트 코드 지침은 `3b588e3`에 커밋했다. 커밋 직후 작업 트리가 깨끗함을 확인한 뒤 Black 변경을 시작했다. 사용자의 후속 커밋 요청에 따라 Black 설정과 포맷 diff는 리팩터링과 구별되는 별도 커밋 단위로 고정한다.

루트 `pyproject.toml`에서 Black 26.5.1, 줄 길이 88, Python 3.11~3.14 대상 구문을 설정하고 `requirements-dev.txt`에 도구 버전을 고정했다. 저장소의 `.venv`에 설치했으며 전역 Python·모델·hook 설정은 변경하지 않았다. 준비와 실행 명령은 루트 `CODE-QUALITY.md`가 안내한다. 설정 선택은 [Black 공식 문서](https://black.readthedocs.io/en/stable/usage_and_configuration/the_basics.html)의 프로젝트 설정·버전 고정·대상 구문·제외 옵션을 확인했다.

원자료 snapshot, Workspace의 과거 records·source와 도구별 skill symlink는 `force-exclude`로 제외한다. Skill 원천은 `.agents/skills`에서 한 번만 포맷한다. 제외된 경로를 명시적으로 입력하는 검사도 포맷할 파일이 없다고 반환했다.

현재 Python 파일 86개 중 52개가 포맷됐다. 최신 전체 포맷 요청에 따라 Recover·Verify·제품·설치 helper 코드도 개행·표기만 정리했으며 내부 리팩터링이나 기능 변경은 하지 않았다. 변경한 Python 파일 52개는 커밋의 AST와 모두 동일했고 LLM 전달 문자열도 그대로다.

## 검증

- 저장소 루트의 Black 검사: 86개 파일 모두 추가 포맷 불필요
- `reference-project/`에서 같은 루트 설정으로 Black 검사: 83개 파일 모두 추가 포맷 불필요
- helper 테스트: Python 3.14에서 7개 통과
- Maintain 테스트: Python 3.11에서 82개 통과
- Reference 전체 회귀: Python 3.14에서 141개 중 140개 통과. 이전 기준선에서도 실패했던 Verify의 `test_timeout_covers_descendant_after_group_leader_exits` 한 건은 여전히 실패
- `git diff --check`: 통과. snapshot·과거 기록의 Python 파일에는 변경 없음

Black은 기본 안전 검사를 사용했고 `--fast`·preview·unstable 모드는 켜지 않았다. 실제 host lifecycle·의미 판단 품질·비용 개선은 이번 검증 대상이 아니다.
