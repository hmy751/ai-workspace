# 협업 경험을 보존하고 Personal·스킬로 연결하는 안

2026-10-27 **후속 사용자 합의가 저장 위치 제안을 대체한다.** Personal의 정의를 넓히고 이번에 논의한 협업 경험·판단 등의 내용을 Personal에 둔다. 내부 계층은 구성하며 발전시키고, 이 선택으로 Work를 제한하지 않는다. 내용 선별·해석·반영의 상세 기준은 아직 미정이다. [직접 원문과 합의 범위](2026-10-27-ticket05-interview.md#후속-합의--personal을-넓히고-이번-내용을-둔다)를 따른다. 실제 prototype·스킬·운영 구조는 변경하지 않았다.

## 이전 제안과 리뷰의 범위

아래는 Work 중심 보존을 제안해 [개선 리뷰 한 명](2026-10-27-ticket05-collaboration-learning-review.md)을 받은 당시 내용이다. 후속 Personal 배치를 검토한 리뷰가 아니며 현재 확정된 저장 구조로 읽지 않는다. 경험의 재사용·사용자 판단·기존 기준 적용에 관한 검토 근거는 후속 구체화에 재사용할 수 있다.

당시 추천은 **경험과 근거는 기존 Work records에, 여러 작업에서 다시 판단할 개인 기준은 Personal에, 실제 수행 순서·역할·검사·호출의 변화는 스킬에 둔다**는 것이다. 관련 경험을 한 개선 주제로 연결해 다시 읽고 적용 결과까지 확인한다. 새 위키나 개인 mode 스킬을 기존 세 영역 옆에 곧바로 더하지 않는다.

## 요청과 보존할 기대

사용자 원문:

> 그럼 우리 기존 구조에서는 이런 협업 경험을 어디에 모아두고 Personal이나 스킬에 어떻게 반영하면 좋을까? 로렌이랑 맷 방식에서 가져올 만한 걸 기준으로 설명해봐
> 그리고 그 다음에 이 지점에대해서 리뷰어 하나 돌려봐 개선 리뷰어로 끌어올릴 단순 적절하다 판단 말고 여기서 더 잘하게 하려면 어떻게 해야하나 그런리뷰도

[진행 중인 인터뷰](2026-10-27-ticket05-interview.md)에서 사용자는 AI의 수행과 자신의 질문·판단·위임을 함께 돌아보고, 배운 점이 당장 context 본문이 아니어도 수집될 수 있기를 바랐다. 기존 본문 전체의 내용·목적·지침 대조도 원하지만 이번 제안은 그중 **협업 경험의 보존·재사용·반영**을 구체화한다. 실패나 반복 교정만 수집하는 안이 아니다.

## 기록은 다음 판단에 필요한 만큼 남긴다

다음은 필수 양식이 아니라 한 경험의 의미를 다시 판단하기 위한 질문이다.

- 어떤 목적·상황에서 사용자와 AI가 어떻게 일했고 실제로 무엇이 달라졌는가?
- 사용자 직접 평가·실제 산출물·AI 해석은 각각 무엇이며, 무엇을 아직 모르는가?
- 다음에도 유지하거나 달리 해볼 여지가 있다면 어떤 조건에서 무엇을 해볼 것인가?

이미 원기록이 충분하면 새 ‘경험 카드’를 만들지 않는다. 관련된 별도 장면이 생기면 기존 주제에 연결해 동일한 발견인지 다른 조건인지 비교한다. 기존 해석과 맞지 않는 경험도 남겨 일반화의 범위를 조정한다. 단발 관찰이라는 이유로 버리지 않고, 반복 횟수만으로 기준으로 올리지 않는다.

예를 들어 [기존 Promise 인터뷰](../source/noline-evaluation/reviews/interview-20261012.md)에는 사용자가 이해하려고 파고든 점, AI가 혼동 지점을 더 빨리 짚을 여지, 두 갈래 설명의 도움이 함께 있다. 이 경험을 ‘추가 질문이 많으니 실패’나 ‘앞으로 항상 두 가지 예시를 제시’로 바꾸지 않는다. 먼저 무엇을 구별하면 이해에 도움이 됐는지와 어떤 설명 부담이 남았는지를 보존한다.

## 기록에서 실제 반영까지

1. **관련 경험과 현재 기준을 함께 읽는다.** 사용자가 개선 루프를 요청했거나 특정 경험을 함께 돌아보기로 한 대화 경계에서, 개선 Main이 관련 주제의 기록과 Personal·스킬 본문을 대조한다. 전체 대화·모든 Work를 매번 훑지 않는다. 다음 유사 작업의 준비나 새로운 반례로 재검토할 주제를 current·Ticket에서 찾을 수 있게 한다.
2. **무엇이 바뀌어야 할지 판단한다.** 이미 있는 기준의 미적용인지, 기준 자체가 부족한지, 이번 작업의 조건·도구·정보가 달랐는지 본다. 성공한 방법의 재사용과 아직 해보지 않은 더 좋은 방법도 다룬다. AI가 선택한 행동을 사용자 선호로 자동 취급하지 않는다.
3. **기록만 남김, 이번에 시험, 지속 기준 변경을 고른다.** 중요한 개인 선호·이해·감수할 비용이 근거로 풀리지 않을 때 구체 장면과 대안을 사용자에게 묻는다. 명시적으로 채택한 기준의 반영이나 이미 위임된 범위에 반복 승인을 요구하지 않는다. 시험은 적용할 장면·사람과 AI가 각각 바꿔볼 행동·기대 변화·비용을 밝힌다. 사용자에게 도움이 된 판단 질문이나 위임 방법도 제안할 수 있지만 매 대화의 숙제나 의무로 만들지 않는다.
4. **맞는 대상에 통합하고 읽기 경로를 잇는다.** 개인 판단은 [context-update](prototypes/development-workflow/skills/context-update/SKILL.md)로 기존 Personal 본문 전체의 의미·중복·충돌·필요한 설명을 대조해 통합한다. 수행 흐름은 담당 스킬에 넣는다. 같은 판단을 양쪽에 전문 복제하지 않고, 스킬은 필요한 Personal 기준을 언제 읽고 어떻게 판단에 사용할지 연결한다. 제품 계약의 발견이라면 Project, 코드·검사·도구의 변화라면 해당 수행으로 연결한다.
5. **선택한 시도를 다음 실제 작업으로 연결하고 결과를 다시 본다.** 실행할 Work가 정해지면 개선 Main이 적용할 상황·바꿔볼 행동·확인할 결과·근거 위치를 그 Main에게 전달한다. 실행 Work는 필요한 설명을 자기 current·Ticket에서 이해할 수 있게 유지하고, 실제 사용 여부·결과·사용자의 평가·추가 부담을 자기 기록에 남긴다. 개선 Main이 이 결과를 회수해 주제의 이해와 유지·수정·철회를 판단한다. 실행할 곳이 아직 없으면 개선 Work의 열린 다음 행동으로 남기며 자동으로 재사용될 것처럼 기록하지 않는다. 이 전달·회수는 시험으로 선택한 항목에 한정하고 단순 보존한 모든 경험에 요구하지 않는다. 문서 반영 완료와 효과 확인을 구별한다.

Personal과 스킬은 양자택일이 아니다. 개인 기준이 판단의 이유·조건을 설명하고 스킬이 그 기준을 사용하는 순서·책임을 연결해야 한다면 함께 바뀔 수 있다. 반대로 기존 스킬이 관련 Personal을 이미 충분히 읽는다면 스킬을 바꾸지 않는다. 형성 자료는 채택 이유를 보존하는 곳이며 미분류 경험을 전부 넣는 곳으로 쓰지 않는다.

표의 반영 위치는 설계 후보이며 실제 Personal·스킬을 수정한 결과가 아니다. 사용자에게 질문을 덜 하게 만드는 것 자체를 성공 기준으로 삼지 않는다. 중요한 학습·선택 질문은 협업의 일부다. DB·인증 장면은 당시 대화의 구별·선택을 확인한 것이며, 그때 AI가 말한 인증 처리의 일반성이나 제품의 기술적 적절성을 이번에 새로 검증한 것은 아니다.

작게 확인하려면 다음 실제 유사 논의 한 건을 골라 위 기본안·추가 선택의 구별을 적용해볼 수 있다. 실행할 Work가 정해진 뒤 그 Ticket에 필요한 설명과 확인할 결과를 남기고, 관련 기록을 읽지 않은 다음 Main도 무엇을 해볼지 복원할 수 있는지 먼저 본다. 그 뒤 실제 대화 결과를 대조한다. 이 순서는 재진입 경로의 확인과 협업 효과의 확인을 구별하는 시험 제안이며 아직 실행하지 않았다.

## 로렌·맷에서 가져올 것과 조정할 것

**맷의 [chief-of-staff](../source/workflow-reference-supplements/2026-10-27-learning-perspectives/repository/skills/skills/in-progress/chief-of-staff/SKILL.md)**에서 오래 남길 발견을 그때그때 보존하고, 관련된 기존 주제를 갱신하며, 판단 전에 다시 읽는 방식을 가져온다. 우리에게는 Work records와 현재 판단을 가진 Ticket·current가 있으므로 별도 wiki를 기본 추가하지 않는다. 역사 기록에 날짜·당시 조건을 남기되, 현재 채택한 기준은 Personal·스킬의 현행 본문이 설명한다. 원문 링크만 남기는 방식은 우리 근거 보존 기준에 맞춰 필요한 발췌를 함께 남긴다.

**로렌의 [automate-me](../source/workflow-reference-supplements/2026-10-25-pstack-context/automate-me/SKILL.md)**에서 여러 대화의 신호를 대조하고, 말로 드러나지 않은 의도는 사용자에게 보충받고, 결과가 실제 AI 행동에 쓰이도록 연결하는 방식을 가져온다. 개인 선호를 모두 새 mode 스킬에 넣거나 복수 관찰을 모든 채택의 필수 조건으로 만들지는 않는다. 명시적 사용자 기준은 한 번의 발화로도 충분할 수 있고, 사용자 방식에 맞추는 것과 그 방식 자체를 더 좋게 만드는 것은 별도로 판단한다.

## 개선 리뷰와 현재 확인

Main이 첫 제안을 작성한 뒤 새 컨텍스트의 개선 리뷰어 한 명이 기존 계약·외부 두 원문·인터뷰와 보존된 개발 원문을 직접 대조했다. 현재 구조의 기본 책임은 유지하고, ① 주제의 이해를 종합하며 선택한 시도를 실행 Work로 전달·회수하는 연결, ② 사용자에게도 유용한 판단 질문의 실제 사례, ③ 이미 있는 explain 기준의 적용을 먼저 보는 분기를 보완했다. Main은 원문과 현행 explain을 대조하고 세 개선을 제안에 채택했다. 모든 경험의 전달 의무나 모든 선택의 대안 비교로 확대하지 않았다. 세부 근거·초안 대비 변화·비용은 [리뷰 기록](2026-10-27-ticket05-collaboration-learning-review.md)에 남겼다.

실제 운영 설치·사용 실험·효과 측정은 하지 않았다. 기록 전체의 구성은02, 저장소 사이 전달·배포는06, 실제 적용 관찰은07과 연결한다. 이 경계는05가 제안의 근거·도착점·후속 관찰을 구체적으로 설명할 책임을 대신하지 않는다.
