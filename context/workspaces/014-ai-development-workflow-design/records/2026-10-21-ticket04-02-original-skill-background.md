# 04-02 — 두 설명 스킬의 원래 형성 자료 구성

사용자는 다음 작업에 앞서 SKILLS-CONTENT-POLICY를 읽고, 앞서 지정한 외부 자료를 이용해 두 스킬이 원래 가졌던 background를 먼저 구성하도록 요청했다. [브리핑 배경](prototypes/development-workflow/skills/work-artifact-briefing/_background/README.md)과 [설명 복구 배경](prototypes/development-workflow/skills/explanation-recovery/_background/README.md)에 각각 맥락·발췌 근거·과정 기록·읽기 안내를 만들었다.

## 자료와 구성 판단

외부 `memory-harness-research`의07/06 공동 적용 자료가 안내하는09 이해 지원 연구·005 도출 기록·008의09-05 및09-06 품질 보강·07/08 Spec/Ticket 통합 논의를 읽었다. 확인 당시 HEAD는 `40a9f4ef6d087ddbb1d0ace21549ee92a8cf3b1f`이고 작업 트리는 clean이었다. 외부 파일은 수정하지 않았다. 처음에005·008 기록을 context/workspaces 아래로 해석해 찾지 못했고, 링크를 정확히 해소해 저장소 루트 workspaces의 실제 문서를 확인했다.

원래 설계의 목적은 사용자가 역할·실제 연결·근거를 이해해 자기 판단을 내리는 것이다. 두 스킬은 입력과 조사·대화 수명이 달라 분리됐고, 자연어 이해 요청에 대한 선택 허용은 사용자가 발견하지 못한 문제의 선제 탐지와 다르다. 브리핑의 역할·값·조건·구조 표현 및 구조 선택 설명, 복구의 작은 답·앞선 발화 우선·실제 오류 정정은 각각 형성 근거가 있다. 이를 최신04-02 제안의 채택 근거로 소급하지 않았다.

현재 prototype의 두 SKILL.md는 보류한 이전 수정안이다. 원래 형성 이유와 후속 제안의 지위를 각 배경에 밝혔고, 본문에는 그 지위와 배경의 조건부 읽기 안내만 추가했다. 호출·조사·설명·판정·종료 지침은 수정하지 않았다. 공통 설명 기준의 실행 정본과 다른 스킬은 유지했다.

발췌는 외부 문서의 연속 구간을 그대로 보존하고 문서별 경로·행·SHA-256을 붙였다. 원문 안의 과거 상대 링크는 text 블록 안에서 보존해 현재 prototype의 실행 링크로 바꾸지 않았다. 사용자 발화는 당시 기록에 남은 인용임을 표시했다. 최초 채팅 전문이나 원 영상·실행 자료를 새로 확보한 것은 아니며, 연구·리뷰 보고와 실제 효과를 구별한다.

## 확인과 다음 상태

현재 실행 기준이 SKILL.md에 남고, 목적·의미 변경 시 선택 이유와 근거를 가까운 자료에서 찾도록 구성했다. 13개 연속 발췌의 원문·행 범위·SHA-256이 일치하고 두 SKILL.md는 안내 문단을 제외하면 HEAD 본문과 동일함을 직접 대조했다. 열람 화면을 갱신해 문서142개·코드5개의 원문과 해시, 내부 링크806개·앵커248개를 확인했고 누락은0개였다. 브라우저 실측은 수행하지 않았다. 형성 이유를 읽은 실제 새 독자의 수행이나 새로운 응답 비교를 실행한 결과는 아니다.

04-02는 계속 미완료다. 첫 보고의 책임 분석과 원래 스킬의 책임·한계를 함께 대조할 준비 자료가 생긴 상태이며, 이 작업으로 새 수정안·테스트·설치·커밋을 수행하지 않았다. 병렬 작업인01-01·04-03 및 그 source 수집 변경은 이번 적용 대상에서 제외했다.

## 사용자 지적 뒤 형성 내용 보완

사용자는 “링크로 때우려고 하는것 같은데 더 가져와 필요한만큼 내용을 구성해”라고 지적했다. 최초 구성은 목적·경계의 요약과 짧은 정책 발췌에 치우쳐, 왜 해당 선택이 필요했는지 자체적으로 판단할 구체적인 장면과 대안이 부족했다.

두 context 본문에 원래 문제와 선택 과정을 통합했다. 브리핑에는 실제 LLM 판단·전체 readable flow·사용자 답변이 국소 결과로 대체된 차이, 호출 시점의 네 후보와 미해결 책임, 체크인·체크아웃의 값 대비와 구조 분리의 이득·제약을 넣었다. 복구에는 wait-what에서 가져온 취지와 달리 정한 호출 조건, TripFact 관련 반박의 당시 재확인 기록, 단순 뜻 질문과 오류 정정의 완결된 두 대화, 정정 예시 자체를 다시 고친 이유를 넣었다. evidence에는 해당 원문과 당시 preview의 연속 구간을 가져와 링크 없이도 대비할 수 있게 했다.

이는 새로운 실행 규칙·수정안·시험 결과가 아니다. 당시 분석, 기록이 보고한 대화 관찰, 작성자가 구성한 예시를 구별했다. 원문 저장소와 SKILL.md 실행 내용은 변경하지 않았다.

보완 뒤 원문 발췌19개의 내용·행 범위·SHA-256을 대조했다. 원문 내부의 코드 fence를 포함하는 긴 발췌는 바깥 fence를 네 개로 처리했다. 갱신한 열람 화면은 문서142개, 내부 링크809개·앵커252개에서 누락0개이며 브라우저 실측은 하지 않았다. 본문에서 원래 문제·검토 대안·선택 이유·실제 관찰과 작성 예시의 구별을 확인했다. 독립 독자의 이해나 사용 효과를 검증한 것은 아니다.
