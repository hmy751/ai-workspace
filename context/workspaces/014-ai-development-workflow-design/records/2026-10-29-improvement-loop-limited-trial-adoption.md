# 선택한 한정 시도의 기존 작업 연결과 종료 정리 반영

사용자는 누적 작업·기록의 커밋 뒤 첫 번째 개선안을 구체적으로 설명해 달라고 요청했다. 이전 결과는 `df884f81`에 커밋했고, Main은 Personal의 기존 주제에 선택·이유를 남기며 특정 작업의 기존 재개 본문에 행동·범위를 연결하고 종료 때 임시 지시를 정리하는 안을 설명했다. 사용자는 “그래”라고 수용했다.

## 반영한 범위

- [improvement-loop](prototypes/development-workflow/skills/improvement-loop/SKILL.md): 현재 대화의 즉시 수행, 특정 다음 작업의 기존 지시·재개 연결, 실행 위치 미정, 범위 종료와 수행자의 마무리 책임을 구별했다. Work 생성·후보 등록은 요구하지 않는다.
- [적용 사례](prototypes/development-workflow/skills/improvement-loop/references/application.md): ‘다음 설계 논의 한 번에 비교 후 질문하기’를 선택했다고 가정해 Personal 선택·기존 작업 재개·종료 정리·이후 판단을 펼쳤다. 실제 후보 채택·실행 결과가 아니다.
- [USAGE](prototypes/development-workflow/noline-demo/context/USAGE.md): 해당 작업에 이미 선택된 시도의 적용·종료 범위와 마무리 책임을 읽도록 연결했다. 모든 후보 읽기나 루프 순서를 넣지 않았다.
- [Personal 관리](prototypes/development-workflow/noline-demo/context/personal/experience/MAINTENANCE.md): 실행 위치·미정·실제 사용·미사용·도움·부담·미확인을 같은 주제에 보존하고 실제 지침 전문은 복제하지 않도록 했다.

관련 형성 맥락과 [근접 선택 기록](prototypes/development-workflow/skills/improvement-loop/_background/records/2026-10-29-limited-trial.md), 현재 진입·05·상태·산출물 연결을 갱신했다. 기존 Personal 역사적 경험과 인증 demo의 작업 지시는 유지했다. 새 루트 문서·관리층·자동 실행·개선 리뷰어를 추가하지 않았다.

## 확인 범위

Main은 현재 본문에서 다음 장면의 책임과 경로를 대조했다. 이는 문서 계약 대조이며 실제 후속 세션 수행이나 독립 검토가 아니다.

| 장면 | 본문에서 확인한 처리 |
| --- | --- |
| 현재 대화에서 바로 수행 | 스킬에서 즉시 수행하며 보존용 Work 생성은 요구하지 않는다. |
| 특정 다음 작업에서 실행 | 기존 재개 본문에 상황·행동·종료 범위·마무리 책임·Personal 연결을 두며 USAGE가 해당 선택을 읽는다. |
| 소비할 작업 미정 | Personal에 선택 의사·미정 범위를 보존하고 실행 연결 완료라고 하지 않는다. |
| 다른 작업 또는 종료된 시도 | USAGE에서 적용 범위를 확대하지 않는다. 종료 지시는 수행자가 제거·종료 갱신하고 경험은 보존한다. |
| 적용 기회 없이 종료 | 미사용으로 남기며 자동 연장·성공/실패 판정을 하지 않는다. |
| 실제 수행했으나 효과 불명확 | 수행과 효과를 구별하고 다음 요청 루프에서 필요한 선택을 판단한다. |

문서·링크·표시 사본의 기계 확인 결과는 아래에 기록한다. 실제 후속 대화에서의 회수·수행·종료·효과는 미확인이다. 두 번째 ‘같은 목적에서 수행 수단 비교’ 개선안과05 최종 마감은 아직 남아 있다.

확인 결과: viewer 재생성 뒤 문서212개·코드5개의 원문/SHA 일치, 내부 링크1219개·앵커300개에서 누락0, 화면 스크립트 문법 통과를 확인했다. 변경된 기존 Markdown의 로컬 링크 경로883개도 누락0이며 고정 리뷰 입력·원보고에는 변경이 없다. `git diff --check`를 통과했다. 브라우저 렌더링·제품 동작 검사·새 독립 리뷰는 이번 범위에서 수행하지 않았다. 이번 후속 변경은 아직 커밋하지 않았다.
