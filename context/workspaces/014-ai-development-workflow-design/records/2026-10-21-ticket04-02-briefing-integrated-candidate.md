# 04-02 — 브리핑 통합 수정안과 작업 흐름 연결안

사용자는 유지·보완·실행 연결의 구체안을 바탕으로 브리핑 전체 수정안을 요청했다. 복구 스킬은 일단 유지하고, 내용을 크게 줄이지 않되 서술이 길게 이어지지 않도록 형식을 개선하라고 했다.

비교 기준은 보고서 사건 Git archive의 `.claude/skills/work-artifact-briefing/SKILL.md`다. 문서 결과를 원래 질문에 연결하는 부분과 질문별 종료를 구체화했고, 사용자 요청에 따라 설명의 가독성 기준을 같은 본문에 통합했다. 기존 결과 목록과 반복된 종료 설명은 실제 설명·근거·종료 절에 합쳤다. 역할·값·근거·구조 표현·현재성·Spec/Ticket·권한·기록 책임은 유지했다.

이 파일은 전체 문구를 검토하는 후보이며 운영 SKILL.md가 아니다. 복구 스킬, 기존 prototype의 보류 본문, 공통 기준과 DEVELOPMENT는 수정하지 않았다. 공통 기준 링크는 이 기록에서 열리는 경로다. 실제 스킬 반영 시에는 그 위치의 shared 경로를 사용한다. 기존 형성 자료는 후보의 목적과 과거 선택을 검토할 때 읽으며 새 제안의 자동 채택 근거는 아니다.

아래의 호출 description은 기존과 같고, 본문에서 ‘시작’은 목적·조건별 행동을 쉽게 찾도록 재배열했다. 조사 종류나 완료 판단의 권한을 넓히지 않았다. 정책 `SKILLS-CONTENT-POLICY`와 `skill-creator`의 범위·중복 기준을 적용했다. 효과 검증은 수행하지 않았다.

---

```yaml
name: work-artifact-briefing
description: 사용자가 `/` UI에서 `$work-artifact-briefing` skill을 직접 호출했거나, 이미 존재하는 코드·변경·문서·분석·review 결과의 전체 역할·대표 흐름·실제 연결·현재 상태 또는 근거가 보장하는 범위를 이해하려 할 때 원자료를 조사해 설명한다. 한 값·위치 조회, 단순 요약·진행 보고, 구현·수정·진단·review·acceptance 판정이 주목적인 요청에는 자동 적용하지 않는다.
```

# 작업물 이해 브리핑

이미 존재하는 작업물이 **전체에서 무슨 역할을 하고, 실제로 어떻게 연결되며, 무엇까지 확인됐는지** 설명한다. 사용자가 그 의미와 근거를 이해해 다음 질문이나 지시를 만들 수 있게 한다.

최근 코드 변경, 현재 구조와 동작, 특정 시점의 과거 상태, 문서·분석·review 결과와 코드 외 산출물을 다룬다. 파일 목록·diff 통계·test 숫자를 나열하는 것으로 설명을 대신하지 않는다.

목적·선택 이유를 확인하거나 스킬의 의미를 바꿀 때는 [형성 자료](prototypes/development-workflow/skills/explain/_background/legacy/work-artifact-briefing/README.md)에서 관련 배경과 근거를 읽는다. 현재 요청의 실행 기준은 이 본문과 해당 조건의 실행 자료를 따른다.

## 시작

1. **질문과 목적을 잡는다.** 설명할 대상·시점과 사용자가 이해하려는 내용을 확인한다. 이미 밝혀진 내용을 되묻지 않는다.
2. **관련 기준을 찾는다.** 실제 프로젝트의 root AI 지침과 그 지침이 안내하는 관련 맥락, 필요한 기존 문서와 공통 [설명과 근거 기준](prototypes/development-workflow/skills/shared/explanation-and-evidence-criteria.md)을 읽는다.
3. **답을 바꾸는 기준 상태를 확인한다.** 현재 대상이면 branch·HEAD·working tree·관련 runtime 설정을, 과거 대상이면 commit·날짜·산출물 생성 시점과 당시 원자료를 확인한다. 현재성을 확인하지 못하면 설명의 효력 범위를 밝힌다.
4. **질문에 필요한 원자료를 조사한다.** 관련 Project 정본과 source·진입점·사용처·설정·실제 연결·test를 확인한다. 실제 동작이 중요하면 허용된 범위에서 trace·log·실행 관찰도 확인한다.

### Work의 목표·진행을 설명할 때

관련 Spec·Ticket에서 다음을 골라 실제 코드·산출물·검증 결과와 연결한다.

| 자료 | 확인할 내용 |
| --- | --- |
| Spec | 이루려는 결과와 공통 기준 |
| Ticket | 맡은 결과·범위, 실행 맥락·접근, 완료 조건·확인 방법 |
| 실제 결과 | 보고된 진행과 실제 수행, 확인할 계획과 이미 확인한 결과의 차이 |

전체 Spec·모든 Ticket을 기본 입력으로 삼지 않는다. 문서의 존재나 완료 표시만으로 실제 수행·검증 또는 전체 목표 충족을 인정하지 않는다. 코드 개선에서는 **기존 동작을 보존했다는 근거**와 **책임·중복·변경 부담을 개선했다는 근거**를 구별한다.

## 대상에 맞춰 조사한다

### 방금 또는 특정 변경

- 사용자가 정한 base가 있으면 따른다. 없으면 현재 working tree·staged change·관련 commit history를 보고 비교 기준을 밝힌다.
- Diff와 함께 변경 후 source, 실제 사용처와 호출 경로를 확인한다.
- 전후 변화가 전체 역할·대표 흐름·상태·외부 효과에 어떤 차이를 만드는지 연결한다.

### 현재 구조와 동작

- 사용자 입력이나 대표 사건의 진입점에서 결과·외부 효과까지 따라간다.
- 각 component의 책임·경계·호출·소비 관계를 정확한 file·symbol·사용 위치와 연결한다.
- Interface나 type의 존재와 실제 runtime provider·설정·연결을 구별한다.

### 과거 코드나 작업물

- 당시 commit·보존 문서·대화·review·산출물 중 필요한 원자료에 시점을 고정한다.
- 당시 보고, source로 확인한 사실, 현재의 해석을 구별한다.
- 과거 상태를 현재 working tree에도 그대로 유효하다고 확대하지 않는다.

### 문서·분석·review 결과

- **질문과 결과를 연결한다.** 어떤 질문과 기준에 답하려던 산출물인지 확인하고, 현재 설명할 결과가 그 질문의 어느 부분에 답하는지 연결한다.
- **후속 자료의 맥락을 잇는다.** 이전 문제를 다시 확인한 자료라면 당시 문제·그 뒤 변경·이번 확인의 관계 중 현재 결론을 바꾸는 부분을 함께 설명한다.
- **근거의 간극을 다룬다.** 직접 확인한 finding과 작성자의 해석·미확인을 구분한다. 확보한 근거가 현재 질문에 답하지 못하면 그 간극을 밝히고, 답에 필요한 사실은 허용된 범위에서 더 확인한다. 새 진단·review나 실행이 필요하면 현재 설명으로 확인한 범위와 이어서 수행할 일을 구별한다.
- 문서가 가리키는 live code·test·설정이 중요하면 현재 사실을 소유한 원자료까지 내려가 대조한다.

## 이해할 수 있는 결과로 설명한다

**현재 질문의 결론과 대상의 전체 역할을 먼저 보여 주고, 대표 흐름에서 필요한 세부로 내려간다.** 사용자가 이름과 호출 순서를 혼자 조립해 역할을 추측하게 하지 않는다.

| 설명할 내용 | 연결하는 방법 |
| --- | --- |
| 핵심 이름과 책임 | 중요한 이름을 처음 쓰는 자리에서 가리키는 데이터·책임과 사용자가 하려는 일에서의 역할을 설명한다. 기존 file·symbol 이름은 실제 위치를 찾을 수 있게 남긴다. |
| 실제 연결과 변화 | 대표 입력·사건이 component와 상태 변환을 거쳐 결과가 되는 과정을 보여 준다. 변경 설명이면 전후 차이가 그 과정에 미치는 영향을 연결한다. |
| 중요한 주장과 근거 | 무엇을 확인했는지와 해당 source 위치를 주장 가까이에 둔다. source상 가능한 동작, 실제 연결·관찰, test·compiler의 보장 범위를 구별한다. |
| 미완성과 열린 판단 | stub·mock·hard-coded·미연결·미구현·미확인 중 답의 의미를 바꾸는 것을 드러낸다. AI 해석과 사람이 결정할 부분, 더 확인할 위치도 구별한다. |

### 추상 설명만으로 차이가 드러나지 않을 때

- 대표 장면의 **입력·중간 값·결과** 중 필요한 값을 연결해 무엇이 왜 달라지는지 보여 준다.
- 실제 확인한 값인지 설명용 값인지 밝힌다. source에서 재구성한 동작, 관찰한 실행, 제안한 동작을 구별한다.
- 대표 흐름만 보면 오해할 수 있는 중요한 조건은 결과 차이를 함께 비교한다.

모든 브리핑에 사례를 추가하거나 모든 실패 경로를 펼치지는 않는다.

### 다음 변경이나 선택을 위한 설명일 때

- 중요한 구조 선택이 **무엇을 쉽게 만들고 어떤 제약을 남기는지** 현재 질문과 연결한다.
- 당시 선택 이유는 보존된 근거로 확인할 때만 말한다. 현재 구조에서 도출한 효과와 구별한다.
- 모든 구조의 장단점·선택 이력을 기본으로 조사하거나 일반 동작 설명을 전체 architecture review로 확대하지 않는다.

### 읽기 쉬운 형식을 고른다

- 핵심 답과 판단을 가르는 조건은 먼저 보이게 하고, 이유와 상세 근거는 해당 내용 가까이에 둔다.
- 비교할 조건·전후 차이·책임 대응은 표나 목록으로, 인과와 선택 이유는 짧은 문단으로 연결한다. 실제 코드가 필요한 설명에는 관련 코드와 그 의미를 함께 둔다.
- 문단이 길어져 서로 다른 질문이나 조건이 섞이면 소제목·문단·표로 구분한다. 분량을 줄이기 위해 중요한 전제·값·한계를 삭제하지 않는다.
- 직접 호출에서는 `작업물 이해 브리핑 — <대상>`을 기본 제목으로 쓰고, 자연어로 선택된 짧은 답에서는 생략할 수 있다. 고정 목차·줄 수·표 개수를 요구하지 않는다.

## 관계를 구조로 보여 줄 때

결론과 전체 역할을 말한 뒤, 관계·분기·상태 변화를 문장만으로 계속 되짚어야 하고 그 관계를 놓치면 답의 의미가 달라질 때 **현재 질문에 필요한 가장 작은 부분 구조**를 보여 준다.

실행·상태 변화에는 flow, 책임·소유·의존에는 tree나 map, 전후 차이·정확한 대응에는 delta 표현이나 table을 고려할 수 있다. 고정 대응은 아니며 문장이나 짧은 목록이 더 명확하면 그것을 쓴다.

| 확인할 것 | 표현 기준 |
| --- | --- |
| 중심 관계 | 한 구조에서는 실행 순서·의존·역사·근거 강도 중 현재 질문의 중심 관계 하나를 우선한다. |
| 관계의 근거 | Node뿐 아니라 화살표·묶음·방향도 호출·시간·데이터 이동·소유·의존에 관한 주장이다. source·설정·실행 관찰·당시 산출물·설계·review 근거가 지지하는 관계만 표시한다. 설명을 위해 도출한 묶음은 설명용임을 밝힌다. |
| 활성·완성 상태 | 기본·opt-in·disabled·stub 등의 차이가 결론을 바꾸면 구분한다. 미확인은 근거 한계로 남긴다. |
| 재구성과 실제 실행 | source·설정으로 재구성한 흐름은 그 범위와 live trace가 아니라는 점을 밝힌다. 관찰된 실제 실행은 trace·log·실행 관찰이 있을 때만 말하며, 근거가 섞이면 연결이나 구간별로 구분한다. |
| 생략 범위 | 대표 경로나 질문 관련 부분만 보였다면 전체 architecture처럼 보이지 않게 범위를 밝힌다. 중요한 부분은 정확한 source·사용 위치·필요한 실행 근거로 내려간다. |

## 근거와 판정 경계

- 설계 의도·현재 source·실행 관찰·test·compiler·rule·AI 해석이 답하는 질문을 섞지 않는다.
- 직접 확인한 불일치와 그 때문에 제한되는 설명 범위를 드러낸다. 변경의 영향을 설명하는 데 필요한 source·history·test는 이 스킬 안에서 더 조사한다.
- 요구 위반·위험 수용·최종 acceptance를 설명 속에 몰래 확정하지 않는다. 그 판정까지 요청받았다면 확인 근거와 열린 선택을 보여 주고 판정 책임을 밝힌다.
- 기본 행동은 read-only 조사와 설명이다. 설명 요청만으로 code·문서·review 결과·Workspace 상태의 수정으로 확대하지 않는다.

## 끝낼 때

**현재 질문에 답했고**, 대상의 역할·실제 변경이나 연결·결론을 바꾸는 근거 한계와 미확정이 드러나면 현재 브리핑을 끝낸다.

| 사용자의 목적 | 답에 필요한 마무리 |
| --- | --- |
| 구조와 동작 이해 | 그 역할과 연결을 이해하는 데 필요한 답으로 마친다. |
| 진행·남은 일·다음 선택 판단 | 무엇이 해결·미해결·판단 대기인지와 그것이 다음 행동에 갖는 의미까지 연결한다. |

추가 세부는 현재 질문에 필요한 부분부터 펼친다. 모든 file·symbol·branch·history·설정·test를 전부 조사할 필요는 없다. 기준 source·runtime·산출물이 바뀌면 결론도 달라질 수 있을 때만 재확인 조건을 남긴다.

### 확인한 차이와 기록 연결

- Main은 설명 중 확인한 차이·정정과 근거 한계를 최종 응답에 드러낸다. 서브가 설명했다면 그 내용을 Main에게 반환한다.
- Spec·Ticket·Workspace 문서 갱신은 root AI 지침이 안내하는 상위 운영 계약에 따라 Maintain에 맡겨 중복 수정을 피한다. 다음 실행이 문서에 의존하면 필요한 실제 반영을 확인한다.
- 설명을 제공한 사실만으로 새 요구나 작업 완료를 확정하지 않는다.

# 별도 연결안 — 조사·검토의 첫 결과보고

브리핑은 기존 작업물 이해를, recovery는 앞선 응답의 뜻·논리 복구를 계속 맡는다. 아래는 작업 흐름이 소유할 실행 책임의 후보다.01-01·04-03에서 정하는 실제 절차의 결과 통합·보고 부분에 연결하며 새 agent 수나 고정 관문을 정하지 않는다.

| 시점 | main이 맡을 일 | 다음 행동을 정하는 기준 |
| --- | --- | --- |
| 조사·위임 시작 | 원래 질문에 필요한 대상·조건과 수집·판단 담당을 전달한다. | 화면·파일의 수가 아니라 어떤 질문에 답할 자료인지 |
| 결과 반환 | 관찰·코드·test가 실제로 답하는 조건과 원래 질문을 대조한다. | 필요한 관찰을 확보했는지, 다른 조건의 관찰인지 |
| 중요한 간극 발견 | 필요한 추가 확인을 수행·조정하거나 결론의 범위를 제한한다. | 결론에 미치는 영향, 허용 범위, 확인 비용과 구체적인 제약 |
| 첫 결과 전달 | 원래 문제·이번 결과·근거·남은 문제·그에 따른 행동을 종합한다. | 맡은 조사·검토가 끝났는지와 무엇이 아직 남았는지 |

## 작업 절차에 통합할 문구 후보

Main은 작업을 시작하고 결과를 받는 과정에서, 이번 판단이 답해야 할 질문과 확보한 근거를 대조한다.

- 위임할 때는 필요한 대상·조건과 수집·해석의 담당을 전달한다.
- 반환된 자료가 그 질문에 답하는지 확인한다.
- 중요한 간극이 남으면 결론에 미치는 영향, 허용 범위와 확인 비용·제약을 따져 필요한 확인을 이어가거나 현재 결론의 범위를 제한한다.
- 미확인 표시는 조사 종료의 이유를 대신하지 않는다.

첫 결과를 전달할 때는 원래 문제와 이번 결과를 연결해 현재 답·근거·남은 문제와 그에 따른 행동을 종합한다.

- 실제로 마친 조사·수정·확인과 남은 작업을 구별한다.
- 자료 수집이나 보고서 파일 생성만으로 맡은 검토가 끝났다고 보고하지 않는다.
- 이 설명은 사용자 재질문을 기다리지 않고 작업 결과의 일부로 수행한다.

## 공통 설명 기준의 사용 연결

작업 결과보고가 기존 공통 기준을 직접 사용하도록 연결하는 안이다. 현재 shared의 적용 범위는 세 스킬에 한정돼 있으므로 작업 절차에 링크만 추가해서는 충분하지 않다.

| 함께 맞출 위치 | 변경 내용 |
| --- | --- |
| 작업 절차의 첫 결과보고 | 사용하는 시점과 공통 설명 기준으로 가는 읽기 경로 |
| 공통 기준의 적용·수명 | 명시적으로 사용하는 작업 결과보고도 consumer에 포함. 소비자 소멸·통합 시 재검토 조건도 함께 맞춤 |
| skills 안내 | 세 스킬과 작업 결과보고의 공통 기준 사용 관계 |

공통 기준 첫 문단의 교체 후보:

> 이 문서는 `work-discussion`, `explanation-recovery`, `work-artifact-briefing`이 적용되거나, 작업 수행 절차가 조사·검토·구현의 첫 결과를 설명하는 기준으로 명시해 사용할 때 적용한다. Skill별 호출과 행동은 각 SKILL.md가, 조사·구현·검토의 수행과 종료는 해당 작업 절차가 소유한다. 이 문서가 일반 대화와 모든 응답의 자동 적용 workflow가 되지는 않는다.

공통 기준의 근거 구별·설명 깊이는 한 곳에서 유지한다. 조사 조정·충분성 판단·첫 결과 전달의 실행 책임은 작업 절차가 소유한다. 이번에는 연결안을 제시한 것이며 실제 공통 기준과 작업 절차는 바꾸지 않았다.

## 확인 범위

당시 원문과 대조해 호출·역할·조사 대상·값과 조건·구조 표현의 근거·종료·부작용·기록 책임을 유지했는지 확인했다. 새 의미는 문서 질문과 결과의 연결 및 근거 간극 대응, 목적별 종료, 사용자가 요청한 읽기 쉬운 응답 구성이다. 반복된 결과 항목은 대응 절에 통합했다. 이 확인은 문구와 구성의 대조이며 새로운 응답 실행·사용자 이해 효과 검증이 아니다.
