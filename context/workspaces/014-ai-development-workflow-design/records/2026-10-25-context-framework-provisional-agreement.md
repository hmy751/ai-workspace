# 04-03 — 맥락 사용·반영 구성의 잠정 합의와 재개 기준

후속 2026-10-26: 이 잠정 틀을 바탕으로 [네 항목별 초안·독립 개선 리뷰·통합안](2026-10-26-context-integrated-proposal.md)을 만들었다. 현재 다음 행동은 사용자와1번부터 구체안을 논의하는 것이다. 아래는 잠정 합의가 형성된 당시 경로이며 사용감 유보·실행 미승인의 경계는 유지한다.

2026-10-25. **현재 제시한 틀을 다음 구체화의 잠정 작업안으로 삼기로 합의했다.** 사용자는 USAGE라는 공통 참조와 context-update라는 스킬로 나누는 데 완전히 납득한 것은 아니라고 했고, 그 유보를 남긴 채 이 정도 틀에서 잠정 합의를 보자고 요청했다. 단순히 제안을 듣고 넘어간 상태도, 세부 구성까지 최종 확정한 상태도 아니다.

이번 수행은 논의·원문·잠정 합의와 current의 기록 갱신이다. 새 USAGE·context-update 생성, 기존 실행 본문 이관·교체, 설치·runtime 연결·효과 시험은 수행하지 않았다.04-03 전체는 계속 진행 중이며 다른 Ticket의 완료 상태를 바꾸지 않는다.

## 유보가 남는 부분

**읽기와 반영의 책임을 구별하는 것과, 읽기는 참조 파일·반영은 스킬이라는 서로 다른 형태로 나누는 것은 별도 판단이다.** 사용자가 걸린 부분은 후자의 사용감이다. 읽다가 반영 필요를 발견하고 반영하려면 다시 읽는 연결을 실제로 펼쳤을 때 자연스러운지는 더 살핀다.

- `USAGE`와 `context-update`의 정확한 이름·파일 형태·호출 방식은 최종 고정하지 않는다. 현재 배치는 잠정 출발점이며 필요하면 묶음을 조정한다.
- 공통 참조로 옮길 실제 조항과 각 영역에 남길 기준, 지정된 Personal·Project 반영을 하나의 수행으로 묶는 범위를 구체화한다. 기존 일반 문장을 양쪽에 그대로 두어 관리 정본을 늘리지 않는다.
- 이 유보를 담당자의 원문 직접 읽기, Personal·Project·Work의 내용 책임, Main의 Work 유지·전체 연결까지 다시 미정이라는 뜻으로 넓히지 않는다.
- 구현·설치·효과·제거 성공은 아직 확인하지 않았다. 외부 자료에서 확인한 지시·책임 배치도 실제 운영 효과의 증명이 아니다.

하나의 context 스킬 안은 이전부터 비교 가능한 대안이었다. 이번 유보만으로 그 안으로 즉시 되돌아가거나 현재 안을 폐기하지 않는다. 반대로 잠정 합의가 나왔다는 이유로 사용자의 불편함을 해소된 것으로 기록하지 않는다.

## 이번 잠정 합의를 판단한 직접 발화

아래는 이 대화에서 파일 구성을 요청한 시점부터 잠정 합의까지의 사용자 발화를 본문 그대로 보존한 것이다. 대화 전체의 축어 전사본은 아니며 앞선 핵심 발화·형성 과정은 위 연결 기록에서 찾는다. 오탈자는 고치지 않았다.

사용자 — 파일 배치 요청:

> 그럼 디렉터리랑 파일 구성등도 일단 보여줘봐 어떻게 구상하고 있는지

Main은 현재 `development-workflow/skills/`와 `noline-demo/context/`의 위치를 유지한 트리를 제시했다. 새 USAGE·context-update 및 형성 자료는 추가 후보로 표시하고, 기존 Work 구조를 유지하며 실제 생성·이동·설치는 하지 않았다고 설명했다. 그 배치의 보존본은 위 구체안에 추가했다.

사용자 — 분리 방식에 대한 유보:

> 음 크게 나쁜것 같진 않은데 뭔가 USAGE랑 conex-update가 나뉘니까 음 느낌이 딱 백프로 괜찮다? 정도의 느낌은 아닌것 같아 뭐 일단 그렇네

Main — 응답 중 판단에 필요한 발췌:

> 책임을 구별해야 한다는 것과 파일·호출 형태까지 갈라야 한다는 것은 별개인데요.

Main은 영역별 내용 책임·Main의 작업 연결·일상 유지와 경험 개선의 구별은 유지하되 USAGE/context-update의 묶음은 후보로 두겠다고 답했다. 사용자의 느낌을 명확한 반대 이유로 억지 정리하거나 곧바로 다른 구성으로 뒤집지 않겠다는 응답이었다.

사용자 — 잠정 합의와 기록 요청:

> 그래 그럼 이정도 틀로 일단 잠정 합의를 보자 여태 논의들 잘 기록 남겨놔줘

이 마지막 요청으로 현재 틀의 지위가 **검토 중인 추천안에서 다음 구체화를 위한 잠정 합의안으로 진전**했다. 바로 앞의 유보를 취소하거나 구체 파일·스킬 생성을 지시한 말로 해석하지 않는다.

사용자는 다음 일을 물었고 Main은 ‘기존 조항 대조, 읽기·반영 본문 초안, 참조·스킬의 묶음 다듬기’로 답했다. 사용자는 다음과 같이 정정했다.

> 아니 지금 너무 최근 논의에 집중된것 같은데? 틀은 어느정도 생각했고 우너래 하려던거랑 종합해서 해야되는거 아니야?

이 정정은 잠정 합의를 철회하거나 기존 역할 설계 전체를 다시 열라는 요청이 아니다. **잠정 틀을 원래 과제에 사용할 기준으로 두고, 기존 시스템·새 워크플로·원래04-03의 결과 범위를 합쳐 다음 작업을 정하라는 요청**이다. Main의 직전 답은 원래의 전체 context 연결 과제를 읽기/반영 지침의 본문화로 좁혔고, 저장한 다음 행동도 같은 방향으로 편중돼 있었다.

원래 [재개 기록](2026-10-24-workflow-context-connection-checkpoint.md)은 작업 재개·역할 인수와 추가 탐색·정본/현재 기록 반영·완료 후 재개/독립 작업 생성의 연결안을 요구한다. [첫 연결안](2026-10-24-ticket04-03-context-connection-proposal.md)에는 이미 네 장면과 Noline/Reference 스킬 대조가 있으며, 기존 create가 현재 demo에 없는 Harness를 전제한다는 공백도 확인돼 있다. 이를 재조사하거나 스킬 이름을 보존할 근거로 삼지 않고 현 잠정 틀과 종합한다.

따라서 위 재개 기준과 current·Spec·Ticket의 다음 행동을 전체 연결·보완으로 맞췄다. 의미가 바뀐 사실·현재판과 당시 입력판·접근 실패·변경 반환·다음 재개까지 실제 문서와 역할 경로로 연결하고, 새 Work의 의미 계승·선택/전환과 runtime 의존을 빠뜨리지 않는다. 기존 스킬의 조항 이관은 이 전체 결과에 필요한 만큼 수행할 후속이다. 이번 정정에서 실제 스킬·공통 참조 생성이나 운영 적용을 시작하지 않았다.
