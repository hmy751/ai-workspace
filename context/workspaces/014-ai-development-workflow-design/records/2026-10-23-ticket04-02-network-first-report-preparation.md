# 04-02 — Network 첫 완료 보고의 자료 확보와 적용 배치 비교 준비

**자료는 확보했고 비교 조건은 제안 상태다. 응답 시험은 미실행이며, 후속 질문으로 스킬 적용의 적절성부터 다시 판단할 지점이 열렸다.** 사용자는 “첫 완료 보고 당시 코드랑 변경 내역 확보해서 시점 비교부터 준비해봐. 실제 대화 어디서 시작하고 어떤 조건으로 비교할지 먼저 보여줘. 바로 테스트 돌리진 말고”라고 요청했다. 현재 스킬 본문·운영 설치는 변경하지 않았다.

[원자료06](../source/artifact-explanation-scenes/06-network-consumer-delivery/README.md)에 첫 완료 보고 직전 상태를 보존했다. [비교 준비 묶음](experiments/artifact-explanation-network-placement-2026-10-23/README.md)은 동결 기존판·동일 목록·공통 안내·조건 차이를 소유한다.03의 network.ts 흐름 질문과 같은 대화지만 더 이른 작업이며 코드 상태도 다르다.

## 후속 논의 — 현황 파악과 스킬 적용을 같은 일로 전제하지 않는다

자료 준비 뒤 사용자는 다음과 같이 말했다.

> 근데 이게 파악하란게 처음부터 아티팩트 브리핑으로 해야되는건가? 싶기도 하고 음 일단 워크스페이스 기록 잘 남길거 한번 훑어보면서 남겨봐 다른세션에서도 이 워크스페이스 작업 흐름을 이어갈정도로

이는 적용 적절성에 대한 의문과 기록 정리 요청이다. 브리핑 조기 적용의 승인이나 모든 현황 파악에서의 적용 금지로 확정하지 않는다.

| 구별할 지점 | 현재 의미 |
| --- | --- |
| 대화 시작9의 “현황 파악” | 당시 작업 맥락을 복원하는 요청이다. 이 단어만으로 작업물 이해 브리핑이 주목적이라고 확정하지 않는다. |
| 입력 대화9~844 | 완료 보고의 맥락을 제공하는 원문 범위다.9부터 스킬을 켜거나 작업을 재실행한다는 뜻이 아니다. |

| 이후920의 명시 브리핑 요청 | 실제로 존재한 후속 요청이지만 생성 입력에서는 제외한다. 그 요구를895 이전에 소급해 주지 않는다. |

현재 스킬 description은 작업물의 역할·흐름·연결·상태 이해를 다루며 단순 요약·진행 보고, 구현·review가 주목적인 요청은 자동 적용에서 제외한다. 따라서 **첫 보고에서 필요한 충분한 설명 책임**과 **그 책임을 이 스킬의 호출로 수행해야 하는지**를 나누어 판단해야 한다. 최초 티켓 파악 비교에서 스킬을 양쪽에 적용했던 사실도 자연 적용의 적절성을 입증하지 않는다.

다음 재개에서는9의 현황 파악,895의 완료 보고,920의 작업물 이해 요청 각각의 목적을 당시 합의·스킬 조건과 대조한다.895에서 빠진 설명 책임이 무엇인지와 그 책임을 기존 수행 흐름·브리핑 중 어디에 연결할지 판단한 뒤, 아래 A/B가 실제로 답할 질문과 적절한 비교인지 정한다. 준비한 조건은 유지하되 채택된 실행안으로 취급하지 않는다. 단순히 실행 요청만 기다리는 상태라는 앞선 안내는 이 후속 논의로 갱신한다. 이번에는 기록만 정리하며 스킬 본문·발동 규칙·실험 프롬프트를 바꾸지 않는다.

## 확보한 코드와 변경 내역

- 당시 HEAD는 `7cfa7db7f4a56f05f618163b80c77848032e28a3`다. 부모 원 로그 해제 해시는 기존 corpus와 일치한다. 당시 워커3개와 검토자1개의 원 로그도895 이전에 한정해 대조했다.
- **작업 전52개 → 첫 보고 전69개** 코드·테스트·설정 파일을 구성했다.63개 경로가 변했고 그중17개는 새 파일이다.6개는 이전 구현을 유지했다. 이미 있던 미커밋 Network Store 등을 이번 작업에서 새로 만든 것으로 세지 않는다.
- 69개 중33개는 당시 전체 파일 읽기 출력과 동일하고26개는 기록된 diff의 Git blob 해시와 일치한다. 나머지10개는 기록된 생성·치환·patch·포맷 과정으로 복원했다. 모두 원 파일을 그대로 복사했다는 뜻은 아니다.
- Root·두 상세 화면·일정 화면의 최종 주요 구간도 당시 후속 읽기 출력과 일치했다. 전후 diff를 별도 이전 사본에 적용한 결과69개 모두 이후 사본과 일치했다. 이는 복원 묶음의 정합성 확인이며 제품 테스트 재실행이 아니다.
- 당시 Spec·합의·Ticket과 갱신 기록, 공통 근거 기준, 호출 관계를 확인할 지원 소스12개, 최종 검사·독립 검토의 원문을 함께 확보했다.205개 테스트 통과와 기존 지도 타입 오류3개는 과거 관측으로 표시한다.

임시 백업 원 디렉터리는 남아 있지 않다. 당시 state/output의 dirty 전문과 실행 환경 전체는 복원하지 않았고, 그 문서의 HEAD판을 첫 보고 당시 최신 상태처럼 넣지 않았다. 직접 관측과 기록 기반 복원의 파일별 지위·중간 문제는 source manifest와 provenance에 남겼다. 필요한 설명 자료를 확보한 것과 전체 역사적 실행 재현은 별개다.

## 본문을 고정한 두 조건

본문은 앞선 저장 용량 시점 비교에서도 사용한 **원래 기존판**으로 고정한다. SHA-256은 `40a916e543313333a084da927e3e5200aebc73548fa99eecc4968fa1cb3caff2`다. 스킬 내용은 같고 공통 근거 링크만 실행 사본 안에서 찾을 수 있게 했던 동일 판본이다. 직전 채택판·이번 책임 설명 보완판과 비교하는 시험이 아니다.

| 조건 | 같은 점 | 다른 점 |
| --- | --- | --- |
| A — 기존 조건의 자연 선택 | 동일한 완료 시점, 대화·코드·문서·검사, 기존판 스킬 목록과 접근 가능 본문 | 별도 직접 호출 없이 다음 응답을 작성한다. 스킬을 선택할지는 실행자가 결정한다. |
| B — 첫 보고 전 명시 적용 | A와 모두 동일 | 결과 자료를 읽기 전에 같은 스킬 전문을 읽고 적용하라는 문장 하나만 추가한다. |

추가 문장 전문:

> 이번 응답에 사용할 결과 자료를 읽기 전에 `work-artifact-briefing` 스킬 전문을 읽고 적용하세요.

GPT-6-sol medium, 대화 상속 없는 독립 실행으로 각1회만 수행하는 안이다. Main의 설명 목차·도식 의무·코드 개수·범위 오판 지적·기대 답을 추가하지 않는다. 두 조건 모두 원자료의 당시 판단을 받되 현재 Main의 정답 해석은 받지 않는다. B의 명시 적용은 실험 조작이며 원래 사용자 발화로 위장하지 않는다.

**이는 자연 선택과 첫 보고 전 명시 적용이라는 호출 배치 비교다.** 두 실행 모두 반드시 서로 다른 시점에 읽게 만드는 순수 시점 실험으로 부르지 않는다. A가 스스로 같은 시점에 적용하면 시점 차이 미성립으로 기록한다. A를 일부러 못 읽게 하거나 뒤의 사용자920를 A에만 제공해 차이를 만들지 않는다. 새 본문·새 작업 흐름 지침을 동시에 넣지 않는다.

## 무엇을 확인하고 무엇을 확인하지 않는가

1. 먼저 실제 도구 읽기 순서와 적용 여부를 확인한다. A의 자연 선택·미선택과 B의 결과 자료 전 전문 읽기·적용이 실제로 갈렸는지 본다. 선언만으로 확인하지 않는다.
2. 같은 첫 보고에서 사용자가 변경의 역할·범위·대표 연결·근거 한계를 판단할 수 있는지 원 코드와 대조한다. 테스트 숫자·파일 목록·길이·도식 개수로 우세를 결정하지 않는다.
3. 당시 AI의 범위 판정을 반복하는지, 사실과 선택의 근거를 구별하는지도 살피되 ‘범위 초과를 반드시 발견해야 한다’는 정답을 생성자에게 주지 않는다. 잘못된 정당화를 더 자세히 쓴 것은 개선으로 올리지 않는다.

이미 완료된 코드를 고정한 비교여서 구현 전에 범위 확대를 막는 효과는 검증하지 않는다. 실제 사용자의 이해 향상·재질문 감소·지속 효과도 한 쌍의 대리 응답으로 확정하지 않는다. 원래895와 뒤의963은 역사적 비교 자료이며 모델·맥락이 같은 통제군으로 취급하지 않는다.

## 실행 전에 유지할 자료 경계

실행 지시가 오면 허용 자료만 두 독립 공간에 동일하게 복사한다. source 폴더 전체·원 로그 위치·evaluation·복원 스크립트·현재 이 판단 문서·상대 응답은 주지 않는다. 필요한 파일은 전문을 조각으로 읽고 누락·잘림 여부를 확인한다. 스킬을 선택했다면 본문과 공통 근거 기준도 전문을 읽어야 한다. 읽기 로그와 실제 도구 이력을 함께 보존한다.

현재 준비 단계와 후속 기록 정리에서는 새 서브 호출·응답 생성·제품 검사·스킬 수정·커밋을 하지 않았다. 다음은 위 후속 논의의 요청 성격·적용 적절성과 비교 목적을 판단하는 것이다. 자료 준비만으로 실행에 착수하지 않는다.
