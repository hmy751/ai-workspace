# context/personal 위치 선택과01·새 구체화의 실제 본문 비교

2026-10-19. 사용자는 개인 기준을 ai-workspace의 `context/personal/` 층에 두기로 선택했다. [85](2026-10-19-85-personal-location-proposal-and-format-provenance.md)의 글로벌 배치 추천은 대체한다. 이어01에서 반영한 내용과 이번 Main이 새로 구체화한 내용을 실제 문장으로 나란히 비교하고 이유까지 설명하라고 요청했다. **위치 선택과 본문 전체의 채택, 실제 파일 이동은 구별한다.**

## 사용자 요청

> 아니 그냥 context 하위에 personal 층 두자 글로벌에 두면 관리도 어렵고 잘 안쌓이고 수정 분리도 어려워 보여
> 01에서 결정했던 내용과 니가 이번에 새로 구성한 부분을 실제 본문으로 나란히 비교해봐. 왜 그렇게 구체화했는지도 같이 설명하고, 아직 파일은 옮기지 마.

## 선택한 위치와 유지하는 책임

개인 기준의 위치 방향은 `/Users/hammyeong-yeon/Desktop/ai-workspace/context/personal/`이다. 개발 기준은 그 아래 `development/`에 두는 구성으로 이어갈 예정이며, 구체 문장·파일 구성 전체를 이번 발화로 채택한 것은 아니다. 선택 이유는 사용자가 직접 든 **관리·축적·수정 분리**다. 글로벌에 두자는85의 추천을 유지하거나 실제 위치가 계속 미정이라고 쓰지 않는다.

현행 [context 계약](../../../README.md)은 아직 `workspaces/`와 `source/`를 정의한다. 이번 선택은 Personal이라는 지속 책임을 그 아래에 추가할 방향이며, 이미 존재하던 canonical을 확인한 결과로 소급하지 않는다. 실제 `context/README.md` 변경, 운영 Personal 디렉터리 생성, 기존 파일 이동·통합, 전역 지침·스킬·브릿지 변경은 하지 않는다.

[81](2026-10-19-81-personal-context-direction-and-next-step.md)도 같은 물리 경로를 설계 전제로 삼았지만, 그때 함께 두었던 Project의 개인 기준 직접 참조·채택·갱신 관리 책임까지 복원하지 않는다. [84](2026-10-19-84-personal-project-ownership-and-format-correction.md)의 다음 구별은 유지한다.

- Personal은 여러 Project에 가져갈 개인의 판단·이유·조건을 소유한다.
- Project는 자기 제품의 의미·개발 계약·현재 현실을 독립적으로 설명한다.
- Main/workflow가 작업에 필요한 개인 주제와 대상 Project 본문을 별도로 선택하고 충돌·열린 선택을 판단하며 구현·검토 입력과 결과별 갱신을 연결한다.
- Work에는 이번 요구·선택·변경·검토·확인 한계를 남긴다. 한 작업의 결과로 개인 기준이나 제품 계약이 자동 변경되지는 않는다.

현재 [적용 시안](prototypes/personal-project-applied-2026-10-19/README.md)의 `personal-context/`는 독립 책임을 보여 주는 시안 배치다. 이번에 그 파일들을 운영 경로로 옮기는 것은 아니다. [workflow](prototypes/personal-project-applied-2026-10-19/workflow.md)의 책임을 선택한 실제 위치에서 찾도록 연결하는 세부 안내·전달·설치와 새 skill 필요성은 후속에서 구체화한다. 기존 read-project-context는 대상 Project의 본문을 선택하는 책임을 유지한다.

## 실제 본문 비교에서 구별할 것

[비교 산출물](prototypes/criteria-format-comparison-2026-10-19/README.md)은01의 실제 본문과 이번 Personal·workflow의 실제 본문을 나란히 놓고 다음을 대조한다. 요약 설명만으로 원문을 대신하거나 이번 문장을 이미 결정돼 있던 본문처럼 보이지 않게 한다.

| 비교할 것 | 읽을 지위 |
| --- | --- |
| 이전 본문과 이번 본문 | 각 파일에서 실제 작성된 문장을 보여 준다. 가상 제품 계약이나 사례를 일반 의무로 승격하지 않는다. |
| 유지한 의미 | 앞선 사용자 요청과 시안 반영으로 이어 온 판단·관계가 무엇인지 설명한다. |
| 추가하거나 달라진 부분 | 새 질문·조건별 사례·설명량·본문 분리·읽기 연결 중 이번 Main이 구체화한 부분을 밝힌다. |
| 왜 새로 썼는가 | 이번 주제·독립 책임·읽는 상황에서 어떤 판단을 가능하게 하려는지와 그 근거를 설명한다. 근거가 있다는 이유로 사용자 채택과 같은 지위로 올리지 않는다. |

01에서의 선택은 **[66](2026-10-18-66-principles-cases-and-refinement-prototype.md)의 원칙·사례·과정 연결 보완, [68](2026-10-18-68-principle-application-and-choice-basis.md)의 목적·조건·비용에 따른 적용 등 세 보완, [72](2026-10-18-72-short-common-and-detail-prototype.md)의 짧은 공통과 이름·가독성 독립 절을 시안에 반영하라는 요청**으로 구별한다. 본문 모든 문장·파일 배치·스킬 운영의 최종 결정은 아니다. [73](2026-10-18-73-prototype-reservations-and-ticket03.md)의 전체 만족·최종 수용 유보와01-02 미완료도 함께 유지한다.

[57](2026-10-16-57-criteria-organization-and-guiding-questions.md)의 사용자 생각과 [61](2026-10-17-61-reference-comparison-for-format-design.md)의 외부 비교는 판단 근거다.85에서 구별했듯 일반 원칙·질문·대비 방식의 근거와 이번에 새로 쓴 질문 문장·사례·파일 배치는 같은 지위가 아니다. 실제 유지·추가·변경의 세부 평가는 위 비교 산출물에서 맡으며 이 기록에 다시 정본으로 복제하지 않는다.
