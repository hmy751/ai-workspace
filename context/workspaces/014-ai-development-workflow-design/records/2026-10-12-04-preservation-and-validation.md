# 근거 보존과 새 독자 확인

사용자가 요청한 독립 기록 Workspace를 ai-workspace의 014에 만들었다. 원문을 이동하지 않고 필요한 사본을 넣었으며, 기록 요청을 설계 구현으로 확대하지 않았다. 저장소의 Workspace 색인만 현재 작업인 014를 active로 가리키도록 갱신했다.

현재 대화의 보존 끝은 “배경이 없는 새로운 세션”도 이어갈 수준을 요청한 발화, 원본 2744행이다. 이 이후의 이번 보존 작업은 이 기록과 current/state로 이어진다. 모든 원문 도구 trace를 포함한 채팅 전체 덤프는 만들지 않았다. 추출 방식·출처·범위·hash는 manifest에 있다.

원본 파일 사본과 선택 사건 파일을 합친 1,090개 manifest 항목의 크기·SHA-256을 다시 대조했다. 현재 대화 추출 3파일과 읽기본 21편의 hash도 확인했다. 작성 문서의 내부 링크, 대화 원문 행 anchor, 읽기본이 가리키는 내부 파일의 존재를 확인했다. 기계 확인 결과는 [검증 내역](receipts/preservation/2026-10-12.json)에 남겼다. 제품·하네스 코드를 바꾸지 않았으므로 앱 테스트나 Harness 실행은 수행하지 않았다.

## 이전 배경을 주지 않은 독자의 확인

이전 대화를 상속하지 않은 별도 검토자에게 이 Workspace 경로만 주고, 목적·합의와 제안·정정·다음 행동·근거 접근 경로를 자신의 말로 복원하도록 요청했다. 기대 답이나 이전 요약은 주지 않았다. 파일 수정이나 Workspace 밖에서의 배경 수집도 맡기지 않았다. 당시 작성 중이던 이 기술 검증 기록의 미존재만 검토 대상에서 제외했다.

검토자는 다음을 복원했다.

- Noline Ticket 06까지의 경험 평가에서 전체 작업 방식의 설계 논의로 넘어왔으며, 현재는 코드 개선 하나나 운영 체계의 구현 단계가 아니다.
- Maintain의 보존 목적과 Project context의 역할을 다음 작업에만 한정하지 않는다는 최신 정정이 유효하다. 자동 Maintainer는 재개하지 않지만 구체적인 제거·대체 설계는 아직 없다.
- Main의 기록 책임, 조건부 reviewer, 구현·검토·보고·기록 순서 등은 후보이며 일괄 채택된 방식이 아니다.
- 다음에는 한 영역의 목적·내용·대안·영향을 근거와 사례로 구체화한다. 첫 영역은 미정이고, 전체 평가 재수집이나 즉시 구현을 시작할 근거는 없다.

원문 재검토도 수행했다. 설계 대화의 큰 그림 요청·범위 정정·보존 요청, 전체 대화의 Maintainer 중단 의향을 확인했다. 기록 시점 비교에서 내부 blob과 corpus `01a0f772…`의 `source_line` 69·76을 열어 AI의 다음 행동 제안과 사용자 정정을 대조했다. PR 강연 번역과 code-review 사본의 내용도 현재 미채택 후보와 구별했다.

검토 결과 이해를 막는 누락·상충은 발견하지 못했다. 진입 문서의 반복은 최신 정정을 먼저 알리는 역할로 읽혔다. 이는 이 독자가 실제로 선택해 읽은 범위의 재진입 확인이며, 모든 후속 AI의 이해나 설계의 정확성을 보장하는 것은 아니다.

## 보존과 확인의 한계

핵심 설계 논의와 평가 근거는 내부 사본에서 읽을 수 있지만 전체 의존성을 닫지는 않았다. 읽기본에는 사본으로 연결한 링크 617개와 보존하지 않은 외부 링크 889개가 있다. 같은 경로의 반복 인용을 포함한 링크 발생 횟수이며, 파일 수나 누락 주장 수가 아니다. 원래 문서의 외부 링크는 당시 그대로 남겼다.

실제 Noline 제품 코드·DB·앱 실행 환경, 모든 Git 이력·도구 trace·연구 prototype, 외부 강연 원영상과 제공되지 않은 참조 파일은 포함하지 않았다. 새로운 제품 상태·동작 검증에는 해당 저장소와 실행 환경이 필요하다.

추가 보존한 별도 worktree는 현재 관찰판으로, 10월 1일 역사판과 동일하다고 증명하지 않았다. 세 rollout의 현재 전체 hash도 이전 corpus meta 값과 달랐다. 지정한 현재 원본 행과 선택 payload의 동일성은 확인했지만 과거 전체 판본 동일성까지 확장하지 않는다. 자세한 범위와 제외 사유는 supplement manifest에 있다.

사본의 보존 성공을 기존 평가의 인과 증명이나 현재 미채택 설계의 승인으로 해석하지 않는다. 앞으로 사용자 선택이나 새 사실이 생기면 current와 새 기록을 갱신하고, 과거 근거 사본은 당시 판본으로 유지한다.
