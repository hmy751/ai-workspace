## Development 문서에 대한 마지막 논의

Main이 후속으로 맥락 선택·인계·구현·검토·확인·반환과 기존 스킬의 연결을 추천하자 사용자는 다음과 같이 답했다.

> 그건 다른 티켓에서 좀 더 구체화 해야겠다
> 근데 여기서 궁금한게 Development 이 문서는 어찌보면 음 개발 워크플로 스킬 등의 어떤 진입점이자 본체 같은 내용같은데 맞을까?

Main은 현재 [DEVELOPMENT.md](prototypes/development-workflow/noline-demo/context/work/DEVELOPMENT.md)가 맥락 선택뿐 아니라 역할 간 전달, 충돌 처리, 구현·검토와 결과 갱신까지 직접 설명하므로 **개발 워크플로의 진입점 역할과 절차 본문을 함께 가진 시안**이라고 설명했다. Personal·Project의 내용은 각각의 본문이 소유하고, 이 문서는 그것을 실제 작업에 사용하는 방법을 다룬다. 자동으로 호출되는 스킬로 연결된 상태는 아니다.

스킬 본문에 통합할지, 별도 워크플로 문서를 유지하고 스킬이 진입·실행을 맡을지는 후속 선택이다. 현재 파일명·위치·최종 Owner, 기존 스킬의 책임과 겹치는 부분도 함께 판단해야 한다. 두 곳에 같은 절차를 별도로 관리하는 구성으로 확정하지 않았다.

사용자의 마무리 요청:

> 그래 나중에 워크플로나 그런 작업 할때 더 구체화 해야겠다 일단 지금까지 대화세션이랑 작업 고려해서 워크스페이스 기록할거 잘 남기고 커밋하자

따라서 이번에는 기록·커밋으로 묶고 워크플로·스킬 구체화는 진행하지 않는다. 관련 책임은 [01-01 개발 흐름](../current/tickets/01-development-workflow/01-01-development-flow.md)과 [04-03 맥락 스킬](../current/tickets/04-skill-improvements/04-03-context-skills.md)에 연결했다. 현재 로그인 예제로 단계별 담당·입력·행동·결과를 대조하자는 제안은 Main의 추천이며 확정된 재실험 시나리오는 아니다.

## 이어갈 때 유지할 판단과 미정

- 대상물 안에서 필요한 상황·코드·조건·이유를 이해할 수 있게 한다.014의 작성 기록은 작성자의 근거이며 대상물의 필수 입력이 아니다.
- Ticket은 다룰 범위를 제한한다. 그 안의 내용은 실제로 사용할 수 있게 완성하며 링크·검사 통과나 지적 항목 반영만으로 충분성을 대신하지 않는다.
- 개인 기준은 Personal, 이번 선택은 Work, 제품의 계약·지속 규약·현재 사실은 Project가 관리한다. 프로젝트 자체의 품질 기준과 필요한 설명 중복은 가능하다.
- 검토자가 직접 품질 수정하는 B 방향은 유지한다. A/B 이름 비교의 B와 이 개발 역할의 B는 서로 다른 비교다.
- 검토 겸임·생략 조건, 인계와 최종 실제 확인 담당, DEVELOPMENT의 최종 위치·스킬 관계, 실제 발견·적용·갱신 효과는 후속에서 구체화한다. 새 역할·스킬·운영 설치를 이번에 확정하지 않았다.
- 관련 Ticket의 미완료와 전체 본문 품질·최종 수용 유보를 유지한다. 이번 부분별 반영 요청이나 커밋을 전체 acceptance로 올리지 않는다.

다음 재진입은 [current/index](../current/index.md)와 [state](../current/state.md)에서 시작한다. 본문·판단 이유가 필요할 때100~102를, 워크플로 작업을 재개할 때01-01·04-03과 현재 DEVELOPMENT를 선택해 읽는다. 기록 전체나 과거 시안을 기본 입력으로 모두 읽지 않는다.

## 기록·커밋 범위와 확인

현재 안내·Spec·관련 Ticket·output·기록 색인을 이번 사용자 방향에 맞췄다. 프로토타입의 이번 마무리 추가 수정은 없으며97~102의 실제 반영을 함께 커밋한다. 앞선 작성 기록의 원문은 보존하고 이동된 자료를 가리키는 링크만 이어 맞춘 변경을 포함한다. 최종 커밋 식별은 이 파일의 Git 이력에서 확인할 수 있다.

커밋 전 확인 결과:

- 열람 화면의 Markdown53개·코드5개가 현재 원문·SHA와 일치한다. 내부 링크259개·참고 링크4개·앵커27개에 누락이 없으며 로컬 링크는 모두 대상물 내부를 가리킨다.
- A/B는 이름 두 쌍 외에 주석까지 동일하다. 화면 스크립트와 생성·검사 도구의 문법 확인을 통과했다.
- 이번 커밋 대상의 Markdown53개에서 로컬 링크919개를 확인했다. 최종 개행·공백 검사와 `git diff --check`를 통과했다.
- 변경 경로는 모두014 Workspace 안이다. 실행 예제와 원자료, reference-project·운영 스킬·루트 지침은 기준 HEAD와 비교해 변경이 없다. 기존 prototype의 작성 근거·배치 확인 파일은 바깥014의 보존본으로 옮긴 변경이며 기록 폐기가 아니다.

브라우저 실측·제품 검사 재실행·실제 Noline 통합·스킬 설치·새 작업자의 수행 효과는 이번 확인 범위가 아니다. 커밋은 위 범위의 결과와 재개 상태를 보존하며 전체 수용이나 Ticket 완료를 뜻하지 않는다.
