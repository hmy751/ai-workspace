# 04-03 — 큰그림 대화를 복원하고 외부 조사 질문을 정한다

상태: **조사 범위 제안.** 이번에는 대화·기록을 재검토하고 보존 자료 안내·파일목록에서 후보를 선별했다. 새 웹 조사·자료 수집·원문 전체의 심층 비교·구성 채택·실행 스킬 변경은 하지 않았다. 사용자가 먼저 설명받으려 한 것은 무엇을 외부에서 조사할지다.

후속: 사용자가 이 방향의 실제 조사를 요청해 [Matt·Lauren 조사와 기존 시스템·새 workflow의 종합](2026-10-25-context-reference-synthesis.md)을 마쳤다. 아래는 조사 전 질문·범위의 형성 기록이다. 현재 추천·자료 확보·남은 일은 후속 종합에서 읽는다.

## 사용자 요청

> 우리 지금 이 큰그림 논의를 쭉 이어왔는데 여기를 다시 훑고 우리 논의에서 관련된 부분을 잘 보고 레퍼런스 에서 얻을 게 잇는지 봐봐 그러니까 맷이나 로렌 자료 보면 스펙을 떠나서 지금 처럼 스킬 관리 책임 이나 이런게 유사한 부분이 있는지 보고 차용할게 있는지 찾아와봐 그래서 이걸 보고 우리가 지금 큰그림논의에 사용한 것들과 뭐 많잖아? 기존시스템도 고려했고 어쨋든 이런걸 다시 종합해서 어덯게 볼지도 정해보게
> 일단 지금 직전 뿐 아니라 다시 큰 글미 논의 한 대화들을 쭉훑어봐 그래서 외부에서 뭘 조사하면 좋을지 나한테 설명해보고

직전의 제거 가능성만 조사하거나 현재 제안한 하나의 context 스킬을 뒷받침할 사례만 찾지 않는다. 개발 중 맥락 사용·유지와 직접 요청을 중심으로 기존 시스템·새 역할·기록·경험 개선·전환을 함께 비교할 질문을 만든다.

## 대화 전체에서 복원한 질문

| 논의가 진행된 지점 | 현재 조사에서 보존할 질문 |
| --- | --- |
| 기존 read는 필요한 맥락을 Work로 가져오는 목적이었는데 새 workflow의 반복 사용과 맞는가 | 원래 스킬의 의미와 실제 수행 책임을 대조한다. read도 반복 선택을 지원했다는 사실을 유지하면서 새 범위·역할·연결의 차이를 본다. |

| 기존 스킬 유지에 얽매이지 말되 억지 신설도 피하자 | 스킬·공통 지침·작업 흐름·영역별 관리 기준의 경계를 실제 구성에서 비교한다. 이름과 파일 수를 근거로 삼지 않는다. |
| 주로 개발 중 자연스럽게 읽고 갱신하되 직접 요청도 지원하자 | 작업 흐름 내부 사용과 직접 요청이 같은 실행을 사용하는지, 서로 다른 입력·종료·권한을 어떻게 연결하는지 본다. |
| 변화 반영은 경험 루프와 어떤 관계인가 | 일상 유지, 경험 해석과 개선 선택, 실제 반영, 효과 관찰의 책임을 구별한다. |
| 여러 영역에 걸친 스킬을 유지하고 교체할 수 있는가 | 공통 지침과 대상별 지식·규칙·도구를 어디에 두며, 변경·교체·제거 시 어떤 관계를 조정하는지 본다. |

[재개 범위](2026-10-24-workflow-context-connection-checkpoint.md), [구성 비교와 정정](2026-10-25-context-responsibility-and-skill-architecture.md), [구체 책임안과 유지·교체 논의](2026-10-25-context-responsibility-concrete-proposal.md)를 재검토했다. 하나의 맥락 스킬이라는 포장은 Main의 미채택 제안이다. 담당자의 직접 원문 읽기·Main의 Work 유지·내용 Owner 구별은 이미 확인한 입력이다.

## 조사할 다섯 관계

1. **전체 작업 흐름과 재사용 스킬의 책임:** 어떤 판단을 상위 흐름이 하고 어떤 판단을 개별 스킬에 남기는가. 직접 요청과 작업 중 사용은 어떻게 이어지며 스킬 작성·수정 기준은 누가 소유하는가.
2. **원문·작업별 맥락·담당자의 연결:** 필요한 지식을 어떻게 선택·발견하고 어떤 내용을 작업 기록에 남기는가. 담당자가 추가로 읽고 결과를 반환하며 다음 작업이 이어받는 경로는 무엇인가.
3. **일상 유지와 경험 개선의 연결:** 기록·사실 정정, 개선 후보, 채택, 실제 반영, 효과 관찰을 어떤 단위가 맡는가. 문서·스킬 수정 외에 코드·검사·도구 변경을 선택하는 경로도 있는가.
4. **공통 실행 방법과 프로젝트별 내용의 소유:** 재사용 스킬과 대상별 계약·규칙·실행 지식·도구가 어떻게 분리되는가. 대상 변화로 무엇이 오래됐는지 누가 확인하고 어느 범위까지 고치는가.
5. **변경·교체·제거 시의 유지 범위:** 한 스킬이나 대상 구조를 바꿀 때 실제로 수정하는 소비자·문서·도구는 무엇인가. 독립된 책임인지, 단순히 파일만 나눈 것인지 확인한다.

## 조사 순서와 결과를 종합할 방법

먼저 저자의 전체 진입·스킬 작성 및 연결을 읽어 구성의 실제 책임을 잡는다. 그다음 원문·작업 기록·담당자의 사용 경로와 공통/대상별 내용의 유지 사례를 따라간다. 경험 개선은 일상 반영과 만나는 지점을 중심으로 살핀다. 모든 자료를 동등하게 완독하는 목록이 아니라 질문별로 필요한 본문과 직접 참조를 선택하는 조사다.

현재 보존 자료에서 시작하고 연결된 중요한 원문이 없거나 판본 차이가 판단을 바꿀 때 원저장소·공식 자료로 범위를 넓힌다. 기존 source는 읽기 전용이며 새 근거가 필요하면 판본과 출처를 별도로 보존한다. 보존판 Matt1.3.1·pstack0.15.29와 예전 강연·조사 판본을 섞지 않는다.

각 발견은 외부 원문이 실제로 정한 책임·구현 관계, 우리의 기존 시스템과 같은 점/다른 조건, 가져올 수 있는 원리, 가져오기 어려운 부분을 연결해 정리한다. 가이드 설명·실제 SKILL 계약·실행 코드·운영 효과 증거를 구별하고, 자료에 없는 책임은 임의로 채우지 않는다.

종합 대상에는 기존 read/update/create·Recover/Maintain의 분담, 새 development의 역할·인수/반환, Personal·Project·Work의 정본과 관리 기준,02·05·06·07의 남은 책임을 모두 포함한다. 최종 비교는 하나의 맥락 스킬, 읽기/반영 실행의 분리, workflow와 공유 상세의 조합을 열어 둔다. 현재 후보를 입증하는 조사로 좁히지 않고 실제 사례가 지지하는 경계와 조정안을 사용자와 판단한다.

이번 결과는 이 조사 계획을 사용자에게 설명할 준비다. 외부 자료의 실제 차용안이나 새로운 스킬 구성을 확정한 결과는 아니다.
