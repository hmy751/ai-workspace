**`catch`가 P1의 에러 자체를 `undefined`로 바꾸는 것은 아니에요. 에러를 받은 함수가 `undefined`를 정상적으로 반환하고, 그 반환 결과가 P2에 담기는 겁니다.**

지금 코드를 생략 없이 풀면 이렇게 됩니다.

```ts
const P2 = P1.catch((error) => {
  // P1이 실패하면 이 함수가 실행됩니다.
  // error에는 P1의 오류가 들어옵니다.

  return undefined;
});
```

여기서 `error`는 **이 함수가 받은 것**이고, `undefined`는 **이 함수가 반환한 것**이에요. 원래 코드의 `() => undefined`는 받은 오류를 사용하지 않아서 `error`라는 매개변수 이름을 생략한 형태입니다.

그리고 Promise에는 다음 규칙이 있습니다. **`catch` 안의 함수가 값을 정상적으로 반환하면, 그 `catch()`가 만든 P2는 그 값을 가진 성공 상태가 됩니다.** `undefined`도 정상적으로 반환할 수 있는 값입니다. 오류를 뜻하는 특별한 값이 아니에요.

두 코드를 비교하면 차이가 드러납니다.

```ts
// P1이 실패했을 때
const P2 = P1.catch((error) => {
  return undefined; // 정상 반환 → P2 성공, 값은 undefined
});

// 대신 이렇게 썼다면
const P2 = P1.catch((error) => {
  throw error;      // 다시 오류를 던짐 → P2도 실패
});
```

따라서 `P2.then(operationB)`에서 B가 실행되는 이유는 **`undefined`가 특별히 오류를 없애서가 아니라, catch 함수가 오류를 다시 던지지 않고 정상적으로 끝나 P2가 성공했기 때문**입니다. 여기서 `undefined` 대신 `123`을 반환해도 P2는 성공합니다.

앞서 제가 “에러가 안 터지고 이어진다”고 한 범위는 **P2 뒤에 이미 연결된 B**였어요. P1은 여전히 실패 상태라서, 호출자가 `await P1`을 하면 그곳에서는 오류가 발생합니다. 그 오류를 처리하지 않은 채 같은 함수의 다음 줄에서 B를 등록하려 했다면, 그 줄까지 도달하지 못합니다.
