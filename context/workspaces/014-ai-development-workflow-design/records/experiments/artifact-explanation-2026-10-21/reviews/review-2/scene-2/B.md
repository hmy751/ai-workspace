**`catch` 함수는 P1의 오류를 받아 실행되고, 그 함수가 정상적으로 반환한 `undefined`가 P2의 결과가 됩니다.** 받는 것과 반환하는 것을 나눠 보면 됩니다.

앞에서 본 코드를 풀어 쓰면 이렇습니다.

```ts
const P2 = P1.catch((error) => {
  // P1이 실패하면 이 함수가 실행됩니다.
  // error에는 A에서 발생한 오류가 들어옵니다.
  return undefined;
});
```

여기서 **오류가 `error`라는 인자로 들어왔다고 해서 이 함수도 자동으로 오류를 던지는 건 아닙니다.** 이 함수는 실행을 시작한 뒤, 그냥 `return undefined`로 정상 종료합니다.

`catch()`가 만드는 P2의 결과는 이 함수가 어떻게 끝났는지에 따라 정해집니다.

- `return undefined`로 끝나면: P2는 성공하고, 결과값은 `undefined`입니다.
- `throw error`로 끝나면: P2도 실패하고, 그 오류를 갖습니다.

`undefined`가 오류를 없애는 특별한 값인 것은 아닙니다. 여기서 `return 123`을 해도 P2는 성공하고 결과값만 `123`이 됩니다. **핵심은 `catch` 함수가 다시 오류를 던지지 않고 값을 반환했다는 점입니다.**

그래서 다음 코드에서:

```ts
const P3 = P2.then(() => operationB());
```

P2가 성공했으니 `then` 안의 함수가 실행되고, B가 시작됩니다. 이 함수는 P2의 결과값인 `undefined`를 사용하지 않습니다.

앞서 제가 “에러가 안 터지고 이어진다”고 한 건 범위를 분명히 해야 했습니다. **A는 실패했고 P1은 여전히 실패 상태입니다.** 호출자가 P1을 `await`하면 오류가 납니다. 다만 B가 기다리는 P2는 `catch` 함수가 정상 종료한 결과이므로 성공 상태여서, 이미 그 뒤에 연결된 B는 실행될 수 있다는 뜻입니다.
