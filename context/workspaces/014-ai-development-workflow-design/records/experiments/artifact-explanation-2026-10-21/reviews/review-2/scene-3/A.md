**제가 반환 구조를 설명하면서 `access`를 빠뜨렸습니다. 앞선 대화에서 `access`를 없애기로 정한 적은 없습니다.** 요청하신 변경은 정책 확인이 필요한 `refetch`를 `query`에서 분리하는 것이었습니다.

그 취지를 유지하면 반환 형태는 다음과 같습니다. 아래는 정정한 설계 형태입니다.

```tsx
const { query, access, actions, view } = useSchedulesRead(tripId);
```

- `query`: `refetch`를 제외한 조회 데이터와 상태. 성공 여부에 따른 데이터 타입 관계는 유지합니다.
- `access`: 데이터를 표시하거나 조회할 수 있는 조건. 화면에서 버튼 활성 여부나 제한 안내를 결정할 때 사용합니다.
- `actions`: 호출 시 정책을 확인하는 실행 함수. `actions.refetch()`가 재조회를 수행하거나 차단 결과를 반환합니다.
- `view`: 접근 조건과 조회 상태를 조합한 표시 결과. 목록·폼의 해당 영역에서 필요할 때 사용합니다.

예를 들어 재조회 버튼은 `access`를 보고 비활성화할 수 있고, 실제 호출은 `actions.refetch()`가 정책을 확인합니다. **현재 가능한 일을 알려 주는 `access`와, 실행을 맡는 `actions`는 역할이 다르므로 함께 둘 수 있습니다.**

다만 제공된 대화만으로는 실제 코드에서도 `access`가 빠졌는지까지 확인할 수 없습니다. 확실한 것은 제 설명에서 누락됐다는 점입니다. 적용 범위는 말씀하신 **일정 목록 한 곳**으로 유지해야 합니다.
