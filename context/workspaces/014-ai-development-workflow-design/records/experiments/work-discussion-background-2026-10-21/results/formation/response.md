work-discussion은 구현 전에 사용자가 받을 결과와 보존할 의미를 맞추고, AI가 조사할 사실과 사람이 정할 선택을 나누는 스킬이다. 이번 자료가 지지하는 간결화 방향은 이 책임을 줄이는 것이 아니라, 같은 판단을 반복해 설명하는 문장을 합치는 것이다. 다만 제공 목록에는 현재 `SKILL.md`와 `SKILLS-CONTENT-POLICY.md` 본문이 없어, 특정 문장이 실제로 중복인지나 정확히 어느 문단을 삭제할지는 확정할 수 없다. 아래는 형성 자료에 근거한 편집 제안이다.

현재 구성에는 기존부터 이어진 책임과 이번에 최소 보완한 책임이 함께 있다. 직접 호출, 사실 조사, 필요한 선택, 부족한 대체 결과와의 대비, Spec/Ticket 연결은 보존 기준판에 이미 있었다. DB·인증 사례에서는 AI가 모두 재시도를 추천했어도 사용자는 설명을 듣고 DB 실패에만 재시도를 채택했다. 따라서 질문과 선택은 제거할 비용으로만 취급할 수 없다. Spec이 전체 결과와 공통 기준을, Ticket이 확인 가능한 실행 결과와 진행을 맡는 구분도 유지할 이유가 있다. 내부 연결이나 테스트 통과가 사용자에게 필요한 결과를 대신하지 않도록 하는 경계다. 다만 각 조항이 처음 채택된 전체 대화까지 확보한 것은 아니다. (`_background/context.md`, `_background/evidence.md`)

이번 최소 보완의 계기는 “이 Ticket을 더 구체화할 것이 있는가”라는 질문에 이미 정한 요구를 새 보완처럼 반환한 장면이다. 실행 전 Ticket에도 표시 차이 보존과 검사 기준이 있었다. 새로 관찰한 반올림 차이는 그 보존 요구를 확인할 검사 사례였는데, 기존 요구와 새 관찰의 역할을 구별하지 못했다. 기준판에도 이미 정한 것을 다시 열지 말라는 원칙은 있었으므로, 원칙을 새로 발명한 수정이라기보다 기존 정의와 대조하고 요청에 맞춰 답하는 동작을 더 분명히 한 수정이다.

큰 교체안은 충분한 Ticket의 재서술 제안을 줄였지만 기존판도 필요한 선택을 잘못 열거나 착수를 막지는 않았다. 비교의 독립 검토는 모두 충분으로 판정했다. 그래서 큰 안 전체 대신 기존 정의 대조·새 관찰 연결·요청별 반환만 기존 문장에 통합했고, reconsider-work는 유지했다. 최소안도 두 조건에서 각 한 번 확인한 prototype이다. 정확도 향상이나 장기 안정성을 입증한 결과로 확대하면 안 된다. (`_background/records/2026-10-21-selection-and-policy-application.md`, `_background/evidence.md`)

간결화할 때의 제안은 다음과 같다.

- **유지:** 직접 호출이라는 적용 경계, 사실 조사와 사람의 선택 구분, 이미 정한 요구와 새 요구·변경 구분을 남긴다. 충분성 질문에는 실행 가능 여부와 실제 부족분부터 답하고, 새 관찰은 기존 요구를 검증하는 사례인지 새 선택이 필요한 사안인지 판단하도록 한다. 이는 이번 최소 보완의 핵심이므로 줄이는 과정에서 사라지면 안 된다.
- **유지:** Spec/Ticket의 책임 구분과 “이해안 반환만으로 지속 문서 반영이 끝난 것은 아니다”라는 경계를 남긴다. 대표 장면과 부족한 대체 결과의 대비, 핵심 수행을 미루지 않는 Ticket, 동작 보존과 구조 개선의 별도 확인도 역할을 대체할 문장이 있는지 확인한 뒤 편집한다.
- **통합:** 기존 정의 확인, 이미 정한 선택을 다시 열지 않기, 유지·구체화·변경 구분이 여러 곳에서 반복된다면 하나의 판단 문단으로 합친다. 충분성 판단과 새 관찰의 검사 연결도 그 문단에 붙일 수 있다. 다만 새 Work 전체를 구체화하는 요청까지 충분성 점검 하나로 축소하지 않는다.
- **삭제 후보:** 현재 본문에 형성 경위, 실험 횟수·진행 순서, 큰 안의 미채택 이유가 반복돼 있다면 실행 판단에 필요한 문장만 남기고 형성 자료 안내로 대체한다. 같은 책임을 다시 말하는 요약도 후보가 된다. 형성 자료는 이미 선택적으로 읽도록 구성돼 있으므로 사용 때마다 필독하도록 추가하지 않는다. 실제 중복의 존재는 현행 본문 확인 전까지 미확정이다.
- **판단 유보:** Main·Maintain 책임을 단순히 낡은 문구로 보고 삭제하거나 새 담당자로 바꾸는 결정은 이번 간결화와 분리한다. 자료상 기존 계약은 유지됐고 실제 운영 책임 변경은 별도 후속이다. DB·인증 수행 문제를 해결한다며 사례나 절차를 덧붙이는 것도 근거가 부족하다. 현재 본문을 보지 않고 모든 사례를 지우거나 실행 절차를 background로 이동하는 결정 역시 유보한다.

가능한 수정 문단은 다음과 같다. 현행 본문 전체를 대체하는 안이 아니라, 기존 정의 대조와 충분성 반환을 합칠 때의 후보 문단이다.

> 먼저 요청과 관련된 기존 Spec·Ticket을 확인해 유지할 요구, 새 구체화, 변경을 구별한다. 기존 정의의 충분성을 묻는 요청에는 실행 가능한지와 실제 부족분부터 답하며, 충분하면 이미 정한 요구를 새 보완처럼 제안하지 않는다. 새 관찰은 기존 요구를 확인할 검사 사례인지, 결과를 바꾸는 미선택 사안인지 판단해 연결한다. AI가 조사할 사실은 확인하고, 필요한 사용자 선택은 이유와 영향이 드러나게 제시한다.

다음 수정자는 현행 본문과 이 후보를 대조해 같은 책임이 중복된 위치부터 합치는 것이 타당하다. 이 자료만으로는 실제 읽기 부담의 주된 원인, 문단 삭제 뒤 새 Work 전체를 다룰 때의 영향, 긴 이력에서 필요한 자료를 찾는 능력, 실제 제품 효과를 판단할 수 없다. 특히 이번 자료 구성 자체는 실행 본문을 쪼개거나 절차를 옮길 필요가 없다고 판단하고 안내만 추가한 작업이었다. 따라서 형성 자료가 생겼다는 사실을 실행 본문 삭제의 근거로 삼지는 않는다.
