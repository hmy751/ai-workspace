# 품질·완료 판단

완료에는 실제 코드 개선과 동작 보존의 근거가 모두 필요하다. 타입·린트 통과, 줄 수 감소, 함수 분리 개수만으로 가독성 개선을 판정하지 않는다.

- 채택한 범위에서 값·조건·함수의 의도와 책임을 이름·타입·가까운 코드로 설명할 수 있고, 반복되는 해석과 우회가 변경 전보다 줄어든다.
- 의미가 같은 중복은 줄고, 필요한 차이는 숨겨지지 않는다. 줄 수를 줄이기 위해 간접 호출이나 범용 옵션을 늘리지 않는다.
- 관련 입력·실패·취소·재진입의 동작과 기존 데이터 계약을 보존했다는 근거를 변경 위험에 맞게 남긴다. 저위험 표현 수정에 구현을 그대로 복제하는 테스트를 만들지 않는다.
- 전체 후보를 처리·변경 불필요·다른 Work의 동작 수정·보류 중 무엇으로 판단했는지 근거를 남기며 조용히 누락하지 않는다. 중요한 가독성 문제를 그대로 둔 채 후보 분류만 끝낸 것을 완료로 보지 않는다.
