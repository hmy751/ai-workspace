# 인증 인터셉터 — 6.0 sol medium 결과

**두 판 모두 동작을 요약했고, 사용자 교정 전에 코드와 함께 자세히 설명하는 수준으로는 나아가지 않았다.** 수정판은 세션 의미와 근거 위치를 더 명시했지만, 기존판에도 핵심 역할·요청 흐름·갱신 공유·실패 구분이 있었다. 이번 한 쌍에서 수정판의 뚜렷한 우세는 확인하지 못했다.

## 실행 조건

사용자는 Luna의 두 응답 차이가 작으면6.0 sol medium으로 다시 시험하도록 요청했다. 기존판r36과수정판r91을 각각 새 worker에서 `gpt-6-sol`, `medium`, `fork_turns=none`으로 한 번 실행했다.

앞선6.1-sol 인증 입력11개를 그대로 복사했다. 두 조건 사이의 유일한 입력 차이는skill/SKILL.md이며 실행 전후 해시를 대조했다. 원문9~20, 당시 관측 코드와 사용처, 공통 기준이 같다. 사용자55·73의 교정, 당시 첫 답48, 이전 실험 결과, 기대 답은 주지 않았다. 스킬을 질문 조사 시작에 명시 적용하는 조건도 동일하다.

[기존판 전체](r36/output/response.md) · [수정판 전체](r91/output/response.md). 조건·입력·출력 해시는conditions.json과results.json에 있다. 응답과 읽기 기록을 수정하지 않았다. 두 읽기 기록은11개 파일을 읽고 폴더 밖 접근은 없었다고 보고한다. 이 기록은 자기보고이며 시스템 수준 접근 격리는 아니다. 토큰 사용량은 측정하지 않았다.

## Main의 대조

| 확인점 | 기존판 | 수정판 | 판단 |
| --- | --- | --- | --- |
| 역할 | 공통 인증 처리와 이전 세션 차단 | 같은 두 역할 | 핵심 역할 설명은 양쪽에 있음 |
| 코드와 함께 읽기 | 코드 블록 없음, 기호와 함수 이름을 문장에 포함 | 코드 블록 없음, 기호·함수 이름과 줄 위치를 문장에 포함 | 당시 사용자55의 교정에 해당하는 보완은 두 판 모두 약함 |
| 흐름 | 여행 목록 요청의4단계 | 대표 요청의4단계 | 입력·상태를 구체적으로 따라가기보다 동작 요약 중심 |
| 세션 의미 | 토큰과 다른 로그인 세대 표식이라고 설명 | 서버 ID가 아니라는 구분과 재시도 때ID 유지 이유를 명시 | 수정판의 국소적 구체성 |
| 갱신 공유 | 같은 세션의 Promise 공유 | 요청A·B의 Promise 공유 | 같은 핵심을 전달 |
| 실패 | 재시도401,refresh401/403,연결 오류,저장 실패·세션 변경 | 재시도401,refresh401/403,연결 오류 | 기존판에만 자세히 적은 조건도 있음 |
| 출처 | 파일·symbol을 문장에 포함 | 주장 가까이 파일·줄 위치를 반복 표기 | 근거 탐색에는 차이가 있으나 코드 설명 깊이와는 구별 |

Main이 제공된auth-interceptor.ts·auth.ts·auth-transport.ts와 대조했다. 요청 ID 유지, 현재 세션 검사, 토큰 부재 시 갱신, 일반401 한 번 재시도, refresh token 부재와401/403의 재인증 처리, 다른 오류 전달, 메모리 선차단·저장, 같은 Promise 공유의 주요 설명은 코드에 맞는다. Luna 수정판의 “재전송도 실패하면 재로그인”이라는 조건 확대는 이번 두 응답에서 나타나지 않았고, 두 답 모두 다시401인 경우로 구별했다.

다만 실제 코드 블록을 펼쳐 renewSession의 분기, await 전후 값, catch의 재검사, 정리용Promise와원Promise의 차이를 따라 설명하지 않았다. 설명의 짧음 자체를 실패로 보지는 않는다. 당시 사용자55가 코드와 함께 자세히 설명하라고 요청했던 근거에 비춰 보완 범위를 판단한다. 사용자73의 재질문이 실제로 없어질지는 확인하지 않았다.

## 세 모델의 관찰을 구별한다

| 실행 | 기존판 | 수정판 |
| --- | --- | --- |
| 6.1 sol medium | 주요 코드 블록과 문법·값을 자세히 설명 | 주요 코드 블록과 흐름·값을 자세히 설명 |
| 6.0 luna medium | 요약 중심, 실제 코드 블록은sessionId 할당1줄 | 요약 중심, 실제 코드 블록은할당·검사2줄 |
| 6.0 sol medium | 코드 블록 없이 동작 요약 | 코드 블록 없이 동작 요약 |

입력은 판본별로 세 실행에서 동일 바이트다. 그래도 모델별·판본별1회이므로 출력 차이를 안정된 모델 성능 차이나 본문 수정의 인과 효과로 확정하지 않는다. 이번 관찰은 “기존판과 수정판의 차이가 작다”가 항상 “둘 다 충분하다”는 뜻은 아님을 보여 준다.6.1-sol은 양쪽 모두 자세했지만6.0 luna·sol은 양쪽 모두 코드와 연결한 설명이 얕았다.

사용자가 직접 모델을 바꿔 재실행하도록 요청한 기록이다. 유리한 결과를 얻으려고 질문·스킬을 보완하거나 재생성하지 않았다. 스킬 자연 선택·발동 시점·첫 작업 보고의 설명 책임은 시험하지 않았다. 운영 스킬·복구 스킬은 유지하며04-02 완료나 사용자 이해 개선으로 표시하지 않는다.
