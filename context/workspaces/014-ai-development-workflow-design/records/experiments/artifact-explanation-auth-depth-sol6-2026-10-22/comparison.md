# 새 후보 인증 비교 — Main의 대조

**이번 한 쌍에서는 새 후보가 요청 코드를 실제로 펼치고 값·대기 전후 상태를 연결하는 차이가 나타났다.** 기존판은 코드 블록 없이 흐름을 요약했다. 다만 새 후보도 갱신 함수·catch·정리용Promise까지 코드를 펼치지는 않았으며, 사용자 이해 개선이나 스킬의 안정된 효과를 확정하지 않는다.

## 같은 조건과 공개 범위

r42는 원래 기존판r31, r85는 코드 설명 깊이를 통합한 새후보다. GPT-6-sol medium, fork_turns=none의 새 worker에서 각1회 실행했다. 이전 후보r74와 직접 비교한 것은 아니다. 입력11개 중skill/SKILL.md만 다르며 실행 전후 동일성을 해시로 확인했다. 그 외 입력은 앞선 인증 시험과 같다.

문법 질문9·답13·전체 코드와 질문20까지 제공했고, 이후 실제 첫 답·교정·기대 답·현재 논의·이전 실험 결과는 숨겼다. 두 조건 모두 질문 조사 시작에 스킬을 명시 적용했다. 자연 선택·발동 시점 시험은 아니다. 새 후보는 이 사례에서 얻은 교정을 근거로 작성했으므로, 원문 교정을 숨긴 재시험이지 보지 않은 사례로의 일반화 검증은 아니다.

[기존판 전체](r42/output/response.md) · [수정판 전체](r85/output/response.md). 두 응답과 읽기 기록은 그대로 보존했다. 두 읽기 기록은11개 자료를 읽고 범위 밖 접근이 없었다고 보고한다. 자기보고이며 OS 접근 격리나 독립 실행 추적은 아니다. 토큰 사용량은 측정하지 않았다.

## 코드 사실 대조

Main은 기존에 확인한 동일auth-interceptor.ts·auth.ts·auth-transport.ts·사용처와 두 응답을 대조했다. sessionId 유지, 세션별 갱신 공유, 응답·재시도 검사, 요청401 재시도1회, refresh401/403과 네트워크 오류의 구별, 메모리 선차단·저장, Store의false 반환 설명은 코드에 부합한다.

새 후보의 요청 코드 블록은 실제 파일에서accessToken 부재 시throw하는 부분을 생략했다. 응답이 “핵심 줄만 골랐고” 실제에는 해당 검사가 있다고 명시하고 바로 앞에서 조건을 설명하므로 전체 원본 코드로 오인시키는지의 한계를 함께 본다. 실행 가능한 완전한 코드 교체안으로 제시한 것이 아니다. 값은 설명용이라고 밝혔고 실제 앱 실행을 관찰했다고 주장하지 않았다.
