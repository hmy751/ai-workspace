# 인증 인터셉터 — 코드 설명 깊이 후보와 기존판 비교

사용자는 새 통합 후보로 인증 사례를6.0 sol medium에서 기존판과 비교하고, 교정·기대 답을 주지 않은 두 응답 전체를 요청했다. 이전 응답을 재사용하지 않고 새 worker 두 개로 각1회 생성한다.

- 모델 `gpt-6-sol`, 추론 `medium`, 대화 상속 `fork_turns=none`을 지정했다.
- r42는 원래 기존판r31, r85는 코드 설명 깊이를 보완한 새 후보다. 바로 전 통합 후보r74와의 직접 비교가 아니다.
- 입력11개 중skill/SKILL.md만 다르다. 대화·코드·사용처·프로젝트 지침·공통 기준·프롬프트는 앞선 인증 시험과 같은 바이트다. conditions.json에 매핑과 해시를 보존한다.
- 사용자9의 문법 질문·AI13의 답·사용자20의 전체 코드와 동작 설명 요청까지 제공한다. 이후 실제 첫 답48·사용자55와73의 교정·보완 답·현재 논의·이전 실험 결과·기대 답은 제공하지 않는다.
- 양쪽 모두 질문 조사 시작에 지정 스킬을 읽고 적용한다. 별도 출력 목차·코드·도식 의무를 프롬프트에 넣지 않았다. 코드 설명 행동의 차이는 비교 대상 스킬 본문에만 있다.
- 새 후보는 이 사례의 교정을 근거로 설계했다. 생성자에게 교정 원문을 숨겼더라도 이번 장면은 설계에 사용한 사례의 재시험이며, 보지 않은 사례로의 일반화를 확인하는 시험은 아니다.

실행자에게 필요한 자료만 선택 복사하고 폴더 밖 접근을 제한했다. 이는 지시상 경계이며 시스템 수준 격리는 아니다. 읽기 기록은 자기보고다. 현재 공통 상위 지침도 남아 있으므로9월 당시 실행의 완전 재현으로 보지 않는다.

응답과 읽기 기록은 각output에 원문 그대로 보존하고 Main 대조는comparison.md에 둔다. 입력·출력 해시와 조건은 JSON에 보존한다. 모델별·판본별1회이며 사용자 이해 개선·자연 선택·발동 시점·안정된 본문 효과는 별도 확인이 필요하다. 운영 스킬·복구 스킬은 변경하지 않는다.
