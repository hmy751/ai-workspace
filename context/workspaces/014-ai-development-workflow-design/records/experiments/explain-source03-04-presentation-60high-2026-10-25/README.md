# 03·04 — 코드 동반·표현 보완 뒤 다섯 응답

2026-10-25. 사용자 “그럼 수정하고 같은 상황 테스트 해보자” 요청으로 [코드·표현 보완](../../2026-10-25-ticket04-02-code-presentation-adoption.md)을 적용하고 동일한 상황을 비교한다. 제목의 사례번호는 [이전 입력과 조건](../explain-source03-04-60high-2026-10-24/README.md)을 따른다.

## 조건

03은 원문1209 network 흐름 질문의 수정 직전 explain/수정판/설명 스킬 없음,04는2632 테스트 변경 필요성 질문의 수정 직전/수정판이다. 모델은 모두 GPT-6-sol high이며 새 컨텍스트에서 각각 최초1회 생성한다. 수정 직전판은7c490d2, 수정판은f3c582a다. 옛 두 스킬이나 더 이른 explain 판본을 대조군으로 바꾸지 않았다.

같은 사례의 공통 대화·코드·프로젝트 자료, prompt·reader·필수 읽기·이미지 목록은 이전 시험과 바이트 그대로 같다. preparation-check.json에서 동일성을 확인했다. 조건별 스킬 본체·상세만 이번 비교 판본으로 공급하며 배경·현재 개선 논의·평가·이전 시험 답은 제공하지 않는다.03 기본 응답에도 앞선 실제 대화와 프로젝트 지침은 있다. 완전히 지침 없는 모델 시험이나 처음 보는 비공개 평가가 아니다.

조건 표시 순서는 응답 생성 전에 사례별로 무작위로 정해 conditions.json에 보존한다. 조건을 보지 않고 읽으려면 answer-03-A/B/C.md, answer-04-A/B.md 또는 blind-responses.md를 연다. 생성된 첫 응답은 수정하지 않으며 사용자 평가 전 조건표와 Main 평가를 공개하지 않는다.

읽기는3000자 조각으로 기록하며 필수·선택 파일 완독, 입력/조각 해시와 응답 전 read-check를 검사한다. 선택 파일을 같게 강제하지 않는다. 별도 폴더와 reader는 OS 접근 격리가 아니며 잘림·범위 밖 접근 보고는 실행자 보고와 구별한다. 같은 공통 prompt에 수정·재실행 금지가 있으므로 무수정을 스킬만의 효과로 인정하지 않는다.

이 시험은 고정된 역사적 결과의 직접 설명 비교다. development 첫 전달 호출 연결·실제 제품 동작·안정된 우세·사용자 이해·04-02 전체 완료를 증명하지 않는다.03을 설계 토론에서 다뤘지만 수정판 실행 상세에 그 답을 정답 예시로 넣지는 않았다.

## 상태

다섯 조건을 각각 새 컨텍스트의 GPT-6-sol high로 최초1회 생성했다. 입력·제어 파일과 읽기 조각 해시, 필수·선택 파일 완독, 스킬 선행 읽기, 응답 전 read-check를 모두 통과했다. 응답과 실행 메모·읽기 기록은 각 실행 폴더에, 원문 복사본은 answer 파일과 blind-responses.md에 보존했다. 상세는 results.json에서 확인한다. 출력 잘림·범위 밖 접근 여부는 실행 메모의 자기보고이며 읽기 로그만으로 모든 도구 접근을 증명하지 않는다.

사용자가03-C는 보기 편하지만 동작 설명 같고04는 차이가 작다고 평가했다. [조건 공개와 구체 판단](comparison.md)에 코드 동반·배치의 국소 개선, 전체 역할·협력 설명의 미완,04의 추가 이득 미관찰을 구별했다. 각 조건1회이고 첫 전달 호출 연결은 시험하지 않았다.

입력 사본의 대화 말미 공백·원본 diff의 공백 줄은 바이트 동일성을 위해 보존했다. 이 원문 영역의 Git 공백 경고는 정규화하지 않았으며 새 작성 문서와 구별했다.
