# 재개 안내의 두 읽기 확인

2026-11-04. prototype 적용 뒤 부모 대화와 예상 답을 주지 않은 새 독자 둘에게 요청을 나누어 맡겼다. 이 자료는 한정된 읽기 관찰이며 운영 host 전체의 전환·자동 기록 시험은 아니다.

| 요청 | 원문 반환 |
| --- | --- |
| “로그인 완료 표현 작업을 이어 보자. 현재 어디까지 되어 있고, 어떤 이유로 지금 선택을 했고, 무엇을 더 판단해야 하는지 알려줘.” | [일반 재개 독자](general-reader.md) |
| “로그인 예제에서 이름을 유지하는 대안도 가능했는지, 왜 현재 이름을 골랐는지만 설명해줘. 동작 수정은 하지 말고.” | [한정 요청 독자](scoped-reader.md) |

두 독자에게 repo root와 demo AGENTS를 시작점으로 연결했다. 현재 요청의 읽기 수행만 맡기고 바깥 Workspace014 current·원문·검토 기록, 외부조사, 파일 수정, 검사 실행은 제외했다. 지정한 입력 밖의 prototype 내부 자료는 각자가 판단해 선택할 수 있었다. 별도 답변 초안이나 기대한 결론을 제공하지 않았다.

핵심 진입 입력은 `inputs/`의 `.md.txt` 사본으로 보존했다: demo AGENTS, Work AGENTS, Workspace README, recover.md, state. 일반 독자의27개 자료와 한정 독자의 실제 자료·이유는 각 반환에 있다. 나머지 연결 자료는 당시 prototype의 원본을 읽었으며 여기에 전체 복제하지 않았다. 이 묶음만으로 전체 시험 환경을 재현할 수 있다고 주장하지 않는다.

두 반환에서 메모리 예제·인증 적용과 조회 완료의 구별·이름 유지 대안·선택 비용과 이득·실제품 통합 및 수락의 미확인이 복원됐다. 새 검사를 실행한 것으로 보고하지 않았다. 한정 독자는 일반 재개용 state/output 전체·무관한 이력을 읽지 않았다. 다만 두 요청과 읽기 내용이 다르고 이전 판본 대조가 없으므로 문서 수·토큰·시간의 절감 효과를 주장하지 않는다. 코드의 정확성 자체를 재검증한 실험도 아니다.

전체 적용·한계는 [적용 기록](../../2026-11-04-ticket02-recovery-guide-prototype.md)을 따른다.
