# ③ 목록·상세·폼 종합 UX 검토

**현재 판단:** 정상 연결에서 일정 목록 → 일정 상세 → 연결 경비 상세로 이동하고, 일정 상세에서 경비 작성 화면으로 들어가는 기본 경로는 실제 화면에서 확인됐습니다. 연결 제한·복구 때 기존 내용과 초안을 보존하고 첫 조회 실패를 빈 결과와 구별하는 처리는 코드와 자동 검사에 있습니다. 그러나 이 화면들을 **하나의 실제 연결 전환·실제 통신 단절·저장 실패 흐름으로 이어서 확인한 근거는 아직 없습니다.** 따라서 06번의 종합 UX 확인은 진행 중이며, 화면이 몇 개 보였다는 이유로 완료 판정할 수 없습니다.

## 지금 실제로 본 흐름

10월 4일 수집은 iPhone 15 Pro 시뮬레이터의 온라인 상태에서 기존 활성 파리 여행을 이용했습니다. 네트워크 강제 설정은 사용하지 않았고 여행·계정·서버 데이터도 바꾸지 않았습니다.

## 제한·오류·작성 흐름을 코드와 검사에 대조한 결과

**조회 실패는 빈 결과와 분리돼 있습니다.** 일정·경비 목록은 조회 불가일 때 제한 안내, 첫 조회 중일 때 로딩, 첫 조회 실패일 때 ‘불러오지 못했어요’와 재시도, 기존 내용 갱신 실패일 때 이전 내용과 작은 오류 안내를 각각 선택합니다. 일정 상세는 일정 본문과 연결 경비 조회를 따로 처리해, 일정은 보이지만 경비만 실패한 경우에도 일정 전체를 빈 화면으로 바꾸지 않습니다. 경비 상세도 최초 조회가 진행 중이면 ‘경비를 찾을 수 없습니다’로 단정하지 않습니다. 관련 화면 검사는 캐시 복귀, 첫 실패 후 재시도, 갱신 실패 중 기존 내용 유지, 다른 여행의 늦은 응답 배제를 다룹니다. 이 검사는 Repository와 네트워크 상태를 대체한 자동 검사이며, 이번 조사에서 새로 실행한 실앱 오류 장면은 아닙니다.

**이전 일정 생성 결함 두 건은 현재 코드와 자동 검사에서 개선 근거가 있습니다.** 작성 단계가 연결 상태로 자동 전환되지 않고 사용자 행동으로 바뀌며, 생성 화면에는 한 시점에 검색 영역 또는 단일 폼이 표시됩니다. 과거 수동 작성 중 온라인 복귀 시 폼 숨김, 장소 선택 뒤 일반·수동 폼 동시 장착은 현재 생성 화면의 단계 구조와 화면 테스트의 대상입니다. 다만 과거 취소 시 React 경고가 같은 native 조작에서 사라졌는지, 날짜·시간 picker와 키보드를 포함한 전체 작성 흐름은 새 화면 관찰이 없습니다.

**경비 작성의 중요한 값 보존도 제한된 근거가 있습니다.** 앞선 시뮬레이터 기록에서는 Debug offline/unknown 전환 중 경비 생성·수정의 미저장 제목, 금액, 일정 연결이 복귀 뒤 남았습니다. 현재 코드는 경비 폼을 유지하고 저장 실패 이유를 저장 영역에 표시하며, 사용자가 다시 저장을 누를 때만 재시도합니다. 자동 검사에는 활성 여행의 Local 저장, 비활성 여행의 저장 차단과 명시적 재시도, 날짜 변경과 일정 연결의 독립성이 있습니다. 이번 추가 화면 수집에서는 경비 폼을 빈 상태로 열었다 취소했을 뿐입니다. **실제 통신 단절 중 Local 저장**과 **기존 일정이 연결된 비활성 경비 초안을 열린 채 제한·복구하는 native 경험**은 여전히 확인해야 합니다.

## 다음 화면 확인을 한 묶음으로 진행할 순서

1. 같은 비활성 여행의 일정·경비 목록과 각 상세를 연 상태에서 온라인 → offline/unknown → 온라인으로 전환합니다. 선택한 여행·탭·상세의 맥락이 유지되고, 제한 중 내용이 가려지며, 복귀 직후 기존 내용이 먼저 나타나는지 봅니다. Debug 강제 전환 결과와 실제 통신 단절 결과는 별도로 기록합니다.
2. 첫 조회 실패와 기존 내용 갱신 실패를 각각 만듭니다. ‘항목 없음’·‘0원’으로 오인되는지, 이전 내용·오류 문구·재시도 버튼이 실제 터치 후 회복되는지 확인합니다. 일정 상세에서는 연결 경비만 실패하는 경우도 분리해 봅니다.
3. 일정 생성의 직접 입력·장소 선택·취소를 날짜·시간 picker와 키보드까지 조작합니다. 과거 React 경고의 동일 재현 조건을 다시 확인합니다. 이어 경비 생성·수정은 이미 일정이 연결된 초안으로 제한 → 복구 → 사용자가 다시 저장하는 흐름을 봅니다. 서버에 한 번만 반영됐는지도 결과에서 확인합니다.
4. 활성 여행은 실제 통신을 끊은 상태에서 기존 Local 목록·상세 접근과 경비 저장이 계속되는지 확인합니다. Debug 표시만 바꾼 시험을 이 결과로 대체하지 않습니다.

별도 눈에 띈 경계도 있습니다. 일정 상세의 ‘지도에서 보기’ 버튼은 현재 누르면 콘솔 기록만 남기는 코드이므로, 화면에 보이는 행동이 실제 이동을 제공한다고 말할 수 없습니다. 이번 네트워크 종합 UX 확인과 구별해 담당 범위를 정할 필요가 있습니다. 경비 삭제 실패 이유 유실과 경비 상세의 특정 Debug 재시도 불일치는 사용자가 보류한 상태를 유지합니다. 복구 토스트 역시 지금 새로 추가할 근거가 생긴 것은 아닙니다.
