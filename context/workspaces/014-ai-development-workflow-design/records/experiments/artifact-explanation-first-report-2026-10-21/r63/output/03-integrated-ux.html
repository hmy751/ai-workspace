③ 목록·상세·폼 종합 UX

초안 유지와 제한·복구를 잇는 코드는 이미 있습니다. 남은 핵심은 실제 단절·native 조작에서도 그 경험이 성립하는지 확인하는 것입니다.

대조 기준: 제공된 HEAD 0b3b167 tracked snapshot · 조사 방식: 읽기 전용 · 제품 코드 변경 없음

코드·테스트 본문을 직접 읽었습니다. Jest·시뮬레이터·DB 검증은 이번에 실행하지 않았습니다. 날짜 보고서의 독립 계산만 별도로 실행했습니다. 원래 요청의 6.1 sol 병렬 운영은 이번 환경 제약으로 수행하지 못했습니다.

이미 만든 흐름을 다시 구현할 단계는 아닙니다

조회 조합은 여행 없음, 제한, 최초 로딩·실패, 정상 데이터, 기존 데이터를 유지하는 갱신 실패를 나눕니다. 제한 중에도 Query 캐시는 별도로 지우지 않습니다. 사용자는 같은 여행·탭을 유지하고, 접근이 허용되면 기존 내용을 먼저 볼 수 있습니다.

일정 생성은 검색·작성·장소 변경 단계를 사용자 행동으로 바꾸고 초안을 조건부 폼보다 위에 둡니다. 연결 복귀가 작성 단계를 바꾸거나 두 폼을 동시에 붙이는 과거 문제는 코드와 기존 테스트 본문에서 개선 근거를 확인했습니다. 실제 취소 경고가 없어졌다고 이번에 관찰한 것은 아닙니다.

장면별 확인 결과와 빈칸

사용자 장면직접 읽은 근거아직 필요한 확인
비활성 목록·상세에서 단절 → 복구정책을 우선해 캐시를 가리고, ready에서는 캐시를 다시 사용. schedule-recovery·expense-recovery·read-query-consumers에 관련 assertions.같은 여행과 지도 선택을 유지하는 실제 화면 전환.
최초 조회 실패첫 실패를 error로 표시. 일정 상세 오류·경비만 실패·홈 경비 실패를 빈 결과나 0원과 구별하는 검사 본문.서버 실패를 만든 실제 화면에서 문구·버튼 가시성 확인.
기존 내용 갱신 실패ready + refreshFailed로 내용을 유지하고 갱신 실패 안내. retry 가능 여부를 따로 전달.좁은 폭에서 본문·재시도, 연속 단절·재시도 경험.
일정 작성 중 연결 변화create-schedule-flow가 단일 폼·제목·장소 유지, unknown 저장 차단, 복구 후 명시적 저장을 검사.native 날짜/시간 picker 확인·취소, 키보드, 전체 저장·재진입.
경비 작성·수정날짜와 일정 연결을 독립적으로 유지. 생성 flow는 다른 날짜 연결, null 해제, 저장 실패 후 입력 유지와 명시적 재시도를 표현.비활성 기존 연결 보유 초안의 제한·해제·복구를 실제 앱에서 수집.
활성 Local 저장Router·생성 flow가 활성 offline/unknown의 Local 경로를 표현. native DB·HTTP는 대체됨.실제 통신 단절에서 저장 → 재진입 → 복구 sync 후 서버 반영. Debug override로는 입증할 수 없음.

Debug 화면 검증과 실제 단절을 구분합니다

Debug override는 표시 제한을 재현하지만 Router 쓰기를 Local·Remote 모두 막는 계약입니다. 따라서 Debug offline에서 입력이 남았다는 사실은 실제 offline Local 저장 성공의 근거가 아닙니다. 과거 대화의 활성 홈 일정 2개·EUR 56 유지도 홈의 표시 대조 결과에 한정됩니다.

이전 기록에는 개발 DB에 반영된 경비 두 건과 날짜·연결·명시적 재시도 확인이 있습니다. 현재 환경에는 그 DB와 로그가 없으므로 과거 보고로만 취급합니다. 기존 523 passed / 1 skipped 기록 역시 이번 실행 결과가 아닙니다.

수집은 한 여행·상태 묶음으로

  1. 비활성 여행을 online에서 열어 목록·상세와 기존 연결이 있는 폼을 준비합니다.
  2. offline·unknown에서 각 화면의 제한 문구, 선택 유지, 폼 값을 빠르게 수집합니다. 수집자는 원인 판정을 보류하고 조건·조작·보이는 결과를 남깁니다.
  3. online 복구 직후 기존 내용, 자동 저장 없음, 명시적 재시도 결과를 수집합니다.
  4. 활성 여행은 별도 실제 단절 세션에서 Local 저장과 복구 후 반영을 확인합니다. 쓰기 환경을 고정해야 합니다.

우선 캡처는 전체 화면과 오류 영역의 확대를 함께 확보하면 됩니다. native picker·실제 단절 저장은 입력과 결과가 바뀌는 별도 실행이라 후순위 수집 묶음으로 둡니다.

스크린샷·실행 증거

이 보고서에는 앱 스크린샷이 없습니다.

앞선 홈 보고서와 9월 30일 HTML·캡처는 Git 제외 자료로, 이번 입력에 제공되지 않았습니다. 시뮬레이터·DB도 없습니다. 과거 대화의 관찰 보고를 이번 직접 관찰로 바꾸거나 화면을 재구성해 캡처처럼 제시하지 않았습니다.

목록·상세는 정상/제한/복구 세 장면을 같은 여행으로, 폼은 연결 전 입력과 차단 후 입력·복구 후 재시도 결과를 쌍으로 수집해야 합니다. 이번에는 그 이미지를 확보하지 못했습니다.
