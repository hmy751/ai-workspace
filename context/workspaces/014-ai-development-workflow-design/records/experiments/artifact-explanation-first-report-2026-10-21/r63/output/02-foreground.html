② 앱 복귀 시 네트워크 재확인

재확인 기능은 준비되어 있지만, 앱으로 돌아오는 사건과 연결되지 않았습니다. 남은 구현은 앱 수명에서 기존 refresh()를 호출하는 연결입니다.

대조 기준: 제공된 HEAD 0b3b167 tracked snapshot · 조사 방식: 읽기 전용 · 제품 코드 변경 없음

코드·테스트 본문을 직접 읽었습니다. Jest·시뮬레이터·DB 검증은 이번에 실행하지 않았습니다. 날짜 보고서의 독립 계산만 별도로 실행했습니다. 원래 요청의 6.1 sol 병렬 운영은 이번 환경 제약으로 수행하지 못했습니다.

현재 답과 사용자에게 생기는 차이

다른 앱을 보는 동안 연결이 바뀌면 복귀 직후 기존 관측이 오래됐을 수 있습니다. AppInitialization은 mount 때 네트워크 구독을 시작하고 해제 때 정리하지만 AppState를 구독하지 않습니다. 앱의 src·app·tests를 검색해 foreground 연결을 찾지 못했습니다. 다만 NetInfo나 OS가 자체 관측을 전달할 가능성까지 부정하는 결론은 아닙니다.

기존 refresh()는 실제 NetInfo.refresh()를 요청합니다. 이미 확인된 online/offline을 먼저 unknown으로 지우지 않으며, 새 관측에 따라 상태를 갱신합니다. 따라서 복귀용 별도 네트워크 저장소나 polling을 추가할 필요는 없습니다.

있는 동작과 빠진 연결

구간직접 확인한 내용판단
앱 준비DB → 인증 복원 후 children 연결. 네트워크 확인 결과를 기다리지 않음.foreground 재확인을 준비 완료의 새 조건으로 넣지 않음.
재확인 중복진행 중 activeRefresh의 동일 Promise를 반환.수동 재확인과 복귀가 겹쳐도 기존 장치를 재사용.
늦은 결과session·activeRefresh·observationRevision을 모두 검사.새 listener 관측을 오래된 refresh 결과가 덮지 않도록 구성됨.
실패·미응답unknown이면 확인 불가 안내, 기존 확정 상태는 유지. 작업은 10초 후 종료 가능.실제 인터넷 도달·서버 정상 응답을 보장하는 timeout이 아님.
복귀 → refreshAppState 사용·연결을 찾지 못함.구현과 앱 수명 통합 검사가 남음.

화면과 sync까지 이어지는 범위

관측이 바뀌면 정책 훅은 실제 상태와 표시 override를 구별해 조회 접근을 계산하고, 조회 조합은 제한 또는 캐시 내용을 선택합니다. SyncProvider는 실제 네트워크·인증·override·종료 일시 중단에 따른 실행 가능 조건의 변화를 구독합니다. 단, refresh가 기존 online을 그대로 반환하면 조건 변화가 없으므로 복귀마다 sync를 새로 시작하는 계약은 아닙니다.

전역 Query의 refetchOnReconnect와 refetchOnWindowFocus는 false입니다. 복귀 연결이 생긴다는 이유로 모든 조회·sync를 강제 실행하거나 완료를 기다리게 해서는 안 됩니다.

기존 검사와 다음 검사

확인 방법기존 테스트 본문추가할 확인
Store 단위network.test.ts는 동시 Promise 공유, 실패, timeout, 새 listener 이후 오래된 결과, cleanup 이후 결과 무시를 assertion으로 표현. 이번 재실행 없음.기존 검사를 재사용해 변경 후 회귀 확인.
앱 수명layout.test.tsx는 실제 RootLayout과 Store를 쓰되 native·DB·sync를 대체. AppState 복귀 검사는 없음.background → active, inactive 경유, active 반복 이벤트, mount/cleanup, 수동 refresh와 겹침을 검증.
실앱이번 관찰 없음.이전 online/offline/unknown 각각에서 연결 변경 후 복귀. 화면 선택·초안 유지와 sync 중복 여부 관찰.

스크린샷·실행 증거

이 보고서에는 앱 스크린샷이 없습니다.

앞선 홈 보고서와 9월 30일 HTML·캡처는 Git 제외 자료로, 이번 입력에 제공되지 않았습니다. 시뮬레이터·DB도 없습니다. 과거 대화의 관찰 보고를 이번 직접 관찰로 바꾸거나 화면을 재구성해 캡처처럼 제시하지 않았습니다.

수집할 최소 장면: 복귀 전 네트워크 상태 → 다른 앱으로 이동 → 연결 변경 → 복귀 직후 화면과 재확인 완료 화면. 캡처만으로 refresh 호출 횟수는 알 수 없으므로 시각과 호출 로그를 함께 남겨야 합니다.

다음 행동

AppInitialization의 네트워크 감지 수명에 복귀 listener를 연결하고 cleanup에서 제거하는 작은 구현이 적절합니다. 이전 상태를 기억해 실제 복귀만 재확인하도록 하고, 중복·늦은 결과는 Store에 맡깁니다. 현재 보고서 작업에서는 구현하지 않았습니다.
