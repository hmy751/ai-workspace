foreground 네트워크 재확인

재확인 기능은 준비돼 있습니다. 앱 복귀 사건을 연결하고 화면·sync까지 확인하는 일이 남았습니다.

코드 기준: 제공된 HEAD 0b3b167 스냅샷 · 검토 작성: 2026-10-21 · 이어받은 대화 시점: 2026-10-04

근거 범위 — 이번에 코드·테스트 본문을 직접 대조했습니다. 앱·시뮬레이터·DB·전체 Jest는 실행하지 않았습니다. 대화와 저장 기록의 과거 통과·관찰은 새 실행 결과와 구별합니다. Git 메타데이터가 없어 branch·working tree는 재확인하지 못했습니다.

앱으로 돌아왔을 때 지금 연결을 다시 확인하는가

앱 시작 시 네트워크 감지는 구독하지만, background 또는 inactive에서 active로 돌아온 사건을 받아 재확인하는 코드 연결은 없습니다. AppInitialization은 mount에서 init, unmount에서 cleanup을 호출합니다. client src·app을 검색한 범위에서 AppState 사용은 발견되지 않았습니다. NetInfo 자체가 플랫폼에서 이벤트를 주는 가능성과 앱이 복귀 때 한 번 확인하는 보장은 구별해야 합니다.

화면과 sync에 이어지는 영향

관측이 바뀌면 조회 정책과 SyncProvider가 실제 상태를 소비합니다. 비활성 여행은 실제 online을 확인해야 Remote 요청이 열립니다. sync는 인증·DB·override·진행 중 실행 조건도 맞아야 시작합니다. 앱 복귀 때 상태가 계속 online이면 복귀 자체가 새 sync 이유가 되지는 않습니다. 이번 연결을 “돌아올 때마다 강제 sync·전체 refetch”로 확대하면 기존 책임이 달라집니다.

작게 마무리할 수정과 검사

앱 전체 관측 수명을 가진 AppInitialization 근처에서 이전 AppState를 추적하고, 비활성 상태에서 active로 전환할 때 기존 refresh()를 호출하는 것이 적절합니다. initial active와 active 반복은 복귀로 세지 않고 listener는 unmount에서 정리합니다. 별도 polling·강제 unknown·unknown에서만 재확인은 추가하지 않는 기존 결정을 유지합니다.
