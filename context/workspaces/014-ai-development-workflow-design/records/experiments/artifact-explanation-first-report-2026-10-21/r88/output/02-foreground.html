② 앱 복귀 시 네트워크 재확인

앱 복귀 사건과 재확인 기능을 잇는 작업이 남아 있습니다.

화면 증거 미확보
시뮬레이터·DB·기존 HTML과 캡처가 제공되지 않았습니다. 새 스크린샷은 없으며, 이 보고서는 제공된 코드·검사 본문·티켓과 제한된 날짜 실행을 근거로 작성했습니다. 과거 대화의 실행 보고는 이번 직접 관찰과 구별합니다.

현재 답

기존 네트워크 재확인 기능은 있지만, 앱이 백그라운드에서 돌아올 때 호출하는 연결은 없습니다. 따라서 Store의 중복·지연 응답 방어가 있어도 앱 복귀 시의 오래된 관측을 적극 갱신하는 경로는 완성되지 않았습니다.

앱 소스와 테스트에서 AppState 사용을 검색했으며 찾지 못했습니다. NetInfo 자체 listener가 상태 변화를 전달할 수 있으므로 “복귀하면 반드시 stale하다”는 재현 결론까지 내릴 수는 없습니다.

어디까지 연결되어 있나

경계확인한 구현보장 한계
앱 수명AppInitialization이 mount 시 networkStore.init(), 해제 시 cleanup()background → active 사건의 구독과 refresh 호출 없음
재확인Network Store의 refresh()가 NetInfo.refresh() 호출완료 자체를 online으로 간주하지 않음
동시 호출activeRefresh.promise 공유foreground 호출과의 결합 검사는 새로 필요
늦은 응답세션·작업 identity와 observationRevision 대조구현·mock 검사 본문 확인, native 실행 미확인
화면과 sync조회 조합은 정책을 소비하고 SyncProvider는 realStatus 변화로 eligibility 계산복귀 사건부터 실제 화면·sync까지의 실행 관찰 없음

구현할 결과와 확인 순서

앱 수명을 맡는 application 경계에서 background/inactive에서 active로 돌아오는 전환을 감지해 기존 refresh()를 호출하는 것이 적절합니다. 초기 mount와 반복 active 알림을 전환으로 오인하지 않고, 해제 시 listener를 정리해야 합니다. 이전 상태가 online·offline·unknown 어느 것이든 같은 재확인 경로를 사용합니다.

새 polling·강제 unknown 전환은 필요하지 않습니다. 수동 재확인과 겹침, 빠른 왕복, 해제 후 응답, refresh 뒤 더 최신 listener 도착을 결합 검사하고, 실제 한 번의 앱 왕복에서 관측·화면 제한·sync 시작을 함께 확인하면 됩니다.

수집해야 할 화면과 기록

동일한 여행을 유지한 채 online으로 나가기 → 연결을 바꾸고 돌아오기 → 제한 안내 → 다시 online 복귀를 수집합니다. 스크린샷만으로 refresh 횟수나 sync 중복은 판별하기 어려우므로 AppState·재확인 호출 횟수·최신 realStatus 기록도 필요합니다. 이 자료는 이번에는 수집하지 못했습니다.

코드·티켓은 읽기 전용으로 조사했습니다. Jest·실앱·서버 DB 검증은 이번에 실행하지 않았습니다. 작성일 2026-10-21. 코드 근거는 접힌 영역에서 원문과 줄 번호로 확인할 수 있습니다.
