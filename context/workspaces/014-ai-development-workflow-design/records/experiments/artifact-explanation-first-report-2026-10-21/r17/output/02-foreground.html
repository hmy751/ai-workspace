② 앱 복귀 시 네트워크 재확인

기존 refresh를 복귀 수명에 연결할 작업이 남았습니다. 실제 foreground 전환은 이번에 실행하지 않았습니다.

대상: 제공된 HEAD 0b3b167의 tracked snapshot. Git 메타데이터·당시 실행 환경은 제공되지 않았습니다. 제품 코드 변경 없음.

판단과 사용자에게 미치는 영향

재확인 동작은 구현됐지만, 앱으로 돌아온 사건에 연결된 앱 코드는 없습니다.

다른 앱에 있는 동안 네트워크가 바뀌었을 때 복귀 시 관측을 다시 요청하는 연결이 남았습니다. 다만 NetInfo 자체 listener가 관측을 전달할 수 있으므로, “복귀하면 반드시 오래된 상태가 남는다”는 실제 결함 재현까지 확인한 것은 아닙니다.

현재 연결

부분직접 확인한 코드남은 일
앱 수명AppInitialization mount에서 networkStore.init(), unmount에서 cleanup(). DB→인증 복원→앱 진입은 네트워크 확정과 별개.background/inactive→active 변화에서 refresh를 호출할 앱 수명 연결.
재확인networkStore.refresh()가 NetInfo.refresh()를 요청. 동시 호출은 같은 Promise 공유.복귀 이벤트와 수동 버튼이 겹칠 때 실제 integration 확인.
늦은 관측refresh 시작 시 revision과 listener 최신 revision을 비교하고 cleanup된 session 응답 무시.연속 복귀·해제·재진입까지 AppState 소비 테스트로 연결.
화면·sync화면 표시 override와 실제 요청 관측은 분리.복귀 결과가 비활성 화면 제한과 실제 online sync 시작 조건에 전달되는지 관찰.

검증 근거의 범위

직접 확인: 앱 source 전체에서 AppState 참조를 찾지 못했습니다. Network Store와 관련 테스트 본문에서 중복 Promise 공유, 오래된 refresh 배제, cleanup 후 응답 무시를 확인했습니다.

테스트 파일의 존재와 검사 내용 확인: tests/shared/store/network.test.ts 223행·297행·356행. 이번에 Jest를 실행한 것은 아닙니다. Store 단위의 검사는 아직 없는 앱 복귀 연결의 검증이 될 수 없습니다.

이전 기록: 06 티켓은 foreground 후속과 전체 UX 수락을 남겨 두었습니다. 대화의 홈 online/offline/unknown 관찰은 background 복귀 검증이 아닙니다.

수정한다면 지켜야 할 경계

앱 실행 수명을 소유하는 AppInitialization에서 실제 복귀 전환을 구별해 기존 refresh를 호출하는 방향이 적절합니다. 현재 active 상태로의 단순 rerender와 실제 복귀를 구별하고 listener 정리도 같은 수명에 둡니다. 인증 복원·DB 준비·Splash를 다시 시작할 이유로 삼지 않습니다.

복귀 직후 강제로 unknown으로 바꾸거나 polling을 추가하지 않습니다. unknown일 때만 확인하는 것으로 한정하지도 않습니다. 이미 Store가 맡는 중복·timeout·늦은 결과 방어를 새로 복제할 필요는 없습니다.

스크린샷과 다음 수집

이번 보고서에는 앱 스크린샷이 없습니다.
기존 HTML·캡처·시뮬레이터가 입력에 포함되지 않았습니다. 대화 속 관찰은 이전 보고로만 인용하며, 코드 발췌나 설명용 예제를 실제 화면으로 대체하지 않았습니다.
  1. 앱 online 화면을 기준 캡처한 뒤 background 이동 → 실제 연결 변경 → foreground 복귀 화면·상태 로그를 같은 여행에서 수집.
  2. 빠른 복귀 반복과 수동 재확인을 겹치고 요청 수·최종 관측·화면을 함께 수집.
  3. 활성 여행은 Local 이용 유지, 비활성 여행은 제한 해제 또는 유지, 실제 online 복구는 sync 시작 조건까지 별도 로그 확인.
