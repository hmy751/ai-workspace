워커 구현과 독립 검증까지 끝났습니다. **Ticket 06에서 합의한 첫 네트워크 연결 범위는 구현·자동 검사 기준으로 충족됐고, 독립 검증자는 수정이 필요한 P1/P2 문제를 더 발견하지 못했습니다.** 제가 티켓·합의 기록과 대조해 채택한 범위 안의 결과이며, Ticket 06 전체 완료와는 구별합니다.

이번 개선의 핵심은 실제 요청을 허용하는 조건과 화면에서 보여 주는 상태가 각각 필요한 곳에 연결됐다는 점입니다.

- **sync는 자동·수동 호출이 같은 실행 경계를 사용합니다.** `SyncProvider`가 DB 초기화 성공, 인증 준비와 로그인, 실제 online, debug 강제 설정 해제를 확인합니다. 실행 중 작업은 React의 표시 상태를 바꾸기 전에 보관하므로 같은 순간에 두 번 호출해도 engine은 한 번 실행되고 두 호출자가 같은 완료를 기다립니다. 실제 debug 버튼의 engine 직접 호출도 제거했습니다. Root는 초기화 시도가 끝난 것과 DB 사용 가능을 구별하고, 앱 복귀 때 연결을 재확인합니다.
- **데이터 저장 위치는 작업 대상 여행으로 판단합니다.** 예전에는 활성 여행 A가 하나 있으면 비활성 여행 B의 수정까지 Local로 갈 수 있었습니다. 이제 Router에 B의 `tripId`가 전달돼 B의 활성 여부로 분기합니다. 일정·경비 수정과 삭제도 이미 알고 있는 `tripId`를 전달하므로, B의 데이터가 Local에 없다는 이유로 정상적인 온라인 서버 작업이 막히지 않습니다. Trip 수정 요청도 기존 서버 계약에 맞춰 PUT으로 연결했습니다.
- **내용 제한과 복구는 캐시 존재와 별도로 판단합니다.** 일정·경비 목록과 상세 화면은 비활성 여행에서 연결이 끊기면 이전 서버 캐시를 보존한 채 제한 안내를 보여 줍니다. 같은 여행을 계속 보고 있다면 실제 online 복귀 후 재조회가 성공해야 내용을 다시 엽니다. 다른 여행으로 이동한 뒤 도착한 이전 응답은 복구 판단에 사용하지 않습니다. 폼과 Drawer는 유지하고, 저장 거부 이유는 기존 오류 안내로 한 번 전달합니다. 실패한 저장을 자동 재실행하는 기능은 추가하지 않았습니다.
- **debug 표시가 실제 요청 조건을 바꾸지 않습니다.** 화면을 online으로 강제해도 실제 offline/unknown이면 장소 검색·길찾기 요청과 Google 지도 마운트를 열지 않습니다. 강제 설정 중에는 Router를 통한 Trip·Schedule·Expense 쓰기와 새 sync도 차단합니다. 일정 카드의 안내는 화면 상태 변화에 맞춰 갱신됩니다.

가독성 측면에서도 조건을 더 분산시키지 않았습니다. Router는 실행 시점 차단과 오류 전달을, 화면은 내용·안내 선택을, Provider는 sync 시작과 실행 공유를 맡습니다. Network Store의 기존 자원 소유 구조는 유지했고, 추가 파일 분할이나 범용 startup framework는 만들지 않았습니다.

독립 검증은 구현 보고만 확인한 것이 아니라 합의 본문·수정 전 코드·수정 후 실제 호출부를 대조했습니다. 그 과정에서 **초기 unknown 이후 여행 목록이 회복하지 않는 문제, 여러 화면의 복구 조회가 서로 취소되며 요청을 중복 전송하는 문제, 일정 제한 안내 중복, Home 여행 삭제의 제한 이유 누락**을 발견했고 최종 코드에서 보완됐습니다. 특히 복구 조회는 진행 중 요청을 공유하도록 바꿨으며, 실제 React Query를 사용하는 회귀 검사에서 두 소비자가 요청 한 번을 공유하고 성공 전에는 캐시 내용을 숨기는 것을 확인했습니다.

최종 검사 결과는 다음과 같습니다.

- 전체 client Jest: **20개 묶음, 205개 테스트 통과**.
- 독립 검증자의 별도 실행: 영구 회귀 검사 한 개를 추가하기 전 **19개 묶음, 204개 테스트 통과**, 별도 React Query 검사 2개 통과.
- 변경 파일 형식 검사와 ESLint 통과. ESLint 오류는 없고 기존 경고 6개가 남았습니다. 변경 차이 검사도 통과했습니다.
- 전체 타입 검사는 기존 지도 관련 오류 3개로 실패했습니다. 이번 변경 경로에서 추가 타입 오류는 확인되지 않았습니다.

**실제 Expo·기기 NetInfo·SQLite·외부 API·서버·화면 이동 전체 흐름은 아직 실행 확인되지 않았습니다.** sync의 `completed`도 engine이 반환됐다는 뜻이며 queue 전체 반영 성공을 보장하지 않습니다. DB/auth 실패 화면·인증 진입 제어·나머지 초기화와 Splash 연결은 Ticket 06 후속 범위이고, Local 저장과 queue 기록의 원자성·sync 결과와 재시도·cleanup은 각각 14·15·16의 책임으로 남습니다.

이번 결과와 검증 한계는 티켓과 품질 개선 기록에 반영돼 있습니다. 제품 코드·테스트·관련 문서는 미커밋 상태입니다.
