# Explain — 질문과 실제 대상을 연결해 설명한다

사용자가 이번 질문의 뜻과 관계를 이해하고 자기 판단을 이어갈 수 있게 설명한다. 개념의 뜻, 코드·산출물의 구조와 동작, 결과와 선택의 이유, 앞선 설명의 보완을 다룬다. 구조를 이해하는 것 자체가 목적일 수도 있으며 모든 설명에 다음 행동을 붙이지 않는다.

이 본문이 설명의 공통 수행을 맡는다. [설명을 구성하는 상세](references/constructing-explanations.md)는 실제 자료에서 설명할 부분을 고르고 연결하는 방법을, [앞선 설명 상세](references/prior-explanation.md)는 원래 발화의 뜻과 현재 타당성을 대조하는 일을 맡는다. 두 상세는 필요에 따라 함께 쓰며 고정된 유형·단계·출력 목차가 아니다.

## 이번 질문에서 설명의 중심을 잡는다

사용자가 가리킨 대상과 현재 질문, 앞선 대화에서 공유한 내용을 함께 보고 무엇을 이해하면 답이 되는지 잡는다. 이미 밝혀진 맥락을 되묻거나 사용자에게 혼동 원인을 먼저 진단해 달라고 요구하지 않는다. 짧은 질문에도 중요한 조건이 있을 수 있고, 전체 설명 요청도 관계가 단순하면 짧게 답할 수 있다.

이름의 뜻을 묻는다면 그 자리에서 무엇을 가리키는지 답한다. 동작이나 관계를 묻는다면 어떤 부분이 어떻게 이어져 결과를 만드는지, 선택 이유를 묻는다면 어떤 요구와 조건에서 그 선택이 나왔는지 설명한다. 한 질문에 여러 일이 섞이면 함께 답한다. 질문이 앞선 설명의 특정 말·누락·모순·자기평가를 겨냥하면 [앞선 설명 상세](references/prior-explanation.md)를 읽어 실제 발화부터 대조한다. 후속 질문이라는 이유만으로 앞선 설명의 실패나 사용자의 혼동을 단정하지 않는다.

## 답에 필요한 자료를 고르고 설명한다

직접 답을 먼저 주고, 그 답을 이해하는 데 필요한 관계를 실제 대상과 함께 펼친다. 중요한 이름은 처음 등장하는 자리에서 가리키는 대상·역할을 풀어 쓴다. 역할의 이름과 호출 순서만 나열해 사용자가 의미를 조립하게 두지 않는다.

예를 들어 ‘저장 완료와 목록 갱신 완료는 다르다’를 설명하려면 저장 요청만 보여서는 부족하다. 저장 뒤 갱신을 요청하는 부분과 실제 목록을 구성하는 부분을 함께 골라, 각각 어떤 결과까지 맡는지 설명한다. **자료를 읽은 뒤 관련 내용을 모두 요약하기보다, 현재 질문을 푸는 관계가 드러나는 부분을 골라 그 부분 가까이에서 뜻을 설명한다.** 링크는 재접근을 돕고, 이해의 핵심은 응답 안에서 연결한다.

여러 부분의 역할·상태·조건, 선택 이유나 관찰에서 나온 결론을 원자료와 연결해야 하면 [작성 상세](references/constructing-explanations.md)의 해당 절과 예시를 읽는다. 코드·문서·앞선말이라는 대상 종류로 배타적인 경로를 고르지 않는다. 이미 대화와 기본 설명으로 답이 되는 질문에 모든 상세를 읽히지 않는다.

자료가 더 필요하면 이번 답을 바꾸는 공백부터 확인한다. 프로젝트 사실은 실제 대상의 진입 지침과 관련 맥락·원자료에서 찾고, 이 스킬의 위치를 제품 저장소로 가정하지 않는다. 방금 변경한 결과라면 비교 기준과 변경 후 사용처를, 과거 대상이면 당시 자료를 선택한다. 현재성·실행 여부·검증 범위가 답을 바꿀 때 [공통 설명과 근거 기준](../shared/explanation-and-evidence-criteria.md)을 읽고 적용한다. 익숙한 개념이나 대화 안의 뜻만으로 답할 수 있으면 저장소 조사부터 시작하지 않는다.

원자료의 일부만으로 주장을 뒷받침할 수 없으면 필요한 연결을 더 확인하거나 설명의 범위를 낮춘다. 사실이 부족한 것을 문장으로 메우지 않고, 이미 필요한 자료가 있는데도 ‘미확인’이라고 적는 것만으로 확인을 대신하지 않는다.

## 관계가 보이는 형태로 답을 구성한다

설명을 가르는 조건이 있으면 같은 상황에서 조건이 달라질 때 결과가 어떻게 달라지는지 보여 준다. 코드 발췌·표·그림·구체 상황은 그 관계를 더 잘 따라갈 수 있을 때 선택하고, 사용자가 요청한 표현 방식도 반영한다. 실제 관찰과 설명용 예시는 구별한다. 도식의 화살표나 묶음도 관계에 관한 주장이므로 실제 근거보다 강하게 그리지 않는다.

직접 답과 중심 관계를 먼저 드러내고, 그것을 바꾸는 조건은 가까이에 붙인다. 여러 예외·파일·검사 내역을 중심 설명과 같은 비중으로 늘어놓지 않는다. 필요한 상세는 찾아 읽을 수 있게 나누되 핵심 답을 링크 뒤에 남기지 않는다. 사용자의 배경지식이나 이해를 추정해 중요한 전제를 생략하지 않고, 현재 질문과 무관한 문법·배경도 모두 강의하지 않는다.

앞선 설명을 보완할 때는 이미 공유한 지점에 이어 답한다. 기존 표현으로 연결되지 않았다면 실제 대상·값·조건의 대응으로 설명 방법을 바꾼다. 실제 오류가 보이면 해당 주장과 달라지는 결론을 분명히 정정한다. 사용자의 이의에 맞춰 무조건 기존 선택을 바꾸거나, 새 설명을 원래부터 한 말처럼 쓰지 않는다.

## 첫 결과를 전달하는 작업과 연결한다

작업 결과를 전달할 때는 원래 질문에 무엇이 답해졌는지 먼저 구성한다. 그 답을 이해하려면 변경의 관계나 선택 이유를 따라가야 할 경우 이 설명 방법을 사용한다. 설명할 필요가 분명해지면 자료를 고르고 읽는 과정부터 적용하며, 모든 조사가 끝난 뒤 문장만 다듬는 단계로 고정하지 않는다.

필요한 연결을 만들 수 없는 이유가 사실 부족이면 작업 담당자가 기존 권한 안에서 더 확인할지 판단한다. 확인할 수 없다면 그 이유와 답에 미치는 영향을 밝힌다. 표현을 보완할 일과 원래 조사·구현을 더 수행할 일을 구별하며, 설명 스킬을 사용했다는 사실로 전체 작업이 충분해졌다고 판단하지 않는다. 항상 전체 브리핑이나 재검사를 시작할 필요는 없다.

## 답의 범위와 마무리를 지킨다

현재 질문의 직접 답과 이해에 필요한 관계가 드러나고, 결론의 의미를 바꾸는 조건·미확정이 보이면 응답을 마친다. 설명한 사실과 사용자가 실제로 이해·동의한 사실은 다르다. 침묵으로 이해 완료를 선언하거나 quiz·재진술·형식적 승인을 기본으로 요구하지 않는다. 질문식 학습을 요청했다면 그 방식으로 돕는다.

설명에 필요한 확인과 근거 있는 추천은 할 수 있다. 설명 요청만으로 코드·문서·작업 결과를 수정하거나 제품 선택·최종 acceptance를 새로 확정하지 않는다. 별도의 변경 요청이나 기존 위임이 있으면 그 권한을 따른다. 지속 기록은 실제 대상의 관리 규칙과 담당자가 맡고, 이 스킬이 별도 상태 저장소나 고정된 Maintain 담당을 만들지 않는다.

목적·구성·이전 선택을 재검토할 때는 [형성 자료](_background/README.md)를 읽는다. 현재 실행에 필요한 내용은 위 본문과 해당 조건의 상세에 있다.
