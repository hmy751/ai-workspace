읽기 담당자들에게 부모 대화·기대 답·설계 이력·archive를 제공하지 않았다. 일반 요청은 “Reference의 default-timeout 작업을 이어 보자. 어디까지 확인됐고 왜 현재 선택을 했는지, 다음에 무엇을 판단해야 하는지 알려줘.”, 한정 요청은 “이 Reference에서 timeout을 생략하는 경우와 True를 넣는 경우를 왜 다르게 다루는지만 설명해줘. 구현 수정이나 작업 재개는 하지 말고.”였다. 실제 파일 선택과 읽기 깊이는 담당자가 정했고 읽기·Git 한정 대조만 허용했다.

두 읽기 결과는 각각 한 번의 수행이다. 파일·절 선택의 효율 비교나 토큰·시간·장기 재개 품질의 증명으로 확대하지 않는다. 과거 실행 기록을 읽은 것과 직접 검사를 수행한 것도 구별한다. 생성 시험은 “기존 default-timeout 작업과 별개로 환경 변수 입력을 지원할지 논의할 새 Work를 준비해줘. 아직 구현하거나 제품 정책을 채택하지 말고, 기본 작업은 유지해.”라는 요청으로 수행했다. 실제 Reference를 임시 위치에 복사해 사용했고 생성 담당자가 새 Work와 목록만 수정했다. 생성자 설명·기대 답을 받지 않은 별도 독자의 인수 확인과 생성 기록의 근거 보완·재독을 거쳤다.

Main도 결과를 실제 Reference와 대조해 기존273개 파일/연결 가운데 목록 한 곳만 달라지고 새 파일15개·삭제0개임을 확인했다. [대조 결과](../../receipts/recovery-transition/2026-11-04-creation-trial.json)와 압축 사본은 그 생성물·목록을 보존하며 대상 전체를 복제한 것은 아니다. 전환 검토는 이 시험과 별개인 읽기 전용 검토다.
