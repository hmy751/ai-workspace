## 사례 선택과 사전 판단 기준

03·04를 반복 생성하지 않고, 현재 reference-project의 실제 코드 사본에서 새 질문 두 개를 Main이 구성했다. 자연 발생한 사용자 사건 재현이 아니며 같은 저장소의 공개된 코드라 비공개 평가나 일반화의 보장은 아니다. 현재 스킬의 인증·동기화·여행 예시에 이 코드는 없다. 스킬 없음 비교는 이번 범위에 포함하지 않는다. 기존 시험과 성공률을 합산하지 않는다.

- worker: 여러 부분을 연결하는 설명. 별도 프로세스를 시작하는 일과 drain에서 실제 처리하는 일, 저장·알림·의미 판단·적용의 관계, session별 직렬 실행과 generation별 실패 후 보류의 구별을 실제 코드로 설명하는지 본다. 함수별 요약이나 모든 분기 나열, 등록/비동기 예시의 억지 이식은 충분성 기준이 아니다. worker의 호출부·저장 도구 사본을 함께 제공하며 제공되지 않은 내부 구현·현재 활성화·exactly-once를 추정하지 않는지도 본다.
- scalar: 한 조건의 필요성을 묻는 짧은 판단. Python bool/int 관계와 True가 양수 검사까지 통과할 수 있다는 사실을 현재 positive integer 계약에 연결하는지 본다. 함수 전체 강의·코드 수정·동작 검사를 새로 수행했다는 주장은 요구하지 않는다.

본체·상세를 읽은 사실과 응답에서 수행된 관계를 구별한다. 코드 수·제목 수·단어 포함으로 효과를 채점하지 않는다. worker에서 장문의 절차 설명만 늘거나 scalar에서 범위가 불필요하게 커지면 그 사실을 남기고 원하는 답이 나올 때까지 재생성하지 않는다.

## 실행 상태

네 조건을 각각 새 GPT-6-sol high 컨텍스트에서 최초1회 생성했다. 공통 입력·prompt 동일성, 입력/조각 해시, 필수·선택 파일 완독, 본체 선행 읽기와 응답 전 read-check를 통과했다. 최초 원문은 실행 폴더 output과 answer 파일·blind-responses.md에 바이트 그대로 보존했다. 모두 실행 메모에서 잘림·범위 밖 접근·코드 수정·제품 검사 재실행 없음을 보고했다. 이는 자기보고이며 로그만으로 OS 접근 격리를 증명하지 않는다.

사용자는 전반적으로A가 더 나아 보이며 B의 response_end 접수부터 시작하는 흐름은 좋다고 했다. [조건 공개·대조 판단](comparison.md)에 도입 관계 구성의 국소 이득과 전체 우세 미확인, 직전판A 선호를 구별했다. 이 결과로 설명의 일반 우세·실제 사용자 이해·04-02 전체 완료를 주장하지 않는다. 스킬 본체·상세·인증 원문 대조의 통과와 실제 응답 품질은 별개다.
