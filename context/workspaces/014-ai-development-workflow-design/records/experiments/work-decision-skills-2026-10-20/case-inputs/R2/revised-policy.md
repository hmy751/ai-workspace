# 후속 정책 발췌

비활성 여행의 offline/unknown 제한은 유지한다. 실제 연결이 돌아와 접근 정책이 허용되면 같은 계정·여행의 기존 데이터를 먼저 표시하고, 화면을 재조회 성공이나 sync 종료까지 기다리게 하지 않는다. 기존 Query의 캐시·갱신 기준을 활용하고 sync·저장·삭제의 갱신이 겹쳐 추가 조회가 발생하는 것은 허용한다. 실제 변경이 화면에 반영되는 책임은 유지한다.

화면은 정책 제한·내용 배치와 선택·입력 보존을 맡는다. Query는 조회가 가능한 동안 캐시와 조회 상태를 관리한다. Router·인증 계층은 기존 실행 시점의 실제 연결·세션·소유권·Local/Remote 분기를 유지한다. sync는 push→pull과 실제 변경 뒤 갱신을 맡는다.

기존 데이터가 있는 background 재조회 실패 때 내용을 유지하고 실패·재시도를 안내하는 것은 Main의 추천이며 별도 채택 전이다. 데이터가 없을 때는 일반 조회·로딩·오류 흐름을 사용한다. 2-C에서는 토스트가 연결 복귀를 알리는지 데이터 갱신 성공을 알리는지 정해야 한다. 초기 unknown·단순 재확인에는 복구 토스트를 붙이지 않고 같은 장애에 반복 표시하지 않는 기준은 유지한다. 토스트를 위해 강제 GET나 화면 대기를 되살리는 방향은 피한다.
