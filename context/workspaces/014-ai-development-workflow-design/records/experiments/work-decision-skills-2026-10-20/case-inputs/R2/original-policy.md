# 기존 결정 발췌

네트워크가 끊겨도 여행이 사라진 것처럼 보이거나 탭이 닫히면 사용자는 데이터가 없어졌다고 이해할 수 있다. 활성 여행은 이미 준비된 Local 데이터를 계속 사용할 수 있으므로, 네트워크 변화로 활성 여행 자체를 바꿀 이유도 없다.

그에 따라 여행 기본 정보·탭·사용자 선택을 유지하고, 비활성 여행의 일정·경비 내용에 제한 안내를 표시하기로 했다. 이미 offline일 때 새 비활성 여행을 선택하려 하면 기존 선택을 유지하고 연결 뒤 선택하도록 안내한다. 보던 비활성 여행에서 연결이 끊긴 경우에는 그 여행 선택을 유지하며 오프라인 준비된 활성 여행으로 돌아갈 행동을 제공한다. 활성 여행이 없으면 이 기기에서 쓸 수 있는 여행이 없다고 설명한다.

복구 시 같은 비활성 여행을 보고 있을 때만 다시 조회한다. 사용자가 이동한 뒤 원래 여행으로 강제 복귀하지 않는다. 복구 조회가 성공하면 한 번의 토스트면 충분하다는 사용자 판단을 채택했다. 실패는 일반 조회 오류로 처리한다. 초기 연결 확인과 단순 재확인 완료는 장애 복구 토스트의 대상이 아니다.

React Query 캐시는 앞서 서버에서 받은 응답이 앱 메모리에 남아 있는 것이고, 활성 여행의 Local SQLite와는 다르다. 새 요청을 막아도 이전 data가 남을 수 있다는 설명 뒤 사용자는 “복잡도가 너무 높아질것 같아 … 그냥 자연스레 제한을보여주는걸로 하자”라고 선택했다. 캐시를 삭제하거나 별도 관리하지 않고 화면에서 접근 정책에 따라 제한 안내를 선택한다. 캐시 존재를 오프라인 이용 권한으로 취급하지 않는다.
