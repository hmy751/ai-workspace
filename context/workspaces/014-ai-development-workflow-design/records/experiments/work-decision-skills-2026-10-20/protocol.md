# 작업 판단 스킬 비교 — 실행 전 계획

## 범위

동일 모델·추론 설정을 상속한 fresh subagent에 각 입력을 하나씩 제공한다. 기존 대화는 전달하지 않는다. 각 조합 2회, 총16회다. 피실행자는 다른 조건·버전·평가기준·사후 정정·권고 답변·현재 분석 기록에 접근하지 않는다. 실행 순서는 고정 seed로 섞었다. 버전은 파일 경로에서 노출하지 않는다.

제품 코드 전체를 재현하는 시험이 아니다. 보존 문서와 당시 조사에서 확인했다고 보고된 사실을 입력으로 제공한 뒤, 작업 정의와 재판단의 응답을 비교한다. 파일 범위 제한은 지시 기반이며 OS별 격리 sandbox가 추가된 것은 아니다. 관찰 가능한 도구 접근과 응답을 확인한다.

## 조건과 provenance

- D1: 경비 합계 추가 구체화. user source_line74, 실행 전 Ticket blob d5ed37…, 공통 품질의 앞부분7b6b1cdf…를 사용한다. 관련 링크는 원문 사본 밖으로 나가지 않도록 표시 문구로 변환했다. observations는 응답105에 있는 현재 계산·표시의 사실 보고만 추출·재서술했다. 보강 제안과 사후125 정정은 포함하지 않는다. 응답을 재현하는 시험이 아니라 해당 관찰을 이미 얻은 상태의 판단 비교다.
- D2: D1에서 금액 표시 보존 조건을 표시 통일 요구로 바꾸고, 최종 표시 기준이 미정인 상태를 만든 가상 변형이다. 나머지 합산·정렬·강조는 보존한다. 실제 Noline 결정으로 해석하지 않는다.
- R1: 복구 알림 재검토. user2499, 9/16 original policy9778a2…의 해당 절, 9/29 policy c16641…의 범위·역할·열린 판단 문단과 현재 시스템 facts를 사용한다. facts는2492·2528·2542에 보고된 관찰만 추출·재서술했다. 알림 추천안이나 사용자2549 이후의 정정·미추가 선택은 포함하지 않는다.
- R2: R1의 현재 구현은 유지하고 사용자가 복귀를 놓쳤다는 가상 UX 관찰을 추가한다. 어떤 추가 수단이 정답인지는 제공하지 않는다. 실제 UX 실행 기록이 아니다.

판본과 각 입력의 해시는 run-manifest.json에 고정했다. 새 스킬은 제안 기록의 교체문구를 적용한 독립 사본이며, 형성 배경·사례 정답·검증 표는 피실행자에게 제공하지 않는다. 기존 Reference와 source는 수정하지 않는다.

## 평가 관점

응답의 용어나 목차 출현을 채점하지 않는다. 현재 정의와 새 제안의 관계, 실제 남은 판단, 추천이 원래 목적과 현재 사실에 연결되는지, 사실·추론·선택의 구별, 불필요한 작업 재개방 또는 필요한 작업 생략을 본다. 원사례에서 기존 요구를 새 보강으로 만드는지, 복구 기능의 목적·현재 기여를 재판단하는지 관찰한다. 반대 조건에서는 필요한 선택·기여를 놓치지 않는지 본다.

독립 평가자는 버전 매핑 없이 입력과 응답을 대조한다. 실행 결과가 좋거나 나쁘다는 Main의 예상은 제공하지 않는다. 각 답변의 판단 근거와 제한을 확인한 뒤 Main이 원자료와 최종 대조한다. 반복2회는 안정성 탐색이며 통계적 성능 보장이 아니다. 결과를 본 뒤 입력이나 스킬을 바꾸어 같은 시행으로 계산하지 않는다.
