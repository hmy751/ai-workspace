지금 티켓은 구현을 시작할 수 있을 만큼 구체적입니다. 범위, 동작 보존, 화면 확인, 가독성 개선 판단이 이미 정해져 있어 새 요구나 설계 결정을 더 붙일 필요는 없어 보입니다.

검사 예시만 하나 보강하면 좋겠습니다. 관찰 자료에서 `1.005`는 화면 계산식으로 `1.00`, helper로 `USD 1.01`이었습니다. 두 표시의 차이가 천 단위 구분자에만 있지 않으므로, 이 값을 기존 **계산 순서·표시 문자열 보존 검사**의 입력에 포함하면 됩니다. 반올림 정책을 새로 결정할 문제가 아니라, 정해 둔 보존 조건을 확인할 구체적인 사례입니다.

이 티켓을 첫 작업으로 선택하면, 실제 함수와 화면 렌더에서 변경 전 결과부터 확인하면 됩니다. 제공된 것은 제한된 계산식 관찰이므로 화면 검증까지 끝났다고 볼 수는 없습니다. 이번에는 티켓 수정이나 구현 없이 보완 의견만 정리했습니다.
