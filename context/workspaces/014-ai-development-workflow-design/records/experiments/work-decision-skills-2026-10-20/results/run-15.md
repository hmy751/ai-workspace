더 구체화할 부분은 있어. **범위를 더 나누기보다, 현재 티켓의 보존 조건에 예상 결과를 붙이는 게 핵심이야.** 맡은 범위와 확인 방법은 이미 충분히 잡혀 있어.

작업 이해안 — 경비 합계 티켓 보완

1. **화면과 helper가 어디까지 같고 어디서 달라야 하는지 명시하기.** KRW·JPY는 0자리, 나머지는 2자리라는 규칙은 같지만, 최종 표시 문자열까지 같아지는 작업은 아니야. 현재 티켓에 있는 천 단위 구분자 차이에 더해, 관찰된 `1.005`의 표시 차이도 남기면 좋아. 화면은 `1.00`, helper는 `USD 1.01`이야. 자릿수 규칙을 정리하면서 포맷 방식을 합치면 이 차이가 사라질 수 있으므로, 기존 보존 요구에 포함해 적어두자는 뜻이야.

2. **검사할 항목에 기대 결과를 붙이기.** 지금은 ‘기본 통화 유무·동률·빈 경비’를 다룬다고만 되어 있어. 아래 결과를 함께 적으면 구현자가 무엇을 보존해야 하는지 바로 알 수 있어.

   - 기본 통화가 경비에 있으면 합계가 작아도 먼저 표시한다.
   - 기본 통화가 없으면 합계 내림차순이고, 동률이면 먼저 등장한 순서를 유지한다. 이때도 첫 항목의 강조와 ‘주 통화’ 문구를 보존한다.
   - 빈 경비는 기본 통화의 0을 표시하고, 기본 통화도 없으면 `USD 0.00`을 표시한다.
   - 금액은 개별 반올림 없이 합산한 뒤 표시한다.

3. **개선됐다고 볼 코드상의 차이를 한 문장 더 구체화하기.** “강조는 기본 통화 여부가 아니라 첫 표시 항목이라는 의미로 읽히고, 통화별 소수 자릿수 규칙은 반복 해석이 줄어들며, 화면과 helper 각각의 포맷 차이는 가까운 코드에서 드러난다” 정도면 돼. 함수 수나 공통화 방식은 실행 중 정해도 이 기준으로 결과를 판단할 수 있어.

이 내용은 기존 Spec의 동작 보존·가독성 기준을 이번 티켓에 구체화하는 보완이야. 추가 제품 선택을 만들 필요는 없어 보여. 구현에 들어가면 먼저 실제 export와 화면 코드에서 위 관찰이 여전히 맞는지 확인하고, 티켓에 정한 전후 비교로 보존과 개선을 각각 확인하면 돼.

근거는 제공된 제한적 계산·표시 관찰이며, 실제 화면 검증 결과는 아직 없어. 위 내용은 보완 제안이고 Spec·Ticket에는 반영하지 않았어. 첫 구현 티켓으로 확정되지 않은 상태도 그대로야.
