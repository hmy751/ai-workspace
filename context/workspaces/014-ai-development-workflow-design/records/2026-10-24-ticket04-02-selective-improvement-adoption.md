# 04-02 — 선별한 설명 개선안의 구체화와 반영

2026-10-24. 사용자 요청으로 [개선안과 독립 개선 리뷰](2026-10-24-ticket04-02-selective-improvement-proposal.md)를 실행 prototype에 반영했다. **본체·작성 상세·첫 결과 연결·형성 자료 갱신을 마쳤다.** 정적 확인과 Main의 수행 경로 대조를 완료했으며 새 응답 비교·운영 설치·실제 사용자 이해 향상·04-02 전체 마감은 하지 않았다.

> 그럼 정말 아까 레퍼런스랑 우리 합의랑 다 종합한거지? 맞다면 스킬 구체화 해서 반영해봐

## 무엇을 바꿨는가

[explain 본체](prototypes/development-workflow/skills/explain/SKILL.md)는 질문의 범위를 지키고, 핵심 대상에서 결론까지 필요한 연결을 만드는 일을 중심으로 정리했다. 기존 본체에 흩어진 자료 선정·구현 대응·형태·첫 결과 전달을 통합했으며 같은 요구를 끝에 추가하는 방식은 쓰지 않았다. 전체 요청을 한 대목으로 좁히지 않고 역할 설명과 선택의 적절성 질문을 구별한다. 코드에서 나온 핵심 주장은 첫 결과 전달에서도 실제 처리와 의미를 대응시킨다.

[작성 상세](prototypes/development-workflow/skills/explain/references/constructing-explanations.md)는 일반 원칙 반복과 저장·조회 긴 예시를 교체했다. 인증은 전체 요청과 특정 대목의 후속이 요구하는 범위를, 동기화는 실제 요약에서 빠진 상태 반영·보관 값·반환의 연결을, 여행은 역할과 선택 판단에 맞는 근거의 차이를 보여 준다. 보고서의 원래 질문·관찰·결론 연결은 유지했다. 사례를 모든 답의 필수 내용이나 단독 정답으로 만들지 않았다.

[앞선 발화 상세](prototypes/development-workflow/skills/explain/references/prior-explanation.md)는 수정하지 않았다. 원뜻과 현재 타당성의 대조·이미 공유한 이해·정정의 책임은 유효하며 이번 관찰에서 주된 개입 대상으로 판단하지 않았다. 공통 근거 기준·기존 두 스킬의 보존판·원자료·과거 시험 응답도 유지했다.

[development의 결과 전달](prototypes/development-workflow/skills/development/SKILL.md#확인한-결과와-사용자가-판단할-내용을-돌려준다)은 첫 결과를 구성할 때 explain 사용을 명시한다. 이전의 ‘관계나 이유가 필요하면’이라는 추가 선택을 거치지 않는다. 단순 결과는 그 크기에 맞게 전달하고 전체 브리핑을 의무화하지 않는다. 답에 필요한 사실이 부족하면 Main이 맡은 권한 안에서 확인하거나 담당자에게 연결하며, 설명 스킬이 개발·검증·전체 상태 책임을 소유하지 않는다.

[스킬 안내](prototypes/development-workflow/skills/README.md), explain과 development의 가까운 형성 자료, 열람 화면, Workspace current·Ticket·output을 함께 갱신했다. 별도 agent·hook·설치 설정은 만들지 않았다.

## 종합한 근거를 어떻게 선별했는가

원래 목적과 Noline 경험은 ‘사용자가 실제 대상과 선택을 이해해 자기 판단을 이어가게 한다’는 결과를 정한다. 원래 스킬의 분리나 배경 문구를 고정 규칙으로 삼지 않는다. 인터뷰는 재설명 부담과 학습의 가치를 함께 보존하고, 직접 대화는 전체 요청·선택 검토·역할 브리핑을 서로 다른 질문으로 가른다. 이전 A/B는 자료를 읽어도 설명이 요약에 머물렀다는 관찰이며 모델·문구·통합의 단일 원인을 확정하지 않는다.

Matt에서 공통 수행·조건부 상세·완료 조건의 배치를, pstack에서 작업 결과와 설명 기능 연결·현재 동작과 이유의 구별을, Vercel에서 요청 범위·필요한 자료·확인의 연결과 기계 검사/판단의 구별을 참고했다. 다른 호스트의 호출 방식, 숙련 개발자 전제, 고정 모드 수·agent 분업은 가져오지 않았다. 외부 구조는 우리 목적을 대신하는 권위가 아니다.

독립 개선 리뷰에서 지적한 인증의 범위 축소, 여행의 선택 판단을 역할 소개로 대신한 문제, 실제 부족한 문단의 보완을 채택했다. 모든 사례·옛 조항·외부 방법을 상시 항목으로 편입하지 않았다. 상세 근거와 판본은 [가까운 형성 자료](prototypes/development-workflow/skills/explain/_background/README.md), 조사 범위는 [레퍼런스 기록](2026-10-24-ticket04-02-skill-routing-source-research.md)에 있다.

## 확인과 남은 한계

- 변경된 두 스킬의 YAML은 Ruby 표준 YAML parser로 해석했다. `quick_validate.py`는 기본·저장소·앱 Python에 PyYAML이 없어 실행하지 못했으며, 이름·허용 필드·description·미완성 표기는 별도 정적 검사로 대조했다. 패키지를 새로 설치하지 않았다.
- 코드 발췌는 보존 원문과, 실제 인용 문장은 최초 응답과 대조했다. 예시가 원문 인용인지 새 설명 상황인지 본문에 구별했다.
- 열람 화면을 재생성하고 `viewer/check.mjs`를 통과했다. 문서161개·코드5개, 원문/해시 일치, 내부 링크900개·앵커 링크265개, 누락 경로·앵커0이다. 브라우저 화면·제품 동작 검사는 아니다.
- 이전 두 실행 본문, 앞선 발화 상세, source·시험·리뷰 사본은 변경하지 않았다. 변경 Markdown 링크와 `git diff --check`를 확인했다.

이번 선택은 실행 본문 반영을 완료한 것이며 효과 입증이 아니다. 실제 질문에서 필요한 연결이 빠지는지, 전체 범위를 좁히거나 무관한 설명을 늘리는지 관찰해야 한다. 추가 시험이 필요할 때는 기본 응답과의 차이·다른 장면으로의 일반화·자연 호출 중 무엇을 판단할지 먼저 정한다. 같은06 답을 반복 생성하는 일을 다음 자동 작업으로 두지 않는다.
