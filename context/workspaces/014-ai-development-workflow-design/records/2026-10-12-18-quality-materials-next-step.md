# 01-02로 진행하기 전 자료 논의와 기록 체크포인트

2026-10-12. 사용자는 **01-02부터 구체화하되, 먼저 자료를 더 구체적으로 정리해 함께 논의하기로 했다.** 이번에는 그 작업에 들어가기 전 지금까지의 기록을 정리하고 커밋한다. 코드·설계 기준의 채택, 실제 코드 대비안 작성, 스킬·하네스·제품 변경까지 승인하거나 수행한 것은 아니다.

## 사용자 정정과 다음 순서 선택

기록 17에서 AI는 관련 Ticket을 같은 개발 장면에서 함께 구체화하는 방법을 제안했다. 사용자는 다음과 같이 정정했다.

> 아직 좀 안 와닿아 티켓들 보면 연결 되어 있는데 음 지금 설명은 확신이 안드네 지금 무조건 다 고려해서 하자는건 아니고 어떤 결정이 필요해보인다는거지
> 그리고 근거 해서 강연 내용 말한거 보면 잘 안와닿아 내가 좋다고 봤던 포인트들이 다 없어보여서 이건 뒤에 나눌건가?
> 다시 파악해봐

AI는 두 강연 전체 번역, 관련 설계·검토·설명·회고 자료, Vercel의 관련 본문, 이전 사용자 발화를 다시 확인했다. 자료를 참고한 사실과 구체적인 방법을 설계에 반영한 정도를 구별하지 않았고, 다음에 필요한 결정 대신 Ticket 연결과 동시 구체화를 앞세웠다고 판단했다.

이어 AI는 01-01의 역할 흐름을 잠정안으로 두고 01-02에서 품질 기준과 그 기준을 구현자·검토자에게 어떻게 배치할지 먼저 다루자고 제안했다. 사용자 응답:

> 그래 그럼 01-02부터 구체적으로 봐보자. 근데 그전에 자료를 더 구체화 하고 나랑 논의했으면 좋겠어
>
> 일단 이 작업들 하기전에 기록할거 하고 커밋부터 해놓자

**채택된 것은 다음에 다룰 Ticket과 자료 논의의 선행 순서다.** AI가 추천한 개별 설계 기준이나 상세 역할 배치 전체가 채택된 것으로 해석하지 않는다. 기록 17의 01·02·03·04 동시 구체화 제안은 현재 다음 순서가 아니다. Ticket의 연결은 유지하되 지금의 결정을 위해 필요한 부분부터 다룬다.

## 다시 확인한 자료의 구체적인 내용과 현재 공백

아래는 원자료에서 다시 확인한 방법이다. 사용자가 좋게 본 포인트의 전체 목록을 확인받은 것은 아니며, AI가 복원한 핵심 후보와 남은 설계다.

| 자료의 방법 | 현재 설계에서 구체화할 내용 |
| --- | --- |
| [PR 병목 강연](../source/lectures/01_PR_병목_강연_전체번역.md) 챕터 3~4, [codebase-design](../source/lectures/codebase-design.ko.md): 작은 인터페이스 뒤에 복잡한 동작을 모아 호출자가 알아야 할 순서·설정·오류 처리를 줄이고, 함께 바뀌는 지식·수정을 모은다. | ‘구조 품질을 본다’는 표현을 실제 전후 대비로 구체화한다. 깊은 모듈·locality·호출자 부담을 어떤 기준으로 사용할지와 바꾸지 않는 편이 나은 경우를 비교한다. 용어나 세부 규칙 전체를 그대로 채택한 것은 아니다. |
| 같은 자료: 호출자가 사용하는 인터페이스를 통해 동작을 검사하며, 구현을 되풀이하는 테스트·내부 구조에 민감한 테스트·실패를 가리는 mock을 살핀다. | 검사 통과 여부 외에 어떤 테스트를 유지·교체해야 하는지, 설계 변경과 검사 경계가 어떻게 함께 달라지는지 보여준다. |
| PR 병목 강연 챕터 5: 탐색·구현·디버깅으로 부담이 큰 구현자와 별도 맥락의 검토자를 나누고, 상세 코딩 표준을 검토자에게 집중시킨다. 검토자는 직접 개선된 코드를 만든다. | B의 직접 수정 방향은 선택했다. 어떤 기준이 공통 필수이고 무엇을 검토 단계에 집중할지는 미정이다. [제공 code-review 자료](../source/lectures/code-review.ko.md)의 Standards·Spec 분리 검토와 보고 종료, 강연의 직접 수정 제안을 구별한다. |
| [Agent 신뢰 강연](../source/lectures/03_Agent_신뢰_강연_전체번역.md) 챕터 5~8·10: 코드베이스가 다음 AI가 확장하는 본보기다. 반복 문제는 구조로 예방할 수 있는지 먼저 보고, 자동 검사와 지침·스킬을 함께 개선한다. | 한 작업의 수정뿐 아니라 남기는 코드 패턴의 질을 다룬다. 프로젝트 전체 표준이나 새 lint·스킬의 채택은 별도 판단이며, 이번 검토자의 수정권에 자동 포함하지 않는다. Dune의 주석 금지 등 특수 선택도 그대로 가져오지 않는다. |
| Agent 신뢰 강연 챕터 4: 재사용 가능한 앱 제어 CLI와 기능 의미·접근 방법을 담은 Feature Map을 결합해 AI가 직접 실행·관찰하게 한다. | 01-03에서 검증을 가능하게 하는 수단과 기존 도구의 충분함을 구체화한다. 검증 담당자를 정한 것과 실행 능력을 갖춘 것을 구별한다. |
| PR 병목 강연 챕터 6~7, [pr](../source/lectures/pr.ko.md)·[retro](../source/lectures/retro.ko.md): 사람이 변경 전후·이유·근거·영향을 이해하기 쉽게 보여주고, 반복 피드백을 다음 작업의 코드·검사·표준·탐색·도구 개선으로 잇는다. | 설명은 04-02, 경험 반영은 05에서 구체화한다. 일반적인 Main 보고·기록 책임만으로 이 방법을 반영했다고 보지 않는다. |
| [Vercel 자료](<../source/lectures/vercel-product-design (1).md>): 제품 판단의 이유·예외·실제 사례를 근거로 기준을 발전시키고, 기계적으로 검사할 내용과 맥락 판단을 나눈다. 필요한 정본을 선택해 읽고, 미정과 채택을 구별하며 효과를 비교한다. | 품질 기준을 추상적 형용사로만 정하지 않도록 구체적인 판단 사례를 사용한다. 개발 중 기준 사용과 이후 기준 개선은 연결하되 같은 절차로 고정하지 않는다. |

01-02의 첫 결정 후보로 AI가 제안한 것은 **어떤 설계·테스트 기준을 사용할지**, **그 기준을 구현자와 검토자에게 어떻게 나누어 적용할지**다. 세 화면이 각각 저장·캐시 갱신·실패 복구 순서를 관리하는 가상 사례에서, 단순 중복 추출과 관련 동작을 책임지는 모듈로 모으는 대안을 비교하자고 제안했다. 이 사례는 설명용이며 Noline의 실제 코드 상태나 앞으로 반드시 사용할 사례로 확정하지 않았다.

## 커밋 이후의 첫 작업

01-02의 최종 기준이나 구조 개선안을 바로 확정하기 전에, 위 자료를 사용자가 비교·판단할 수 있게 더 구체적으로 정리해 논의한다. 단순 출처 목록이나 일반적인 품질 원칙의 반복으로 끝내지 않는다.

- 자료가 실제로 권하는 방법과 그 이유, 구체 예시·적용 조건을 보여준다. 강연의 주장과 제공 스킬의 동작, AI의 적용 제안을 구별한다.
- 기존 ai-workspace 기준에서 이미 다루는 것과 다른 것, 구체성이 부족한 것을 대조한다. 기존 기준을 읽을 때 원문을 따라 확인하고 자료의 어휘로 재포장하는 데 그치지 않는다.
- 지금 선택해야 할 차이와 이후 Ticket에서 구체화할 내용을 드러낸다. 관련 Ticket 전체를 동시에 완성하는 계획으로 확대하지 않는다.
- 사용자가 좋게 본 지점을 전부 확인했다고 가정하지 않고, 제시한 내용에 대한 응답을 받아 취사선택을 이어간다. 추상적 품질 기준 전체를 사용자에게 먼저 정의하도록 요구하지 않는다.

B의 검토자 직접 수정 방향은 유지한다. 최종 실제 확인도 검토자가 이어가는 것이 최신 진행안이며 원 구현자에게 되돌릴 의무는 없다. 이 흐름의 상세 충분성·적용 조건·효과는 아직 미확인이다. 자료와 기존 구성에서 후보를 만들고, Noline 과거 사례는 그 후보를 검토하는 데 쓴다. 전체 목표는 Project·Work·스킬·개발 방법·기록·경험 반영을 포함하며 01-02로 축소되지 않는다.
