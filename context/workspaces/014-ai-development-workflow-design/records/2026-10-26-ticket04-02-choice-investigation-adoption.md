# 04-02 선택 판단·조사 충분성 반영과 확인

2026-10-26. 사용자가 배경을 종합한 방향의 본체·상세·형성 자료 반영, 기존 의미 확인, 2번·4번 GPT-6-sol medium 재시험을 요청했다. [종합 판단](2026-10-26-ticket04-02-choice-and-investigation-improvement-proposal.md#배경과-원대화를-함께-본-종합-재판단)을 적용했다. **실행 본문과 형성 자료 반영·의미 대조·표시 검사·두 최초 수행을 완료했다.** [응답 대조](experiments/explain-choice-investigation-60medium-revised-2026-10-26/comparison.md)상 2번의 구체 근거와4번의 일부 검사 본문 확인에는 개선이 있지만 대안 비용·폼 근거 확인은 남았다. 수정 성공과 두 문제의 완전 해결을 구별한다.

## 반영한 것

| 위치 | 변경과 이유 |
| --- | --- |
| explain 본체의 선택 절 | 실제 소비와 명시된 지원 목표를 같은 기준으로 비교한다. 일부 적용을 목표 축소로 해석하지 않고 과거 제안·유효한 계약·현재 구현을 구별한다. 상세 읽기 연결은 보조로 둔다. |
| 작성 상세의 반환 항목 일반 예시 | 같은 사용 조건에서 필요한 정보·판단·행동과 현재안·대안의 결과·부담을 대조한다. 특정 필드 반환을 정답으로 제시하지 않는다. |
| development의 결과·확인 연결 | Main·조사 담당이 기존 검사를 근거로 쓸 때 검사 적절성·재사용을 적용한다. 중요한 공백의 가능한 확인·담당 연결과 실행 불가의 영향을 작업 수행 책임으로 유지한다. |
| verification의 독자·검사 적절성·실행 공백 | 실제 경로·입력·assertion 대조와 영향·비용에 따른 추가 확인을 구체화한다. 부분 적용과 독립 검증 전체를 구별한다. |
| 두 스킬의 _background | context의 현재 선택 이유, evidence의 사용자 원문·시험 관찰·Main 정정, 가까운 변경 기록과 안내를 맞췄다. 옛 기록은 그대로 유지한다. |

기존 여행 복구 사례는 이미 같은 실패 조건에서 책임 이동의 이득과 부담을 보여 주므로 보존했다. 새로운 완성 정답이나 picker의 특정 결함을 실행 예시에 넣지 않았다. 사실 확인·설명의 권한을 확장하지 않았고 공통 근거·앞선 발화 상세·auth 예시·review·execution은 변경하지 않았다. 스킬의 이름·description·설치·설정도 유지한다.

`skill-creator`, `subagent-delegation`, 기존 문서 작성 기준과 로컬 `SKILLS-CONTENT-POLICY`를 적용했다. 실행 지침의 적용 조건·결과와 형성 이력을 나누고, 시험에는 형성 자료·평가를 공급하지 않았다. 전역 하네스 변경이 아니므로 전역 snapshot·설치를 수행하지 않았다.

## 기존 의미 대조

Main이 수정 전 본문과 실제 diff를 아래 의미별로 대조했다. 파일 일치 검사는 의미 판단과 구별한다.

| 유지해야 할 의미 | 대조 결과 |
| --- | --- |
| 실제 질문에서 시작하고 뜻·역할·선택·앞선 말의 범위를 구별 | 질문 범위 절·앞선 발화 상세를 그대로 유지. ‘어디 갔나’에 현재 위치부터 답하고 선택 필요 때만 비교한다. |
| 단일 explain 진입점과 조건부 두 상세 | 새 모드·스킬·라우터 없이 기존 선택 절과 일반 예시를 교체. |
| 실제 코드·역할·흐름·전체/부분·읽기 쉬운 구성 | 해당 절과 인증·동기화·여행 예시는 유지. 선택 질문을 무조건 코드 전체 해설로 만들지 않는다. |
| 당시 의도와 현재 추론, 동작 보존과 개선 이득, 전후 자료 | 기존 대조 조건 유지. 과거 자료가 없을 때 차이를 만들지 않는 상세도 유지. |
| 사용자의 이의를 즉시 수정 명령으로 취급하지 않기 | 유지·변경 판단을 역할 설명이나 이의만으로 결정하지 않게 명시. 별도 기존 위임의 권한은 유지. |
| 명시된 목표와 계약 보존 | 일부 적용과 목표 축소를 구별. 가능한 확장을 새 요구로 만들지 않으며 채택된 계약을 비교 기준에 둔다. |
| 현재성·실제 수행·미확인·수락의 구별 | shared와 explain 사실 확인·권한 절 유지. 파일 대조를 실제 실행으로 세지 않게 구체화. |
| 개발 수행과 설명의 책임 | explain 첫 결과 연결 그대로 유지. 추가 확인과 완료 판단은 development의 기존 책임에 남음. |
| 검증의 세 수행과 기존 근거 재사용 | 기본 검사·적절성·잔여 공백, 재사용·재실행 조건 유지. 이름 검색에서 실제 검사 근거로 이어가는 부분만 보완. |
| 개선 검토·독립 검증·수정·재검증의 분리 | review·execution 불변. 검증 시작·축소·독립성·제품 수정 제한·원 구현자 수정과 재확인 불변. 부분 방법 적용은 독립 검증으로 세지 않음. |
| 확인 공백을 작업으로 연결하되 불필요한 전수 조사 피하기 | 필요한 담당 연결·권한·준비 조건 유지. 결론 영향과 비용으로 추가 확인 범위를 정함. |

작은 뜻 질문, 앞선 말 자기평가, 현재 소비만 있는 좁은 API, 여러 소비 지원이 명시된 부분 적용, 과거 검사 재사용, 실제 환경이 없는 조사, 제품 수정 후 별도 검증의 상황에 대입했다. 작은 질문에 전체 검토·모든 자료 읽기를 요구하지 않으며, 다른 소비가 미적용이라는 이유로 명시 목표를 지우지 않는 구성을 확인했다. 이 대입은 Main의 정적 의미 확인이며 새 모델의 행동 성공을 증명하지 않는다.

## 정적 확인과 실행 조건

- `git diff --check` 통과.
- 원래 `quick_validate.py`는 기본·번들 Python 모두 PyYAML 부재로 실행 불가. 설치 없이 기존 Ruby YAML 파서로 frontmatter 구조·허용 필드·이름 형식/길이·description 형식/길이·미완성 placeholder를 대조하여 두 스킬 통과. 원래 검사기가 통과했다고 기록하지 않는다.
- viewer 생성은 기본 탐색에서 marked를 찾지 못해 이미 설치된 번들 모듈 경로를 지정했다. 새 evidence 앵커 네 개의 표기 차이를 수정한 뒤 재생성·검사 통과: 문서170개·코드5개 원문/SHA 일치, 내부 링크956개·앵커284개, 누락0개, 화면 스크립트 문법 통과. 브라우저 화면 조작·데모 제품 검사는 이번 변경 범위가 아니다.
- 실행 스킬 네 파일의 변경과 앞선 발화·공통 근거·주요 예시·검토/배치 보존을 대조했다. 시험 입력은 최초 실험의 고정 사본에서 복사했으며 원자료·의뢰·열람 도구·필수 입력은 동일하다.
- [보존 구간·판본·정적 확인 기록](receipts/explanation-improvement/choice-investigation-2026-10-26.json)에 변경 네 파일의 전후SHA, 보호 파일5개·보호 구간6개의 바이트 일치를 남겼다. 이는 위 의미 대조와 별도 확인이다.
- 2번은 explain 본체·작성 상세만 교체, 4번은 여기에 development 본체·검증 상세까지 교체했다. 실행 스킬만 새 판본이며 `_background`, 기존 답·평가·기대 결론은 제외했다. 새 컨텍스트와 `gpt-6-sol`·`medium`을 명시해 두 담당자를 배치했다.

이번 변경은 prototype 안에만 적용했다. 병행 중인04-03 변경과 source 원본을 수정하지 않았으며 커밋·전역 설치·Ticket 마감은 수행하지 않았다. 한 번의 재시험은 해당 사례의 관찰이며 일반 효과나 문구 단독의 인과 증거가 아니다.

두 실행의 원응답·읽기·해시 확인을 완료했다. 4번의 일부 선택 자료 출력 잘림은 실행 메모와 대조 기록에 제한으로 남겼다. 충분한 답이 나올 때까지 재생성하거나 결과를 보고 실행 지침을 다시 고치지 않았다.
