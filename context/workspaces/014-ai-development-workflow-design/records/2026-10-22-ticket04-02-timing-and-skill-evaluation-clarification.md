# 04-02 — 적용 시점·스킬 본문·별도 지침을 구별한 정정

현재 작업은 **기존 설명 스킬을 어떤 요청과 시점에 적용해야 하는지, 기존 본문에 실제 부족함이 있는지** 판단하는 것이다. 첫 보고 의무를 별도 지침에 추가한 실험을 스킬 조기 적용이나 본문 개선의 증거로 사용하지 않는다. 적용 시점·실제 수행·본문 효과를 구별하고, 특정 보고서 사건이 애매하면 기존 source의 다른 장면도 비교해 검증 대상을 고른다.

이 기록은 2026-10-21 네 조건 실행 이후 현재 대화에서 나온 사용자 정정과 Main의 재대조·제안을 보존한다. 아래 사용자 발화는 현재 대화의 직접 발췌이며, 과거 Noline 사건 원문과 구별한다. 새 테스트·스킬 수정·별도 지침 추가는 수행하지 않았다.

## 사용자 정정의 직접 근거

보고서 작성 범위:

> 근데 스킬에 보고서 작성이 있어? 지난 대화에서도 보면 보고서는 안 만들엇던 것 같은데?

흐름 연결의 의미:

> 흐름 연결이란게 뭐야? 스킬 발동 시점을 더 빨리 했다는거야?

개입 대상의 정정:

> 지침을 왜 추가해? 지금 스킬 수정중인데? 그럼 완전 다른거잖아? 애초에 대화 시점을 좀 더 앞당겨서 다르게 시키면 됐잖아 뭐 스킬을 좀 더 앞당겨서 발동시키게 한다던가? 아니야?

분석과 실행의 순서:

> 그럼 새 source랑 기존 스킬 다시 보고 어느 시점에 발동했어야 하는지부터 짚어봐. 별도 지침 추가하지 말고, 기존판 조기 적용이랑 수정판 효과를 어떻게 나눠서 검증할지 먼저 보여줘. 바로 테스트 돌리진 말고

이번 기록 요청과 다음 탐색:

> 근데 애매하면 다른 소스도 보자 뭐가 있는지 이거 말고도 더 있을거 아니야? 지금 까지 종합 논의를 고려해서 
> 아 그전에 지금 어쨌든 시점이랑 뭐 싈 자체 평가 뭐 이런거에 대해서 얘기를 나누고 했잖아? 이것 부터 기록 필요한곳에 남기자 또 오해하지 않게

## 앞선 네 조건 시험에서 실제로 바꾼 것

[네 조건 시험](experiments/artifact-explanation-first-report-2026-10-21/comparison.md)은 같은 보고서 작성 요청에서 기존/수정 briefing과 별도 첫 결과보고 지침의 추가 여부를 조합했다. Main이 당시 사용한 ‘흐름 연결’이라는 이름은 다음 변경을 가리켰다.

| 실제 변경 | 그 변경이 아니었던 것 |
| --- | --- |
| 프로젝트 시작 지침에 첫 결과보고 절차로 가는 경로 추가 | briefing 호출 시점을 앞당김 |
| 질문·근거 대조, 추가 확인 판단, 현재 답·남은 일·다음 행동 종합을 별도 절차에 요구 | 기존 briefing 본문만 수정 |
| 공통 설명 기준의 소비 범위를 해당 절차까지 확장 | 같은 스킬의 적용 시점만 통제 |

따라서 연결 조건의 첫 응답이 조금 더 구체적이었다는 관찰은 **별도 행동 지침을 추가한 조건의 결과**다. 스킬 조기 적용의 효과도, 스킬 수정이 불필요하다는 증거도 아니다. 조건별 1회·동일 핵심 결론·산출물의 작은 결함이라는 한계도 유지한다. 원응답·HTML·입력·검토 기록을 고치거나 없애지 않고, Main의 해석과 후속 선택을 바로잡는다.

보고서 작성 역시 briefing의 필수 행동이 아니었다. source의 사용자603은 “나머지 4개 보고서 각각 만들어줘”라고 했고, Main이619 직후부터 실제 작업을 이어 수행하도록 지시해 HTML 네 편씩 총16편이 생성됐다. 앞선 인증·UTC 응답 비교와 달리 작업 재수행으로 범위가 커졌다. 실행4개와 독립 검토1개는 모두 GPT-6.1-sol medium이었지만, 대화·코드의 반복 읽기와 산출물 생성·재검토가 늘었다. 정확한 실행별 토큰 사용량은 확인하지 않았으므로 수치나 비용 비율을 추정하지 않는다.

## 새 source와 기존 스킬을 다시 대조한 사실

원문은 [보고서 사건 input](../source/artifact-explanation-scenes/01-report-delivery/input/conversation.txt), 기준판은 [당시 briefing 본문](experiments/artifact-explanation-first-report-2026-10-21/r17/input/repository/.claude/skills/work-artifact-briefing/SKILL.md)이다. 다음 번호는 이 원문이 보존한 `source_line`이다.

| 시점 | 원문과 판단 |
| --- | --- |
| 12→15 | 사용자 “여기 작업을 이어가려고해 파악해줘” 직후 AI는 “`work-artifact-briefing`과 `read-project-context` 스킬을 적용하겠습니다.”라고 말했다. 최초부터 늦게 발동한 사건이라고 단정할 수 없다. 공개 선언만으로 본문 읽기·조항 수행까지 확인되는 것은 아니다. |
| 216→221 | “티켓에 작업남은게 뭔지 다시 자세히 설명해봐”는 기존 티켓·구현·검증과 남은 범위를 이해하는 요청이다. 기존 스킬의 대상·목적 설정과 Spec/Ticket·실제 결과 대조에 직접 부합하므로, 설명을 위한 조사 시작부터 적용할 명확한 후보 시점이다. |
| 230~249 | 시뮬레이터 수집과 Main의 판단·작업 배치 요청이다. 이 새로운 조사 전체를 기존 설명 스킬이 맡는다고 자동 해석하지 않는다. |
| 603~619 | 새 조사·보고서 작성 요청이다. 결과 설명에 briefing을 활용할 수 있는지와, 기존 스킬이 작업 시작부터 자동 적용돼야 한다는 주장은 구별한다. |

기존 description은 이미 존재하는 코드·문서·분석·review 결과의 이해를 다루지만, 구현·수정·진단·review·acceptance 판정이 주목적인 요청은 자동 적용에서 제외한다. 한편 기존 본문에도 목적 설정, 원자료 조사, 계획/실제 확인 구별, 주장과 근거 연결이 있다. 필요한 행동이 이미 있는지 확인하지 않고 외부 지침으로 중복 보강하지 않는다.

원래 [_background의 호출 시점 대안](prototypes/development-workflow/skills/work-artifact-briefing/_background/context.md#호출-시점을-포함해-검토했던-대안)도 사용자 이해 요청, AI 자발적 호출, 완료 보고 시 호출, 독립 검토를 구별했다. 대안이 검토됐다는 사실은 자동 예방 동작이 구현됐다는 뜻이 아니다.

## 구별할 평가 대상

| 평가 대상 | 확인할 것 | 혼동하지 않을 것 |
| --- | --- | --- |
| 대화의 시작점 | 어떤 요청 직전까지의 원문·자료를 제공했는가 | 원문을 더 앞에서 끊었다고 스킬도 더 일찍 적용됐다고 보지 않음 |
| 선택·적용 시점 | 이번 요청의 조사 전/조사 후/설명 시점 중 언제 본문을 읽고 사용했는가 | 적용 선언·읽기·실제 행동을 같은 증거로 보지 않음 |
| 본문 효과 | 동일한 요청·자료·적용 시점에서 기존판과 수정판의 실제 수행이 어떻게 다른가 | 별도 보고 지침의 효과나 늦게 받은 사용자 교정을 본문 효과로 합치지 않음 |
| 실제 이해와 작업 효과 | 사용자 판단에 필요한 의미와 근거가 전달되고 필요한 조사까지 수행됐는가 | 표·분량·검사 수, 후속 질문 수, 침묵만으로 효과를 확정하지 않음 |

## Main이 제시한 검증안의 지위 — 아직 미채택·미실행

Main은216 직후 같은 요청에서 A 기존판 조사 후 적용, B 기존판 조사 시작부터 적용, C 수정판 조사 시작부터 적용을 제안했다. A↔B는 적용 시점, B↔C는 같은 시점의 본문 차이를 보려는 안이다. 별도 보고 지침은 넣지 않고 원문12~216과 동일한 당시 자료를 사용하며,221 이후 답변·교정·HTML 작성 요청은 제외하는 구상이다. 결과는 채팅 응답과 짧은 조사 기록으로 한정하고 모델은 사용자 지정 6.1 sol medium을 유지한다.

이 안은 사용자가 채택하거나 실행을 승인한 계획이 아니다. A는 당시 행동의 재현이 아니라 시점을 통제하려고 만든 조건이고, 앞선15에 이미 적용 선언이 있어 이번 요청에서의 재적용이라는 한계가 있다. 기존84·209의 설명이 원문에 포함돼 있어 이를 되풀이한 것과 새로 확인한 것도 구별해야 한다. 뒤늦게 적용한 A의 추가 조사·회복을 인위적으로 막아 B에 유리하게 만들지 않는다.

또한216은 기존 상태 설명이고, 문제가 제기된779는 새 조사 결과보고다. 전자의 비교 결과를 후자의 실패 해결로 확대할 수 없다. 적용 조건에 잘 맞는다는 이유만으로216이 스킬의 부족함을 판별하기에 가장 좋은 장면이라고 확정하지 않는다.

## 다음에 이어갈 일

이번에는 논의와 정정을 기록한다. 그다음 기존 source와 앞선 장면 분석에서 보고서 외 사례를 살펴, 원래 질문·첫 응답 전후·사용자 교정·스킬 선택 근거·당시 자료 확보 정도를 비교한다. 인증·일정의 역할 설명·access·Promise·UTC 등 앞서 다룬 사례는 탐색 후보이며 이미 적합한 시험이라고 확정한 목록은 아니다.

이전 시험은 사용자 교정 뒤 요청이나 완성된 설명을 제공한 한계가 있었다. 같은 장면을 고르더라도 그 입력을 그대로 재사용하지 않고, 최초 필요한 설명 전 원문과 당시 유효한 자료를 확보할 수 있는지 확인한다. 한 사건이 애매하다는 이유로 별도 지침을 해법으로 넣거나 전수조사·대규모 산출물 생성으로 넓히지 않는다.

다른 source 비교 뒤 어떤 문제와 시점을 검증할지 먼저 보여 준다. 현재216 제안이나 새 시점 시험을 자동으로 실행하지 않는다. 복구 스킬 유지, 운영 스킬 미반영,04-02 미완료 상태는 그대로다.
