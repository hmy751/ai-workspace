# 사례·일반 본문·진입점을 역할에 맞게 다시 구성

2026-10-19. [개선 리뷰99](2026-10-19-99-case-improvement-review-and-artifact-boundary.md)를 실제 [development-workflow](prototypes/development-workflow/README.md)에 반영했다. 대상물의 읽기 경로에서 바깥 014의 작성·합의 기록 의존을 제거하고, 코드·조건·판단 이유를 본문 안에서 이해하도록 재구성했다. 제품 실행 코드는 바꾸지 않았다.

## 요청과 반영 범위

> 그래 그럼 리뷰 반영해서 현재 프로토타입 제대로 개선해봐. 사례만 고치지 말고 연결된 일반 본문이랑 진입점도 각 역할에 맞게 구성하고, 014 기록에 기대지 않아도 이해되게 해줘. 바뀐 결과랑 왜 그렇게 바꿨는지도 보여줘.

사례 세 편과 연결된 일반 기준 세 편, prototype·context·Personal·개발 입구, 로그인 적용 해설, Work의 현재 선택·상태·입력 경로를 함께 다듬었다. 일반 기준과 상세 사례의 분리는 유지하되 같은 목차를 모든 사례에 강제하지 않았다. 앞선97~99의 미커밋 변경을 보존한 채 이어 작업했다.

예를 들어 같은 주문 API라는 사실만으로 `clearCart()`를 공통 성공 처리에 넣으면 바로 구매도 장바구니를 지운다. 세 화면이 모두 같은 장바구니 구매라면 이번 쿠폰 누락 수정과 공통 흐름 정리를 함께 할 이유가 생긴다. 이 조건 차이를 같은 사례 안에서 따라가게 했다. 제한된 실험 제품에서는 누락만 작게 고치는 선택도 남겼다.

Toast는 항목을 0초에 추가하고 표시 컴포넌트를 1초에 없앴다가 2초에 다시 표시하는 가정으로 시간 의미를 비교한다. 표시 시작 기준은 다시 표시한 뒤 3초, 추가 시점 기준은 처음 추가한 뒤 3초다. 타이머를 옮기는 것이 내부 위치 정리만은 아니라는 점과 현재 방식이 맞는 조건을 함께 설명한다.

## 대상물과 설계 기록의 경계

대상물 안의 `authoring-basis.md`는 [이전 작성 근거 보존본](2026-10-19-prototype-authoring-basis-before-revision.md)으로, 배치 정정의 직접 확인은 [이전 구조 확인 보존본](2026-10-19-prototype-layout-check-before-revision.md)으로 이동했다. 바깥 기존 기록은 이 새 보존 위치로 링크만 갱신했다. Work의 입력·구현 기록에서 바깥 작성 입력을 참조하던 이전 문장도 작성 근거 보존본 뒤에 남겼으며, 현재 연결은 자체 source와 Project 계약을 사용한다. 당시 실행·선택 결과를 새로 수행한 것으로 바꾸지 않았다.

대상물 자체 Work의 입력·선택·구현·검사·비교 기록은 계속 대상물 안에 있다. 바깥 014의 합의·작성 이력은 대상물의 읽기 경로에서 빠졌다. 사례에 필요한 확인 사실·설명용 가정·미정인 제품 조건은 각 내용 가까이에 남겼다. 이 기록100도 대상물에서 읽도록 연결하지 않는다.

## 개선 리뷰의 재독과 직접 확인

처음 개선 리뷰를 맡은 리뷰어에게 수정된 결과물을 읽혀 남은 구성·설명 문제를 받았다. 사례·진입점이 역할을 수행하고 있다는 평가와 함께 다음 두 문제를 지적해 반영했다.

- boolean `isError` 예시가 호출부만 바꾸면 되는 것처럼 보였다. Input의 타입·오류 표시 계약도 boolean에 맞추는 대안임을 주석과 문장으로 밝혔다. 조사하지 않은 호환 비용은 추가하지 않았다.
- walkthrough의 시작 설명이 기존 코드의 표현만 고치는 작업처럼 보였다. 실제 Ticket이 새 실행 예제 작성임을 앞에서 밝히고, 초기 입력의 Promise 거부 가정과 실행 예제에 추가한 동기 조회 오류 분리를 구별했다. 출처에 없는 요청문 인용도 제거했다.

표시 화면을 다시 생성하고 기존 정적 검사를 실행했다. Markdown 53개와 소스·검사 코드 5개의 원문·SHA가 모두 일치했다. 내부 전환 링크260개, 다른 로컬 파일 링크4개, 앵커27개에 끊어진 경로가 없었다. 모든 로컬 링크가 대상물 내부를 가리킨다. 이 경계를 벗어나는 링크를 실패로 잡는 확인도 `viewer/check.mjs`에 추가했다.

전체 A/B 코드 두 개는 함수명·callback명 두 쌍을 대응하면 주석까지 동일하다. 화면 스크립트 문법과 지원하지 않는 링크 거부 검사도 통과했다. 원본 Markdown의 코드펜스·후행 공백과 `git diff --check`를 확인했다. 브라우저 배치·클릭은 실측하지 않았다.

인증 예제 코드·테스트·시작 source에는 HEAD 대비 변경이 없음을 확인했다. 제품 검사는 다시 실행하지 않았고 이전 7개 검사 결과를 이번 본문 개선의 새 검증으로 사용하지 않는다. 실제 독자의 이해 속도, 실제 Noline 설치·통합, 전체 본문에 대한 사용자 수락은 확인한 것으로 올리지 않는다.

## 현재 선택과 남은 범위

세 주제와 연결된 진입점의 편집 개선은 현재 실물에 적용했다. 전체 기준·운영 방식의 최종 수용, 구체 스킬 연결, 검토 겸임·생략과 최종 확인 책임은 별도로 남는다. 티켓 범위 안의 완성도를 높인 이번 변경을01-02·03 전체 완료로 해석하지 않는다. 다음에는 실제 수정본에 대한 사용자 판단을 이어받아 필요한 본문 보완과 workflow·기존 스킬 연결을 같은 실물에서 구체화한다.
