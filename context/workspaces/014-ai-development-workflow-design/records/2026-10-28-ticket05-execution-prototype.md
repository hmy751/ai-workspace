# 05 — 합의한 루프를 프로토타입 실행 본문과 Personal에 연결

후속: [개명·기록 점검과 독립 검증/개선 리뷰](2026-10-28-improvement-loop-review-synthesis.md)를 완료했다. 아래 검사는 초기 작성판의 결과이며 현재 판본과 리뷰 후속은 이 기록에서 구별한다.

2026-10-28. 사용자 요청: “좋아 그럼 합의한 걸 바탕으로 프로토타입에 실행 구체안 만들어줘 필요한 정보는 놓치지말고 종합해서”.

**네 묶음 합의를 프로토타입의 실제 실행 지침·저장 위치·읽기/반영 경로로 구성했다.** [당시 실행 구체안 보존판](reviews/improvement-loop-2026-10-28/input/prototype/improvement-loop.md)에서 전체 관계와 대표 흐름을 읽고, [improvement-loop](prototypes/development-workflow/skills/improvement-loop/SKILL.md)에서 수행한다. 전역 설치·자동 실행·실제 효과 검증·05 전체 마감은 아니다.

## 실제로 만든 구성

- improvement-loop 본체: 현재 Main의 대화 전체 검토, 관련 본문 전체·수행·새 가능성 탐색, 추천·공동 선택·실제 반영·종료.
- 조건부 상세: 압축/누락 구간의 원문 접근, 실제 사용과 효과·부담·한정 비교 판단.
- Personal: 기준과 경험의 상위 경계 확대, `experience/README.md` 길잡이와 미분류 기록, `MAINTENANCE.md`, 세 주제 상세. 경험 모음의 관리 계약은 스킬 밖 Personal에 남는다.
- 실물 예시: 설계 논의의 열린 방법 후보, 문서 편집 성공 경험, 설명 보완의 제한적 효과와 현행 유지 판단. 새로운 실제 제품 사건·새 기준 채택으로 표시하지 않았다.
- 연결: demo AGENTS·context 진입·USAGE·development·context-update·스킬 안내·prototype 진입과 가까운 형성 자료. 선택한 개선을 Work로 강제 등록하는 절차를 넣지 않았다.

파일명은 Main의 구체화 선택이다. 세 주제로 Personal 전체를 고정 분류하지 않는다. 기존 개발 기준·제품 계약·작업 상태의 정본은 유지한다. 후보가 채택되면 실제 대상이 현재 내용을 소유하고 경험 주제는 근거·결과를 잇는다.

## Main이 실제 입구에서 확인한 범위

Personal 입구 → 경험 길잡이 → 설계 논의 주제를 열어, 왜 후보인지·반영되지 않은 대상·다시 볼 조건을 찾았다. 길잡이의 미분류 검사 질문은 실제 도구 결함이 아니라 아직 사례가 없는 요구임을 확인했다. 다음 일반 작업에서 후보를 적용할 지시로 읽지 않도록 본문·USAGE의 경계를 대조했다.

문서 품질 주제의 첫11편 긍정 평가와 추가8편·스킬 단독 인과·main 판본의 제한을 보존 조사와 대조했다. 설명 효과 주제는 과거 비교·현행 유지와 새 루프의 효과를 구별한다. 반영을 마친 가상 상황은 경험 관리에서 열린 후보 해제·실제 대상 연결·채택 지침 전문 비복제의 경로로 대입했다. 실제 후보를 새로 채택·수정한 시험이나 독립 모델의 다음 세션 재조회 시험은 아니다.

대표 조건도 Main이 문서에 대입했다. 일반 완료만으로 자동 루프를 실행하지 않음, 새 조건 없는 보류안 반복 제안 안 함, 명확한 문제는 반복을 기다리지 않음, 원문 누락 시 부분 진행과 전체 검토 미완료 구별, 새 역할 후보가 곧 필수 리뷰어가 되지 않음. 실제 모델 수행의 성공률·효과를 측정한 결과는 아니다.

## 검사와 남은 확인

기본 Node 모듈 탐색에서 marked가 없어 첫 viewer 생성은 실패했다. 앱이 제공한 기존 번들 marked 경로로 다시 생성했다. 기본/번들/저장소 Python에 PyYAML이 없어 skill-creator의 quick_validate 실행은 실패했다. 패키지는 설치하지 않았고 Ruby YAML 파서로 이름·description·허용 키·길이·미완성 placeholder를 대체 확인했다. 이 검사를 원 validator 통과라고 보고하지 않는다.

최종 viewer 검사와 링크·diff 결과는 아래 확인 결과를 따른다. 브라우저 렌더링·새 독립 리뷰·새 모델 응답 시험·운영 설치·제품 코드 테스트는 수행하지 않는다. 이번 변경은 제품 코드가 아니라 지침·컨텍스트와 표시 사본이다.

남은 것은 실제 실행안의 사용자 점검과 필요한 보완, 05 완료 조건에 맞춘 최종 판단이다. 실제 host 설치·원문 접근의 연속성/완전성·다른 host 지원은06에서 구체화하고, 실제 요청·후속 재조회·사용 효과는07의 적용 관찰에 연결한다. 05에서 작성한 상세를 설치·효과 완료로 바꾸지 않는다.

최종 확인 결과: viewer 재생성 후 문서206개·코드5개의 현재 원문/SHA 일치, 내부 링크1192개·앵커299개에서 누락0개, prototype 밖 로컬 문서 의존0개, 화면 스크립트 문법 통과. skill 메타데이터 대체 확인과 `git diff --check`도 통과했다. 제품 동작·브라우저 조작·독립 모델 실행의 검증은 아니다.

변경·신규 Markdown47개의 로컬 링크 경로도 대조했다. 간이 추출이 괄호 포함 기존 파일명 두 곳을 잘라 표시한 것은 실제 파일 존재로 재확인했으며 실제 경로 누락을 찾지 못했다. 보존된 최초 리뷰 snapshot은 수정하지 않았다.
