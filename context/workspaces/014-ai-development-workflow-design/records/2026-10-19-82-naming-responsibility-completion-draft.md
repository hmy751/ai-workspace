# 이름과 책임·완료 범위의 개인 기준·Project 가이드·읽기 안내 시안

> 후속 정정: 이 기록에서 전제로 둔 ai-workspace 내부 Personal 위치와 Project의 개인 기준 직접 참조는 [84](2026-10-19-84-personal-project-ownership-and-format-correction.md)에서 최신 사용자 정정에 따라 대체했다. 아래는 당시 판단·작성·확인 이력으로 보존한다.

2026-10-19. [81](2026-10-19-81-personal-context-direction-and-next-step.md)의 다음 추천이었던 한 주제를 사용자가 선택하고 실제 본문 작성을 요청했다.

> 그래 그럼 아까 말한 이름과 실제 책임·완료 범위로 개인 기준 본문, Project 가이드, 읽기 안내를 실제로 만들어서 나란히 보여줘. 아직 기존 파일은 옮기거나 합치지 말고.

요청에 따라 [비교 입구](prototypes/personal-project-naming-2026-10-19/README.md), [개인 기준](prototypes/personal-project-naming-2026-10-19/personal-criterion.md), [Project 가이드](prototypes/personal-project-naming-2026-10-19/project-guidance.md), [읽기 안내](prototypes/personal-project-naming-2026-10-19/reading-guide.md)를 새로 작성했다. 이는 본문을 검토하기 위한 시안이며 개인 기준 항목 전체·최종 배치·운영 채택을 확정한 것은 아니다.

## 본문에 각각 남긴 의미

개인 기준은 이름·타입·공개 계약에서 실제 책임과 완료 범위를 예상할 수 있게 하는 판단을 소유한다. 부분 처리와 전체 조율, 요청과 완료, 표현의 문제와 동작의 문제를 구별하고 주변 맥락·수정 비용에 따라 유지할 수 있게 했다. 모든 이름을 길게 만들거나 모든 후속 작업을 기다리는 규칙으로 만들지 않았다.

Project 가이드는 Noline의 인증 저장·상태 적용과 전체 세션 변경, 후속 Query 갱신의 구체 관계를 설명한다. 개인 기준의 핵심을 짧게 상기하되 실제 적용에 필요한 내용은 자체 본문에 두었다. 기존 인증 가이드가 소유한 순서·실패 계약을 요약해 연결하며, 개인 원칙이 로그인 완료의 제품 의미를 결정하지 않는다.

읽기 안내는 Project README에 연결할 내용이다. 인증 작업은 Project 가이드에서 시작하고 일반 명명 판단이 쟁점일 때 개인 기준을 추가한다. 제품 의미·실제 구현을 확인할 조건과 변경을 돌려보낼 책임을 설명한다. 세 본문 전체를 매 작업의 필수 입력으로 지정하지 않았다.

이 비교를 위한 세 파일은 실제 운영에서 파일 수를 고정하는 제안이 아니다. 개인 주제의 파일명은 후보이며 Project 적용 본문은 기존 가독성 가이드 안의 절로 둘 수도 있다. 실제 배치와 중앙 개인 기준의 접근·배포 경로는 아직 구성하지 않았다.

## 문서로 확인한 경계

별도 근거 확인 담당자는 Noline 관찰판에서 인증 완료·실패 분류와 책임 분리를 확인했다. 로그인 경로의 실제 action명·반환형·Promise 해소 시점·무효화 대기 여부·화면 반영 시점은 이 문서들만으로 확정할 수 없다고 보고했다. 따라서 본문에는 코드·호출부 대조가 필요한 것으로 남겼다. sync pull 경로에서 재조회를 기다리지 않는다는 별도 서술을 로그인 경로로 옮기지 않았다.

보존된 관찰판의 현황 문서는2026-09-25 제품 기준 `759cba3` 대조와 당시 제품 검사 미실행을 명시한다. 이번 작업에서도 실제 Noline 코드·제품 실행을 확인한 것은 아니다. 새로운 코드 동작·완료 시점·사용자 안내 정책을 확정하지 않았다.

## 이번 변경과 다음 판단

새 시안·이 기록과 Workspace의 현재 안내를 갱신했다. source, 기존 리팩터링·가독성 가이드, 기존01-02 prototype, reference-project, 루트 context 계약을 변경하지 않았다. `context/personal/` 생성·기존 파일 이동/통합·제품 적용은 없다.

다음에는 세 본문이 각각 충분한지, Project의 짧은 전제 재서술과 독립 기준의 중복 사이 경계가 적절한지, 실제 읽는 장면에서 필요한 계약에 닿는지 사용자와 판단한다. 한 주제를 작성한 것을01-02·03·04-03·06의 완료나 실제 수행 효과로 올리지 않는다.

## 본문 검토와 확인 범위

별도 검토자는 위 사용자 요청과 실제 시안에서 시작해 두 장면의 판단을 복원했다. 로그인 뒤 갱신 helper에서는 실제 반환·호출부를 확인해 요청만 하는 것이 계약에 맞으면 표현을 좁히고, 약속한 완료를 충족하지 못하면 동작 문제로 다루는 구별을 찾았다. 인증과 무관한 함수 이름에서는 개인 본문만 선택해 판단할 수 있고 인증 문서를 강제하지 않는다고 확인했다.

개인 일반 판단과 Noline 구체 계약, 짧은 전제 재서술과 기존 인증 가이드의 소유 관계를 대조했고, 확인한 범위에서 수정이 필요한 근거 과장·책임 혼합은 발견하지 못했다. 이는 별도 검토자의 문서 읽기 결과이며 사용자 수용이나 실제 작업자의 수행 효과를 뜻하지 않는다. 제품 실행·중앙 개인 기준의 접근/배포 경로는 검증하지 않았다.

Main은 새 Markdown5개에서 로컬 링크 대상24곳과 그중 앵커5곳을 확인했고 누락은 없었다. Workspace 진입점의 후속 갱신은 본문 작성 사실과 검토 대기를 반영하며, 과거 기록81과 기존 시안의 본문은 유지한다.

진입점 갱신 뒤 전체 변경 Markdown14개에서 로컬 링크 대상406곳의 존재와 `git diff --check`를 확인했다. 변경은 이 Workspace의 새 시안·기록과 현재 안내에 한정됐고 source·기존 prototype은 변경하지 않았다. `context/personal/`도 생성하지 않았다. 새 커밋은 만들지 않았다.
