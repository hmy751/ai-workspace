# 데모 공통 본문·형성 자료 관리 원칙 — 진입 문서 작성

2026-10-20. 사용자는 데모 전체에 새 배치를 적용하기 전에 context 아래에 대문자 이름의 기준·정책 문서를 먼저 만들도록 요청했다. cases가 필수 문서로 굳어지지 않도록, 본문 역할의 내용을 나누어 두는 배치의 한 예로 일반화해 달라고 보완했다.

후속: [112의 작업 정리](2026-10-20-112-formation-context-session-checkpoint.md)에서 사용자 요청에 따라 정책의 viewer 문단을 제거하고 대화·실물·미적용 범위를 정리했다. 아래는 최초 작성과 당시 확인의 기록이다.

## 요청과 반영 범위

사용자 원문:

> 좋아 근데 데모 전체 적용전에 일단 진입 문서? 라고해야한 기준 정책 문서를 context 하위에 대문자로 해서 파일을 먼저 만들었으면 좋겠어 참고로 하나 보완하고 싶은게 cases를 필수 문서처럼 둘까봐 인데 cases말고도 본문 역할인데 나누는 그런 문서들을 저렇게 배치하면 좋겠다는 식으로 말하면 좋을 것 같아
> 일단 진입 원칙? 정책? 그 문서 부터 만들어 놓자

[CONTENT-POLICY.md](prototypes/development-workflow/noline-demo/context/CONTENT-POLICY.md)를 **본문과 형성 자료의 관리 원칙**이라는 제목으로 작성하고 [데모 context 진입점](prototypes/development-workflow/noline-demo/context/README.md)에서 연결했다. 정확한 영문 파일명과 문장은 Main이 요청을 구체화한 것이다.

- 현재 내용을 사용하는 본문 층과, 정확한 이해·수정에 필요한 형성 자료를 구별한다.
- 별도 본문은 `index.<내용을 드러내는 이름>.md`로 연결한다. `index.cases.md`와 `index.details.md`는 선택적 예시이며 필수 파일 목록이 아니다.
- background의 현재 맥락·주제의 형성과 변경 기록·근거는 처음부터 책임을 구별한다. 실제 보존할 내용 없이 빈 파일을 채우지는 않는다.
- 의도·배경·목적, 과거 선택·회피·복귀 판단의 조건과 확인 범위를 남긴다. 모든 작업 기록을 주제 폴더로 복제하거나 과거 판단·원문을 새 결론에 맞춰 덮어쓰지 않는다.
- 일반 사용·의미 변경·충돌하는 근거·표현 수정·이동에 따른 읽기와 갱신을 구별한다. 내용 소유는 Personal·Project·Work에 유지하고 현재 작업자가 필요한 관계를 함께 관리한다.

[110](2026-10-20-110-formation-context-dialogue-review.md)의 전체 구성안에서 **공통 관리 원칙 문서와 진입 연결**을 실제로 반영한 단계다. 기존 이름 기준과 다른 주제를 새 폴더·background로 옮기지는 않았다. 새 workflow·skill·자동화·제품 변경이나 운영 설치도 없다.

## 개선 검토와 확인

별도 검토자에게 사용자 요청과 실제 초안·진입점을 주고 읽기 전용 개선 의견을 받았다. cases 필수화 우려가 문장·트리·갱신표에 일관되게 해소됐는지 살폈다. 적용에 필요한 내용을 본문에서 충분히 설명한다는 문장을 직접적으로 고치고, 작업 전체 기록과 주제에 필요한 형성 자료의 경계를 보완했다. 이것은 문서 해석 검토이며 실제 작업자의 장기 준수 검증은 아니다.

원본 Markdown을 열람 화면으로 재생성했다. 기본 실행에서 로컬 `marked`를 찾지 못했으나 이미 설치된 런타임의 모듈 경로를 지정해 성공했다. 설치나 viewer 코드 변경은 없었다.

정적 검사 결과는 문서56개·코드5개 원문 일치, 내부 링크283개·앵커35개 누락 없음, 이름 기준의 기존 필수 연결5개 유지다. 모든 로컬 링크는 prototype 안에 있다. 브라우저 화면 실측·인증 제품 검사·새 배치의 변경 실험은 수행하지 않았다.107의 변경 실험을 이번 관리 원칙의 운영 효과로 재사용하지 않는다.

현재 안내와 적용 범위를 갱신했으며 커밋은 만들지 않았다.
