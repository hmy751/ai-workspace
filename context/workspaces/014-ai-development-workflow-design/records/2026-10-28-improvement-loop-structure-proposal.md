# Improvement Loop의 파일 배치와 본문 형식 검토

**후속 정정:** 루트 유지와 Personal context 내 근거 통합은 [2026-10-29 재검토·반영](2026-10-29-improvement-loop-consistency-adoption.md)에서 대체됐다. 이 문서는 당시 판단과 수행 기록이다.

**후속:** 사용자가 이 제안의 반영을 요청해 [구조·본문 편집과 확인](2026-10-28-improvement-loop-structure-adoption.md)을 마쳤다. 아래 미반영 표시는 제안 당시 상태다.

2026-10-28. 사용자는 prototype 루트의 `improvement-loop.md` 위치와 references의 파일 구조·내용 형식을 개선 리뷰어와 함께 점검해 달라고 요청했다. **루트 안내는 유지하되 역할을 선명하게 편집하고, 실행 상세와 확인 이력·Personal 근거의 소유를 정리하는 안을 추천한다.** 이 문서는 제안이며 prototype 파일은 아직 변경하지 않았다.

## 위치보다 먼저 나눌 책임

[당시 실행 구체안 보존판](reviews/improvement-loop-2026-10-28/input/prototype/improvement-loop.md)는 스킬 하나의 실행 상세만 설명하지 않는다. 루프 실행, Personal의 경험 보존, context-update와 실제 반영 대상의 관계를 함께 보여준다. 기존 [로그인 walkthrough](prototypes/development-workflow/walkthrough.md)도 여러 구성요소가 한 작업에서 연결되는 해설을 루트에서 맡는다. 따라서 현재 경로는 타당하다.

다만 제목의 ‘실행 구체안’과 본문이 지속 안내, SKILL의 실행 규칙, 이번 작성 현황과 다음 검토를 섞는다. 전체를 스킬의 references로 옮기면 Personal까지 스킬의 부속 자료처럼 보이게 하고, `_background`로 옮기면 현재 구성을 이해하는 설명을 형성 이력에 묻게 된다. **파일명과 위치는 유지하고 제목을 ‘작업 체계 개선 루프 — 구성과 적용 사례’로 바꾸는 안**을 권고한다. 파일명 변경이나 새 guides 폴더는 현재 필요하지 않다.

## 추천하는 실제 구성

아래는 새로운 계층을 추가하는 안이 아니라 현재 파일의 책임을 정리한 것이다.

```text
development-workflow/
  README.md                         전체 질문별 진입
  improvement-loop.md               구성 관계와 적용 사례
  skills/improvement-loop/
    SKILL.md                        호출·핵심 판단·선택·반영·완료
    references/
      conversation.md               대화 원문 확인 방법
      effects.md                    사용 경험에서 다음 판단을 고르는 방법
    _background/                    스킬을 이렇게 정한 이유와 확인 이력
  noline-demo/context/personal/
    experience/                     경험·해석·후보와 그 관리
    _background/experience-collection/
      context.md                    Personal 범위의 선택 이유와 최소 원문 근거
```

| 현재 내용 | 권고 위치와 편집 |
| --- | --- |
| 루트 안내의 파일/책임 표 | 유지. 사용자가 무엇을 이해하거나 고칠 때 어디로 갈지 설명한다. 파일 존재 목록과 구현 완료 보고는 줄인다. |
| 루트 안내의 여섯 시점 흐름 | 전체 관계를 설명하는 짧은 흐름으로 유지한다. SKILL의 세부 의무·예외를 다시 완전하게 정의하지 않는다. |
| 대표 사례 | 루트 안내에 유지한다. 실제 보존 경험, 현재 해석, 가정한 다음 선택을 처음부터 구별하고 선택에 따라 달라지는 행동을 보여준다. |
| 입력·권한·정본 경계 | 전체 관계 이해에 필요한 설명만 안내에 남긴다. 실행 조건은 SKILL·references, 경험 관리 규칙은 Personal의 본문으로 연결한다. |
| 이번 작성 목록·검사 결과·다음 검토 | 기존 [작성 기록](2026-10-28-ticket05-execution-prototype.md)과 Workspace current가 소유한다. 안내에는 prototype의 적용 범위와 실제 운영 미확인 경계를 짧게 남긴다. |
| Codex 원문 접근 절차 | conversation.md 안에서 조건부 방법으로 유지한다. 날짜가 달린 실제 확인 범위는 스킬의 기존 형성 기록에 두고 연결한다. |
| Personal 범위를 넓힌 사용자 원문 | Personal의 기존 형성 맥락에 필요한 발췌를 둔다. 스킬의 evidence는 이 선택을 참조한다. 전체 인터뷰나 네 묶음 근거를 복제하지 않는다. |

루트 README의 상단 추가 안내는 기존 ‘지금 궁금한 것’ 표에 ‘대화 경험에서 개선을 찾아 선택·반영하는 방법’으로 연결하면 다른 구성요소와 함께 찾기 쉽다. `skills/README.md`도 같은 질문별 목록에 통합한다. 현재 이 파일은 위에서 improvement-loop를 안내하면서 바로 다음 ‘현재 실행 본문’ 열거에서는 루프를 빠뜨린다. Main도 실제 본문에서 이 불일치를 확인했다. 별도 수동 전체 열거를 없애거나 실제 목록과 맞춘다. README 전체의 개명·개편까지 이번 수정에 묶을 필요는 없다.

## references의 형식은 용도에 맞게 유지한다

현재 두 파일은 외부 참고 문헌을 모은 폴더가 아니라 **조건이 맞을 때 실행에 사용하는 상세**다. [스킬 본문 정책](prototypes/development-workflow/skills/SKILLS-CONTENT-POLICY.md)에 맞으며, SKILL에도 각각 읽을 조건이 연결돼 있다. `INDEX.md`나 references README를 새로 추가하거나 모든 파일에 같은 목차를 강제할 이유는 없다.

- **conversation.md:** 순서대로 수행해야 하는 확인은 번호 목록이 맞다. 공통 확인 → 로컬 Codex에서 가능한 방법 → 원문을 확보하지 못했을 때의 판단으로 읽힌다. Codex 방법은 실제 환경에서 식별자와 형식을 다시 확인하는 조건을 유지한다. ‘2026-10-28에 여기까지 확인했다’는 과거 증거는 실행 절차와 구별한다. 별도 host 파일은 독립적으로 유지할 방법이 실제 늘 때 판단한다.
- **effects.md:** 확인된 상태에 따라 판단이 달라지므로 현재의 상태/다음 판단 표가 적절하다. 번호를 붙여 모든 행을 순서대로 수행하는 단계처럼 만들지 않는다. 읽음·사용·도움의 차이와 불확실성을 다루는 설명도 유지한다.
- **SKILL.md:** 핵심 판단과 완료를 계속 본체에 둔다. 읽기 범위·Personal 재조회·후보 충분성이 한 구간에 모여 있으므로 문단과 필요할 때의 소제목으로 읽는 목적을 드러낼 수 있다. 길다는 이유만으로 본체를 링크 목록으로 줄이거나 한 문단마다 파일을 늘리지는 않는다.

문장도 ‘하지 않는다’만 나열하기보다 목적과 행동을 먼저 쓴다. 다만 사용자 요청 실행, 전체 대화 훑기, 전체 관련 본문 검토, Work 강제 등록 금지처럼 합의 의미를 지키는 조건은 제거하지 않는다.

예를 들어 안내의 시작은 다음처럼 쓸 수 있다.

> 이 문서는 루프 스킬이 Personal의 경험과 실제 개선 대상을 어떻게 연결하는지 보여준다. 실행할 때는 SKILL.md를, 경험을 보존·갱신할 때는 Personal의 관리 본문을 따른다. 아래 사례는 보존된 경험을 바탕으로 가능한 다음 선택을 설명하며, 후보가 이미 채택됐다는 뜻은 아니다.

conversation.md의 환경별 방법은 다음처럼 시작할 수 있다.

> 로컬 Codex 세션 파일에 접근할 수 있다면 현재 세션 식별자와 파일의 메타데이터를 대조한다. 아래 형식은 확인한 판본의 예이므로 실제 파일 구조를 먼저 확인한다. 현재 세션과 연결된 원문만 시간 순서대로 읽는다.

실행 안내에 필요한 환경 조건과 한계는 남기고, 특정 날짜에 어디까지 시험했는지는 가까운 형성 기록에서 찾게 하는 편집이다.

## Personal의 근거는 Personal에서도 유지한다

현재 [Personal 형성 안내](prototypes/development-workflow/noline-demo/context/personal/_background/experience-collection/README.md)는 범위를 넓힌 사용자 원문을 루프 스킬의 evidence로 연결한다. 링크는 유효하지만 루프 스킬을 교체하거나 제거하면 Personal을 왜 이렇게 정의했는지의 직접 근거도 함께 잃을 수 있다.

새 근거 저장소를 만들기보다 기존 Personal `context.md`에 범위 확대와 Work 강제 등록 정정의 최소 발췌·출처를 보존하는 것을 추천한다. 스킬의 형성 근거는 Personal의 이 부분을 참조하고, 루프의 시점·전체 검토·선택·효과에 대한 근거는 계속 소유한다. 이렇게 하면 현재 실행 수단과 지속해서 유지할 경험 체계의 책임이 자료 배치에도 이어진다.

## 앞선 제안과 다음 반영 범위

[앞선 두 개선 제안](2026-10-28-improvement-loop-review-synthesis.md)은 그대로 미반영이다. 이번 구조 제안이 한정 시도의 일반 작업 소비/종료 연결이나 같은 목적의 개선 수단 비교 사례를 대신하지 않는다. 함께 채택한다면 실행 의미의 보완은 SKILL·Personal의 실제 담당 본문에, 그 결과를 보여주는 사례는 루트 안내에 반영한다.

이번 요청으로 새 파일 이동·실행 의미 변경을 적용하지 않았다. 다음에는 사용자가 선택한 편집 범위에서 본문·들어오는 링크·형성 자료·viewer를 함께 맞추고 확인한다. 기존 리뷰 입력 snapshot과 과거 기록은 당시 판본으로 유지한다. 운영 설치·실제 수행 효과·05 최종 마감은 이번 문서 구조 검토의 결과가 아니다.

## 독립 리뷰와 확인

[독립 구조 개선 리뷰](reviews/improvement-loop-2026-10-28/structure-review.md)를 회수했다. 현재 파일과 실제 정책·보존 외부 자료를 별도 맥락에서 대조한 결과다. Main은 실제 root walkthrough, 스킬 정책, 현재 SKILL·references·Personal 형성 자료와 비교해 위 권고를 구성했다.

- **동의:** 루트 안내 유지·역할 정리, 정상 진입 목록으로 통합, 실행 방법/확인 이력 구별, Personal 근거의 독립 소유, 현재 references 두 파일 유지.
- **더 작은 변경을 추천:** 리뷰어는 Personal 형성 자료에 `evidence.md`를 추가했다. Main은 우선 기존 `context.md`에 필요한 최소 발췌를 함께 두는 안을 추천한다. 근거의 소유 분리는 필요하지만 현재 짧은 범위 선택 하나에 새 파일이 필수는 아니다. 근거가 늘어 이유 설명과 별도 재검토가 필요해지면 나눌 수 있다.
- **선택적 편집:** effects의 판단 소제목은 필요한 부분에만 둔다. 짧은 단락마다 소제목을 붙이는 형식은 요구하지 않는다. SKILL도 읽는 목적이 달라지는 지점만 구별한다.
- **외부 근거의 보완 후보:** 리뷰어는 pstack technical-writing·reflect와 Matt chief-of-staff의 보존 원문을 대조했다. 디렉터리 이름이나 고정 목차를 복제하기보다 독자 질문·조건부 수행·주제별 경험 관리 관점을 선별하는 것이 적절하다. 루프 evidence의 외부 자료 표는 어느 자료의 어느 내용이 현재 어느 선택에 쓰였는지 더 직접 연결할 수 있다. 원형·절·판본과 필요한 설명을 가까이 남기고, prototype 밖 source를 필수 링크 의존으로 추가하지 않는다. 이번 확인을 과거 작성 당시의 직접 조사 이력으로 소급하지 않는다.

제안의 형식 개선을 실제 효과 향상으로 검증한 것은 아니다. 정적 문서 대조이며 실제 루프 수행·운영 설치·장기 사용감은 이번 범위 밖이다.

기록 갱신 뒤 prototype 220개 파일이 기존 검토 manifest와 일치하고 새 파일도 없음을 확인했다. viewer.html은 원래 manifest 제외 대상이며 이번에는 생성하지 않았다. 새 제안·리뷰·관련 current/기록 진입 7개 문서의 로컬 링크 경로 507개에서 누락이 없었고 `git diff --check`를 통과했다. 기존 검토 snapshot과 source는 수정하지 않았고 새 커밋은 만들지 않았다.
