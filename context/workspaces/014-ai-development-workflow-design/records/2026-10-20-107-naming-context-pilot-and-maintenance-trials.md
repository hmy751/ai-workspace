# 이름 기준 옆 맥락 적용과 변경 유지 실험

2026-10-20. 이름 기준 한 묶음에 **현재 본문·형성 맥락·필요한 근거**를 실제로 연결했다. 본문에서 사용할 판단은 유지하고, 그 판단을 만든 목적·과정·열린 부분과 읽기·갱신 조건을 옆에 두었다. 서로 다른 네 변경을 독립 복사본에서 실제 편집해, 필요한 갱신과 보존이 구별되는지 확인했다.

형성 맥락에는 구현 품질을 높이려는 출발점, 설명으로 사용 가능함과 코드 자체의 명료함을 구별한 과정, 내부 사용처의 변경 가능성은 비용 조건이라는 판단, 채택 뒤에도 조건별로 적용한다는 뜻, Personal·Project의 관리 책임을 담았다. 합의 문구를 모으거나 본문의 조항을 다시 요약하는 방식으로 구성하지 않았다.

현재 방향에 대한 사용자 발화와, 작성자가 구체화한 문장·표·사례의 지위를 구별했다. 개별 이름의 최적성, 전체 본문 충분성·최종 수용, 실제 이해 속도·장기 비용의 개선은 확인한 것으로 올리지 않았다. 실제 설계 대화를 Noline demo 제품의 사건으로 바꾸지도 않았다.

## 읽기와 갱신의 운영 범위

일반 적용은 본문과 필요한 사례에서 시작한다. 기준의 의미·우선순위·적용 조건을 바꾸거나 의도가 불명확하면 맥락을 함께 읽고, 동의의 범위·정확한 뜻·충돌을 확인할 때 관련 발췌를 읽는다. 전부를 매번 읽게 하지 않는다.

변경 작업자는 개인 기준의 의미 변경, 뜻이 같은 표현 수정, 충돌하는 새 관찰, 특정 제품·작업의 조건 변경, 파일 이동을 구별한다. 의미가 달라지면 현재 본문과 맥락의 영향받는 설명을 함께 맞추고, 사례와 적용 중인 Work의 영향을 살핀다. 새 근거는 출처를 나눠 보존하며 과거 발화를 새 결론에 맞춰 고치지 않는다. 표현만 다듬으면 해당 문장만 고친다.

[화면 검사](prototypes/development-workflow/viewer/check.mjs)에 시범 묶음의 필수 연결 5개를 추가했다. Personal 입구→맥락, 본문↔맥락, 맥락↔근거다. 없는 파일로 이어지는 링크뿐 아니라 링크 자체를 삭제한 누락도 잡는다. 이 검사는 의미의 일치·사용자 동의·원문의 해석을 판정하지 않는다.

## 실제 변경 실험

이전 대화를 상속하지 않은 새 작업자 네 명에게 각각 prototype 복사본과 README 진입점, 자연어 요청을 제공했다. 다른 복사본·원본014 기록·이전 대화는 읽지 못하게 했고, 예상 결론이나 수정할 파일 목록은 주지 않았다. 의미 변경과 관찰 입력은 **Main이 만든 모의 입력**임을 분명히 했다. 실제 사용자의 새 선호나 실제 독자 실험이 아니다.

작업자는 각 복사본에서 문서를 수정하고 화면을 재생성했다. Main은 보고뿐 아니라 실제 파일 차이·보존된 근거·검사 결과를 대조했다. 실험용 변경은 현재 prototype으로 가져오지 않았다.

| 입력 | 실제 변경과 Main의 판정 |
| --- | --- |

네 실험 모두 기존 다섯 근거 절의 내용은 그대로 보존됐다. Project와 실행 코드도 파일 내용이 동일했다. 새 근거를 추가한 두 실험에서는 기존 근거의 범위를 설명하는 도입 문장만 보완하고 별도 항목을 추가했다.

첫 생성 시 두 작업자는 기본 경로에서 `marked`를 찾지 못했다. Main이 이미 설치된 모듈 경로를 제공한 뒤 성공했다. 문서 관계를 찾는 데 추가 힌트를 준 것은 아니지만, 실행 환경까지 도움 없이 복구한 실험으로 보지는 않는다.

## 기계 검사와 의미 판단의 차이

현재 정상본은 55개 문서·5개 코드, 내부 링크281개·앵커35개, 시범 관계5개를 확인했다. 원문·SHA·A/B 동일 동작·화면 스크립트 문법 검사와 대상물 내부 로컬 링크 경계를 통과했다.

마무리에는 변경된 Markdown18개의 로컬 파일 링크475개에서 누락이 없고 `git diff --check`가 통과함을 확인했다. 실제 이름 본문은 맥락 안내 링크 추가 외에는 HEAD와 동일했다. 실제 prototype의 Project·실행 코드·적용 Work 내용은 실험 전과 같았다.

별도 복사본에서 다음도 실제 실행했다.

- 본문에서 맥락으로 가는 링크 두 개를 모두 제거하고 화면을 재생성했다. 일반 경로 검사는 깨진 링크를 발견할 수 없지만, 추가한 필수 연결 검사는 실패했다.
- 위의 의미 모순을 심고 화면을 재생성했다. **추가한 관계 검사까지 통과했다.** 따라서 구조 검사 통과는 의미 정합성의 증거가 아니다. 네 번째 작업자가 원문·맥락을 읽고 수정한 결과와 구별한다.
- 네 작업자의 결과에도 Main이 추가한 필수 연결 검사를 적용했고 모두 통과했다.

변경 전 문서, 입력, 실제 diff, 보존 대조, 검사 출력은 [실험 receipt](receipts/naming-context-maintenance-2026-10-20/results.json)에 남겼다. 원문 보존용 [기준 문서 snapshot](receipts/naming-context-maintenance-2026-10-20/baseline-documents.json)과 [의미 변경](receipts/naming-context-maintenance-2026-10-20/meaning.patch)·[표현 수정](receipts/naming-context-maintenance-2026-10-20/wording.patch)·[새 관찰](receipts/naming-context-maintenance-2026-10-20/observation.patch)·[불일치 정정](receipts/naming-context-maintenance-2026-10-20/consistency.patch)의 diff를 함께 보존했다. 생성 화면 전체 사본은 보존하지 않고 hash와 검사 결과만 남겼다.

## 결론의 범위와 다음 판단

이 시범 묶음에서는 **처음 읽는 작업자가 연결을 찾고, 변경 성격에 따라 고칠 곳과 보존할 곳을 구별하는 것**을 확인했다. 자동 갱신이나 장기간 여러 주제를 운영해도 관계가 계속 유지된다는 보장은 아니다. 한 모델 계열의 작업자, 한 주제, 한 번씩의 실행이며 모든 유형의 누락·모순을 시험하지 않았다.

브라우저 표시·클릭 실측, 실제 독자의 이해 효과, 제품 동작 검사는 이번 문서 변경에서 수행하지 않았다. 실행 코드는 바뀌지 않았다. 형성 맥락 파일의 Codex 열기 요청은 queued였으며 화면을 직접 확인한 것으로 기록하지 않는다.

다음에는 사용자가 이 맥락이 본문을 이해하고 고치는 데 필요한 내용을 담는지 판단할 수 있다. 실제 후속 수정에서 새로 필요해지는 근거·읽기 부담을 관찰해 형식을 다듬는다. 다른 모든 기준으로의 확대, 별도 자동화, Development의 최종 Owner·스킬 연결은 이번 완료 범위에 포함하지 않는다.
