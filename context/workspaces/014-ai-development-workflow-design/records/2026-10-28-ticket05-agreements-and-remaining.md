# 05 — 네 묶음 합의와 남은 실행 구체화 점검

후속(2026-10-28): 사용자 요청으로 [프로토타입 실행안과 연결](2026-10-28-ticket05-execution-prototype.md)을 작성했다. 아래의 미구현·다음 구체화 표기는 해당 논의 시점이며 최신 실물·확인 상한은 후속 기록을 따른다.

2026-10-28. **네 묶음의 운영 방향은 모두 합의했다.** 현재 [전체안](2026-10-27-ticket05-integrated-proposal.md), [사용자 발화](2026-10-27-ticket05-interview.md), [05 완료 조건](../current/tickets/05-improvement-loop.md#완료-조건과-확인-방법)을 Main이 대조했다. 새 독립 리뷰·운영 실행·효과 검증은 아니다.

## 합의한 범위

| 묶음 | 현재 합의 |
| --- | --- |
| 발견의 반영 | 관찰과 해석을 구별해 경험 보존·좋은 방법 구체화·기존 내용 변경·새 방법/역할·유지를 판단한다. 이득·근거·부담을 보고 한정 시도와 지속 채택을 구별한다. |
| 검토 범위 | 이번 대화 전체를 훑고 관련 본문·실제 결과·기준 전체를 깊게 살핀다. 필요한 연결과 기회를 따라 확장하며 원문 공백을 숨기지 않는다. |
| 선택·반영·종료 | 추천·이유와 다른 후보를 보여주고 선택한 가능한 개선을 실제 대상에 반영·확인한다. Work 기록은 자연스러운 기존 방식에 맡기며 별도 등록·이관을 강제하지 않는다. |
| 축적·다음 사용 | Personal의 길잡이·주제별 상세·아직 묶지 않은 기록을 다음 루프에서 찾아 대조·갱신한다. 관련 실제 사용의 도움·부담과 불확실성·부작용을 보고 유지·수정·범위 축소·철회 또는 필요한 비교를 선택한다. |

사용자 요청 실행·AI의 시점 제안·기존 세션 진행·필요시 외부 조사와 중요한 질문이라는 앞선 합의도 유지한다. 현재 본문·기준의 충분성 검토, 좋은 경험·새 역할 발견까지 포함하며 수집함 정리나 실패 교정으로 범위를 좁히지 않는다.

## 현재 실물과 남은 구체화

| 구체화할 것 | 확인한 현재 상태 | 다음 실행안에서 정할 내용 |
| --- | --- | --- |
| 루프 실행 절차의 배치 | [스킬 진입](prototypes/development-workflow/skills/README.md)과 [development](prototypes/development-workflow/skills/development/SKILL.md)는 기존 수행·반영을 소유하지만 새 경험 루프의 실행 본문은 아직 없다. | 사용자 요청을 받는 현재 Main이 따를 본문 위치, 기존 context-update와 대상별 수행의 연결. 별도 호출 스킬은 가능한 추천안이며 아직 생성·채택하지 않았다. |
| Personal의 실제 구성·읽기 | [Personal](prototypes/development-workflow/noline-demo/context/personal/README.md)은 현재 개인 판단 기준 중심이며 협업 경험·후보 길잡이와 주제별 기록은 없다. [USAGE](prototypes/development-workflow/noline-demo/context/USAGE.md)의 질문별 읽기가 후보 재조회까지 자동 보장하지 않는다. | 기존 기준과 경험·미결 후보의 관계, 길잡이·상세·미분류 기록의 실제 파일, 루프가 그곳을 찾는 경로. 실제 예시 한 주제로 내용을 채워 읽을 수 있게 한다. |
| 전체 세션 대화의 입력 | 설계는 전체 훑기·관련 원문 확인·공백 구별을 요구하지만 현재 prototype에 host별 전체 세션 원문 접근 방법은 없다. 이번 점검에서 live 로그를 탐색하거나 새 수집기를 설치하지 않았다. | 현재 세션 식별과 원문 위치·범위 확인, 압축된 앞부분의 복구, 누락·접근 불가 시 한정 검토 표시와 가능한 부분 수행. 요약만 읽고 전체 훑기를 완료했다고 말하지 않는다. |

이는 방향을 정하는 추가 장기 인터뷰보다 Main이 실제 배치와 수행 예를 묶어 제시할 항목이다. 파일 이름·추천 개수·상태 점수·반복 횟수 등을 별도 사용자 결정으로 모두 돌릴 필요는 없다. 서로 다른 선택이 목적·부담·권한을 바꿀 때 그 차이를 제시한다. 다른 저장소 설치·동기화는 [06](../current/tickets/06-framework-transition.md), 전체 실제 적용·장기 관찰은 [07](../current/tickets/07-integrated-rehearsal.md)과 연결한다.

## 05 완료 조건에 대한 현재 근거와 한계

| 기존 완료 조건 | 현재 판단 |
| --- | --- |
| 서로 다른 성격의 실제 사례에서 이유·범위·시점 설명 | 전체안에는 문서 편집 성공·재개 우선순위·설명 개선의 제한적 효과와 현재 인터뷰 사례가 있다. 도구 부족 항목은 사용자 기대와 검토 조건의 예이며 실제 결함을 확인한 사례가 아니다. 필요하다면 기존 보존 원자료에서 적절한 실제 사례를 선택해 추가 대입한다. |
| 한 후보의 근거·해석·대상·대안·비용·선택 연결 | 전체안의 문서 편집·재개 사례가 끝까지 설명한다. 실제 후보 채택·반영을 실행한 증거는 아니다. |
| 미채택 후보가 기준으로 둔갑하거나 유실되지 않음 | Personal의 구성·상태 의미와 재조회 방향은 합의했다. 실제 저장·읽기·갱신을 통한 확인은 아직이다. |
| 다음 사용에서 볼 결과·부담·미확인 구별 | 실제 사용·효과 불명확·부작용 처리까지 합의했다. 실제 효용은 다음 관련 사용에서 확인한다. |
| 설계 대입과 새 상황 적용·관찰 계획 구별 | 기존 사례 대입은 설계 설명이고 실효 검증이 아님을 표시했다. 구체 실행안을 만든 뒤 07에 넘길 관련 관찰 입력·범위를 연결해야 한다. |

따라서 이번 결론은 **운영 방향 합의 완료, 실행안 구체화·확인과05 최종 마감은 아직**이다. 구현 뒤에도 실제 효과를 선행 완료 요건으로 과도하게 올리지 않는다. 설계·대표 읽기/갱신 확인과 운영 효과를 구별한다.

## 다음 행동 추천

실행 절차 배치·Personal 실물·대화 입력을 하나의 구체안으로 제시한 뒤, 같은 주제의 후보가 첫 루프에서 보존되고 다음 루프에서 다시 발견·보완되며 채택된 본문과 혼동되지 않는지 대표 장면으로 확인한다. 좋은 경험·즉시 반영·미결 유지·효과 불확실성·원문 공백을 필요한 만큼 대조한다. 기존 확인을 무조건 반복하거나 모든 단계에 별도 역할을 붙이지 않는다. 실제 후보의 선택·설치 권한을 네 묶음 합의만으로 추론하지 않는다.

확인: 최신 문서와 실제 prototype 진입·관련 본문,06/07 책임을 읽었다. 기록 변경 뒤 `git diff --check`를 통과했다. source·prototype·전역 스킬·런타임은 변경하지 않았으며 새 커밋은 만들지 않는다.
