# 04-02 — 현재 수정안의 다음 비교 장면 선정

후속: 사용자가 시험을 지시해 [동일 조건의 두 최초 응답 비교](experiments/artifact-explanation-trip-list-body-2026-10-23/comparison.md)를 완료했다. 당시 파일·도구 관측을 source05에 보강했고, 두 판본 모두 실제 코드 없이 설명했다. 아래는 실행 전의 선정 판단이며 미실행 표기를 현재 상태로 가져오지 않는다.

## 추천과 현재 지위

**다음 우선 후보는 여행 생성·수정·삭제와 목록 갱신의 첫 전체 브리핑 요청3905다.** 기존 source에 이미 있던 장면이며, 10월20일 제안에도 이후 교정3962가 근거로 쓰였다. 완전히 알려지지 않은 별도 검증 표본이라고 부르지 않는다. 이번에는 교정 전의 실제 요청·첫 답·교정 순서를 다시 대조해, 현재 수정안의 추가 비교 후보로 추천한다. 사용자가 이 장면의 실행을 선택한 상태는 아니며 새 시험·스킬 변경은 하지 않았다.

지금까지 인증의 최신 수정안 비교에서는 실제 코드·값·대기 전후 설명이 나타났지만 같은 사건에서 만든 보완의 국소 관찰이었다. 저장 용량은 기존판의 적용 배치 비교였고, 직전 최초 티켓 파악은 현재 상태·남은 일을 설명하는 요청이었다. 여행 목록 장면은 **한 코드 조각에서 여러 파일의 작업 전체로 설명 대상을 넓혀, 근본 역할·대표 흐름·필요한 실제 코드가 연결되는지** 볼 수 있다. 더 긴 답이나 수정판의 우세 자체를 목표로 삼지 않는다.

## 원문 근거와 순서

원천은 [공개 대화](../source/noline-evaluation/corpus/01a1052a-4e61-7072-9b81-ff44449e5b85/messages.jsonl)와 같은 세션의 보존 압축 rollout이다. 아래 번호는 source_line이다. 이번 확인은 관련 구간3650~3995와 도구3910~3932에 한정했고 전체 대화를 새로 전수 조사하지 않았다.

| 순서 | 당시 실제 상황 |
| --- | --- |
| 3875 | AI는 오래된 목록 반영·연결 전환·API 서버 장애의 세 문제를 고쳤다고 보고했다. 훅·Router·로컬 저장소의 책임과 검사·실앱 미확인을 구별했다. |
| 3885 | 사용자: “cancelAndInvalidateQueries 갑자기 이 메서드는 뭐지?” |
| 3898 | AI는 이전 조회 취소 후 재조회하는 공통 함수라고 설명하고 코드 두 줄과 삭제 전 조회의 예를 제시했다. 이 선행 설명은 시험에서 숨길 이후 정답이 아니라 당시 이미 사용자가 받은 맥락이다. |
| 3905 | 사용자: “전체 작업 설명해봐 어떤건지 [$work-artifact-briefing](/Users/hammyeong-yeon/Desktop/10_work/noline/.claude/skills/work-artifact-briefing/SKILL.md)” |
| 3909 | AI는 스킬 적용을 선언했다. 날짜 확인에서 여행 저장·조회 수정으로 이어진 이유, 각 코드의 역할과 검증 범위를 설명하겠다고 했다. |
| 3937 | 첫 전체 브리핑. 역할·전후 비교·담당 표·데이터 예·조회 갱신 순서·근거 링크는 있었지만, 설명에 실제 구현 코드를 함께 놓지는 않았다. |
| 3944~3955 | 사용자가 다른 여행이 이미 활성화된 경우 등 생성 조건을 질문했고 AI가 구별했다. 추가 질문 자체를 설명 실패로 세지 않는다. |
| 3962 | 사용자: “근데 앞선 설명은 설명만 잇으니까 좀 어렵네 멘탈모델 도식화 구체적 코드도 고려하고 코드는 순수 동작 보다도 각 코드가 맡는 핵심적 역할 고려해서 잘 설명해줘 다시 브리핑 해봐” |

3937의 첫 문장은 다음과 같다.

> 이번 작업은 “여행을 저장하는 곳과 화면에서 다시 읽는 곳이 서로 어긋난 문제”를 고친 거야.

따라서 이 사건을 ‘기존판은 근본 역할도 구조도 전혀 설명하지 않았다’고 단순화하지 않는다. 문제 후보는 이미 있는 역할·흐름 설명이 사용자가 실제 구현을 이해하는 데 필요한 연결까지 제공했는가다. 코드나 도식 개수로 판정하지 않는다. 후속의 구현 책임 일관성 지적과 실제 수정은 설명 구성만의 효과와 구별한다.

## 다음 비교에 쓸 경계

- **시작점:**3905의 전체 작업 설명 요청. 선행 작업 목적·변경 논의·3885~3898을 필요한 연속 원문 범위로 제공한다. 짧은 Main 요약으로 대체하지 않으며 정확한 시작 범위는 자료 구성 단계에서 고정한다.
- **동일 적용:**사용자가 직접 호출한 시점에 두 판본을 각각 적용한다. 모델·추론은 직전과 같은 GPT-6-sol medium을 유지하는 안이다.
- **판본 차이:**기존판과 현재 채택한 prototype 본문만 다르게 한다. 별도 설명 목차·도식 의무·기대 답·새 작업 지침을 넣지 않는다.
- **제외:**3909 이후 계획·첫 답3937·조건 설명3955·교정3962·재브리핑3977·이후 구현 재판단은 생성자의 입력에서 뺀다.
- **볼 효과:**전체 작업의 역할과 필요한 코드·값·처리 관계를 목적에 맞게 연결하는가. 전체 작업 요청을 모든 줄의 해설로 과도하게 넓히지 않는가도 함께 본다.
- **볼 수 없는 효과:**자동 선택·조기 발동, 실제 독자의 이해 개선, 구현 자체의 적절성까지 이 한 비교로 입증하지 않는다. 역사적 적용 선언은 확인했지만3905 직후 SKILL.md 전문을 새로 읽었다는 증거와 같지 않다.

## 자료 준비 상태

공개 원문은 중앙 corpus에 보존돼 있다. 같은 원 rollout의 `.jsonl.zst` 존재와3910~3932의 실제 코드·문서 읽기 로그도 확인했다.3915·3923에는 당시 출력 잘림이 있고3932에는 그 표시가 없다. 이는 일부 당시 코드가 남아 있다는 근거이며 필요한 구현 전체를 확보했다는 뜻은 아니다.

시험을 준비한다면 당시 미커밋 변경·호출부·공통 helper를 별도로 확보하고 완독 가능한 입력을 만들어야 한다. 앞선 보고서 사건의 `0b3b167` archive를 후속 변경 상태로 대체하지 않는다. 이후 재브리핑의 설명용 코드 발췌를 원 코드 대신 넣지도 않는다. 현재는 후보 선정까지이며 실행 준비 완료가 아니다.

## 후속 — Network 사례 전체의 시점 후보와 본문 후보를 구분

여행 목록의 책임 설명 보완 비교 이후, 다음 후보로 Network1209를 추천했다. 사용자가 “잠깐 근데 여기서 시점도테스트 되나?”라고 물었을 때 Main은 동일 시점에 두 판본을 적용하는 시험 조건만 설명했다. 사용자는 “아니 이 사례 자체 말이야”라고 정정했다. 질문은 제안한 시험 조건이 아니라 이 사건 전체에 시점 비교 구간이 있는지였다.

원 corpus를 다시 확인하면 앞선 구간에도 후보가 있다.

| 원문 위치 | 확인한 사실 |
| --- | --- |
| 895 | 품질 개선·독립 검증 완료, 수정 항목과205개 테스트를 짧게 보고했다. 변경의 구체적인 역할·범위 설명은 제한적이었다. |
| 901 | 사용자: “근데 지금 개선한게 우리 기존 범위를 벗어나려고 한건 아니지? 설명해봐” |
| 913 | AI는 동작 결함 수정까지 기존 합의 범위라고 설명했다. 이 범위 판정을 검증된 사실로 채택하지 않는다. |
| 920~926 | 사용자가 브리핑 스킬을 직접 호출하며 자세한 설명을 요청했고 AI가 적용을 선언했다. |
| 963~970 | 상세 설명 후 사용자는 가독성·응집도라는 목적보다 동작 개선으로 범위가 커졌다고 지적하며 철회를 요청했다. |
| 1209 | 철회와 새 가독성 작업 뒤 `network.ts` 자체의 흐름을 설명해 달라는 별도 질문이다. |

따라서 사례 전체에는 **895의 최초 결과 보고에서 변경의 역할·범위를 설명하는 경우와,920의 추가 요청 뒤 설명하는 경우를 살펴볼 시점 비교 후보**가 있다.1209만으로 사례 전체의 시점 검증 가능성을 부정하지 않는다. 다만 이 후보의 대상은 네트워크 소비 연결 작업의 변경 설명이며,1209의 Store 내부 흐름 설명과 같은 설명 과제가 아니다.

현재 증거만으로 ‘스킬을 늦게 적용해서 범위 오판이 발생했다’고 단정하지 않는다.913에서도 범위를 잘못 해석한 채 설명했고, 더 이른 브리핑이 구현 범위 문제까지 해결한다는 보장은 없다. 고정 본문을 일찍 적용하는 효과와 자연스러운 스킬 선택은 별도 질문이다.895 시험에는 철회 전 당시 변경 코드·차이를 확보해야 하며, 현재 준비된1209의 철회 후 자료를 그대로 쓰지 않는다. 신규 시험은 시작하지 않았다.

후속 확보: 사용자의 준비 지시에 따라 [895 직전 자료·두 조건](2026-10-23-ticket04-02-network-first-report-preparation.md)을 구성했다. 앞선 “당시 변경 확보 필요”는 이 확보 범위만큼 해소됐으며 새 응답 시험은 미실행이다.
