# 지정 작업을 구현하고 검토한다

목표는 Ticket의 요구를 현재 제품 계약에 맞게 구현하고, 검토에서 발견한 관련 문제를 수정하여 확인 가능한 결과로 돌려주는 것이다. 작업 경로와 맡은 역할은 전달받은 요청을 따른다.

## 같은 작업 계약에서 시작한다

[Project 안내](../../../context/project/README.md)를 읽고 지정된 작업 Workspace의 README에서 `ticket.md`와 현재 진행을 찾는다. 구현과 검토를 위해 별도의 요구 문서를 다시 만들지 않는다.

Ticket의 목표·보존할 동작·제외 범위·완료 조건을 확인한 뒤 현재 코드, 실제 호출부와 영향받는 검사를 읽는다. 구현 보고에 적힌 설명만으로 현재 동작을 판정하지 않는다. 함수 이름이나 파일 배치만으로 책임을 추측하지 않고 입력에서 결과·실패·정리까지 이어지는 경로를 본다.

[짧은 공통 적용 관점](../../../context/project/quality.md#applying-principles)을 읽고, 요청과 코드에서 발견한 판단을 [Project의 작업별 읽기 안내](../../../context/project/README.md#reading-route)에 대입해 관련 기준·계약을 고른다. Main이 기준 제목을 지정하지 않아도 같은 입구를 사용한다. 이름·표현을 포함해 필요한 상세를 선택하며, 모든 절을 매번 순서대로 읽는 절차로 만들지 않는다. 원칙만으로 선택이 분명하지 않거나 과거와 다른 결론을 검토한다면 연결된 사례의 성립 조건·미정을 읽고 현재 사용처와 대조한다. 사례의 결론을 그대로 복사하지 않는다.

질문은 코드를 읽고 판단할 관점이다. 근거로 답할 수 있는 것을 사용자에게 다시 묻거나 모든 질문의 답을 보고서에 나열하지 않는다. 제품 정책이 실제로 미정이거나 Ticket의 요구와 현재 계약이 충돌하면, 어느 동작이 달라지는지와 필요한 선택을 작업 책임자에게 전달한다.

<a id="implement"></a>

## 구현 역할

Ticket과 관련 기준을 근거로 변경할 경로와 유지할 경로를 정한다. 요청한 동작을 완성하는 데 필요한 호출부와 검사도 함께 수정한다. 공통 구조 개선을 포함할지는 이번 목표와의 직접 관련성, 제품 규모, 변경 비용과 기존 동작 보존을 함께 판단한다.

변경 후 영향받는 동작을 직접 확인한다. 실행할 명령과 환경은 해당 Project 계약·실행 안내에서 확인하고, 이번 변경의 정상 경로와 실패·부작용을 다룰 검사를 선택한다. 우리 코드가 도구를 연결하면서 생긴 동작과 경계를 확인하며, 도구 내부 구현을 그대로 반복 검사하는 것을 목표로 삼지 않는다. 실행할 수 없거나 검사하지 않은 경로는 그 이유와 함께 남긴다.

해당 작업의 `records/implementation.md`에 변경한 책임·보존한 계약, 실행한 검사와 결과, 미확인 사항을 남긴다. 검토자에게 같은 Ticket, 변경한 코드 범위와 이 기록을 전달한다. 구현 검사의 통과를 검토 완료로 기록하지 않는다.

<a id="review"></a>

## 검토 역할

같은 Ticket과 관련 Project 기준을 먼저 읽고 변경 코드와 실제 호출부를 대조한다. 구현 기록은 수행한 변경과 검사의 재접근 경로로 사용하며, 그 결론을 검토 결과로 대신하지 않는다. 요청 충족 여부와 코드의 계약·책임·읽기 부담을 함께 살핀다.

Ticket 범위 안에서 필요한 품질 수정을 발견하면 검토자가 직접 고친다. 기존 계약을 완성하는 수정과 공개 계약·제품 정책을 바꾸는 선택을 구별한다. 전자는 맡은 범위에서 수행하며 후자는 근거와 영향을 작업 책임자에게 돌린다. 구현자가 설명한 설계와 실제 동작이 다르면 원요구·Project 계약·코드를 대조해 판단한다.

수정한 경로의 검사와 관련 회귀를 다시 확인한다. 구현자의 검사에서 빠진 계약 경로가 있는지 살피고, 필요한 장면을 직접 재현한다. 변경 전 검사 통과나 타입 검사만으로 수정 뒤의 동작을 확인했다고 판단하지 않는다.

해당 작업의 `records/review.md`에 발견한 문제, 직접 수정한 내용과 적용한 기준, 수정 후 검사 결과, 남은 한계를 남긴다. 작업 책임자에게 무엇을 유지·수정·보류했는지와 그 이유, 실제 확인한 범위, 추가 결정이 필요한 사항을 돌려준다. 근거가 충족되지 않은 완료 조건은 완료로 바꾸지 않는다.

## 현재 계약과 작업 기록을 연결한다

구현·검토를 거쳐 현재 계약이 달라졌다면 관련 Project 문서를 실제 결과와 맞추고, 변경 이유와 검사 증거는 작업 기록에 남긴다. 한 사례에서 얻은 개선을 공유 품질 규칙으로 자동 승격하지 않는다. 다른 작업에도 적용할 이유와 조건이 확인되면 기준 수정 후보로 제시한다.
