# 장바구니 주문의 현재 동작

PC 주문 페이지·모바일 주문 페이지·빠른 주문 모달은 모두 **현재 장바구니 전체를 주문한다**. 빠른 주문 모달을 장바구니와 무관한 바로 구매 흐름으로 해석하지 않는다. 이 문서는 세 화면이 보존해야 할 현재 동작을 소유하고, 개별 수정의 목표와 진행은 해당 Workspace가 소유한다.

## 주문 성공과 화면 완료

각 화면의 성공 처리에는 주문 요청 뒤 orders·catalog 캐시 무효화 호출과 장바구니 정리가 반복돼 있다. 캐시 관리는 QueryClient가, 장바구니 상태 변경은 기존 장바구니 기능이 맡는다. 화면 이동과 모달 완료 표시는 각 사용처가 결정한다. HTTP 요청 계층은 이 화면별 선택을 맡지 않는다.

캐시 무효화 완료를 기다린 뒤 장바구니 정리·화면 완료로 진행하는 계약은 현재 두지 않았다. **무효화 호출과 재조회 완료는 구별한다.** 이 비대기 조건은 이번 시안을 위해 둔 추가 가정이다. 새 제품에서 그대로 적용할 규칙이 아니며, 실제 작업에서는 코드·호출부와 대조해야 한다.

## 현재 알려진 문제와 미확인

세 화면의 성공 처리에 coupons 캐시 무효화가 빠져 주문에 사용한 쿠폰이 목록에 남는다고 가정한다. 수정 목표와 확인할 범위는 [주문 쿠폰 갱신 작업](../workspaces/order-coupon-refresh/README.md)에 있다. 이 문서는 아직 쿠폰 누락을 해결한 상태로 갱신하지 않았다.

실패·입력·로딩의 세부 정책은 이 시안에 지정하지 않았다. 실제 변경에서는 현재 코드와 동작을 확인해 보존할 범위를 구체화해야 한다. 이번 쿠폰 문제만으로 새로운 완료·대기 정책을 도입하거나 미확인 동작을 검증 완료로 기록하지 않는다.

같은 흐름을 공유할지의 일반 판단은 [공통 제공 범위](quality.md#shared-choice), 호출과 완료 의미의 구별은 [공개 계약](quality.md#public-contract)에서 찾는다. 현재 제품 동작의 근거는 [주문 장면71의 가정 구분](../../../../../2026-10-18-71-order-reading-and-criteria-boundaries.md)이며, 과거 사례와 현재 제품 계약의 역할은 다르다.
