# HTTP-07 — 검토자에서 Main으로

> 가정된 구현/검토 결과. 아래 재현·수정·확인은 가상 검토자의 완료 보고다. 실제 소스·테스트 파일이나 실행 로그를 생성한 기록이 아니다.

**완료를 권고한다.** 본문 대기 중 10초 timeout이 사라지는 문제와 요청 실패 뒤 타이머가 남는 문제를 직접 재현했다. 타이머 정리를 본문을 `await`하는 `try`의 `finally`로 옮겨 수정했고, 기존 반환·오류 장면과 관련 회귀 확인을 통과했다. 공개 호출과 오류 형태, 화면 정책은 유지했다.

## 구현자 보고를 받아 확인한 범위

[구현자 인계](implementation.md)는 정상·오류 본문 장면의 통과와 타이머 관련 미확인을 보고했다. 이를 완료 근거로 그대로 승인하지 않고, `src/api/fetcher.ts`의 요청 시작·헤더 수신·본문 대기·실패 처리와 `src/api/fetcher.test.ts`의 확인 장면을 대조했다.

판단 기준은 [Ticket의 요구와 보존 범위](../ticket.md#원래-요구와-보존할-것), [공개 계약](../../../project/quality.md#public-contract), [프로젝트 HTTP 계약](../../../project/http-client.md)이다. 10초 제한과 오류 전달을 실제 호출자가 신뢰할 수 있는지가 이번 판단의 중심이었다. [develop](../../../../.agents/skills/develop/SKILL.md)의 직접 수정 범위 안에서 처리했다.

## 직접 재현한 문제와 수정

| 장면 | 수정 전 직접 확인한 동작 | 판단과 조치 |
| --- | --- | --- |
| 헤더는 도착하지만 본문 읽기가 끝나지 않는다. | 헤더 수신 직후 `clearTimeout`이 호출됐다. 본문이 대기하는 동안 제한 시간이 지나도 timeout으로 종료되지 않았다. | 10초 제한이 본문 처리까지 포함한다는 계약을 충족하지 못했다. 헤더 직후의 해제를 제거하고 본문 완료·실패까지 타이머를 유지했다. |
| 헤더를 받기 전에 요청이 실패한다. | 헤더 뒤에 있는 타이머 정리까지 도달하지 못해 요청 종료 뒤에도 타이머가 남았다. | 요청 종료와 타이머 정리의 수명이 어긋났다. 성공과 실패가 모두 거치는 `finally`에서 정리하도록 했다. |

`clearTimeout`을 본문 읽기를 `await`하는 `try`의 `finally`로 옮겼다. 본문 처리를 기다리지 않고 `try`를 빠져나가면 같은 문제가 남으므로 구현자가 추가한 `await`를 유지했다. `catch`에서는 timeout을 먼저 식별하고 본문 파싱 실패와 구별하는 흐름을 확인했다. timeout 때문에 본문 읽기가 중단돼도 `code: TIMEOUT`이 파싱 오류 분류로 덮이지 않았다.

이는 새 timeout 기능이 아니라 기존 10초 계약의 빈틈을 수정한 것이다. 오류 클래스·메서드 인자·정상 반환을 바꾸거나 공통 toast·인증 이동·재시도·호출자 취소를 추가하지 않았다.

## 수정 뒤 확인

가정 환경에서 `pnpm exec vitest run src/api/fetcher.test.ts`와 `pnpm exec tsc --noEmit`을 통과했다. 아래는 검토자가 수정 뒤 직접 확인한 결과이며, 이 문서 폴더에서 실제 실행한 결과는 아니다.

| 확인 장면 | 결과 |
| --- | --- |
| 정상 JSON 응답 | 기존 JSON 반환을 유지한다. |
| 정상 문자열 응답 | 기존 문자열 반환을 유지한다. |
| HTTP 200과 깨진 JSON | `APIError`로 전달되며, 네트워크 연결 실패와 구별되는 본문 파싱 실패의 의미가 남는다. |
| HTTP 500과 깨진 JSON | `APIError`의 `status: 500`을 유지한다. |
| timeout이 아닌 본문 읽기 실패 | 본문 스트림이 읽는 도중 실패하면 `APIError`로 전달되고, 요청 시작의 네트워크 연결 실패나 TIMEOUT과 구별되는 의미가 남는다. |
| 요청 시작의 네트워크 연결 실패 | 본문 읽기·파싱 실패와 구별되는 네트워크 실패로 전달된다. |
| 비객체 오류 본문 | 속성 접근 예외가 새지 않고 기존 오류 형태로 전달된다. |
| 헤더 이후 느린 본문 | 본문 읽기 중 10초 제한이 적용되고 `code: TIMEOUT`으로 종료된다. 파싱 오류로 바뀌지 않는다. |
| 정상 완료 뒤 타이머 | 본문 처리까지 끝난 뒤 요청 타이머가 남지 않는다. |
| 실패 뒤 타이머 | 헤더 수신 전 실패, 본문 파싱 실패, timeout 종료 뒤 요청 타이머가 남지 않는다. |

타입 검사와 함께 `get`·`post`·`put`·`delete` 호출, 기본 URL·헤더, `APIError(status, code, message)` 형태와 화면 정책의 변경 여부를 대조했다. 보존 범위에 해당하는 변경은 없었다.

## Main에 넘기는 완료 판단과 한계

HTTP-07의 로컬 요청 계약은 충족됐다. 구현자 단계에서 남아 있던 공백은 위 직접 재현·수정·재확인으로 해소했으며, 추가 제품 결정이나 공개 API 변경을 요청할 사항은 없다.

외부 실서버 장애와 브라우저 UX는 확인하지 않았다. UI 정책 변경 없이 요청·본문 처리의 계약을 정비한 범위에서 완료를 권고한다. 배포 환경·브라우저 동작 전체의 검증으로 확대하지 않는다.

**Main 수락:** 이 권고를 받아 [Ticket](../ticket.md#main의-종료-결정)을 완료로 닫고, [HTTP 클라이언트 문서](../../../project/http-client.md)를 완료 계약에 맞춰 갱신했다. 이번 문제는 기존 계약을 만족하지 못한 구현의 빈틈이므로 일반 품질 기준에 새 의무를 추가하지 않았다.
