# HTTP-07 — 구현자에서 검토자로

> 가정된 구현/검토 결과. 아래는 가상 구현자의 인계 기록이며 실제 실행 로그가 아니다. 당시 보고와 미확인 범위를 보존한다. 현재 최종 결과는 [검토 기록](review.md)에 있다.

**본문 오류의 전달과 HTTP 상태 보존을 수정했다. 정상·오류 본문 장면과 타입 검사는 통과했으며, 느린 본문과 타이머 정리의 회귀 확인은 남아 있다.** 이 인계에서 작업 완료를 판정하지 않는다.

## 변경한 내용과 보존한 계약

변경 대상은 `src/api/fetcher.ts`와 그 동작을 확인하는 `src/api/fetcher.test.ts`다. 응답 본문을 반환하는 경로에서 `await`를 사용해, 본문 읽기·파싱의 rejection이 fetcher의 `catch`를 거치도록 했다. 본문 처리 오류를 기존 `APIError` 형태로 분류하고, 이미 받은 HTTP 상태를 파싱 실패 때문에 잃지 않도록 했다. 오류 본문이 객체라는 전제로 속성을 읽던 처리도 정비했다.

`get`·`post`·`put`·`delete` 호출, 정상 JSON·문자열 반환, 기본 URL·헤더, 10초 timeout 설정과 `APIError(status, code, message)` 형태는 유지했다. toast·이동은 사용처에 남겼으며 재시도·인증 이동·공통 toast·호출자 취소 기능은 추가하지 않았다.

판단의 출발점은 [Ticket의 보존 계약](../ticket.md#원래-요구와-보존할-것)과 [일반 기준의 공개 계약](../../../project/quality.md#public-contract)이다. 호출자가 내부 파싱 순서를 알아야 오류를 처리할 수 있는 상태를 고치는 데 범위를 두었다. 오류 서비스 전체를 확대할 필요는 없다고 판단했다. 현재 프로젝트 계약은 [HTTP 클라이언트](../../../project/http-client.md), 검토자의 직접 수정 절차는 [develop](../../../../.agents/skills/develop/SKILL.md)에 있다.

## 구현자가 확인한 결과

가정 환경에서 `pnpm exec vitest run src/api/fetcher.test.ts`로 아래 장면을 확인했고, `pnpm exec tsc --noEmit`도 통과했다. 이 예시 폴더에서 해당 명령을 실행한 것은 아니다.

| 장면 | 구현자가 보고한 결과 |
| --- | --- |
| 정상 JSON 응답 | 기존과 같은 JSON 값을 반환한다. |
| 정상 문자열 응답 | 기존과 같은 문자열을 반환한다. |
| HTTP 200과 깨진 JSON | 본문 파싱 실패가 공통 `catch`에 도달해 `APIError`로 전달된다. |
| HTTP 500과 깨진 JSON | `APIError`를 전달하면서 `status: 500`을 보존한다. |
| 비객체 오류 본문 | 본문의 속성 접근 때문에 별도 예외가 새지 않고, 기존 오류 형태로 전달된다. |

이 표는 구현자의 확인 보고다. 검토자는 보고와 변경 코드를 대조하고 필요한 장면을 직접 확인해야 한다.

## 검토자에게 넘기는 판단과 공백

본문 읽기가 오래 걸릴 때에도 10초 제한이 유지되는지, 정상 완료와 실패 뒤 타이머가 정리되는지는 아직 확인하지 않았다. 본문을 `await`하도록 바꾼 것이 기존 타이머의 수명과 어떤 관계를 만드는지 검토가 필요하다. 본문 읽기 중 timeout이 일반 파싱 실패로 바뀌지 않는지도 확인해 달라.

위 확인과 함께 기존 정상·오류 장면이 유지되는지 대조해 달라. 원래 계약 안에서 필요한 품질 수정은 직접 수행하고, 바뀐 부분과 재확인 결과를 Main에 전달한다. 새로운 공개 API나 화면 정책이 필요하다고 판단하면 그 이유와 영향을 Main이 다시 판단할 수 있게 남긴다.

외부 실서버 장애나 브라우저 UX는 확인하지 않았다. 이 인계는 로컬 요청 계약과 그 검토를 대상으로 한다.
