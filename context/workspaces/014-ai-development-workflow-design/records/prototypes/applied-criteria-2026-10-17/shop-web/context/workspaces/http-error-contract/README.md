# HTTP-07 — 공통 fetcher 오류 계약 정비

> 가정된 구현/검토 결과. 가상 프로젝트 `shop-web`에서 작업이 완료된 상태를 보여 주는 문서 예시다. 이 폴더에는 실제 구현·테스트 파일이나 실행 결과가 없다.

**상태: 완료.** 본문 읽기·파싱 실패를 기존 `APIError`로 전달하고, 깨진 오류 본문에서도 HTTP 상태를 보존한다. 10초 제한은 본문 처리가 끝날 때까지 적용하며, 요청이 끝나거나 실패하면 타이머를 정리한다. Main은 검토자의 직접 수정과 재확인 결과를 받아 이 작업을 닫았다.

`get`·`post`·`put`·`delete` 호출, 정상 JSON·문자열 반환, 기본 URL·헤더, `APIError(status, code, message)` 형태는 유지했다. 화면의 toast와 이동은 사용처가 계속 맡는다.

## 결과를 확인하거나 이어서 판단할 때

- [Ticket](ticket.md): 원래 요구, 보존할 계약, 완료 판단과 남은 확인 범위.
- [구현자 → 검토자 인계](records/implementation.md): 본문 오류 처리 변경과 구현자가 확인한 장면. 느린 본문과 타이머 정리는 당시 미확인이다.
- [검토자 → Main 결과](records/review.md): 검토자가 재현한 타이머 문제, 직접 수정, 수정 뒤 확인과 완료 권고.

현재 프로젝트의 HTTP 계약은 [HTTP 클라이언트 문서](../../project/http-client.md)가 소유한다. 이번 완료 결과에 맞춰 갱신됐으며, 위 인계 기록은 각 단계 당시의 상태를 보존한다. 유지·수정 판단에 사용한 일반 기준은 [공개 계약](../../project/quality.md#public-contract), 구현과 직접 수정 검토의 절차는 [develop](../../../.agents/skills/develop/SKILL.md)에서 찾는다.

외부 실서버 장애와 브라우저 UX는 확인하지 않았다. UI 변경 없이 로컬 요청 계약을 정비한 이번 범위의 완료이며, 배포 환경과 화면 동작까지 검증했다는 의미는 아니다. 재시도·인증 이동·공통 toast·호출자 취소 확장은 포함하지 않았다.
