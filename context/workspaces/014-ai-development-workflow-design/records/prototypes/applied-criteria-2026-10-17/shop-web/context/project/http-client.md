# 공통 HTTP 클라이언트 계약

이 문서는 HTTP-07 반영 뒤 `src/api/fetcher.ts`를 사용하는 코드가 따르는 현재 계약이다. 구현·검토 과정과 검사 결과는 [HTTP-07 Workspace](../workspaces/http-error-contract/README.md)가 소유한다.

## 요청과 정상 응답

`get`·`post`·`put`·`delete` 호출 방식을 유지한다. 기본 URL과 기본 헤더는 기존 설정을 사용하며, HTTP-07에서 변경하지 않았다. 정상 응답은 기존 방식대로 JSON이면 파싱한 값, 문자열 본문이면 문자열로 반환한다.

공통 클라이언트는 전송, 응답 본문 해석, 오류 전달과 10초 timeout을 맡는다. 상품 가공과 페이지 규칙, 오류를 어떤 토스트로 표시할지, 실패나 성공 뒤 어느 화면으로 이동할지는 사용처가 맡는다.

## 오류의 형태와 의미

기존 `APIError(status, code, message)` 형태를 유지한다. 본문 읽기와 JSON 파싱에서 발생한 실패도 이 형태로 전달한다. 사용처가 본문 처리의 내부 순서를 알아야 오류를 잡을 수 있는 경로를 두지 않는다.

| 상황 | 사용처에 전달할 의미 |
| --- | --- |
| 본문을 정상적으로 읽은 HTTP 실패 | 기존 HTTP 상태와 오류 code·message를 보존한다. |
| 성공 HTTP 응답의 본문 읽기 또는 JSON 파싱 실패 | `APIError`로 전달하며, 네트워크 연결 실패와 본문 처리 실패를 구별한다. |
| HTTP 500을 받은 뒤 본문 파싱도 실패 | `status`는 500을 유지한다. 본문을 해석하지 못했다는 이유로 이미 받은 HTTP 상태를 버리지 않는다. |
| 실패 본문이 `null` 등 예상 객체 형태가 아님 | message·code를 꺼내는 과정에서 별도 예외가 발생하여 공통 오류 전달을 벗어나지 않게 한다. |
| 응답 본문을 읽던 중 10초가 지남 | `code`가 `TIMEOUT`인 `APIError`로 전달한다. 이를 일반 파싱 실패로 바꾸지 않는다. |

공통 형태를 유지하기 위해 서로 다른 실패의 의미를 모두 네트워크 오류로 바꾸지 않는다. 이미 확보한 HTTP 정보와 실패가 발생한 단계는 오류를 해석하는 데 필요한 근거로 보존한다.

## timeout과 자원 정리

10초 timeout은 요청을 시작할 때부터 응답 본문 처리가 끝날 때까지 적용된다. 헤더를 받은 직후 timer를 해제하지 않는다. 본문이 느리게 도착하는 동안에도 시간 제한이 유지되어야 한다.

정상 완료와 실패 모두에서 요청에 사용한 timer가 정리된다. 오류를 변환하는 경로와 자원 정리 경로를 함께 확인하여 완료된 요청의 timer가 남거나, 본문 처리 중 먼저 해제되는 일이 없게 한다.

## 지원 범위와 미정 사항

위 계약에서 화면 이동과 토스트 결정은 사용처의 책임이다. 자동 재시도와 호출자 취소의 기존 지원 여부는 이 가상 사례의 전제에서 정하지 않았다. 이 기능이 필요한 작업은 기존 API와 동작을 먼저 확인해야 하며, 이 문서만으로 지원·미지원을 단정하지 않는다.

HTTP-07에서 추가하거나 확장하지 않을 기능은 [Ticket의 제외 범위](../workspaces/http-error-contract/ticket.md#원래-요구와-보존할-것)가 소유한다. 이번 작업에서 제외했다는 사실은 현재 제품의 미지원을 뜻하지 않는다.

## 검사 방법

프로젝트 루트에서 HTTP 동작 검사는 `pnpm exec vitest run src/api/fetcher.test.ts`, 타입 검사는 `pnpm exec tsc --noEmit`으로 수행한다. 이 가상 프로젝트에 Vitest·TypeScript가 설정되어 있다는 전제다. 자동 검사로 요청 계약을 확인하며, 화면 정책을 바꾸는 작업은 관련 UI 흐름도 별도로 확인한다.

관련 판단 기준은 [공통 계약의 신뢰](quality.md#public-contract)다. 이번 작업의 수행 결과는  [구현 기록](../workspaces/http-error-contract/records/implementation.md)과 [검토 기록](../workspaces/http-error-contract/records/review.md)에서 확인한다.
