# 장바구니 주문 후 쿠폰 목록 갱신

> 가상 작업의 구현 전 상태. 실제 제품 코드·수정·검사 결과는 없으며, 문서를 찾아 판단하는 형태를 보여 주는 시안이다.

**상태: 작업 요구와 현재 동작을 읽고 변경안을 판단하는 단계.** PC·모바일 주문 페이지와 빠른 주문 모달에서 주문에 사용한 쿠폰이 목록에 남는 문제를 다룬다. 세 화면은 모두 같은 장바구니 전체 주문이며, coupons 무효화 누락을 수정 대상으로 가정했다. 구현·검토 완료는 아직 없다.

## 이 작업을 이어받을 때

[Ticket](ticket.md)에서 목표·보존할 동작·수정 범위와 확인할 사항을 읽고 [현재 주문 동작](../../project/order-workflow.md)을 실제 코드·호출부와 대조한다. 맡은 역할은 같은 작업 경로와 함께 전달받은 [develop](../../../.agents/skills/develop/SKILL.md)를 따른다.

공통 관점과 상세·사례를 선택하는 안내는 [Project 읽기 경로](../../project/README.md#reading-route)가 소유한다. 이 작업에서는 같은 흐름의 공유 범위, 캐시·장바구니·화면의 책임, 호출과 완료, 새 이름이 전달하는 의미가 판단 후보다. 모든 상세와 과거 사례를 읽었다는 사실을 완료 조건으로 삼지 않는다.

이 문서와 Ticket을 실제로 전달받아 어떤 의문에서 상세를 여는지, 구현 전 어떤 판단을 돌려주는지는 [주문 적용 장면](../../../../order-walkthrough.md)에서 볼 수 있다. 그 장면의 변경안도 구현 결과가 아니다. 구현·검토 기록과 현재 제품 계약은 실제로 확인한 결과가 생길 때 갱신한다.
