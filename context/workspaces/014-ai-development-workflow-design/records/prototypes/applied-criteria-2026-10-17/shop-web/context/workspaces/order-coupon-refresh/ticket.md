# 장바구니 주문 후 쿠폰 목록 갱신

> 가상 작업 요구. 실제 구현·검사·완료 결과가 없는 상태에서 판단에 필요한 입력을 채운 예시다.

**상태: 구현 전.** 이번 목표는 주문 성공 뒤 사용한 쿠폰이 목록에 남는 문제를 해결하는 것이다. PC·모바일 주문 페이지와 빠른 주문 모달 모두 현재 장바구니 전체를 주문하며, coupons 캐시 무효화 누락이 원인이라고 가정한다. 실제 작업에서는 문서의 가정과 코드·호출부를 대조한다.

## 바꿀 것과 보존할 것

세 화면의 주문 성공 처리에서 누락된 쿠폰 갱신을 보완한다. 같은 업무 흐름의 반복을 함께 정리할지는 이번 수정과의 직접 관련성, 같은 정책의 변경 위치를 줄이는 이득, 연결·추가 계약·확인 비용을 비교한다. 공통 Hook 도입이나 특정 이름 자체가 완료 조건은 아니다.

현재 orders·catalog 무효화 호출, 장바구니 정리, 화면별 이동·모달 완료 방식은 보존한다. 캐시 무효화 완료를 기다리지 않는 현재 흐름도 유지한다. 이 조건과 미지정된 실패·입력·로딩의 세부 사항은 [현재 주문 동작](../../project/order-workflow.md)에 있다. 코드에서 다른 상태가 확인되면 차이와 영향을 먼저 판단한다.

다른 주문 종류의 통합, 새로운 화면 완료·대기 정책, 제품 전체 리팩터링은 이번 목표에 포함하지 않는다. 관련 기준의 읽기 경로는 [Project 안내](../../project/README.md#reading-route), 구현과 직접 수정 검토의 절차는 [develop](../../../.agents/skills/develop/SKILL.md)가 소유한다.

## 완료를 판단하려면 확인할 것

아래는 필요한 확인이며 현재 결과는 모두 미실행이다. 구체적인 검사 방법과 실패·로딩의 보존 대상은 실제 구현 환경·코드에 맞춰 정한다.

| 확인할 동작 | 현재 상태 |
| --- | --- |
| 세 화면의 성공 처리에서 coupons 무효화가 호출되고 사용한 쿠폰이 실제 목록에 반영된다. | 미실행. 호출 추가와 사용자에게 보이는 반영을 구별해 확인해야 한다. |
| orders·catalog 처리와 장바구니 정리가 유지된다. | 미실행. 공통화하면 세 사용처의 연결을 함께 대조해야 한다. |
| 화면별 완료 방식과 캐시 갱신을 기다리지 않는 흐름이 유지된다. | 미실행. 호출과 완료 순서의 의미를 구별해야 한다. |
| 기존 실패·입력·로딩 동작을 의도하지 않게 바꾸지 않는다. | 미실행. 상세 정책은 실제 코드·동작에서 먼저 확인해야 한다. |

구현자는 바꿀 책임·보존할 계약과 선택 이유를 남기고, 검토자는 같은 Ticket·현재 계약·변경 결과를 대조한다. 이 문서에 계획이 있다는 이유로 검사 통과나 작업 완료를 기록하지 않는다.
