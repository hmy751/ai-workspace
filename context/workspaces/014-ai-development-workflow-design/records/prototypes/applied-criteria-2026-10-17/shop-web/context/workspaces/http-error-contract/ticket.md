# HTTP-07 — 공통 fetcher 오류 계약 정비

> 가정된 구현/검토 결과. 아래 요구·처리 결과·완료 판단은 가상 프로젝트의 완료된 작업 예시이며, 실제 코드 수정이나 명령 실행을 기록한 것이 아니다.

**상태: 완료. Main이 검토자의 직접 수정과 재확인 결과를 받아 종료했다.**

## 원래 요구와 보존할 것

`src/api/fetcher.ts`에서 응답 본문을 읽거나 파싱하다 실패해도 호출자가 기존 오류 계약으로 처리할 수 있게 한다. 서버가 HTTP 500을 반환했는데 본문까지 깨진 경우, 파싱 오류 때문에 서버의 상태 정보가 사라지지 않아야 한다. 10초 timeout은 응답 헤더 수신에서 끝나지 않고 본문 처리까지 포함한다.

이번 작업에서 보존할 계약은 다음과 같다.

- `get`·`post`·`put`·`delete`의 호출 방식, 정상 JSON·문자열 반환.
- 기본 URL·헤더와 10초 timeout 설정.
- 기존 `APIError(status, code, message)` 형태. 본문 읽기·파싱 실패도 이 형태로 전달한다.
- 화면 toast와 이동은 사용처가 결정한다.

재시도, 인증 이동, 공통 toast, 호출자 취소 기능의 확장은 제외한다. 오류 클래스나 공개 API를 새로 설계하는 작업도 포함하지 않는다.

프로젝트 계약의 정본은 [HTTP 클라이언트](../../project/http-client.md), 일반 판단 기준은 [공개 계약](../../project/quality.md#public-contract)이다. 이 Ticket은 그 기준을 이번 오류 처리와 타이머 수명에 적용한다. 새로운 범용 의무 규칙을 정의하지 않는다.

## 완료 조건과 최종 판단

| 완료 조건 | 최종 결과와 근거 |
| --- | --- |
| 정상 JSON·문자열 반환과 기존 호출 계약을 유지한다. | 구현 후 검토자가 기존 장면을 다시 확인했다. [검토 결과](records/review.md#수정-뒤-확인) |
| 본문 읽기·파싱 실패를 `APIError`로 전달한다. | 200의 깨진 JSON과 비객체 오류 본문을 확인했다. 본문 읽기 실패는 느린 본문의 timeout 장면에서도 확인했다. |
| HTTP 500과 깨진 본문이 함께 오면 `status: 500`을 보존한다. | 검토자가 동일 장면을 다시 확인했다. 파싱 실패가 HTTP 상태를 덮지 않았다. |
| 본문 읽기 중 시간 초과는 `code: TIMEOUT`으로 구별한다. | 검토자가 느린 본문에서 문제를 재현하고 직접 수정한 뒤 확인했다. 파싱 오류 분류가 timeout을 덮지 않았다. |
| 정상 완료와 실패 뒤 요청 타이머를 정리한다. | 본문을 `await`하는 `try`의 `finally`에서 정리하도록 검토자가 수정했다. 완료·실패 경로를 확인했다. |
| 타입 검사를 통과하고 화면 정책을 공통 계층에 추가하지 않는다. | 타입 검사 통과와 변경 범위 대조를 검토자가 보고했다. |

## 실제로 오간 작업 결과

구현자는 본문 처리의 rejection이 공통 `catch`에 도달하도록 `await`를 추가하고 오류 분류·HTTP 상태 보존·비객체 본문 처리를 정비했다. 정상·오류 장면을 확인했으나 느린 본문과 타이머 정리는 확인하지 못했다. 그 상태와 검토 요청을 [구현자 인계](records/implementation.md)에 남겼다.

검토자는 구현자의 보고를 검토 입력으로 받아, 헤더 직후 타이머가 해제되는 코드와 헤더 수신 전 실패의 정리 누락을 직접 재현했다. 공개 계약을 유지하는 범위에서 타이머 정리를 `finally`로 옮기고 관련 장면을 재확인했다. [검토자 결과](records/review.md)는 구현자 보고와 구별되는 재현·수정 근거다.

## Main의 종료 결정

Main은 오류 계약과 본문까지 포함한 timeout이 성립하고, 검토자의 수정이 원래 보존·제외 범위 안에 있다는 결과를 받아 HTTP-07을 완료로 판단했다. [HTTP 클라이언트 문서](../../project/http-client.md)는 완료 후 계약에 맞춰 갱신했다. 일반 품질 기준과 개발 절차에는 새 의무를 추가하지 않았다.

외부 실서버 장애와 브라우저 UX는 미확인이다. 이번 변경은 화면 정책을 바꾸지 않는 로컬 요청 계약 정비이므로 그 확인을 이 Ticket의 종료 조건으로 추가하지 않았다. 외부 환경이나 화면에서 별도 증상이 발견되면 해당 현상과 범위를 새로 판단한다.
