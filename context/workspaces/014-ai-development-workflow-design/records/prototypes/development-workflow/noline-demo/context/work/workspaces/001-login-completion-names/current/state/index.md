# 현재 상태

현재 실행 예제는 `signInAndRequestRefresh`와 `onSignedIn`을 사용한다. 기기 저장·인증 상태 적용을 기다리고 후속 조회를 요청하지만 결과는 기다리지 않는다. Login은 ‘로그인 완료’를 알리고 이동을 시작하며 Reauth는 닫기를 시작한다.

[같은 코드의 유지·개명 비교](../../records/2026-10-19-06-naming-alternatives.md)에서 현재 선택과 유지 대안의 이득·비용을 볼 수 있다. 두 안은 이름 두 쌍 외에 주석과 동작이 같다. 이 Work의 선택이며 모든 Project의 명명 규칙은 아니다.

## 확인한 것과 남은 범위

Node.js 동작 검사 7개와 정상·조회 실패 데모를 실행했다. 저장 전 상태 보존, 조회 비대기 완료, 저장 실패와 후속 조회 실패의 구별을 메모리 기반 예제에서 확인했다. [실행 기록](../../records/2026-10-19-03-execution.md)은 당시 결과와 한계, [초기 검토](../../records/2026-10-19-04-review.md)는 그때의 내용·동작 검토를 보존한다. 현재 실행 명령은 [demo 안내](../../../../../../README.md#직접-실행한다)에 있다.

실제 UI·서버·DB·queue 조율, 동시 세션 변경, 저장 중 부분 실패·복구, callback 예외 처리는 확인하지 않았다. 실제품 통합이나 사용자 수락까지 완료한 상태는 아니다. 문서의 후속 보완은 이 동작 검사에 대한 추가 실행 증거가 아니다.

## 이어갈 때

조회 결과까지 기다릴 요구가 생기면 Project의 완료 계약과 소비자의 대기·실패 처리를 먼저 재판단한다. 실제 저장소를 붙이면 부분 실패·복구를 포함한 어댑터 계약과 검사 범위를 추가한다. 표현 보완이라면 관련 본문과 사용처를 고치되 동작 변경을 섞지 않는다.

목표·제약·선택은 [memory](../memory/index.md), 시작 조건은 [source](../../source/index.md), 현재 결과 파일은 [output](../../output/index.md)에서 찾는다.
