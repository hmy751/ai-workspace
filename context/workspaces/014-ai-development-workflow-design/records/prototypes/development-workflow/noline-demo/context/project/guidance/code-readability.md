# 인증 코드에서 이름과 완료 표현을 맞춘다

이 Project의 인증·세션 함수, 상태, callback, 로그와 안내 문구를 만들거나 고칠 때 적용한다. 호출자가 책임과 보장 결과를 오인하지 않도록 표현한다. 특정 함수명을 모든 작업의 정답으로 정하지 않는다.

## 부분 저장과 전체 세션 변경을 구별한다

Auth Store는 귀속 검사·기기 저장·인증 상태 적용을 맡고, 전체 세션 변경 서비스는 진행 중 작업의 종료와 본작업을 조율한다. Store의 부분 action에 전체 세션 변경을 마쳤다는 뜻을 붙이지 않는다. 서비스가 전체 절차를 책임진다면 내부 단계 수와 관계없이 해당 업무 이름을 사용할 수 있다.

호출 경로를 바꿀 때는 명칭뿐 아니라 실제로 거쳐야 하는 절차를 확인한다. 순서와 실패 시 보존할 결과는 [인증·세션 계약](authentication-and-session.md)이 정한다. 연결점만 만들어 둔 실행 예시를 완성된 제품 조율기로 표현하지 않는다.

## 완료 표현을 소비자의 다음 동작과 대조한다

이 Project의 인증 완료는 기기 저장·인증 상태 적용을 마친 결과다. Query 갱신 요청, 재조회 완료, 화면 반영 완료는 별도 결과다. 반환값·callback·로그·사용자 안내가 각각 어떤 결과를 전달하는지 일치시킨다.

후속 조회를 기다리지 않는 경로에서는 인증 완료를 화면 준비 완료로 설명하지 않는다. 조회 결과까지 필요한 경로라면 해당 대기·실패 계약을 확인한다. 이름을 맞추기 위해 모든 후속 처리를 기다리게 바꾸지는 않는다.

완료 알림을 받은 소비자가 지금 무엇을 해도 되는지 실제 동작과 대조한다. 개발자에게 필요한 대기·실패 계약은 코드 가까이 설명하고, 사용자 안내에는 사용자에게 필요한 결과를 말한다. 구현 단계를 나열하는 것으로 안내 문구를 대신하지 않는다.

## 변경의 필요와 비용도 확인한다

표현 정리는 현재 약속한 결과를 더 정확히 알리는 변경이다. 내부 사용처가 적고 오해가 실제 동작에 영향을 준다면 개명이 유효할 수 있다. 공개 API 호환성이 필요하거나 가까운 계약으로 의미가 충분히 드러난다면 이름 유지와 설명 보완이 적절할 수도 있다. 실제 약속을 구현이 지키지 못한다면 이름만 좁혀 해결한 것으로 처리하지 않는다.

저장·상태 적용 이후 조회 실패는 인증 저장 실패와 구별한다. 오류 처리 위치·로그가 성공한 인증을 실패로 설명하지 않는지 본다. 제품 결과를 바꿀 필요가 있으면 표현 정리와 분리해 이유·영향을 판단한다.

현재 코드·사용처는 [인증 흐름](../current/authentication-flow.md), 이번 작업에서 선택한 이름과 비용 판단은 Work 기록에 있다. 그 선택을 이 가이드의 고정 이름 규칙으로 올리지 않는다.
