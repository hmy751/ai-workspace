# 본문과 형성 자료의 관리 원칙

현재 사용하는 내용을 충분히 설명하면서, 나중에 그 내용을 고칠 때 필요한 의도·배경·선택 이유가 유실되지 않도록 함께 관리한다. 본문을 만든 맥락이 작업 기록에만 흩어져 있으면 다음 작업자는 현재 문장이 왜 남았는지 복원하기 어렵다. 주제 가까이에 필요한 형성 자료를 두되, 평소 내용을 사용하는 경로와 구별한다.

이 문서는 **이 데모의 context 안에서 본문과 그 형성 자료를 구성·수정하는 공통 원칙**을 소유한다. 새 주제 묶음을 만들거나 기존 묶음의 구성·의미를 바꿀 때 읽는다. 개인 기준, 제품 계약, 작업 문서 중 어느 영역의 내용인지는 [context 진입점](README.md)의 Personal·Project·Work 구분을 따른다. 여기의 원칙을 적용한다고 내용의 소유 영역이 바뀌지는 않는다.

## 본문 역할과 형성 자료를 구별한다

| 구분 | 맡는 내용 | 읽는 목적 |
| --- | --- | --- |
| 본문과 나누어 둔 본문 | 현재 유효한 기준·설명·계약·절차와 이를 사용하는 데 필요한 상세 | 현재 내용을 이해하고 적용한다. |
| 형성 자료 | 본문을 이루게 한 의도·배경·목적, 중요한 논의와 선택, 필요한 원문·관찰 | 현재 방향을 더 정확히 이해하거나 수정·재검토한다. |

사례, 상세 설명, 조건별 절차처럼 **본문 역할을 하는 내용을 따로 나누어도 본문과 같은 층에 둔다.** 사례는 그중 한 종류이며 필수 문서가 아니다. 짧은 사례나 상세는 본문 안에 둘 수 있고, 나누는 편이 읽기·적용에 도움이 될 때 별도 파일로 만든다. 파일을 나눴다는 이유나 가끔 읽는다는 이유로 형성 자료가 되지는 않는다.

일상 적용에 필요한 이유·조건·예외는 시작 본문과 필요한 별도 본문에서 설명한다. 형성 자료를 확인해야만 현재 내용을 적용할 수 있게 만들지 않는다. 형성 자료에는 현재 요구를 만들게 된 문제와 선택의 관계를 남긴다.

## 주제 단위로 묶고 관계를 이름과 링크에 드러낸다

하나의 주제에 속하는 본문과 형성 자료를 같은 폴더에 묶는다. 주제의 `README.md`는 이 묶음의 범위·구성과 읽기 경로를 안내한다. 시작 본문은 `index.md`로 두며, 제목과 첫 설명에서 다루는 내용과 연결된 분할 본문의 읽을 조건을 밝힌다. `index.md`는 실제 내용을 설명하는 본문이며 파일 목록만 나열하는 색인으로 대신하지 않는다.

본문에서 나눈 문서는 `index.<내용을 드러내는 이름>.md`처럼 연결한다. 예를 들어 상세 설명은 `index.details.md`, 사례는 `index.cases.md`로 둘 수 있다. 접미사는 실제 내용에 맞게 고르며 둘 다 만들 필요는 없다. 각 문서는 맡는 내용을 설명하고 시작 본문으로 돌아가는 링크를 둔다.

```text
주제/
├── README.md                     주제 구성·두 층의 역할과 읽기 안내
├── index.md                       시작 본문
├── index.<내용 이름>.md           필요할 때 나누어 둔 본문
└── background/
    ├── README.md                  형성 자료의 역할과 질문별 읽기 안내
    ├── context.md                 현재 이해할 형성 맥락
    ├── records/                   이 주제의 형성과 변경 기록
    └── evidence.md                필요한 원문·관찰·출처
```

형성 자료는 `background/`에서 찾게 한다. 현재 맥락·당시 기록·근거의 책임은 처음부터 구별하며, 기록이 많아질 때까지 맥락에 누적한 뒤 나누는 방식으로 미루지 않는다. 실제 보존할 내용이 있을 때 해당 파일·기록을 작성하고, 형식을 채우기 위한 빈 파일은 만들지 않는다.

주제보다 상위의 README는 해당 영역의 구성과 관리 안내를 맡는다. 주제의 시작 본문을 index로 둔다는 이유로 모든 README를 바꾸거나, 기존 Project·Work의 문서 체계까지 일괄 재배치하지 않는다.

## 두 층의 입구에서 역할을 먼저 설명하고 읽을 조건을 안내한다

`background/`는 본문을 형성한 의도·배경·목적, 중요한 논의와 선택, 이를 뒷받침하는 근거를 가까이 보존하는 층이다. 시간이 지나도 현재 내용이 왜 이렇게 구성됐는지 복원하고, 더 정확히 이해하거나 수정·재검토할 수 있게 한다. 처음 읽는 사람이나 새 세션도 이를 알 수 있도록 **주제의 `README.md`와 `background/README.md` 양쪽에서 이 역할을 먼저 설명한 뒤 읽을 조건을 안내한다.**

주제의 `README.md`에는 본문과 형성 자료 각각의 역할을 설명하고, 현재 적용에는 `index.md`와 필요한 분할 본문을, 형성 의도 확인·의미 변경·과거 선택 재검토에는 `background/README.md`를 읽도록 연결한다. 주제 README는 묶음의 안내를, `index.md`는 현재 사용하는 내용의 설명을 맡는다. 본문에서 필요한 형성 자료를 직접 연결할 수 있으며, 주제 전체의 안내를 본문에 반복할 필요는 없다.

`background/`를 구성할 때는 `README.md`에 형성 자료의 역할과 대상 본문을 밝히고, **그 주제에서 생길 질문에 맞춰 실제 자료의 읽을 범위를 안내한다.** 현재 선택의 목적과 이유는 관련 `context.md` 설명으로, 당시 대안·정정·유보는 해당 기록으로, 정확한 발화·관찰은 해당 근거 항목으로 연결한다. 파일 목록만 나열하거나 폴더 안의 모든 자료를 순서대로 읽게 하지 않는다. 과거 기록과 원문에는 이전 선택이나 미채택 제안도 포함될 수 있음을 알리고, 현재 적용할 내용은 본문에서 찾게 한다.

공통 구성·보존·갱신 원칙은 이 문서가 소유한다. 두 README는 각 층에서 필요한 안내를 맡으며, 본문이나 `context.md`의 형성 맥락 설명, 공통 원칙 전체를 복제하지 않는다. 개별 자료에 바로 들어와도 역할을 알 수 있도록 각 자료 첫머리에 맡는 내용과 대상 본문 링크를 둔다. 필요한 자료를 이미 찾았다면 README를 반드시 다시 거치게 하지 않는다.

## 형성 맥락·기록·근거는 서로 다른 질문에 답한다

**`background/context.md`는 지금의 내용을 이해할 수 있는 설명이다.** 무엇을 이루려는지, 어떤 문제와 배경에서 필요해졌는지, 왜 현재 선택이 남았는지를 연결해 쓴다. 의도·배경·목적은 가능한 한 담되 고정된 세 제목으로 채울 필요는 없다. 확인한 의도와 작성자의 해석을 구별하고, 알 수 없는 과거 의도를 만들어 넣지 않는다. 중요한 방향 전환과 아직 열린 판단도 현재 설명에 필요한 만큼 포함한다.

**`background/records/`는 이 주제의 형성과 변경 기록이다.** 현재 설명만으로는 복원하기 어려운 논의·선택·정정·유보와 그 이유를 남긴다. 기록을 읽으면 당시 문제와 조건, 검토한 대안, 선택하거나 남겨 둔 것, 확인·반영한 범위를 알 수 있어야 한다. 확정된 결정만 기록할 수 있는 것은 아니며, 모든 대화·편집·진행 보고를 누적하는 것도 아니다.

과거 선택이 실제로 실패한 것인지, 위험을 예상해 채택하지 않은 것인지, 조건이 달라져 교체한 것인지를 구별한다. 그 선택을 다시 검토할 조건이 알려져 있다면 함께 남긴다. 새 판단이 생기면 관련 기록을 연결해 무엇이 바뀌었는지 설명하며, 당시 이유를 새 결론에 맞춰 덮어쓰지 않는다. 현재 맥락에는 지금의 방향을 설명하는 전환 이유를 요약한다.

**`background/evidence.md`는 설명과 기록을 확인할 원자료를 맡는다.** 필요한 발화·관찰·출처를 선별하고, 시점·당시 조건·확인 한계를 그 의미를 판단할 만큼 남긴다. 정확한 문구나 뉘앙스가 판단 근거라면 링크만 두지 않고 최소 발췌도 보존한다. 추가 확인 역할인 안정적인 외부 자료는 링크로 연결할 수 있다. 긴 원자료는 별도 보존 위치를 가리키되, 그 자료 없이도 현재 판단의 핵심 근거를 이해할 수 있게 한다.

맥락을 기록의 목차로 대신하거나 기록마다 맥락과 발췌 전체를 복제하지 않는다. 맥락의 해당 판단에서 필요한 기록·근거 항목으로 연결하고, 기록에서는 관련 본문·근거를 찾을 수 있게 한다. 작업 전체의 기록을 이 폴더에 복제하지 않고, 해당 주제의 이해·수정에 필요한 맥락과 근거를 선별한다. 실제 작성 논의를 제품 사건이나 팀의 합의로 바꾸어 서술하지 않는다.

## 필요한 범위만 읽고 함께 갱신한다

본문을 변경하는 작업자가 관련 자료의 영향을 확인하고 같은 작업에서 필요한 내용을 맞춘다. 파일이 가까이 있거나 링크가 연결돼 있다는 사실만으로 이 책임이 수행된 것은 아니다.

| 하려는 일 또는 달라진 것 | 읽고 처리할 범위 |
| --- | --- |
| 현재 내용을 사용한다. | 시작 본문과 필요한 상세·절차·사례를 고른다. 형성 자료 전체를 기본 입력으로 만들지 않는다. |
| 의미·우선순위·적용 조건을 바꾸거나 현재 문장만으로 의도를 확신하기 어렵다. | 관련 형성 맥락과 필요한 기록·근거를 읽는다. 영향받는 본문과 나눈 문서, 현재 맥락을 함께 맞추고 보존할 판단 변화는 기록에 남긴다. |
| 과거 선택을 되돌리거나 새 근거가 기존 판단과 충돌한다. | 당시 조건과 선택 이유, 새 근거의 범위를 대조한다. 바뀐 사실·해석·선택과 남은 불확실성을 구별한다. 과거 원문을 수정하거나 최신 관찰을 자동으로 우선하지 않는다. |
| 뜻이 같은 문장·오탈자를 고친다. | 해당 부분을 고친다. 모든 자료의 날짜나 문구를 형식상 함께 갱신하지 않는다. |
| 자료를 추가·분할·이동·개명하거나 읽을 조건을 바꾼다. | 들어오는 링크와 주제 README·background README의 관련 읽기 안내를 맞춘다. 표시 사본이 있다면 함께 갱신한다. 위치 변경을 내용에 관한 새 합의로 기록하지 않는다. |

새 근거는 출처를 구별해 추가한다. 잘못 옮긴 발췌나 기록상의 사실 오류를 발견하면 원자료와 대조해 정정하고, 무엇을 바로잡았는지 남긴다. 이 정정과 과거 판단을 새 결론으로 다시 쓰는 일을 구별한다.

## 내용의 책임과 확인 범위를 유지한다

Personal의 개인 기준, Project의 제품 의미·지속 계약, Work의 이번 적용·진행·결과는 각각의 영역이 소유한다. 개인 기준이 바뀌면 적용 중인 Work의 선택에 영향이 있는지 살피고, Project는 자기 계약·규약·구현 사실이 달라지는 경우에 갱신한다. 필요한 설명을 다른 문서에서 다시 풀어 쓸 수 있지만, 동일한 기준을 독립된 정본으로 여러 곳에서 관리하지 않는다.

작업자는 요청받은 범위에서 관계를 유지한다. 편집했다는 사실이 기준의 채택 권한을 새로 주지는 않으며, 이미 요청받은 수정에 반복 승인을 요구하는 절차도 아니다. 현재 요구·근거·작업 권한으로 해결할 수 없는 충돌은 영향을 받는 판단과 함께 열린 문제로 남긴다.

변경을 마칠 때는 주제 README와 시작 본문에서 필요한 자료를 찾을 수 있는지, 본문이 권하는 행동과 맥락이 설명하는 이유·범위가 맞는지, 근거가 그 설명을 실제로 뒷받침하는지 확인한다. 본문만 바뀌었다는 사실로 맥락이 낡았다고 단정하거나, 최근 수정된 파일을 무조건 정답으로 삼지 않는다.
