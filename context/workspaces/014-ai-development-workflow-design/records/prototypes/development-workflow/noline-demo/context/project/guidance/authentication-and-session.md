# 로그인 완료와 후속 조회의 개발 계약

로그인·재인증의 순서, 성공·실패 전달, 후속 조회와 완료 알림을 바꿀 때 읽는다. 로그인은 서버의 인증 응답을 받은 것만으로 끝나지 않는다. 기기 저장·상태 공개·실패 경계는 Noline 보존 문서에서 가져왔으며 비대기 wrapper와 callback 구성은 이 프로토타입에서 선택한 동작이다.

## 기기 저장 뒤에 인증 상태를 공개한다

기존 계정과 DB·queue의 귀속을 확인하고 세션을 기기에 저장한 뒤 새 인증 수단과 `signed-in` 상태를 공개한다. 저장에 실패하면 이전 인증 상태와 로컬 데이터를 보존한다. 저장 성공 전에 인증 완료 callback을 호출하지 않는다.

Auth Store는 귀속 검사·저장·상태 적용을 맡는다. 전체 세션 변경 서비스는 진행 중인 sync·cleanup·접수된 DB 작업의 종료와 본작업을 조율한다. 부분 Store action을 전체 조율을 거친 로그인 진입점으로 간주하지 않는다. 같은 계정의 데이터를 보존하는 이유는 [제품 의미](../common/device-session.md)에 있다.

이 실행 예시는 계정 ID와 메모리 여행 목록의 귀속만 직접 검사한다. 전체 DB·queue 검사는 구현하지 않았으며 서비스의 `waitForActiveWork`는 종료 대기를 연결할 위치다. 이 경계가 있다는 사실만으로 실제품 조율기가 갖춰졌다고 보지 않는다.

## 인증 이후 조회는 별도의 결과를 갖는다

저장·상태 적용 뒤 Query 갱신이 실패해도 인증은 복구된 상태다. 이 실패를 인증 저장 실패로 재분류하거나 완료된 인증을 되돌리지 않는다. 후속 실패를 받는 책임을 호출 경계에서 드러낸다.

현재 예시는 로그인 서비스가 끝나면 wrapper가 Query 갱신을 요청하고, 재조회 완료를 기다리지 않고 `onSignedIn`을 호출한다. 조회 실패는 `onRefreshError`가 받는다. Query 요청 함수가 즉시 던진 오류도 이 후속 실패 경로에 전달한다. 이 동기 오류 처리는 이번 실행 코드를 만들면서 추가한 선택이다.

두 callback은 오류를 처리하고 정상 반환하는 계약이다. callback이 던지는 오류, 저장 어댑터의 부분 저장 실패, 동시 세션 변경은 이 예시의 보장 범위 밖이다. 실제 어댑터로 바꾼다면 그 경계를 별도로 구현·검사한다.

따라서 wrapper 성공은 인증 적용과 갱신 요청 시도까지를 뜻한다. Query 결과·화면 이동·렌더링 완료는 보장하지 않는다. 요청 시작 자체가 실패하면 별도 후속 오류를 알리면서 인증 완료는 전달한다. 조회 결과까지 기다릴 요구가 생기면 서비스 이름뿐 아니라 대기·실패·소비자 동작을 함께 재판단한다.

## 바꾼 경계를 직접 확인한다

저장 전에는 새 상태와 완료 알림이 공개되지 않는지, 저장 실패 때 기존 상태·데이터가 남는지, 조회가 진행 중이어도 인증 완료가 전달되는지 확인한다. 후속 조회 실패 때 이미 완료된 인증이 유지되는지도 본다. 이름만 바꾸는 작업에서도 관련 호출부·안내가 같은 완료 의미를 전달하는지 대조한다.

실제 코드와 현재 실행 근거는 [인증 흐름 현황](../current/authentication-flow.md)에 있다. 자동 검사 통과는 이 프로토타입의 계약 확인이며 실제 제품 통합이나 사용자 수락을 뜻하지 않는다.
