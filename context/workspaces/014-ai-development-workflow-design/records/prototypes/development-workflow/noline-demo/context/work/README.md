# Work context

한 작업의 요구·현재 판단·실행 결과를 Workspace별로 유지한다. 제품 공통 의미는 Project가, 개인 판단은 Personal이 소유하고, Work는 지금 맡은 작업에 필요한 내용을 선택해 사용한다.

- [workspaces](workspaces/README.md): 작업별 current·source·output·records의 관계와 일반 재개의 기본 선택. 기본 선택은 이 목록 한곳에서 관리한다.
- [development 스킬](../../../skills/development/SKILL.md): 관련 맥락 선택·재탐색, 구현·검토·확인과 Main의 종합·결과 전달·Owner별 갱신을 맡는 공통 본문. 개발 절차의 진입점은 Work 밖의 스킬이며 구현 완성·인계·검토 입력·수정·종료를 본문과 상세에서 찾는다. Main은 전체 반영을 조율하고 Work 기록은 [record-work](../../../skills/record-work/SKILL.md)의 담당자에게 맡긴다. Personal·Project 반영은 기존 workflow와 context-update의 책임을 유지한다.
- [작업 지침](AGENTS.md): `recover.md`를 사용하는 재개와 읽기 선택·안내 갱신의 공통 기준, Main과 기록 담당자의 책임
- [생성과 전환](workspaces/CREATE-AND-TRANSITION.md): 요청된 독립 목표의 의미 구성·인수 확인, 기존 또는 새 Work로의 수동 전환 계약. [생성 스킬](../../../skills/create-context-workspace/SKILL.md)은 이 계약을 적용하는 수행 수단이다.

이 프로토타입은 Workspace별 `recover.md`와 직접 읽기로 재개하고, 검사는 development의 기준으로 직접 수행한다. Recover·Maintain·Verify 실행기를 설치하지 않았으며 별도 Verify 사용을 절차로 요구하지 않는다. 기록 수행은 record-work가 맡는다. 목록의 기본 선택 변경은 실제 host 세션 연결과 구별한다. 실행 장치가 남아 있는 대상의 아카이빙·의존 제거와 과거 증거 보존은 그 대상의 실제 계약을 확인해 별도로 전환한다.
