# Work를 이어 가는 방법

Main의 일반 재개에서는 사용자가 지정한 Workspace를 우선한다. 지정이 없으면 [Workspace 색인](workspaces/README.md)에서 현재 예시를 찾는다. 해당 README, `current/memory/index.md`와 Spec·Ticket, `current/state/index.md`, `output/index.md`에서 목표·제약·현재 결과·다음 행동을 확인한다.

범위를 정해 위임받은 담당자는 지정된 작업·판본과 관련 Spec/Ticket·원문을 우선 읽고 판단에 필요한 상태를 추가로 확인한다. 전체 current와 관련 없는 다른 Ticket의 기본 완독을 요구하지 않는다.

[개발 절차](../../../skills/development/SKILL.md)에 따라 관련 Personal·Project 본문을 고르고, 필요한 원자료만 source에서 읽는다. 개인 기준을 읽었다는 이유로 제품 약속을 바꾸거나, 기존 예시의 함수명을 모든 작업에 강제하지 않는다.

Main은 이 지침과 실제 Workspace·Project의 관리 계약을 이해한 뒤 바뀐 의미를 직접 반영하고, 다음 작업이 문서에 의존하면 실제 반영을 확인한다. 제안·채택·수정·확인을 구별하고 현재 상태의 오래된 다음 행동은 갱신한다.

목표·계약·가정은 memory, 전체 상황·다음 행동은 state, 실행 단위의 결과는 Ticket에 맞춘다. 입력은 source, 결과 위치는 output, 선택·시행착오·검사 이력은 records가 맡는다. 원자료와 과거 기록을 새 결론에 맞춰 덮어쓰지 않는다.

검사는 [실행 안내](../../README.md#직접-실행한다)를 사용한다. 이 demo의 직접 확인 결과와 실제 Noline·화면·저장소의 미확인을 구별한다. 자동 Maintain이나 session activation은 연결돼 있지 않으므로 운영 명령을 임의로 실행하지 않는다.
