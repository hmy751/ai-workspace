# 본문 관리 정책을 형성한 자료

이 자료는 [CONTENT-POLICY](../../CONTENT-POLICY.md)의 의도·구성 이유·정정과 근거를 보존한다. 관리 원칙을 적용할 때는 정책 본문을 읽고, 적용 대상이나 자료의 역할을 바꾸거나 이유를 더 정확히 이해할 때 이곳을 사용한다.

| 확인할 질문 | 읽을 자료 |
| --- | --- |
| 왜 현재 본문 옆에 별도 형성 자료를 두나 | [형성 맥락](context.md#읽는-내용과-그-내용이-남은-이유) |
| 왜 사례와 형성 자료를 나누고 당시 기록도 보존하나 | [역할을 나눈 이유](context.md#구성보다-먼저-구별할-역할), [발화](evidence.md#형성-자료와-본문의-구별) |
| 왜 기존 주제 묶음에서 지속 본문 전반으로 적용 조건을 고쳤나 | [범위 정정 기록](records/2026-10-20-scope-and-construction.md), [범위의 근거](evidence.md#적용-범위와-열린-관리-단위) |
| 왜 이동한 일반 본문의 옛 파일은 지우고 기존 절차·관리 진입은 유지하나 | [이동과 진입을 구별한 맥락](context.md#본문-이동을-마치는-것과-기존-진입을-바꾸는-것), [후속 정정 기록](records/2026-10-20-entry-restoration-and-complete-moves.md) |
| Work에는 왜 지금 이 구성을 적용하지 않나 | [Work 적용을 보류한 이유](context.md#work의-기존-체계와-형성-자료는-별도로-논의한다), [사용자 정정](evidence.md#work-전체의-구성-적용-보류) |
| 왜 `_background`와 대문자 `INDEX`를 쓰나 | [파일 목록의 역할 구별](context.md#파일-목록에서도-읽는-역할을-드러낸다), [표기 선택 기록](records/2026-10-20-visible-file-roles.md) |
| 지금의 파일명·배치가 모두 확정된 표준인가 | [열린 판단과 현재 배치](context.md#현재-배치와-열린-판단) |
| 기존 진입을 유지하자는 논의가 어떤 문서 역할의 구별로 이어졌나 | [체계 지침의 형성 자료](../system-guidance/README.md). 현재 개념·진입·분할 기준은 [독립 본문](../../SYSTEM-GUIDANCE.md)이 소유한다. |

이는 데모의 문서 관리 방식을 설계한 과정이다. 제품 계약이나 팀 운영 합의가 아니며, 과거 설명과 현재 원칙이 다르면 무엇이 바뀌었는지 기록과 근거에서 확인한다.
