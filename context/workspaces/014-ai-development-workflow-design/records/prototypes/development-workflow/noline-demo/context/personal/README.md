# Personal context — 개인의 개발 판단

여러 Project에서 사용할 개인의 판단 기준과 그 이유·적용 조건을 제공한다. 제품 요구·팀의 계약·현재 구현은 해당 Project가, 이번 작업의 선택과 진행은 Work가 소유한다. 개인 기준은 그 내용을 읽고 판단할 관점을 제공한다.

## 필요한 본문

[개발 판단](development/README.md)에서 짧은 공통 관점을 읽고, 이번 쟁점에 맞는 상세를 고른다. 현재는 [이름·책임·완료의 일반 기준](development/naming-and-completion.md)과 [조건별 판단 사례](development/cases/naming-and-completion.md)를 별도 파일로 둔다. 일반 기준에는 적용할 판단·핵심 조건·짧은 설명 예시를, 사례에는 당시 상황·선택·한계·근거를 둔다. 사례를 먼저 모두 읽게 하지는 않는다.

## 이 시안에서 선택한 것과 검토할 것

일반 기준과 구체 사례를 구별하고, 판단 질문을 포함하며, 채택한 기준도 조건별로 적용한다는 방향을 반영했다. 이번에는 사용자가 원칙과 상세 사례의 파일 분리를 선택했다. 현재 문장·설명 예시 전체의 채택과는 구별한다. 관찰·사용자 판단·새 구체화는 사례를 읽는 자리에서도 표시하고, 정확한 발췌와 원자료 경로는 [프로토타입 작성 근거](../../../authoring-basis.md)에서 더 확인한다. 본문을 적용하는 데 그 작성 이력을 먼저 읽을 필요는 없다.

## 기준을 고치는 경우

기존 설명으로 판단하기 어려운 조건이 드러나면 어떤 전제가 달라졌는지 확인한다. 개인의 판단 자체가 바뀌었는지, 특정 제품의 요구가 다른지, 이번 작업만의 비용 차이인지 구별한 뒤 해당 내용을 고친다. 한 작업의 함수명이나 선택을 개인 공통 의무로 곧바로 올리지 않는다.

개인 기준은 이 Project의 `context/personal/`에 두고 Project·Work와 나란히 관리한다. 여러 저장소 사이의 배포·동기화와 실제 스킬 연결 방식은 후속 설계 대상이다.
