# 기기 인증과 로컬 여행 데이터의 연속성

로그인과 재인증의 제품 목적은 **사용자가 자기 여행 데이터를 보존하면서 인증이 필요한 작업을 다시 할 수 있게 하는 것**이다. 서버에서 새 인증 수단을 받았다는 사실만으로 기기에 있던 작업을 새 계정의 것으로 취급하거나 폐기하지 않는다.

## 같은 계정으로 돌아온 사용자의 작업을 이어 준다

서버 인증 수단은 갱신되거나 만료될 수 있지만 기기의 여행 데이터는 사용자가 이미 쌓은 작업이다. 같은 계정으로 다시 로그인하면 기존 로컬 데이터를 유지하며 인증을 복구한다. 다른 계정이거나 데이터의 귀속을 확인할 수 없다면, 로그인 편의를 위해 그 데이터를 자동 삭제하거나 새 계정에 귀속시키지 않는다. 계정 전환·데이터 정리 정책이 별도로 필요하다.

이 관계에서 `signed-in`은 사용할 인증 수단을 기기에 저장하고 공개 상태에 반영한 상태다. 서버가 이후 모든 요청을 받아준다는 보장이나 모든 화면이 최신 데이터를 표시한다는 뜻은 아니다.

## 인증 복구와 최신 데이터 조회는 다른 결과다

인증 복구는 인증이 필요한 작업을 다시 시도할 수 있게 한다. 조회는 그 인증을 사용해 화면에 필요한 최신 데이터를 받는 일이다. 인증 복구 뒤 네트워크가 끊겨 조회가 실패해도 이미 저장한 인증과 로컬 여행 데이터가 사라질 이유는 없다.

후속 요청에서 현재 인증 수단의 거부가 별도로 확인되면 새 인증 사건으로 처리한다. 앞선 저장 성공을 실패로 다시 분류하는 것과, 이후 거부 때문에 현재 요청을 차단하는 것은 다르다. 이 demo는 거부 판정과 재인증 전환을 구현하지 않았다.

따라서 일반 조회 실패를 인증 저장 실패처럼 알리면 사용자는 이미 끝난 로그인을 반복하게 된다. 복구 안내와 재시도는 실패한 조회에 맞춰야 한다. 다만 어느 화면으로 언제 이동할지는 그 화면이 최신 조회 결과를 필요로 하는지에 따라 별도로 정한다.

저장·공개 순서와 사건별 실패 처리는 [인증·세션 계약](../../guidance/authentication-and-session/INDEX.md), 이 예제가 실제로 제공하는 계정·데이터 검사는 [현재 구현 범위](../../current/authentication-flow/INDEX.md)가 설명한다.

본문의 범위와 형성 의도·변경 근거를 읽을 경로는 [구성 안내](README.md)에 있다.
