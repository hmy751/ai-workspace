# 요구 동작과 대표 사례

인증 요청과 진행 중 작업의 대기가 끝나면 새 세션을 저장하고 공개 상태에 적용한다. 그 뒤 조회 갱신을 요청하며, 조회 결과를 기다리지 않고 인증 완료를 소비자에게 전달한다. 호출자의 다음 행동이 요구하는 완료 범위가 이름·callback·안내에서 일치해야 한다.

| 장면 | 관찰해야 할 결과 |
| --- | --- |
| 저장이 진행 중 | 새 인증 상태와 완료 알림은 아직 공개되지 않는다. |
| 저장 실패 | 이전 상태와 여행 데이터가 남으며 조회와 완료 알림은 시작하지 않는다. |
| 저장·상태 적용 성공, 조회는 진행 중 | 인증 완료와 소비자의 이동·닫기 요청은 진행한다. 화면 갱신 완료라고 알리지 않는다. |
| 후속 조회가 비동기 실패하거나 요청 자체가 동기 실패 | 이미 적용한 인증은 유지한다. 오류는 조회 실패 경로로 전달한다. |
| 다른 계정이거나 귀속을 확인할 수 없는 데이터 | 예제 Store가 변경을 거부하고 기존 데이터를 임의 폐기하지 않는다. |

Login은 ‘로그인 완료’와 이동 요청, Reauth는 ‘인증을 복구했어요’와 닫기 요청을 담당한다. 함수 호출은 실제 화면 전환·렌더 완료를 보장하지 않는다. 이 예시의 두 내부 사용처는 실제품 전체 조사 결과가 아니다.
