# 인증 계약 본문의 형성 자료

이 폴더는 [인증 완료·실패와 후속 조회의 계약](../index.md)이 어떤 제품 근거와 데모 선택에서 만들어졌는지 보존한다. 저장·공개 순서, 전체 세션 조율, 후속 조회의 대기·실패 경계를 수정할 때 기존 선택의 이유와 한계를 복원하는 자료다.

현재 계약을 적용할 때에는 본문을 읽는다. 형성 자료에는 실제 제품 기준의 보존판과 데모 작성자의 구현 선택·설명 정정이 함께 있으므로 둘의 권위를 구별한다.

| 확인할 질문 | 읽을 부분 |
| --- | --- |
| 왜 Store와 전체 서비스의 책임을 따로 설명하는가 | [저장·공개와 전체 조율의 맥락](context.md#저장-성공을-공개하는-책임과-전체-작업을-조율하는-책임) |
| 조회 실패를 분리하면 반드시 비대기여야 하는가 | [별개 선택이라는 설명](context.md#조회-실패의-분리와-비대기는-서로-다른-선택), [정정 기록](records/2026-10-19-waiting-and-failure-boundaries.md) |
| 제품 원문이 보장한 저장·실패 범위는 무엇인가 | [제품 계약 발췌](evidence.md#로그인-완료와-저장-실패), [공통 데이터 보존 근거](../../../common/device-session/background/evidence.md#같은-계정의-재로그인) |
| 동기 요청 오류와 두 callback의 처리는 어디서 생겼는가 | [데모 선택 근거](evidence.md#실행-예제가-추가한-선택) |
| 최신 결과가 필요한 새 소비자를 연결하려는가 | [대기를 다시 판단할 조건](context.md#소비자의-요구가-달라질-때-다시-판단할-것) |

제품 의미의 공통 발췌는 기기 세션 형성 자료를 재사용한다. 이번 Work의 구현·검사 전체는 기존 Work 기록이 소유하며 여기에는 계약 형성에 필요한 연결만 둔다.
