# 실행 지침과 그 지침을 고칠 근거를 함께 유지하는 이유

[스킬 본문 관리 정책](../../SKILLS-CONTENT-POLICY.md)의 현재 선택을 설명한다. 사용자는 context에 적용한 본문·형성 자료 구성을 스킬에도 적용할 수 있는지 검토한 뒤, 작성·수정 과정에서 놓치지 않도록 먼저 skills 안에 정책 지침을 만들도록 요청했다.

기존 [CONTENT-POLICY](../../../noline-demo/context/CONTENT-POLICY.md)의 목적은 현재 내용을 충분히 적용하면서 그 내용을 만든 이유를 가까이 보존하는 것이다. 스킬도 반복해 사용하고 수정하는 지침이므로 이 목적을 이어받았다. 실행에 필요한 상세와 형성 근거의 구별, 맥락·기록·근거의 서로 다른 갱신 책임, 최소 발췌와 원자료의 연결을 유지한다.

스킬에서는 `SKILL.md`가 실행 진입 본문이고 보조 문서도 현재 판단을 맡을 수 있다. 따라서 일반 문서의 `INDEX` 배치를 그대로 옮기지 않고 기존 진입과 조건부 상세를 유지했다. 공통 실행 기준은 공유 책임으로, 실행 도구·산출물 재료는 실제 사용 역할로 구별했다. 형성 자료는 지침을 이해·수정할 때 읽으며 매 실행의 추가 필독 자료로 만들지 않는다.

예를 들어 기존 정의와 보완 후보를 대조하라는 요구가 왜 생겼는지 남기면, 이후 수정자가 같은 기준을 계속 추가하거나 필요한 구체화까지 줄이는 안을 재검토할 근거가 된다. 이는 형성 자료의 예상 효용이며 이번 정책으로 후속 수정자의 판단이 개선됐다고 검증한 결과는 아니다.

정책은 사용자가 지정한 skills 안에서 해당 구성·갱신 책임을 소유한다. 기존 context 정책의 적용 범위를 전역으로 올리거나 Work의 기존 기록 체계를 바꾸지는 않았다. 두 정책의 공통 원칙을 나중에 한 위치로 합칠지는 열려 있으며, 현재 경로의 존재를 외부 설치 계약으로 취급하지 않는다.

파일명은 [SYSTEM-GUIDANCE](../../../noline-demo/context/SYSTEM-GUIDANCE.md)의 대표 진입 지침 표기와 사용자의 정정을 따라 대문자로 정했다. 이름 자체가 권한이나 모든 요청의 필독 순서를 결정하지는 않는다. 당시 선택과 발화는 [작성 기록](records/2026-10-21-initial-policy.md)과 [근거](evidence.md)에 있다.
