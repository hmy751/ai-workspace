# Development의 형성 자료

개발 실행을 하나의 스킬로 구성한 목적, 관련 기준을 공유하면서 독립적으로 검토하게 된 이유, 현재 실행 본문과 적용 한계를 설명한다. 스킬을 적용할 때는 [SKILL.md](../SKILL.md)와 필요한 [검토 상세](../references/review.md)·[검증 상세](../references/verification.md)·[실행 배치](../references/execution.md)를 사용한다. 이 자료는 의미·구성·과거 선택을 재검토할 때 읽는다.

- [형성 맥락](context.md): 사용자 목표, 스킬과 context의 소유 관계, 파일을 나눈 이유와 열린 실행 설계.
- [근거](evidence.md): 판단을 바꾼 사용자 발화·외부 참고·리뷰 의견의 지위, 이전 DEVELOPMENT 원문.
- [전환 기록](records/2026-10-23-development-skill.md): 최초 구성 제안, 사용자 정정, 독립 개선 리뷰와 적용 요청의 흐름.

현재 실행에 필요한 조건을 이 폴더에만 두지 않는다. 전체 설계 작업의 기록과 이 스킬의 형성 이유도 구별한다. 스킬을 수정하는 주체는 [스킬 본문 관리 정책](../../SKILLS-CONTENT-POLICY.md)을 함께 적용한다.

- [실행 통합 기록](records/2026-10-23-execution-integration.md): 구현·검토·수정·종료·배치·기록 합의의 실제 반영과 확인 범위.

- [검증 통합 기록](records/2026-10-24-verification-integration.md): 검증 역할·기계 검사·수정 왕복을 나눈 이유와 실행 본문 통합, 사용자 정정·확인 한계.
