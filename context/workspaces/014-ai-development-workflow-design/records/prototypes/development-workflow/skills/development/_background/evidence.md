# Development의 선택 근거

현재 구성의 근거를 사용자 요청, 외부 원문, 독립 리뷰와 실제 적용으로 구별한다. 긴 설계 대화 전체를 이 폴더에 복제하지 않고 선택을 재검토하는 데 필요한 최소 원문과 출처를 보존한다. 아래 사용자 발화는 같은 설계 대화에서 발췌했으며 오탈자를 유지했다.

## 독립 개선 리뷰와 Main의 선택

2026-10-23 Astra high 리뷰어에게 사용자 발동 원문·구성 제안과 실제 prototype·합의·외부 원문의 접근점을 제공했다. 읽기 전용 설계 리뷰이며 Main의 파일 구성을 기각할 수 있게 했다. 반환은 전체 구조 적합, 다음 네 보완이었다.

1. Personal 전체와 이번 개발 작업이 소비하는 기준을 구별한다.
2. SKILL.md에 맥락 재선택·종합·전달·갱신까지 Main의 전체 책임을 드러낸다.
3. 한 상세 파일 안에서도 공유 목적·검토자·Main의 독자를 구별한다.
4. 공통 수행 계약과 특정 로그인 데모의 적용을 구별해 이전한다.

Main은 네 보완을 모두 채택해 사용자에게 추천했고 위 적용 요청을 받았다. 리뷰어가 현재 실행 실패를 발견했거나 새 구조의 효과를 시험한 것은 아니다. 고정 호출·수정 권한·모델 등은 후속 설계로 남겼다.
