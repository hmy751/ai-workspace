# 작업 판단 스킬 prototype

work-discussion의 기존 정의 대조·요청별 반환 최소안을04-01 설계 결과로 채택했다. 실제 프로젝트나 전역 스킬에 설치한 상태는 아니다.

스킬을 새로 만들거나 의미·구성을 바꿀 때는 [SKILLS-CONTENT-POLICY](SKILLS-CONTENT-POLICY.md)를 읽는다. 이 지침은 실행 본문·보조 자료·형성 근거의 구성과 갱신을 맡는다. work-discussion에는 [형성 자료와 읽기 경로](work-discussion/_background/README.md)를 구성했다. 다른 스킬의 형성 자료 구성은 후속 작업이다.

| 필요한 일 | 읽을 본문 |
| --- | --- |
| 기존 정의가 충분한지, 무엇을 더 구체화할지 판단한다 | [work-discussion](work-discussion/SKILL.md) |
| 현재성·근거·설명 깊이·판정 경계를 확인한다 | [설명과 근거 기준](shared/explanation-and-evidence-criteria.md) |

각 SKILL.md가 호출 조건과 구체 동작을 소유한다. 공통 기준은 스킬이 적용될 때 읽으며 모든 AI 응답의 상위 지침으로 자동 적용하지 않는다. 공통 기준의 consumer 이름은 각 스킬의 적용 관계이며 이 prototype에 모두 배치·채택됐다는 뜻은 아니다. 공통 기준을 바꾸는 작업 주체는 이 안내와 실제 consumer의 연결을 함께 유지한다.

## work-discussion의 채택 범위

기존 정의와 보완 후보를 대조하고, 충분성 질문에는 충분 여부와 실제 보완부터 답한다. 새 Work의 요구 발견·선택 제안과 필요한 구체화는 유지했다. 충분한 정의와 선택이 필요한 정의를 각1회 확인했으며 일반 성능 향상을 보장하지 않는다. reconsider-work는 기존 유지로 결정해 교체 본문을 만들지 않았다.

공통 기준은 기존 기준판의 내용을 유지한 의존 자료이며 이 폴더에서 읽히도록 상대 경로만 조정했다. 실제 배포 위치·root 운영 계약과 Maintain의 기록 책임 연결은 적용 단계에서 맞춘다.
