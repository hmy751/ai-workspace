# 이름과 완료 범위를 판단할 때 읽는 안내

> Project README의 주제별 읽기 안내에 들어갈 본문 시안. 아래 링크는 이번 비교 파일과 보존 원문을 가리키며 실제 Project에 설치한 경로는 아니다.

이름만 보고 실제 책임이나 완료 시점을 오해할 수 있는 작업에서 다음 본문을 고른다. 이미 읽은 내용으로 판단할 수 있으면 같은 문서를 다시 읽는 절차를 반복하지 않는다.

| 지금 필요한 판단 | 읽을 본문과 얻어야 할 답 |
| --- | --- |
| 함수·상태의 이름이 맡는 일을 충분히 드러내는가 | [개인 기준](personal-criterion.md). 이름·타입·가까운 설명이 전달할 범위와, 표현 수정·계약 또는 동작 수정의 차이를 판단한다. |
| Noline의 인증 action·로그인 완료·후속 갱신을 어떻게 표현하는가 | [Project 적용 가이드](project-guidance.md). Store와 전체 서비스, 인증 완료와 캐시 갱신의 책임·실패 경계를 확인한다. |
| 로그인 완료의 의미나 검사·저장·공개 순서 자체를 바꾸는가 | [기존 인증·세션 가이드](../../../source/supplement/worktree-project-context/context/project/guidance/authentication-and-session.md). 계정·로컬 데이터의 제품 의미까지 바뀌면 [기기 세션](../../../source/supplement/worktree-project-context/context/project/common/device-session.md)도 읽는다. |
| 지금 어느 구현이 그 책임을 맡으며 실제로 무엇을 기다리는가 | [세션 현황](../../../source/supplement/worktree-project-context/context/project/current/session-and-local-data.md). 관련 코드 위치와 확인 범위를 찾고 실제 변경 대상의 구현·호출부를 확인한다. 이 시안의 source에는 제품 코드가 없어 여기서 실제 대기 동작을 확정할 수는 없다. |

인증 관련 작업은 Project 적용 가이드에서 시작한다. 그 문서에 필요한 개인 기준의 핵심이 있으므로 매번 개인 기준 전체를 선행 입력으로 붙이지 않는다. 이름을 유지할지 바꿀지의 일반 판단이나 원칙의 적용 이유가 쟁점이면 개인 본문을 추가한다. 인증과 관계없는 이름 정리에 인증 문서를 함께 읽힐 필요는 없다.

작업 요청과 기존 계약이 다르면 이름을 먼저 고쳐 차이를 덮지 않는다. 예를 들어 ‘로그인 완료’를 ‘모든 화면이 최신 데이터로 바뀐 시점’으로 바꾸려는 요청은 기존 완료 계약과 다르므로 그 동작 변화부터 판단한다. 개인 기준 변경도 기존 Project 계약을 자동으로 바꾸지 않는다.

새로 확인한 내용은 맡는 위치에 돌려준다. 여러 Project에 적용할 개인 판단의 변경은 개인 기준에, Noline의 채택·예외·개발 계약 변경은 해당 Project guidance에, 제품 의미나 현재 지원 관계의 변경은 그 의미를 소유한 common·current에 반영한다. 이번 수정의 선택·검증·미확인과 중요한 변경 이유는 Work에 남긴다. 한 번의 작업 결과만으로 개인 기준을 자동 승격하지 않는다.
