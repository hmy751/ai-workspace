# 인증 코드에서 이름과 완료 표현을 맞춘다

이 문서는 이 Project의 인증·세션 코드에서 역할과 완료를 표현할 때 지킬 개발 기준을 소유한다. 관련 함수·상태·callback·로그·안내 문구를 만들거나 고칠 때 적용한다. 실제 Noline 가이드를 대체하지 않는 시안이다.

## 부분 저장과 전체 세션 변경을 구별한다

Auth Store는 계정·DB·queue의 귀속 검사, 기기 저장, 인증 상태 적용을 맡는다. 전체 세션 변경 서비스는 진행 중인 sync·cleanup·접수된 DB 작업의 종료와 본작업을 조율한다. Store의 부분 action에 전체 세션 변경을 마쳤다는 이름을 붙이지 않는다. 서비스가 전체 절차를 책임진다면 내부 단계 수와 관계없이 그 업무의 이름을 사용할 수 있다.

이 구별은 호출자가 이름만 보고 전체 조율을 거쳤다고 오인해 부분 action을 로그인 진입점으로 쓰는 일을 막는다. 호출 경로를 바꾸는 작업이라면 명칭만 대조하지 말고 실제로 거쳐야 하는 절차도 확인한다. 순서와 실패 시 보존할 결과는 [인증·세션 계약](authentication-and-session.md)이 정한다.

## 인증 완료가 보장하는 결과를 맞춘다

이 Project에서 인증 완료는 계정 확인·기기 저장·인증 상태 적용을 마친 결과다. Query 무효화 요청, 재조회 완료, 화면 반영 완료는 각각 별도 결과다. 완료 callback과 성공 반환·로그·안내 문구에서 어느 결과를 전달하는지 일치시킨다.

후속 조회를 기다리지 않는 경로에서는 인증 완료를 화면 준비 완료의 신호로 설명하지 않는다. 반대로 조회 결과까지 제공하는 경로가 필요하다면 그 대기·실패 계약을 확인한 뒤 표현을 정한다. 모든 함수에 같은 단어를 강제하거나, 이름을 맞추려고 모든 후속 처리를 기다리게 바꾸지 않는다.

“완료 알림을 받은 화면이 지금 무엇을 해도 되는가?”를 소비자의 실제 동작과 대조한다. 개발자에게는 대기·실패 범위를 가까운 계약으로 설명하고, 사용자 안내에는 사용자에게 필요한 결과를 말한다. 구현 용어를 나열하는 방식으로 안내 문구를 대신하지 않는다.

## 실패 표현과 변경 범위도 계약을 따른다

저장·상태 적용 이후 Query 실패는 인증 저장 실패와 구별한다. 오류 이름·처리 위치·로그가 이미 성공한 인증을 실패한 것으로 설명하지 않게 한다. 구체적인 오류 전달과 복구 동작은 인증·세션 계약을 따른다.

표현 정리는 현재 약속한 결과를 더 정확히 알리는 변경이다. 호출자가 필요로 하는 결과 자체를 바꾸어야 한다면 대기·실패·화면 동작의 영향을 함께 판단한다. 관련 코드·호출부·안내 문구가 같은 의미를 전달하는지 확인하고, 기존 동작이 계약을 어겼다면 이름만 좁혀 고친 것으로 처리하지 않는다.

현재 함수·사용처의 연결은 [인증 흐름 현황](../current/authentication-flow.md)에서 확인한다. 특정 작업에서 선택한 이름과 그 비용 판단은 작업 기록이 소유하며 이 가이드의 일반 규칙으로 자동 추가하지 않는다.
