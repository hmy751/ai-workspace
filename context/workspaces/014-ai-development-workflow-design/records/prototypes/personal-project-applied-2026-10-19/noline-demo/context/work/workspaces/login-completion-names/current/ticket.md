# 이름과 실제 완료 범위를 맞춘다

> 가상 작업의 요구다. 아래 함수·시점·사용처는 시안을 위한 가정이며 실제 Noline에서 확인한 사실이 아니다. 최신 시안 상태는 [state](state.md)가 맡는다.

사용자 요청은 `loginAndRefresh`, `callbacks.onCompleted`와 소비자의 완료 표현을 실제 책임·보장에 맞게 정리하는 것이다. 인증 서비스와 후속 Query, 화면 정책의 동작은 유지한다. 이름을 더 강한 완료 보장으로 바꾸거나, 현재 이름에 맞추려고 대기·실패 의미를 바꾸지 않는다.

## 이 작업의 입력과 보존할 것

시작 상태는 [시작 입력](../../../../../../scenario-input.md)에 보존한 당시 Project 현황과 코드에서 읽는다. 현재 연결된 Project 현황은 가상 작업 후 상태이며 최초 입력과 구별한다. 이 장면은 wrapper가 외부 공개 API가 아니고 내부 사용처가 `LoginScreen`과 `ReauthDialog` 두 곳뿐이라고 가정한다.

| 구간 | 이 장면에서 보존할 계약 |
| --- | --- |
| `loginService.signIn` | 전체 세션 조율과 계정·DB·queue 확인, 기기 저장, signed-in 적용이 끝나면 해소된다. 내부 인증 실패는 기존 실패로 전달한다. |
| 후속 Query | 인증 서비스가 해소된 뒤 `invalidateQueries`를 호출한다. 재조회 완료는 기다리지 않고 callback을 호출한다. |
| 후속 실패 | Query rejection은 `onRefreshError`가 맡는다. 이미 끝난 인증 적용을 인증 실패로 바꾸거나 되돌리지 않는다. |
| 소비자의 화면 책임 | LoginScreen의 기존 이동, ReauthDialog의 기존 닫기 동작을 유지한다. wrapper는 전체 렌더 완료를 보장하지 않는다. |

프로젝트의 인증·실패 의미는 [인증·세션 가이드](../../../../project/guidance/authentication-and-session.md), 이 제품에서 지킬 표현 요구는 [코드 가독성 가이드](../../../../project/guidance/code-readability.md)가 소유한다. 두 본문은 개인 기준 없이도 이해할 수 있는 Project 계약이다.

Main은 이번 요청의 성격으로 [개인 개발 공통](../../../../../../personal-context/development/README.md)과 [이름·완료 범위 상세](../../../../../../personal-context/development/naming-and-completion.md)를 별도 입력으로 가져온다. 표현 수단·변경 비용을 비교할 판단으로 사용하며 Project 계약을 자동으로 덮어쓰지 않는다. 입력 선택과 역할 전달은 [실행 연결](../../../../../../workflow.md)이 설명한다.

## 이번에 바꾸고 확인할 범위

함수와 callback의 이름, 내부 사용처 두 곳, 그 사용처에서 완료를 전달하는 표현을 함께 대조한다. 이름 유지와 가까운 설명 보완, 개명과 설명 보완의 이득·비용을 비교한다. 특정 개선 이름을 시작 요구로 정하지 않는다. `await` 추가·제거, 새로운 세션 상태, 재조회 실패 복구 방식, 화면 이동 정책, 외부 API 마이그레이션은 이번 이름 정리에 포함하지 않는다. 필요가 드러나면 근거와 영향을 Main에게 돌려준다.

완료 판정은 개발자용 이름·타입·설명이 인증 적용·조회 요청·화면 반영의 차이를 드러내고, 사용자 문구가 성공한 범위만 정확하게 알리며, 보존 계약이 바뀌지 않았는지를 근거로 한다. 사용자에게 내부 구현 단계를 나열할 필요는 없다. 실제 적용이라면 관련 사용처와 타입 연결, 인증 서비스 실패, 느린 Query, Query 실패, 화면별 callback 동작을 확인해야 한다. 이 시안은 코드 발췌와 확인 계획을 작성하는 데 그치며 그 검사를 실행했다고 기록하지 않는다.

선택 이유·변경과 확인 범위는 [구현 기록](../records/implementation.md), 검토자의 판단·직접 수정·남은 한계는 [검토 기록](../records/review.md)에 남긴다. 이번 개명을 곧바로 개인 기준의 필수 명명 규칙이나 Project의 새 제품 계약으로 올리지 않는다.
