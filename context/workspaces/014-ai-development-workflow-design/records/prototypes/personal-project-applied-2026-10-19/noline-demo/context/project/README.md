# noline-demo Project context

여행 앱에서 기기 인증을 복구하고 기존 로컬 작업을 이어 가는 흐름의 제품 의미·개발 계약·현재 연결을 소유한다. 이 디렉터리는 Noline의 일부 계약을 참고한 가상 Project의 시안이며 실제 제품 정본이 아니다.

## 필요한 Project 내용을 찾는다

| 지금 필요한 판단 | 담당 본문 | 더 읽는 조건 |
| --- | --- | --- |
| 같은 계정으로 다시 로그인할 때 무엇을 보존하는가 | [기기 세션과 작업 연속성](common/device-session.md) | 그 의미를 구현하는 저장 순서·오류 처리를 바꾸면 인증·세션 계약도 읽는다. |
| 로그인 성공과 후속 조회 실패를 어떻게 다루는가 | [인증·세션 개발 계약](guidance/authentication-and-session.md) | 실제 호출이 계약을 지키는지 보려면 코드와 현재 연결을 확인한다. |
| 인증 함수·완료 알림·안내 문구의 의미가 맞는가 | [인증 코드의 가독성 기준](guidance/code-readability.md) | 표현이 약속할 결과는 인증·세션 계약과 호출부에서 대조한다. |
| 현재 어느 함수가 무엇을 기다리고 누가 결과를 받는가 | [인증 흐름의 현재 연결](current/authentication-flow.md) | 실제 작업에서는 해당 코드·호출부와 대조한다. 이 시안은 그 대신 명시된 코드 발췌와 가정을 제공한다. |

`common/current/guidance`는 내용의 책임을 구분한다. 항상 그 순서로 모두 읽는 절차는 아니다. 인증과 관계없는 작업에는 이 인증 본문들을 기본으로 붙이지 않으며, 해당 주제의 계약과 구현을 찾는다. 현재 시안에는 인증 주제만 채웠다.

## 변경된 의미를 담당 본문에 반영한다

제품 의미가 달라지면 해당 common을, 반복해서 지킬 개발 계약이 달라지면 guidance를, 함수·사용처·지원 관계가 달라지면 current를 실제 변경과 대조해 갱신한다. 문서와 코드가 어긋났을 때는 코드가 있다는 이유만으로 계약을 바꾸지 않고, 요구와 사용처에서 무엇이 맞는지 판단한다.

한 작업의 요구·선택·수정·검사와 미확인은 Work에 남긴다. 현재 작업 예시는 [로그인 완료 표현 정리](../work/workspaces/login-completion-names/README.md)다. 이 입구는 Project 내부의 내용과 갱신 책임을 안내한다.
