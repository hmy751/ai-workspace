필요한 입력 Main이 고르는 경로와 가져올 내용
개인의 개발 판단 Personal 입구에서 개발 작업임을 보고 짧은 개발 공통과 관련 주제를 고른다. 이름·완료 표현이 쟁점이면 상세 기준의 뜻·질문·조건별 판단을 가져온다. 관련 없는 개인 주제는 붙이지 않는다.
대상 Project의 의미와 계약 대상의 진입 지침과 Project 안내에서 현재 질문에 필요한 제품·개발 계약을 고른다. 인증의 이름이라면 인증 계약과 표현 가이드를 읽고 해당 코드·호출부를 대조한다. 개인 기준이 없어도 이 경로에서 Project의 약속을 이해할 수 있어야 한다.
이번 Work의 요구·상태·결과 Work의 Ticket과 현재 상태에서 목표·보존 범위·미충족을 읽는다. 이어 하는 작업이면 필요한 구현·검토 기록을 고른다. 과거 선택이 현재 요구인지 이력인지 구별한다.

출처: 시안 README · 형식 근거를 다시 읽는 경로, 62–69행.

다시 검토하려는 질문 과정 근거와 읽는 이유
사용자가 어떤 형식을 원했는가 57 사용자 생각. 일반 원칙·고민 기준·질문이라는 러프한 제안과 고정 양식의 채택을 구별할 때 읽는다.
레퍼런스에서 무엇을 가져왔고 무엇을 보류했는가 61 비교. Matt의 개념·질문·대비, Vercel의 범위·이유·예외·근거, pstack의 관찰·유지 조건, Anthropic의 구체성·선택적 읽기를 참고한 이유와 비용을 확인한다. 외부 저자의 설계 철학·파일 구성 전체를 채택한 기록은 아니다.
이름과 가독성을 왜 별도 상세로 두었는가 45 이름·가독성 보완, 72 시안 반영. 실제 책임을 읽을 수 있게 하려는 의도와 본문 구성 선택을 다시 판단할 때 읽는다.
왜 정답 하나와 결과만 보여 주면 부족한가 64 적용 시안 검토, 65 과정 재사용, 68 선택 근거. Project 계약이 답을 미리 주는 장면의 한계, 조건에 따라 다른 대안이 타당해지는 이유를 확인한다.

이 표는 본문 형식의 근거를 재검토할 때 쓰는 경로다. 일반 작업마다 이 기록 전체를 읽게 하는 절차는 아니다.

이번 비교에서 Main이 작성한 해설

유지·변경과 구체화 이유

작업 단서로 필요한 상세와 사례를 고른다는 방식은 이어받았다. 하지만 01의 Project 입구에서 품질 기준과 제품 계약을 함께 안내하던 배치는, 이번에 Personal은 개인 주제만 안내하고 Project는 자기 담당 문서를 안내하며 Main/workflow가 둘을 선택하는 방식으로 바꿨다. 사용자가 요구한 독립 책임을 구체화한 것이며, 01에서 이 연결 구조까지 확정했던 것은 아니다.

근거를 찾는 위치도 달라졌다. 01은 각 주제 아래에서 실제 대화·사례로 바로 연결했다. 이번 Personal 공통·상세에는 그 연결이 없고, 바깥 시안 README에 형식 논의 근거가 모였다. 일반 적용 본문을 짧게 유지하려는 분리로 이해할 수 있지만 기준의 의미를 재검토하는 사람이 해당 근거를 발견하기는 더 어려워졌다. 개인 기준이 독립적으로 쌓이고 수정되려면, 개인 입구 또는 해당 주제에서 선택적으로 근거에 도달하는 경로를 보완하는 쪽이 맞다. Project에 개인 기준 관리 책임을 돌리는 방식으로 해결하지 않는다.

이번 비교로 판단할 부분

그대로 이어갈 방향은 짧은 공통과 필요한 상세, 의미를 먼저 설명하는 본문, 판단 질문, 조건에 따라 다른 선택이 가능한 대비다. 이것은 현재 문구·파일 수·모든 예시까지 채택한다는 뜻은 아니다.

이번 Main 작성으로 따로 검토할 부분은 두 파일의 배치, 이름 상세 안에 넣은 책임·완료·실패 설명의 범위, 새 질문과 세 사례, 타입 정보 중복에 대한 추가 문장이다. 추가 이유는 위 비교에 적었으며, 분량 증가와 책임 중복 가능성도 함께 남겼다.

현재 주제에서도 보완을 권하는 부분은 기준을 채택한 뒤에도 조건으로 적용한다는 의미와 개인 기준에서 과정 근거를 선택해 찾는 경로다. 조건식·상태 표현과 isError의 구체 경계는 이름·가독성 전체로 범위를 넓힐 때 복원할 부분이다. 별도 책임·동작 상세 역시 개인 개발 기준을 더 구성할 때 판단할 내용이며, 이번 좁은 주제에 모두 없다는 이유만으로 결함이라고 보지 않는다. 이 비교에서는 해당 기준 본문을 고치지 않았다.

위치 선택은 86에 남긴다. 운영 context/personal 생성, 원본 이동·합치기, root context 계약 변경, 글로벌·skill 설치와 제품 적용은 하지 않았다. 01 시안과 현재 Personal의 두 기준 본문도 비교를 위해 유지했다. 최신 위치 선택에 맞춘 변경은 시안의 위치 안내 문구와 Workspace 재진입 기록에 한정한다.
