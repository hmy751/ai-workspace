# 전체 작업 틀에서 본 현재 단계와 남은 설계

2026-10-24. 사용자는 현재까지를 정리·커밋하고 남은 일을 설명하도록 요청한 뒤, Ticket만이 아니라 Spec·04와 검토자 세부 논의 이전의 작업 틀을 읽도록 보완했다. 이번 기록은 현재 단계와 다음 행동을 그 원자료에서 다시 맞춘 결과다. 새 검증 운영안을 설계하거나 실행한 것은 아니다.

## 먼저 복원한 원래 작업 틀

[작업 단계 우선순위](2026-10-13-28-execution-system-priority-and-code-criteria.md)에서 사용자는 Main과 Spec·Ticket을 논의·결정하는 단계와 실제 작업 단계를 구별했다. 우선 구체화할 것은 결정된 작업을 좋은 코드와 확인 가능한 결과로 만드는 시스템이었다. Spec 작성 절차를 처음부터 다시 만드는 일이 중심은 아니었다.

[논의 단위 정정93](2026-10-19-93-workflow-and-skills-discussion-focus.md)에서는 다음과 같이 말했다.

> 어떻게 찾아 읽는가 이런건 04 스킬도 맞고 그리고 우린 구체적 워크플로도 정해야돼 근데 이건 티켓이 안 보이네 스킬 보면서 봐도 될 것 같고
> 아무튼 전반적으로 너무 쪼개란건 아니고 중요한건 좀 섞여있다 이거지

Ticket은 결과와 책임을 관리하는 단위다. 개발 흐름·맥락 선택·기존 스킬을 따로 끝내고 다음으로 넘어가는 고정 순서가 아니다. 필요한 본문을 같은 작업 흐름에서 함께 보완하며02의 Workspace 재설계를 선행 조건으로 두지 않는다.

[구현·검토·검증 구분 원문](../source/discussion/2026-10-22-shared-criteria-independent-review/conversation.md#l1048--user)에서 사용자는 다음처럼 정정했다.

> 잠깐 근데 검토자 얘기했는데 검토자는 구현단계에서 구현자와 같은 단계 역할을 말하는거 맞지? 검증이 아니라
> 그리고 검증도 검증자가 필요하다고 생각해 서브로

이를 받아 Main은 같은 원문의 L1053·L1071에서 다음 틀과 구체화 순서를 설명했다. 역할 구별은 사용자의 직접 정정이고, 다섯 순서의 상세 표현은 Main의 정리·추천이다. 이후 L1480·L1483에서 검토자부터 구체화하고 검증자의 상세 설계는 뒤로 뒀다.

| 작업 틀 | 맡는 관계 | 지금까지 온 지점 |
| --- | --- | --- |
| 작업 정의 | Main과 사용자가 목표·Spec·Ticket의 필요한 선택을 맞춘다 | 기존 동작을 바탕으로 유지·보완한다.04-01 설계 결과는 마감돼 있다. |
| 구현 | 구현자가 맥락을 이해·적용해 첫 결과를 만들고, 개선 검토자가 대안을 비교하며, Main이 판단·수정을 연결한다 | 이번1~15번에서 책임·입력·탐색·권한·호출·수정·종료와 실행 배치·기록을 구체화하고 prototype에 반영했다. |
| 검증 및 수정 | 별도 검증자가 요구·계약과 실제 결과·검사 근거를 대조하고, Main·수정 담당과 수정·재확인을 잇는다 | 별도 역할과 인계 경계는 정했다. 검증자의 상세 수행과 수정 왕복·충분한 완료 근거는 아직 남았다. |
| 전체 연결 | 맥락 선택부터 구현·개선 검토·검증·첫 보고·기록을 한 작업에서 연결한다 | 공통 본문과 일부 연결은 있다. 검증 상세를 포함한 대표 장면 대조와 이후 적용 계획은 남았다. |

따라서1~15번은 전체 개발 체계의 모든 설계를 닫는 목록이 아니다. 구현 단계의 검토를 중심으로 앞뒤 구현·인계·실행·기록 책임까지 구체화한 범위다. [실행 통합 기록](2026-10-23-development-workflow-1-15-integration.md)의 반영 결과는 유지한다.

## 다음에 이어갈 논의

먼저 **별도 검증자와 검증 및 수정 단계**를 구체화하는 것을 추천한다. 무엇을 확인해야 하는지, 어떤 요구·실물·자료·기존 근거를 받는지, 초기 테스트와 같은 가정을 어떻게 피하고 공백을 누가 보완할지, 실패가 나오면 누가 고치고 어떤 범위를 다시 확인할지, Main이 무엇을 근거로 마칠지를 실제 레퍼런스와 기존 구조에 대조한다.01-01·01-03과 필요한04 스킬을 함께 본다.

그 뒤 대표 작업에 전체 흐름을 펼쳐 입력·맥락 선택·구현·개선 검토·검증·보고·기록의 빈틈과 중복을 확인한다. 필요한04-03 본문 보완은 이 과정과 함께 진행할 수 있다. 모든 Ticket 완료를 기다리거나 같은 책임을 Ticket별로 다시 논의하지 않는다. 실제 운영 적용·효과 확인은 설계 확인과 구별해 범위·계획을 정한다.

Main이 앞서 ‘남은 것은 실제 적용’이라고 설명하고 재개 안내를 그렇게 적은 것은 검토자 구체화 이전의 전체 틀과 남은 검증 단계를 충분히 반영하지 못했다. 이번에는 그 전제를 교정했다. 기존1~15번의 승인·실제 반영을 취소하거나 검증 역할이 처음 논의되는 것으로 되돌리지 않는다.

## 정리·보존 범위

[정리 전 Spec·01-01·논의 지도](2026-10-24-workflow-checkpoint-before.txt)를 보존하고, 현재 문서는 합의된 선택과 열린 부분을 맞췄다. 기록·형성 근거·실행 본문·열람 화면과 이번 재개 상태를 커밋한다. 별도04-02의 진행 중 결과와 변경은 작업 트리에 보존하되 이번 커밋 범위에서 구별한다. 자동 Maintain·전역 스킬 설치·새 실행 실험은 수행하지 않는다.
