JS/TS 제어문에 대한 표현 선호와 Project의 실제 formatter·logger·제품 계약을 구별했다. 가이드가 나온 위치만으로 제품 사실을 개인 규칙으로 옮기지 않았다. 형성 자료는 보존 Noline 가이드의 문장과 사용자 발화·이번 구체화를 구별하며, 당시 대화 전문을 새로 검증했다고 기록하지 않는다.

## 확인한 범위

- `viewer/build.mjs`: 문서218개·코드5개를 현재 원문에서 생성했다.
- `viewer/check.mjs`: 원문·SHA 일치, 내부 링크1261개·참고 링크41개·앵커 링크308개, 누락 경로/앵커0개, prototype 밖 로컬 의존0개, 화면 스크립트 구문 통과. 이름 기준의 필수 연결13개도 유지됐다.
- `git diff --check` 통과. 이번 변경은 기준·형성 자료·진입·표시 사본이며 실행 제품 코드는 수정하지 않았다. 실제 브라우저 표시·클릭, 인증 데모 실행, 새 독자의 사용 효과를 이번 확인으로 보고하지 않는다.

## 병행 적용과 남은 판단

이 턴은 prototype 적용만 수행했다. Reference·Noline에 파일을 복사하거나 다른 세션에 메시지를 보내지 않았다.06 담당자는 앞서 적용한 Personal 판본과 위 변경을 대조해 실제 대상의 기존 규약·변경을 보존하며 후속 반영할 수 있다.02의 Work·Maintain·통합 테스트 책임은 유지한다.

01-02 전체는 진행 중이다. 다음 논의는 계산·입력 단위와 경계값의 한정 보완, 책임 배치의 설명·사례 충분성, 적용 후 관찰과 전체 마감이다. 새 표현 주제의 prototype 반영을 실제 운영 효과나 전체 기준의 최종 충분성으로 확대하지 않는다.


## 후속 — 본문의 시각적 구분 보완

사용자가 “서술적이어서 그런가 뭔가 눈에 확 안들어오네”라고 피드백했다. 기준·조건·제약이 긴 문단에서 같은 비중으로 이어지던 본문을, 핵심 문장과 항목·조건별 표로 다시 구성했다. 중괄호·목적별 빈 줄에는 같은 동작의 전후 코드를 추가했다. 주석의 역할과 실패 처리·진단 판단을 표에서 직접 찾게 했으며 기존 적용 조건과 Project 책임은 유지했다. 이번 정정은 표현 본문의 읽기 구성에 한정하며 다른 지침 전체의 형식을 바꾸지 않는다. 이후 사용자가 “그래 더 보기좋네”라고 평가했다. 실제 개발에서의 반복 효과는 별도다.

## 후속 — 빈 줄의 구분 단위 정정

사용자는 같은 목적의 코드라도 띄우되 유사한 변수는 묶는 편이 낫다고 제안했고, Airbnb 비교 뒤 구체 문안·예시에 동의했다. 현재 본문은 관련 변수·짧은 연속 처리는 묶고 선언·조건 검사·실행의 경계는 빈 줄로 구별한다. 입력 변수·guard·요청·결과 반영을 나눈 코드로 예시를 교체했다. [주제 근거](prototypes/development-workflow/noline-demo/context/personal/development/code-expression/_background/evidence.md#빈-줄-기준을-구체화한-선택)에 사용자 발화와 외부 규칙·개인 선택의 차이를 보존했다. 기존 계승안의 ‘같은 조건·결과는 붙인다’는 문장은 제안 당시 기록이며 현재 적용은 수정된 본문을 따른다.

## 이번 구간의 마감과 다음 재개

사용자가 기록·커밋 뒤 다음 논의를 보자고 요청했다. 기존 기준 대조·계승안·prototype 반영, 읽기 구성 보완과 사용자 수용, 빈 줄 기준의 구체화까지 한 변경으로 보존한다. Reference·Noline 병행 작업의 미커밋 변경은 이 커밋에 포함하지 않는다.

최종 표시 사본은 문서218개·코드5개와 일치한다. 내부 링크1263개·참고 링크44개·앵커 링크310개를 검사했고 누락은0개다. 로컬 링크 경계와 화면 스크립트 구문, `git diff --check`를 통과했다. 브라우저 실측·제품 실행·반복 사용 효과를 확인한 것은 아니다.
