# 04-02 — 본체 구조 정리와 기존 인증 예시 분리

2026-10-25. 본체의 적용 조건·판단·설명 구성이 섞인 위치를 정리하고 기존 인증 전체·후속 예시를 함께 분리했다. 새 설명 기법이나 새 예시를 추가한 변경은 아니다. [현재 본체](prototypes/development-workflow/skills/explain/SKILL.md), [작성 상세](prototypes/development-workflow/skills/explain/references/constructing-explanations.md), [분리한 예시](prototypes/development-workflow/skills/explain/references/examples/auth-flow.md)가 현재 실행을 소유한다.

## 승인 범위와 선택

사용자는 본문을 계속 이어 붙이지 말고 구조를 재검토하되 `_background`의 맥락을 보존하라고 했다. [당시 제안](2026-10-25-ticket04-02-body-structure-reconsideration.md)에는 본체 재배치와 긴 인증 예시의 별도 파일화가 함께 있었다. 예시 부분을 처음 보류한 뒤 본체 정리·기록·커밋을 승인했다.

작업 중 사용자:

> 근데 혹시 예시를 새로 만든다기보다 이미 있던 예시를 분리한다엿던건가? 그렇다면 분리해봐

기존 예시를 옮기는 뜻임을 확인하고 최종 범위에 분리를 포함했다. 인증의 전체 설명과 같은 코드의 후속 질문은 범위 대비가 중요해 한 파일에 함께 두었다. 작성 상세는 일반 구성 방법과 읽기 조건을 소유하고, 다른 짧은 예시는 기존 방법 가까이에 유지한다. 중간 INDEX나 별도 실행 모드는 만들지 않았다.

본체의 등록/실행 구별과 코드 단위 선택 기준은 본체에 유지했다. 최초 제안에 있던 이 방법들의 상세 이동까지 일괄 적용하지 않고, 이번에는 본체 안에서 책임·중복·조건 위치를 정리했다. 문서 계층은 사용자 답의 고정 목차나 필수 실행 순서가 아니다.

## 기존 의미와 현재 위치의 대응

수정 전 본체 `fa42690`과 현재 본체를 대조했다. 아래는 Main의 의미 검토이며 독립 리뷰나 모델 응답 시험은 아니다.

| 보존할 의미 | 현재 위치·확인 |
| --- | --- |
| 사용자가 이해·판단을 이어가도록 돕되 재질문 제거·다음 행동을 모든 설명의 목표로 만들지 않음 | 목적 문단 유지. 질문 범위 절에서 이미 공유한 이해·깊이·혼동 단정 금지를 유지했다. |
| 뜻·역할 질문과 선택의 적절성, 앞선 말에 대한 이의 구별 | 질문 범위와 자료 판단 절로 나눴다. 앞선 발화 상세를 읽는 조건과 실제 오류 정정·과거 의미 소급 금지를 한곳에 모았다. |
| 첫 결과부터 원래 목표·맡은 범위·실제 결과를 연결 | 질문 범위 절에 직접 유지. 실제 처리 이해에 코드가 필요하면 첫 전달에도 같은 코드 기준을 적용한다. |
| 확인할 자료·공백과 비교 판단 | 사실 확인과 선택/변경 판단을 하위 절로 구별했다. 당시 의도/현재 추론, 동작 보존/읽기 부담, 확인 가능한 사실은 조사한다는 기준을 유지했다. |
| 전체 관계가 설명 순서와 코드 선택을 결정 | 설명 구성의 첫 하위 절에서 직접 소유한다. 국소 해설·대표 경로를 전체로 대체하지 않고 주요 다른 경로를 잇는다. |
| 등록/현재 실행, 관측/선택 작업, 독립·겹치는 경로 | 적용할 상황을 문장 앞에 두고 기존 구별을 유지했다. 단순 순차 처리와 짧은 한 대목에는 해당 범위로 답한다. |
| 코드 이해 요청에 실제 코드 동반 | 실제 대상과 해설 연결 절. 문법 해설 깊이와 코드 제시는 구별하고, 조건/후속 동작·보관/사용·분기/결과를 함께 보여 준다. |
| 발췌의 조건·반환·오류 의미, 짧은 함수·한 표현의 범위 | 코드 단위의 세 항목 유지. 원문·생략 표시·설명용 코드의 지위를 유지했다. 압축 과정에서 흐려질 수 있던 한 표현의 범위와 등록/즉시 실행 문장은 다시 명확히 했다. |
| 도입 연결과 본문의 구분·코드/해설/조건 인접 배치 | 설명 구성의 배치 절과 기존 표현 선택 표 유지. 핵심 값·실패 조건 생략 금지, 필요한 연결 반복과 단순 반복 구별을 보존했다. |
| 질문에 직접 답하는 충분성·종료 | 기존 충분성 표와 마무리 앵커 유지. 핵심 답·연결·조건을 찾는 기준이며 시험·고정 출력·필수 두 번 쓰기가 아니다. |
| 설명 제공과 이해·동의, 설명/추천과 실제 변경·수락의 권한 | 별도 권한 절로 분리. 기존 상세에서 오는 마무리 앵커에는 새 권한 절로 가는 연결을 두었다. 기존 위임과 실제 작업/기록 담당의 책임을 유지했다. |
| 조건부 상세 읽기와 배경의 역할 | 전체 요청에서는 구성 방법과 분리한 대비 예시를 함께 읽는다. 짧은 표현 질문에는 전체 예시를 요구하지 않는다. 형성 자료는 목적·구성 재검토용이며 일상 실행 필독으로 바꾸지 않았다. |

작성 상세의 일반 원칙 뒤에 이어지던 긴 인증 전체·후속 구간만 옮겼다. 새 예시 파일에는 진입 조건·본체/작성 상세로 돌아가는 링크·기존 출처 연결을 추가했다. 예시의 설명용 상황을 실제 관찰로 바꾸거나 기존 시험을 새 효과의 근거로 재해석하지 않았다.

## 읽기 경로와 배경 대조

- 전체 코드 설명: 본체의 전체 구성 기준 → 작성 상세의 관계 구성 → 인증 전체·후속 예시. 실제 코드·등록/실행·공유 갱신과 실패 조건을 예시 안에서 계속 함께 읽는다.
- 한 표현 질문: 질문 범위 → 실제 대상과 해설의 짧은 표현 조건. 전체 인증 예시나 모든 상세를 읽도록 만들지 않았다.
- 선택 판단: 요구·사용처·대안과 변경 근거 → 작성 상세의 선택 비교. 역할을 설명할 수 있다는 사실로 선택을 정당화하지 않는다.
- 첫 결과 전달: 원래 목표와 결과 → 필요한 실제 처리 또는 관찰 → 충분성과 권한. development의 작업 결과·확인 책임을 바꾸지 않았다.
- 앞선 말의 이의: 실제 발화 대조 → 원뜻/현재 타당성 → 유지·보완·정정. 해당 상세와 예시는 그대로다.

`_background`의 통합·재보완·코드 동반·전체 구성·흐름 가독성 이유와 대조했다. 본체를 링크 목록으로 줄이지 않고 필요한 조건을 실행 본문에 남겼으며, 동작과 이유를 배타적 파일로 다시 가르지 않았다. 현재 맥락·근거·변경 기록에는 예시 보류 뒤 분리 승인으로 범위가 바뀐 순서를 남겼다. 과거 리뷰·실험 입력·legacy·source는 수정하지 않았다.

## 확인 결과와 한계

- 이동한 인증 전체·후속 구간은 제목 단계 `###`→`##`만 되돌려 비교했을 때 이동 전 구간과 바이트 동일하다. 설명·모든 코드·표·조건·생략 안내를 보존했다.
- 작성 상세의 ‘그럴듯한 요약에서 빠진 처리를 채운다’ 이후 구간은 수정 전과 바이트 동일하다. 동기화·여행·전후 판단·첫 결과 예시는 유지했다.
- 앞선 발화 상세, 공통 설명·근거 기준, development 본체는 변경 전 SHA-256과 일치한다.
- YAML frontmatter 파싱 통과. 이름·description 유지. `git diff --check` 통과.
- viewer 재생성·검사 통과: 문서168개·코드 파일5개가 현재 원문과 일치하고, 내부 링크947개·앵커 링크278개에서 없는 경로/앵커0개. 최초 검사에서 새 배경 기록의 앵커 표기 오류를 찾아 수정한 뒤 재검사했다.
- 브라우저 배치·제품 동작 검사·새 모델 응답 시험은 하지 않았다. 구조 정합성·내용 보존 확인을 응답 품질 개선의 입증으로 취급하지 않는다.
