# 논의와 보존 기록

이 폴더는 이번 설계 작업의 분석·비교·제안·정정·검증 등 보존할 과정을 소유한다. current의 실행 재개에 곧바로 필요하지 않아도 보존 목적이 있으면 남길 수 있다. 과거 기록에 적힌 당시 제안은 현재 채택을 뜻하지 않는다.

분석 기록은 과제 이름 또는 현재 Ticket 번호로 읽을 수 있게 정리한다. 대화 인용과 검증 응답 원문은 그대로 보존하며, 과거 검토를 현재 설계의 실행 결과로 해석하지 않는다. 이 색인의 날짜별 기록 번호는 Ticket 번호와 별개다.

- [01 배경과 평가](2026-10-12-01-background-and-evaluation.md): Noline 경험과 후속 비교가 현재 논의에 주는 근거와 한계.
- [02 기반과 강연](2026-10-12-02-framework-and-lecture-reading.md): ai-workspace의 실제 역할과 강연·관련 스킬의 방식, 그대로 합칠 수 없는 차이.
- [03 제안과 정정](2026-10-12-03-proposals-and-corrections.md): 전체 그림으로의 전환, AI 제안의 지위, 사용자가 바로잡은 범위.
- [04 보존과 검토](2026-10-12-04-preservation-and-validation.md): 사본·링크·새 독자 확인의 실행 결과와 한계.
- [05 Spec·Ticket 초안](2026-10-12-05-spec-ticket-draft.md): 비개발 설계 작업에 Spec·Ticket을 적용한 이유, 일곱 결과로 나눈 근거와 미정, 사용자 요청 원문.
- [06 새 세션의 첫 이해와 원문 대조](2026-10-12-06-fresh-session-rehearsal.md): 이전 대화 없이 현재 문서만 읽은 응답을 먼저 고정하고, 원문 확인 뒤 보완한 해석.
- [07 재진입 확인의 판단](2026-10-12-07-reentry-assessment.md): 실제 응답을 원문과 대조한 Main의 판단, 보강한 강조와 확인 한계.
- [08 Ticket의 순서·크기·구체성](2026-10-12-08-ticket-sequence-review.md): 대표 작업 연결을 먼저 살피는 순서와 당시 분할 제안. 이후 사용자가 분할을 요청한 경위는 09에 잇는다.
- [09 Ticket 분할·번호 정리](2026-10-12-09-ticket-split.md): 상위 01~07과 01·04의 하위 Ticket으로 정리한 책임·구조·참조와 확인 범위.

- [10 Workspace 구성·개선 왕복의 범위 보완](2026-10-12-10-workspace-and-feedback-scope.md): 과거 문제에 한정하지 않는 구성 비교와 프로젝트 경험·공통 기반 개선·재적용의 효율 검토 요청, 초기 후보와 미확인.

- [11 세션 마무리와 다음 시작점](2026-10-12-11-session-close.md): 다른 세션에서 구체화를 이어가는 사용자 선택, 최종 기록 점검과 커밋 범위.

- [12 개발 진행의 첫 비교](2026-10-12-12-development-flow-first-comparison.md): 조회 복구 사례의 직접 근거, 세 진행 방식, 우선 제안과 비용·후속 과제. 미채택 초안.

- [13 구현·품질 검토·실제 검증의 워크플로 비교](2026-10-12-13-implementation-review-verification-workflows.md): 강연·Vercel·현행 구성으로 세 안을 만들고 가상 작업과 과거 사례로 대조한 미채택 설계안.

- [14 검토자 직접 수정과 구현자 수정의 상황별 비교](2026-10-12-14-reviewer-editing-scenarios.md): C 기본 추천의 가정과 한계, B/C의 같은 조건 비교와 남은 판단.

- [15 B 방향 선택과 시작점](2026-10-12-15-reviewer-editing-choice-and-start.md): 검토자 직접 수정의 사용자 선택, Main의 Spec·Ticket 작업 정의와 구현 이후 흐름의 연결.

- [16 B의 인수·수정·최종 검증 상세 초안](2026-10-12-16-b-execution-review-verification-contract.md): 구현자 입력, 검토 기준·수정 범위, 최종 실제 검증과 실패 반환·완료 책임의 제안.

- [17 워크플로의 반영 근거와 연결 설계 제안](2026-10-12-17-workflow-basis-and-connected-design.md): 검토자 최종 실제 확인으로 제안 변경, 자료별 반영과 공백, 같은 장면에서 관련 Ticket을 함께 구체화하는 방법.

- [18 01-02 자료 논의와 기록 체크포인트](2026-10-12-18-quality-materials-next-step.md): 여러 Ticket 동시 구체화 제안에 대한 정정, 01-02 전에 자료를 더 구체적으로 논의하자는 선택과 커밋 범위.

- [19 01-02 설계·테스트 방법과 현행 기준 비교](2026-10-12-19-design-and-testing-methods.md): 깊은 모듈·인터페이스 테스트·의존성·구조 탐색·검토 방법의 가상 예시와 기존 기준의 공통점·차이. 미채택 논의 자료.

- [20 전체 설계와 Spec·Ticket 사용 방향 재검토](2026-10-13-20-overall-design-and-ticket-direction.md): 자료별 설명에서 전체안과 중요한 미결정을 중심으로 논의를 모으자는 검토. 사용자 요청과 미채택 제안을 구분한다.

- [21 전체 잠정안의 Spec 반영과 두 층의 구별](2026-10-13-21-spec-integration-and-two-levels.md): 세션 간 전체 구상을 이어갈 Spec의 실제 보완, 014의 설계 문서와 개선할 시스템의 Spec·Ticket을 구별한 근거.

이전 대화의 보존 범위는 [대화 사본](../source/discussion/conversation.md)과 [자료 안내](../source/README.md)에서 확인한다. 그 뒤 설계 논의의 선택·정정에 필요한 발화는 기록 12~18에 직접 인용했으며, 최신 대화 전체를 source에 다시 저장한 것은 아니다. 다음 해석이 바뀌면 당시 기록을 현재 결론으로 덮어쓰지 않고 새 기록과 current에 이어 준다.
