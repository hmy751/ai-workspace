# 논의와 보존 기록

이 폴더는 이번 설계 작업의 분석·비교·제안·정정·검증 등 보존할 과정을 소유한다. current의 실행 재개에 곧바로 필요하지 않아도 보존 목적이 있으면 남길 수 있다. 과거 기록에 적힌 당시 제안은 현재 채택을 뜻하지 않는다.

분석 기록은 과제 이름 또는 현재 Ticket 번호로 읽을 수 있게 정리한다. 대화 인용과 검증 응답 원문은 그대로 보존하며, 과거 검토를 현재 설계의 실행 결과로 해석하지 않는다. 이 색인의 날짜별 기록 번호는 Ticket 번호와 별개다.

- [01 배경과 평가](2026-10-12-01-background-and-evaluation.md): Noline 경험과 후속 비교가 현재 논의에 주는 근거와 한계.
- [02 기반과 강연](2026-10-12-02-framework-and-lecture-reading.md): ai-workspace의 실제 역할과 강연·관련 스킬의 방식, 그대로 합칠 수 없는 차이.
- [03 제안과 정정](2026-10-12-03-proposals-and-corrections.md): 전체 그림으로의 전환, AI 제안의 지위, 사용자가 바로잡은 범위.
- [04 보존과 검토](2026-10-12-04-preservation-and-validation.md): 사본·링크·새 독자 확인의 실행 결과와 한계.
- [05 Spec·Ticket 초안](2026-10-12-05-spec-ticket-draft.md): 비개발 설계 작업에 Spec·Ticket을 적용한 이유, 일곱 결과로 나눈 근거와 미정, 사용자 요청 원문.
- [06 새 세션의 첫 이해와 원문 대조](2026-10-12-06-fresh-session-rehearsal.md): 이전 대화 없이 현재 문서만 읽은 응답을 먼저 고정하고, 원문 확인 뒤 보완한 해석.
- [07 재진입 확인의 판단](2026-10-12-07-reentry-assessment.md): 실제 응답을 원문과 대조한 Main의 판단, 보강한 강조와 확인 한계.
- [08 Ticket의 순서·크기·구체성](2026-10-12-08-ticket-sequence-review.md): 대표 작업 연결을 먼저 살피는 순서와 당시 분할 제안. 이후 사용자가 분할을 요청한 경위는 09에 잇는다.
- [09 Ticket 분할·번호 정리](2026-10-12-09-ticket-split.md): 상위 01~07과 01·04의 하위 Ticket으로 정리한 책임·구조·참조와 확인 범위.
