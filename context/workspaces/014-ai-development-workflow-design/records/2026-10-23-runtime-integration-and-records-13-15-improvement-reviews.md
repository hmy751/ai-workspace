# 13~15번 두 개선 리뷰와 Main 종합

**두 개선 리뷰 종합 뒤13~15번을 모두 사용자 확정했다.1~15번 설계 합의를 완료했다.** [현재 연결안과 승인 경과](2026-10-23-runtime-integration-and-records-13-15-proposal.md)를 따른다. 아래 미확정 표기는 리뷰 당시 지위다.15번 후속 논의에서Main이 지침·관리 계약을 따라 갱신하고 자동 Maintain은 연결하지 않으며, 추후 스킬 보완은 아이디어로 남기도록 확인했다. 실제 실행 통합·수행 효과 확인은 후속이다.

## 요청과 판단 목적

사용자는7~12번에서 전체안 구체화, 목표·기존 구조·레퍼런스를 제공한 두 개선 리뷰, Main 종합과 항목별 논의를 요청했다.1~12번 확정 뒤13~15번도 같은 방식으로 할 수 있는지 물었고 “계속 진행해줘”라고 요청했다. 최초의 검토 목적은 다음 발화로 유지한다.

> 개선 리뷰어야 검증이 아니라 적당한지 보는게 아니라 끌어올릴 포인트가 더 있나

따라서 이번 리뷰는 요구 위반 유무나 적당함 판정에 한정하지 않았다. 맥락 이해·적용, 사용자 기준을 출발점으로 삼는 구현과 독립 개선 판단, Main의 채택·실제 수정·확인과 지속 기록을 더 잘 연결할 선택을 찾았다. 의견 수나 새 규칙 수를 성과로 두지 않았다.

공통 입력은 [입력 안내와 최소 사용자 원문](reviews/runtime-integration-13-15-2026-10-23/README.md), [고정된 리뷰 전 초안](reviews/runtime-integration-13-15-2026-10-23/proposal-before-review.txt), [주요 입력27개 hash](reviews/runtime-integration-13-15-2026-10-23/input-file-hashes.tsv)로 복원한다. 고정 초안 SHA256은 `da6de3049ee5b7916544af969517da715459162a00a9117cc273acc7e535ff41`이다. frozen 파일의 본문 링크는 원래 `records/` 기준이다. 호출 후·종합 전27개 입력이 그대로였음을 대조했다. 그 뒤 제안과 current를 종합 결과에 맞춰 갱신했으므로 현재 파일이 호출 전 hash와 같아야 한다는 뜻은 아니다.

두 리뷰에는1~12번 합의, 사용자 동적 맥락 의도와 모델 선호 원문, 현재 Spec·01-01·04-03, 실제 development·review·Personal·Project·Work 및 기존 맥락 스킬, Matt·pstack·Vercel 보존판과 shared 독립 검토·배치 기준의 접근점을 제공했다. Main은 현재 runtime 도구와 OpenAI Docs의 [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) 본문을 대조한 범위를 입력 안내에 남겼다. 모든 숨은 자동 입력이나 각 리뷰어의 모든 추가 열람을 manifest가 포괄한다고 주장하지 않는다.

## A — 실행 구성·실제 맥락 전달 리뷰의 핵심 반환

다음은 리뷰어 반환의 핵심 원문 발췌다. 생략한 상세 예시는 아래 Main 처리와 제안 본문에서 관계를 보존한다.

> 13번은 **한정 위임의 실제 진입 경로와, 재사용하는 대화의 낡은 전제를 처리하는 방식**을 보완하면 가장 크게 좋아집니다. 검토자 수를 늘리거나 기본 모델을 높이는 것보다 먼저 할 개선입니다.

> 짧은 의뢰문으로 이 지침을 덮지 않는다는 현재 원칙을 따르면, 좁은 검토도 전체 작업 복구로 해석될 여지가 남습니다.

> 이전 전달 이후 목표·계약·대상·권한이 달라졌다면, 무엇이 바뀌었고 이전 판단·검사 근거 중 무엇을 그대로 사용할 수 없는지 함께 전달한다. 담당자는 영향받는 근거만 다시 읽고 확인한다.

> 반환이 부족할 때 자료 누락·접근 제한·낡은 전제라면 그 입력 문제를 먼저 보완하고, 필요한 근거가 있는데 비교·종합이 부족한 경우 판단 배치를 바꾼다는 정도를 추가하십시오.

A는 실제 demo root·Work 지침이 일반 Workspace 복구를 안내해 한정 위임과 어긋날 가능성을 지적했다. 새 대화라도 긴 과거 진행이 파일로 먼저 들어오면 독립 검토의 초점이 흐려질 수 있다는 설계 위험이며 실제 오판의 관찰로 주장하지 않았다. 첫 적용 때 같은 결과의 일반 재개와 한정 검토를 비교해 필수 계약·사용처 접근과 역할 범위를 살피자고 제안했다.

재사용에서는 최신 지시 추가만으로 이전 성공 기준·권한·검사 근거가 무효화됐음을 알기 어렵다고 봤다. 계약의 의미가 바뀐 가정 장면과 이름만 바뀐 장면을 구별해 영향받는 근거만 다시 확인하도록 제안했다. 모델 기본값은 유지하되 입력 부족과 판단 역량 부족을 구별하고, 실제 기준 적용·의미 있는 유지/개선 판단·Main의 재조사 부담을 대표 적용에서 보자고 했다.

유지 의견은 검토자 한 명, 원 구현자 수정, 필요한 질문만 재검토, 관련 Personal을 숨기지 않는 새 검토와 별도 검증이었다. 두 번째 리뷰어·매 수정 새 대화·전체 입력 기록을 상시 요구할 실익은 찾지 못했다. A는 파일을 수정하거나 역할 실행·모델 효과 비교를 하지 않았으며 긴 current·경과 문서는 관련 부분을 선택해 읽었다고 밝혔다.

## B — 기존 스킬·기록 연결 리뷰의 핵심 반환

> 14~15번을 더 끌어올릴 핵심은 **스킬 이름을 연결하는 데서 실제 호출·반환 책임까지 맞추고, 기록 갱신을 다음 실행의 판단 변화까지 연결하는 것**이다.

> 현재 prototype work-discussion도 Spec·Ticket 갱신을 Maintain에 맡기라고 명시한다.

> development는 필요한 목표·완료 선택을 일반 작업 대화에서 구체화한다. work-discussion을 사용할 때에는 해당 스킬의 호출 조건을 따른다. 자동 연결로 바꾸려면 그 호출 조건과 형성 이유도 함께 재판단한다.

> 목표·계약·기준의 적용 조건을 바꾸면 Main은 그 의미를 이미 사용하는 담당자·기존 결과·확인 근거 중 영향을 받는 부분을 확인한다.

> 중요한 선택이 바뀌면 current와 Ticket의 해당 현재 문장을 새 의미로 고친다. 대체된 다음 행동·미정·승인 상태는 필요한 기록에 보존하고, 현재 본문에 같은 무게로 계속 누적하지 않는다.

B는 work-discussion의 직접 호출 전용 조건과 development·초안의 자동 연결처럼 읽히는 문장, 현재 work-discussion에 남은 Maintain 작성 전제를 대조했다. 일반적인 선택 구체화는 Main이 수행하고 직접 호출 경계를 유지하는 쪽을 추천했다. 자동 호출이 더 낫다는 선택은 별도로 비교할 수 있으나 현재안에 이미 포함된 것으로 취급하면 안 된다고 했다.

기록에서는 파일을 고친 뒤에도 이미 일하는 담당자와 과거 검사가 이전 의미를 쓸 수 있음을 지적했다. 판단 결과를 바꾸는 의미 변화에 한해 영향받는 실행·기존 근거를 잇도록 제안했다. 이는 A의 재사용 전제 갱신과 같은 문제를 다른 쪽에서 보완한다.

또 실제014 Spec·04-03 Ticket 상단에 과거 ‘현재 설계·다음 행동’이 누적된 점을 확인했다. [기록·재개 비교](../source/reading/noline-evaluation/reviews/record-timing-followup.md)에서는 원문 보존·열람이 있었어도 다음 행동의 중심이 어긋난 장면과 정정 이유를 복원한 장면이 구별된다. 문서 배치나 기록 시점이 단독 원인이라는 주장 없이, 현재 목표에서 다음 행동이 나오는 이유를 읽고 복원하는 확인이 필요하다고 제안했다.

B는 explain 진입, 한정 위임, 읽기/쓰기 구별, Personal·Project·Work Owner 분리, 모든 의견을 영구 장부로 만들지 않는 경계를 유지했다. 새 collector·reviewer agent·Work 구조를 추가할 실익은 확인하지 못했다. 관련 본문·형성 자료·보존된 관찰을 읽은 설계 리뷰이며 실제 수행 효과는 시험하지 않았다.

## 확인과 남은 경계

설계 문서·현재 진입점의 로컬 링크와 공백 검사를 통과했고 고정 초안의 hash가 유지됨을 확인했다. 주요 입력 중 종합 뒤 바뀐 것은 제안과 해당 Spec·Ticket 상태뿐이며 실제 prototype·source는 유지했다. 대체된 진행 문장은 [원문 보존](reviews/runtime-integration-13-15-2026-10-23/superseded-current-passages.md)으로 옮기고 새 현재 설명에서1~12번 확정·13~15번 추천·다음13번 논의·실행 적용 미완료를 구별했다. 다른 세션의04-02 explain 변경과 기존 staged 변경은 유지했다.

이 리뷰는 런타임의 모든 자동 입력을 실측하거나 GPT-6.1-sol medium의 품질을 입증하지 않았다. 실제 설치·역할별 수행·재진입 효과는 후속 적용에서 확인한다.13~15번 사용자 확정,6~15번 실행 본문 통합,01-02 기준 통합과01-03 구체 검증 수단, 전체 Ticket·Workspace 완료도 남아 있다. 이번 작업에서 커밋은 수행하지 않는다.
