# 04-02 — 기존 본문과 explain 본체·상세의 차이, 보완 후보

사용자 요청: “그럼 기존 스킬이랑 새 스킬 본체랑 상세를 비교해서 어떤 부분이 약해진 건지 파악해봐. 바로 수정하지 말고 어떻게 보완하면 좋을지 먼저 얘기하자”

**본문 대조 결과, 기존 브리핑의 조사·구현 대응·목적별 종료 요구 일부가 일반화되며 약해졌다. 새 상세에도 유사한 취지는 있지만 기존과 같은 구체적 행동을 모두 요구하지는 않는다.** 반면 앞선 발화 복구의 핵심은 대부분 유지됐다. 문구 차이는 확인 사실, 실제 응답의 차이와 그 문구 사이의 인과는 미확정이다. 이번에는 진단과 보완 후보만 기록하며 스킬·상세·형성 자료를 수정하지 않았다.

대조 대상은 explain/legacy에 보존한 삭제 직전 브리핑·복구 본문, 현재 explain 본체·두 실행 상세, shared 근거 기준, 형성 맥락과 관리 정책이다. 기존 복구 본문은 당시 보류 후보였다는 지위를 유지한다.6.0 medium·6.1 high의 읽기 기록과 최초 응답도 대조했다. 새 스킬 두 실행은 작성 상세를 모두 읽었으므로 상세 파일을 열지 않은 것이 이번 관찰의 원인이라고 설명하지 않는다.

## 1. 변경을 설명하기 위한 자료 선택이 덜 구체적이다

기존 브리핑38행은 “Diff와 함께 변경 후 source, 실제 사용처와 호출 경로를 확인한다”고 요구하고, 전후 차이가 역할·흐름·상태·외부 효과에 미치는 영향을 연결하게 했다. 새 본체29행은 “방금 변경한 결과라면 비교 기준과 변경 후 사용처를” 선택한다고 압축했다. 작성 상세는 현재 관계가 드러나는 처리·조건·호출 선정과 주장을 지지하는 충분성에 집중하며 실제 변경 전후를 대조하는 방법은 별도로 풀지 않는다.

관측: 새 스킬 두 실행은 before/와 전체 diff를 직접 읽지 않았다.6.1 기존판은 Provider와ExpenseRepository의 전후를 읽고 그 차이를 실제 설명에 반영했다. 이 동시 관찰로 특정 문구가 원인이라고 확정하지는 않는다.

보완 후보: 현재 설명하려는 주장이 ‘달라졌다·개선됐다·유지했다’라면 그 말을 판단할 비교 대상부터 고르게 한다. 관련 diff·변경 전후 구현·관찰 중 해당 주장에 맞는 자료를 비교하고, 기존 기반·이번 변경·그 결과를 구별해 설명한다. 모든 before 파일을 전수 읽는 규칙으로 만들지 않는다. 본체는 이 조건과 책임을, 작성 상세는 실제 자료 선정과 대조 방법을 소유한다.

## 2. 실제 구현을 응답에 대응시키는 요구가 표현 수단 선택으로 약해졌다

기존73행은 “실제 코드와 그 의미를 함께 보여 준다”, “파일 위치·함수 이름을 알려 주거나 동작을 요약하는 것만으로 이 대응을 대신하지 않는다”고 명시한다. 새 본체35행은 코드 발췌·표·그림·구체 상황을 관계를 더 잘 따라갈 수 있을 때 선택하게 한다. 작성 상세9행의 ‘코드가 필요할 수 있다’와45행의 예시 곁 설명은 취지를 남기지만, 일반 코드 설명에서 실제 처리와 의미를 응답 안에 함께 드러내야 한다는 요구는 덜 직접적이다.

새 본체에도 관계를 실제 대상과 연결하고 핵심을 링크 뒤로 미루지 말라는 요구는 있다. 따라서 코드 설명을 삭제했다고 말할 수는 없다. 문제는 원자료를 읽어 근거로 삼는 것과 사용자가 그 처리의 의미를 따라가도록 보여 주는 것의 구별이 약해진 점이다.

보완 후보: 구현의 조건·대기·반환·위임이 답의 핵심인 경우 필요한 실제 처리와 그 의미를 응답 안에서 대응시킨다는 책임을 본체에 둔다. 발췌할 단위와 곁에 붙일 설명은 작성 상세가 풀어 준다. 매 답에 코드 블록·도식을 강제하거나 동작·역할 질문을 모든 문법 강의로 넓히지 않는다.

## 3. 작업 목표와 개선 근거를 대조하는 구체적인 방법이 약해졌다

기존31행은 코드 개선에서 ‘기존 동작을 보존했다는 근거’와 ‘책임·중복·변경 부담을 개선했다는 근거’를 구별했다. 관련Spec의 목표·기준,Ticket의 맡은 결과·범위,실제 수행을 연결하는 지시도 있었다. 새 본체43행의 ‘원래 질문에 무엇이 답해졌는지’는 올바른 방향이지만, 무엇을 대조해야 작업 목표에 답하는지의 방법은 압축됐다.

공통 기준에는 국소test와 전체 목표 충족을 구별하는 요구가 남아 있다. 따라서 근거 구분 자체가 없어졌다고 말하지 않는다. 다만 ‘전체 완료가 아니다’라는 한계를 밝히는 것과 ‘이번 목표가 무엇에 의해 얼마나 달성됐는지’ 설명하는 것은 다르다. 시험의 두 판본 모두 이 부분은 약했으므로 구체적인 옛 조항을 되살리면 곧 해결된다고도 주장할 수 없다.

보완 후보: 작업 결과 설명에서는 원래 이루려던 결과를 판단할 근거와 실제 산출물의 차이를 연결한다. 가독성 작업이면 어떤 추적·수정 부담을 줄였고 어떤 동작을 유지·변경했는지 설명한다. 특정Spec/Ticket 파일명을 보편 필수 입력으로 고정하지 않고 실제 목표를 소유한 자료를 선택한다. 본체의 첫 전달 책임과 작성 상세의 선택 이유·관찰 절에 배치하며 shared 기준을 복제하지 않는다.

## 4. 목적별 설명 완료 기준이 일반적인 충분성으로 압축됐다

기존 종료121행은 코드 설명에서 사용자가 해당 코드로 돌아가 주요 처리가 왜 그 결과로 이어지는지 따라볼 수 있도록 설명했는지 확인한다. 전체 구조 설명에는 대표 사건의 결과와 구현 대응을, 진행·선택 설명에는 해결/미해결과 다음 판단의 의미를 확인했다. 새 본체49행은 직접 답·관계·조건이 드러나면 종료한다. 합리적인 공통 기준이지만 요약이 충분한 설명인지 판단하는 구체성이 덜하다.

보완 후보: 현재 질문의 목적에 맞는 충분성을 확인한다. 변경 질문이면 전후의 무엇이 달라졌는지, 동작 질문이면 조건이 왜 그 결과로 이어지는지, 뜻 질문이면 실제 지시 대상과 뜻이 드러나는지 본다. 모든 응답에 모든 항목을 요구하거나 사용자에게quiz·이해 승인을 요구하지 않는다. 스킬을 실행하는 AI의 작성 중 판단으로 둔다.

## 유지할 부분과 이번 진단의 한계

- prior-explanation은 실제 발화의 의미, 현재 사실과 과거 뜻의 구별, 뜻 질문과 타당성 이의, 오류의 유지/정정/철회, 과거 답을 임의로 축소하지 않는 기준을 유지한다. 원래 공유 지점에서 이어 설명하는 책임도 본체·상세에 남아 있다. 현재 실패의 핵심으로 볼 근거가 없어 재작성 우선순위로 두지 않는다.
- 하나의 설명 진입점, 조건부 상세 두 개, 필요 이상으로 범위를 넓히지 않는 선택은 유지할 수 있다. 기존 스킬에도 과잉 조사·분량을 경계하는 문장이 있었으므로 새 스킬이 짧아서 실패했다고 단정할 수 없다.
- 기존의 전체 역할·대표 흐름 우선이 새 공통 본문에서 덜 직접적이 된 차이도 있다. 그러나 이번 응답들은 이미 전체 역할을 제시하므로 이를 핵심 미수행의 원인으로 올리지 않는다. 목적별 충분성에 관련되는 범위에서 검토한다.
- 작성 상세는 한 대목의 자료 선정 예시가 강점이지만, 두 주된 예시는 현재 흐름의 관계와 관찰→결론에 집중한다. 변경 전후를 골라 ‘왜 개선인가’를 만드는 일반 방법이 상대적으로 약하다. 예시를 무조건 추가하는 대신 위 방법과 기존 예시의 역할을 맞추는 편을 권한다. source06의 답을 실행 지침에 그대로 넣어 향후 같은 사례 성공을 유도하지 않는다.

## 제안하는 배치와 선택

본체는 설명 목적, 그 목적에 필요한 비교·근거 선택, 실제 대상과 의미를 응답 안에서 연결하는 책임, 질문 목적에 맞는 종료를 직접 맡는다. constructing-explanations는 변경 전후·동작 조건·선택 이유·목표와 결과의 대조를 실제 작성 방법으로 풀고 예시는 그 선택을 설명한다. prior-explanation은 현재 핵심을 유지한다. _background는 향후 보완을 채택할 때 이 판단과 미확인 원인을 보존할 자리이며 현재 실행을 위해 읽히지 않는다.

새 파일이나 별도시점/유형 스킬을 만들 필요는 현재로서는 없다. 우선순위는1·2의 자료 대조와 구현 대응을 분명히 하고,3·4로 목적·종료를 함께 맞추는 것이다. 옛 조항 전수 이식·기존 길이 복원은 충분성 기준이 아니다. 위 내용은 미채택 보완 후보이며 새 시험·본문 변경은 하지 않았다.
