# 04-02 — 코드 읽기 목적을 반영한 브리핑 통합 후보

사용자는 설명 깊이 대조에서 짚은 부족함을 바탕으로 기존 요구를 중복 추가하지 않고 본문에 통합한 수정안을 요청했다. [시험 판본](experiments/artifact-explanation-auth-depth-sol6-2026-10-22/r85/input/skill/SKILL.md)에 후보를 만들었다. 운영·기존 prototype SKILL.md와 복구 스킬은 교체하지 않았다.

## 기준과 변경

기준은 실제 시험에서 사용한10월21일 통합 후보r74다. 운영 기존판r31에서 직접 고쳤거나, 이 폴더의 더 오래된 보류SKILL.md를 고친 것이 아니다. [설명 깊이 대조](2026-10-22-ticket04-02-code-explanation-depth-gap.md), [6.0 sol 응답](experiments/artifact-explanation-auth-sol6-body-2026-10-22/comparison.md), 원래 형성 자료를 근거로 사용했다. 코드·값 연결 요구가 이미 있다는 사실을 유지하고 적용 조건·수행·종료를 연결했다.

| 본문 위치 | 기존 후보의 약점 | 통합 방식 |
| --- | --- | --- |
| 시작1 | 질문과 목적 확인만으로 설명 깊이를 정함 | 현재·앞선 대화에서 역할·구조 파악과 코드 읽기 도움을 구별하고 문법·코드 어려움의 맥락을 실제 설명에 반영 |
| 추상 설명만으로 차이가 드러나지 않을 때 | 일반 사례를 말한 것으로 충분하다고 판단할 수 있음 | 기존 절을 “질문에 필요한 세부를 펼친다”로 교체. 코드·의미 연결, 필요한 문법·분기·대기·반환·오류 관계와 기존 값·조건·근거 기준을 함께 정의 |

코드 블록 개수·전체 줄별 해설·모든 실패 경로를 의무화하지 않는다. 역할을 먼저 잡고 필요한 처리 단위로 내려가는 기존 순서를 유지한다. 특정 인증 코드의Map·401·Promise 정답을 본문에 넣지 않았다. 단순 전체 역할 질문을 상세 강의로 늘리지 않는 범위를 같은 절에 둔다.

name·description, read-only 권한, 대상별 조사, 문서 결과 연결, 현재성·근거 구별, 구조 표현의 조건, Spec/Ticket과 기록 연결은 유지했다. 공통 설명 기준과 스킬 발동 시점·작업 흐름에 별도 지침을 추가하지 않았다. 기존 입력·중간 값·결과 및 중요한 조건 비교는 새 절에서 책임을 유지한다.

## 확인 범위

skill-creator의 좁은 수정·중복 통합·조건별 상세, SKILLS-CONTENT-POLICY의 실행 본문과 형성 근거 구별, instruction-clarity와 human-readable-structure의 조건·행동·종료 연결을 적용했다. 사용자의 요청은 후보 작성이며 운영 설치·효과 확인은 아니다.

파일에서 frontmatter 동일성, 상대 링크2개, 대상별 조사·구조 표현·근거 경계 절의 동일성, 형식 절에서 옮긴 문장의 삭제와 새 절의 단일 배치를 확인했다. quick_validate는 현재 Python에 PyYAML이 없어 실행되지 않았다. 패키지 설치로 확대하지 않고 메타데이터가 원판과 같음과 본문 구조를 직접 확인했다. 새로운 응답 시험은 하지 않았으며 문구 대조만으로 설명 품질 개선을 확정하지 않는다.
