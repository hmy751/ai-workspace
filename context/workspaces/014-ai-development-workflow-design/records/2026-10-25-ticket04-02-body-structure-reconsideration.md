# 04-02 — 배경을 대조한 본체·상세 구조 재검토

현재 지위: 아래는 당시 제안이다. 후속 논의에서 사용자는 예시 분리를 처음에 보류하고 본체 정리를 승인했다. 작업 중 새 예시 생성이 아니라 기존 예시를 옮기는 뜻임을 확인한 뒤 분리도 요청했다. 실제 채택·확인은 [본체 구조 정리 반영](2026-10-25-ticket04-02-body-organization-adoption.md)을 따른다.

2026-10-25. 사용자: “그전에 스킬 본문좀 구조좀 다시 생각해볼까ㅣ? 나눌건 나누고 너무 이어 붙이지만 말고”. 이어 “_background 들 잘보고 괜히 맥락 또 망치면 안되니까”라고 요청했다. 남은 사례 확인에 앞서 현재 본체의 구성부터 논의한다. 아래는 Main 제안이며 실행 본문·상세·배경 파일 변경과 새 응답 시험은 하지 않았다.

## 배경에서 유지할 의미와 다시 판단한 경계

[현재 형성 맥락](prototypes/development-workflow/skills/explain/_background/context.md), [근거 발췌](prototypes/development-workflow/skills/explain/_background/evidence.md), 통합·재보완·최근 구성·가독성 기록, 이전 briefing/recovery의 README·context와 [통합 개선 리뷰](2026-10-23-ticket04-02-composition-improvement-review.md)를 대조했다. 배경 전체의 모든 보존 파일·원자료를 전수 재검증한 것은 아니다.

- 목적은 사용자가 실제 대상과 선택을 이해해 자기 판단을 이어가게 하는 것. 모든 설명을 다음 행동 결정이나 재질문 제거로 좁히지 않는다.
- 기존 두 스킬을 제거한 전제는 유지한다. 짧은 본체를 만들려고 필요한 행동을 잃지 않되 옛 조항 전부를 복원하지 않는다.
- 통합 당시 ‘관계·동작’과 ‘이유·근거’의 별도 상세는 자료 선정·조건 비교가 겹쳐 한 작성 상세로 합쳤다. 리뷰는 파일 두 개가 영구 정답이라고 한 것이 아니지만, 현재도 같은 코드·조건에서 동작과 이유를 함께 설명하므로 둘을 배타적 파일로 다시 가를 근거는 약하다.
- 앞선 발화 상세는 과거 문장의 뜻과 현재 사실·타당성을 각각 대조하는 별도 수행이 있어 유지한다. 후속 질문이라는 이유만으로 복구로 보내지 않는다.
- 본체는 공통 수행을 직접 소유한다. 상세 링크 목록만 남기거나 작성 방법 전체를 다시 조립하게 만들지 않는다.
- 실제 코드 동반, 전체 요청을 국소 해설로 대신하지 않음, 첫 결과의 목표 연결, 역할 설명과 적절성 판단의 구별은 반복 교정으로 구체화한 요구다. 구조 정리를 이유로 ‘필요하면’ 수준으로 약화하지 않는다.

## 현재 본체의 구체적인 구성 문제

첫 절에는 질문 범위, 코드 동반, 전체 관계의 구성, 등록/실행·독립 경로, 앞선 말 대조, 첫 결과 전달이 함께 들어 있다. 다음 절에서 구현 연결·첫 결과·선택 판단·상세 선택이 다시 나타난다. 형식 절과 종료 절에도 범위·조건·재설명 원칙이 반복된다. 선택과 근거 절은 일반 자료 확인과 조건부 적절성 판단, 추가 조사 책임을 함께 가진다. 마지막 절은 충분성, 사용자 이해의 미확인, 정정, 작업 권한과 기록 책임을 함께 다룬다.

이 내용은 대부분 필요한 요구지만, 적용 조건과 책임 위치를 찾기 어렵게 분산돼 있다. 이 구조가 실제 응답 편차의 원인이라고 입증된 것은 아니다. 길이·제목 수보다 같은 판단이 정의되는 위치와 읽기 경로를 정리할 문제다.

## 본체의 권고 구성

| 본체의 묶음 | 소유할 판단과 행동 |
| --- | --- |
| 목적·질문 범위와 상세 선택 | 무엇을 이해하려는지, 이미 공유한 내용, 전체/국소 범위, 뜻과 적절성·앞선 주장 구별. 첫 결과에서도 원래 목표와 결과를 설명할 책임. 조건에 맞는 상세를 연결하되 배타적 모드를 고르게 하지 않는다. |
| 자료 확인과 판단 | 현재 답을 바꾸는 사실 확인, 당시 의도와 현재 효과, 비교 주장에 맞는 전후 근거, 사실 공백이 있으면 맡은 작업으로 돌아가는 판단. 공통 근거 기준의 조건부 연결. |
| 설명 구성 | 관계가 설명 순서를 정하고 실제 대상·코드·조건·결과가 답 안에서 연결되게 한다. 코드 역할·흐름 요청의 실제 코드 동반, 코드와 해설의 인접 배치, 의미별 묶음과 문단 구분은 공통 기준으로 직접 남긴다. |
| 충분성 | 현재 질문의 범위와 필요한 연결이 답에 있는지, 전체 요청의 누락이나 짧은 질문의 과잉이 없는지 확인한다. 추가 절차나 출력 양식으로 만들지 않는다. |
| 권한과 다른 책임 | 설명·추천과 실제 변경·제품 수락, 설명 제공과 이해·동의, 작업 담당의 결과/조사·기록 책임을 구별한다. 충분성 판단 속 긴 문단에 숨기지 않는다. |

위는 스킬 지침의 내부 구성이며 사용자 답변의 고정 순서·목차가 아니다. 조사할 내용, 답변에 보여 줄 내용, 마무리와 권한을 같은 목록에 섞지 않는다. 같은 원칙은 소유 절에 정의하고 다른 절에는 필요한 적용 관계만 남긴다.

## 본체에서 상세로 옮길 내용과 남길 내용

- 본체의 등록/실행·계속 관측/선택적 작업 구별에 관한 긴 설명은 전체 흐름 작성 방법으로 이동한다. 본체에는 독립 경로를 잘못된 단일 순서로 만들지 않는 핵심과 읽기 조건을 남긴다.
- 코드 단위를 고르는 세 항목의 상세한 방법은 작성 상세의 실제 처리 선택 절에서 소유한다. 본체에는 역할·조건·반환을 이해할 실제 코드와 인접 해설이 필요하다는 기준, 발췌가 의미를 왜곡하지 않아야 한다는 제약을 유지한다.
- 동작 설명과 적절성 판단은 본체에서 구별하고 작성 상세에서는 같은 자료의 어떤 조건을 더 비교해야 하는지 연결한다. 선택 판단을 다른 파일로 보냈다는 이유로 코드 설명에서 이유를 없애지 않는다.
- 첫 전달은 본체의 적용 책임으로 남긴다. 첫 결과의 사실·완료 판단은 development가, 설명 방법은 explain이 계속 맡는다. 새 별도 첫 전달 모드나 전용 실행 스킬은 만들지 않는다.
- 과거 발화 복원·유지/정정·새 의미 소급 금지는 prior-explanation이 소유하고 본체에서는 조건과 핵심 경계를 안내한다. 이미 있던 복구 예시를 모두 공통 본체로 가져오지 않는다.

## 상세와 긴 예시의 계층

권고하는 최소 파일 변화는 현재 두 상세를 유지하고, 길어진 인증 전체/후속 예시 한 묶음을 `references/examples/auth-flow.md`로 분리하는 것이다. 현재 작성 상세의 긴 인증 예시가 일반 방법과 다른 사례에 도달하기 전에 대부분의 분량을 차지한다. 원자료를 설명으로 만드는 방법과 특정 코드의 완성 예시를 구별하면 해당 예시의 수정·소비 경계가 분명해진다.

`constructing-explanations.md`는 전체/부분의 관계 구성, 실제 처리와 이유 연결, 선택·전후 비교, 작업 결과의 목표 연결을 방법별로 정리한다. 동기화·여행·보고서의 짧은 예시는 각 판단 가까이에 둔다. 여행의 역할 설명과 적절성 판단을 대비하는 예시는 같은 묶음에 유지한다. 비교해야 뜻이 생기는 내용을 파일별로 잘라 놓지 않는다.

`auth-flow.md`에는 현재 인증 전체 설명과 같은 코드의 후속을 함께 보존한다. 전체→후속의 범위 대비, 실제 코드·등록/실행·공유 갱신·실패 조건, 예시의 출처와 한계를 유지한다. 실행에 쓰는 예시이므로 `_background`로 보내지 않는다. 전체 흐름을 구성하는 요청에서 이 대비 예시를 읽는 현재 책임을 유지해 작성 상세에서 명시적으로 연결한다. 단순 표현 질문은 그 예시 전체를 읽을 필요가 없다. 중첩 목차용 INDEX나 사례마다 빈 파일을 만들지 않는다.

폴더 수·본문 행 수를 목표로 삼지 않는다. 이번 권고는 ‘공통 본체 → 수행 상세 → 필요한 긴 예시’의 읽기·수정 단위 구분이며, 파일 분리 자체를 수행 개선이라고 주장하지 않는다.

## 적용 전에 대조할 것

채택되면 현재 각 요구를 본체 유지·상세 이동·동일 의미 중복 통합 중 어디에 두었는지 대조한다. 실제 코드·조건은 이동 전후 확인하고 전체 흐름, 짧은 표현, 선택에 대한 질문, 첫 결과, 앞선 말의 이의에서 읽기 경로와 권한을 확인한다. 중요한 기준이 상세 이동 때문에 선택 사항처럼 약해지거나 모든 상세를 일괄 읽게 되지 않아야 한다.

현재 스킬 안내·본문·prior-explanation의 상세 링크와 예시 출처, viewer를 함께 맞춘다. 과거 실험 입력·옛 본문·원자료는 보존한다. 실제 변경을 채택할 때 `_background/context.md`에는 현재 구조와 남긴 이유를 맞추고 변경 기록·근거를 잇되 과거 리뷰와 선택을 새 결론으로 덮지 않는다. 형성 자료를 실행의 필독 자료로 만들지 않는다.

참고한 작성 기준은 `skill-creator`의 실질적 본체·조건부 상세와 [로컬 본문 정책](prototypes/development-workflow/skills/SKILLS-CONTENT-POLICY.md), `ai-system_instruction-clarity.md`의 요구·조건·이유 구별이다. 외부 파일 구조를 그대로 채택하지 않았다. 새 reviewer·모델 비교는 이번 요청에서 실행하지 않았다. [앞선 남은 문제 지도](2026-10-25-ticket04-02-remaining-problems-review.md)는 유지하며 구조 논의를 먼저 진행한다.
