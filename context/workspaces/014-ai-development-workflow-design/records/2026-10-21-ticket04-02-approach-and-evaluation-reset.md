# 04-02 — 문제 해결 접근과 검증 범위를 다시 잡는다

2026-10-21. **두 스킬 본문 수정이 해법이라는 전제와 재설명 A/B 중심의 접근을 재검토했다.** 기존 수정안은 보류한 후보로 보존한다. 이번에는 스킬·prototype을 수정하거나 추가 응답 시험을 실행하지 않았다. 원자료 검토와 실험 방법 검토를 별도 주체에게 맡겼고 main이 실제 기준·평가 원문과 대조했다. 사용자 이해 개선이나 새 해법 채택을 확정한 기록이 아니다.

제3자 역할은 셋으로 나눴다. `explanation_source_review`는 원자료 순서·발화·보존 범위를, `explanation_method_review`는 실제 시험 입력·판본·평가·방법을 읽기 전용으로 검토했다. `explanation_advisor`는 현재 대화에서 해법 선행 접근 자체를 조언했으며 source를 직접 읽지 않았다는 한계를 밝혔다. 세 주체 모두 새 해법이나 사용자 acceptance를 결정하지 않았다. main은 역할·자료 범위가 다른 이 결과를 종합했으며, 같은 의견이 나온 수를 효과의 증거로 세지 않는다.

## 이번 정정과 판단 변화

사용자 원문:

> 검증방법도 좀 잘 생각해봐 이미 내가 교정해서 뭐 도식화할거하고.. 뭐 이런 발화 부터 테스트 하면 당연히 차이가 없지
>
> 결과가 좋았다하는데 사실 내가 지시한거 디테일하게 보면 도식화 미리 내가 요구하는것도 있고 또 근본적 역할을 하면서 실제 대화에서 추가요청했잖아?
>
> 추가로 애초에 이 문제를 해결하기 위한 접근법이나 해결 방법 등등 이런게 잘못됐다고 봐 그러니까 지금 계속 삥삥돌잖아? 좀 제대로 확인해봐

원래 결과는 사용자가 작업물을 이해하고 자기 판단으로 질문·선택할 수 있도록 필요한 조사와 설명을 제공하는 것이다. 두 SKILL.md를 반드시 바꾸는 것이 결과가 아니다. main은 원래 요구와 기존 계약을 대조하고도, 특정 사용자 교정을 본문 문구로 옮긴 뒤 이미 교정된 질문으로 답을 비교했다. 두 답이 비슷하면 다른 장면을 고르고, 나중에는 기존판 유지 쪽으로 결론을 넓혔다. 이 방식은 어떤 공백을 어떤 개입으로 해결하는지 판별하지 못한다.

직전의 ‘첫 전달 시점’ 정정도 유지하되 그것만을 새 단일 원인으로 삼지 않는다. 원문에는 이미 브리핑을 선택한 장면, 조사 자체가 부족한 장면, 교정 하나에 집중하며 다른 요구를 잃는 장면, 실제 코드 구조를 재판단한 장면이 함께 있다.

## 기존 계약을 읽고도 해결 방법부터 정했다

- 기존 briefing은 전체 역할, 중요 이름의 책임, 대표 흐름, 구체 값, 조건부 구조 표현과 실제 조사 책임을 이미 갖고 있다.
- 기존 [실행 기준](../source/noline-baseline/context/work/workspaces/spec-and-tickets/EXECUTION-CRITERIA.md)은 사용자 보고에서 변화·충분성 이유·근거·남은 문제를 설명하라고 요구한다.
- [공통 설명 기준](../source/noline-baseline/context/project/guidance/explanation-and-evidence-criteria.md)은 해당 스킬이 적용될 때 소비하는 계약이다. 이 조건은 첫 보고와의 연결을 살필 이유이지 자동 발동을 넓혀야 한다는 증명은 아니다.
- 원래 [설계](../source/research-basis/09-tripproof-cognitive-debt/05-current-solution-design.md)는 작업 경계 강제 호출이나 독립 검토에 별도 입력·대조 기준·소비자 설계가 필요하다고 남겼다. 설명 스킬에 그 책임을 암묵적으로 추가하지 않았다.
- 별도 검토에서 두 스킬과 guidance 기준판은 보존된 역사 blob과 일치했다. 기준판이 틀려서 비교가 실패했다는 근거는 없다. 공통 guidance도 실제 의존성이므로 차이를 만들기 위해 제거하지 않는다.

따라서 장면별로 ‘규칙 부재 / 필요한 시점에 접근되지 않음 / 읽었지만 적용하지 않음 / 사실 조사 부족 / 구현·선택 자체의 문제’를 구별한다. 발동 선언만으로 본문을 읽고 수행한 사실을 인정하지 않고, 현재 실험의 성공으로 과거 원인을 확정하지 않는다.

## 기존 비교에서 남길 것과 철회할 것

원문·판본·동일 입력·최초 응답·해시와 독립된 응답 생성은 보존할 실험 기록이다. 다만 해당 조건에서 후속 요청에 어떤 응답을 만들었는지까지만 말한다.

- 일정 시험은 이미 역할·도식·화면 흐름·코드를 요구한2499에서 시작했다.
- 인증 briefing은 ‘도식화할 건 하고’를 포함했고, 역할과 도식이 구성된 과거 답1546 전체를 입력했다.
- 인증 recovery와 UTC는 혼란·정정 요구가 이미 드러난 뒤의 대응이다.
- 전부 스킬을 지정했고 실제 제품 조사·실행을 제공하지 않았다. 자연스러운 선택·첫 전달·조사 책임을 시험하지 않았다.
- 평가자에게 판본을 숨기는 것과 사용자 의도 근거를 숨기는 것은 다르다. 전자는 독립 비교에 유용하지만 후자는 잘못된 기준을 만들 수 있다.

‘여러 항목을 포함했다’는 관찰과 ‘사용자가 덜 교정해도 판단할 수 있다’는 효과를 분리한다. 차이가 작다는 사실로 수정안 유효/무효, 기존판 유지, 전체 문제 해결을 결정하지 않는다. 두 판본이 같은 핵심을 놓친 경우도 검사한다.

## 해법을 선택할 수 있게 하는 검증

### 먼저 문제와 필요한 자료를 고정한다

한 사건을 첫 요청·조사·첫 전달·후속 교정까지 연결하고, 사용자에게 필요했던 판단, 첫 결과의 공백, 당시 AI가 가진 사실·기준·권한을 적는다. 과거 후속 답을 이상적인 정답으로 삼지 않는다. 필요한 학습·새 설계 질문은 설명 교정 부담과 구별한다.

현재 source에는 제품 코드·DB·앱 환경 전체가 없다. 정확한 당시 조사·첫 결과 재현에는 사건 시점의 코드·변경·관찰 근거가 필요하다. 지금의 완성 설명으로 그 부재를 메우지 않는다. 자료가 충족되지 않으면 충분한 자료가 있는 실제 작업이나 명시적으로 구성한 별도 과제를 사용하고, 역사 재현이라고 부르지 않는다. 외부 저장소 접근 권한은 원문 링크만으로 확대하지 않는다.

### 실제 선택과 본문 수행을 구별한다

먼저 원래 작업 요청과 그 시점의 자료·평소의 스킬 선택 환경에서 첫 결과를 관찰한다. 특정 스킬이나 도식·역할 순서를 시험자가 지정하지 않는다. 실제 사용자 요청에 그런 조건이 이미 있다면 삭제해 과거 재현이라고 부르지 말고 더 앞선 시점 또는 별도 과제를 선택한다. 그 시점에 유효한 사용자 선호는 정당한 맥락으로 유지한다.

실제 host 선택 환경을 복원할 수 없다면 모의 선택 시험이라고 명시한다. 무엇을 읽고 조사하고 판단했는지 기록하며 스킬 이름 언급만을 성공으로 세지 않는다. 빠진 책임이 보이면 기존 스킬을 명시하거나 필요한 사실을 제공하는 별도 실행으로 원인을 좁힐 수 있다. 이는 원인 구분 보조이며 완전한 인과 증명은 아니다.

| 관찰 | 우선 검토할 개입 |
| --- | --- |
| 자연스러운 수행은 부족하지만 동일 사실에서 기존 스킬 지정 후 충분 | 적용 시점·정보 접근·작업 책임 연결. 문구 추가를 먼저 하지 않는다. |
| 스킬을 지정해도 근거를 못 찾고 사실 제공 후 설명 가능 | 조사·인계 책임과 자료 접근. 표현만 수정하지 않는다. |
| 충분한 사실·기존 요구를 읽고도 중요한 연결을 반복해서 놓침 | 해당 행동을 바꾸는 최소 본문 변경. 중복 요구 추가로 대신하지 않는다. |
| 설명은 명료하나 실제 선택·구현이 목표와 맞지 않음 | 구현·검토·재판단. 설명이 설득력 있다는 이유로 완료하지 않는다. |
| 변경 뒤 길이·보고·읽기만 늘고 판단은 나아지지 않음 | 변경을 채택하지 않거나 줄인다. |
| 기존 구성이 해당 조건에서 충분함 | 그 조건의 추가 개입 필요성을 낮춘다. 과거 원인·사용자 이해 완료까지 확정하지 않는다. |

### 평가자가 알아야 할 것과 몰라야 할 것

응답 생성자는 그 시점의 과제·유효 맥락·원자료만 받는다. 이후 교정, 수정 의도, 완성 답, 평가용 기대 연결은 받지 않는다. 평가자는 판본·main의 선호를 모르되 원래 요구, 실제 사실, 필요한 후속 사용자 근거를 받는다. 나중에 생긴 새 요구를 과거의 의무로 소급하지 않는다.

실행 전 질문에 맞는 판단 기준을 고정한다. 예를 들어 보고서라면 기존 문제 중 무엇이 해결됐고 무엇이 남았는지와 그 근거를 찾을 수 있는지, 코드 설명이라면 주체의 존재 이유가 실제 입력·동작에 어떻게 연결되는지다. 표·그림·역할 문장 수를 정답으로 삼지 않는다. 과거 사용자 답을 맞히는 시험도 아니다.

최소 변경을 선택한 뒤에만 동일 조건 비교, 소수 독립 반복, 다른 사건으로의 적용과 짧게 답해야 하는 대조 사례를 본다. 수정한 사례만 반복해서 통과할 때까지 다듬지 않는다. 비교에서 나빠진 부분과 읽기·조사 비용도 남긴다. 실제 사람의 이해는 AI 판정으로 대신하지 않으며 실제 사용에서 반복 교정 부담과 자기 판단에 도움이 되는지 관찰한다. 별도 퀴즈나 재진술을 사용자에게 강제하지 않는다.

## 현재 작업에 반영한 범위

기존 수정안을 다음 채택 대상으로 자동 진행하지 않는다. 우선 사건별 공백과 실제 책임을 연결하고 그에 맞는 개입을 선택한다.01-01과 연결된 첫 보고 책임을04-02 밖으로 밀어내지 않되, 전체 개발 체계를 이번에 새로 만들지도 않는다. 두 스킬을 유지·축소·변경하거나 실행 연결을 보완하는 결론 모두 열려 있다. 현재 상태·Ticket·산출물 진입점은 이 판단으로 맞추고 원래 응답·평가 기록은 그대로 남긴다.
