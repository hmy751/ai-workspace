# 02 — 다음 작업 정정에서 문서별 내용과 중복 비교

2026-10-30. **현재 행동·과제의 판단·판단이 바뀐 경위를 각각 필요한 위치에서 설명하고, 입구마다 상세 계획을 다시 관리하는 중복을 줄이는 안**을 추천한다. 기존 파일 구성을 유지한 채 내용 책임을 먼저 대조한 검토안이다. 아직 채택·실제 재배치·운영 시험을 하지 않았다.

## 비교하는 장면과 판본

사용자는02 재개 기록을 먼저 커밋한 뒤 이번 다음 작업 정정으로 각 문서에 남길 내용과 허용할 중복을 구체적으로 보자고 요청했다. 재개 기록은 `04daae75`에 보존했다.

01-02에서 Main이 ‘날짜 사례의 본문 반영’을 다음 순서로 권했지만, 사용자는 왜 그 작업이 필요한지 물었다. Main은 과거 사례의 미반영만으로 필수 보완이 되지는 않는다고 정정했다. 이어 초대 사례에 현재 기준을 대입했고 기준 유지와 마감 검토로 이어졌다. [책임 배치 기록](2026-10-29-ticket01-02-responsibility-sufficiency.md), `e9bd8bb9`의 실제 diff가 정정과 후속 검토의 보존 근거다.

해당 커밋은 기록과 색인을 포함해7개 문서를 바꿨다. 그중 Workspace README·current/index·state·Ticket 색인에서 ‘날짜/계산 경계가 다음 과제’라는 안내를 함께 고쳤다. 파일 수 자체를 문제 점수로 삼지는 않는다. 핵심 관찰은 같은 다음 계획을 여러 입구에서 반복 관리했다는 것이다. 이 장면에서 잘못된 재개가 실제로 발생한 것은 아니다.

**아래 문안은 날짜 우선 제안을 정정한 직후, 책임 배치 확인과 마감 전에 남겼다면 좋았을 예시다.** 당시 파일의 원문 복원이 아니며 현재01-02 완료 상태를 되돌리는 수정안도 아니다.

## 각 문서에서 직접 읽을 수 있어야 할 내용

### state — 지금 이어갈 일과 선택 이유

> 01-02의 표현 기준 반영은 마쳤다. 다음은 현재 기준으로 구조 유지·변경을 판단할 수 있는지 기존 초대 사례에 대입한다. 과거 날짜 사례가 본문에 없다는 이유만으로 추가 작업을 만들지는 않는다. 세부 판단 조건은01-02 Ticket, 이 방향으로 바꾼 이유는 정정 기록에서 확인한다.

현재 결과·중심·첫 행동과 그 행동을 고른 짧은 이유를 직접 제공한다. 다음 세션이 이유를 알기 위해 과거 대화를 다시 조립하게 하지 않는다. 과거 추천과 사용자 정정의 전체 순서, 비교표 전문은 반복하지 않는다. state는 이번 Workspace 전체의 행동 선택을 맡고, 각 Ticket의 모든 실행 단계까지 복제하지 않는다.

### 01-02 Ticket — 과제의 현재 범위와 판단 기준

> 표현 기준은 반영됐다. 남은 것은 기존 기준으로 유지·분리·수정의 선택을 설명할 수 있는지 확인하고 완료 조건을 종합하는 일이다. 날짜 사례의 추가 반영은 필수 완료 조건이 아니다. 실제 판단의 부족이 드러나면 관련 사례를 다시 사용한다.

이 과제에 직접 들어온 수행자가 범위·완료 조건·현재 결과·열린 판단을 알 수 있게 쓴다. 정정의 현재 효력은 직접 남기되, 당시 대화·제안 경위를 모두 붙이지 않는다. Workspace의 병렬02·06 중 무엇부터 진행할지는 state가 소유한다. Ticket에도 해당 범위의 구체 다음 행동을 둘 수 있지만 state의 전체 우선순위를 별도로 재정의하지 않는다.

### records — 제안·정정·근거의 경위

> Main은 예전 날짜 사례가 현재 본문에 없다는 점을 근거로 추가 반영을 권했다. 사용자는 왜 지금 필요한지 물었다. 재검토 결과, 미반영만으로 필수 과제가 되는 것은 아니므로 기존 기준을 실제 코드에 대입해 부족을 먼저 확인하기로 했다. 날짜 사례는 필요할 때 사용할 재료로 남겼다.

이 설명에 핵심 발화·기존 제안의 위치·판본·확인 한계를 붙인다. 정확한 문구가 판단에 필요하면 최소 원문을 보존한다. 이 사례에는 사용자의 “이게 왜 나ㅗㄴ건지 잘 모르겟네”와 Main의 답 중 “과거에 다룬 사례가 본문에 없다는 이유만으로 다음 필수 과제가 되는 건 아닙니다”가 정정의 핵심이다. 질문만으로 사용자가 모든 사례 추가를 금지했다고 해석하지 않는다.

당시 현재 판단의 짧은 요약이 Ticket과 겹쳐도 남길 수 있다. records는 당시 선택을 복원하는 문서이므로 시간이 지나도 지금의 지시처럼 갱신하지 않는다. 후속 마감과 새 선택은 연결로 이어 주며, 이전 제안이 처음부터 없었던 것처럼 고치지 않는다. 다음 행동에 직접 쓰이지 않는 분석·대안도 후일 재검토 가치가 있으면 보존한다.

## 허용할 중복과 줄일 중복

- **읽는 자리의 판단에 필요한 뜻은 직접 남긴다.** state의 ‘날짜를 먼저 하지 않는 이유’와 Ticket의 ‘날짜 반영은 필수 완료 조건이 아님’은 같은 결정에 근거하지만 서로 다른 질문에 답한다. 한쪽을 링크만 남기면 단독 재개·한정 위임에서 핵심 조건을 놓칠 수 있다.
- **진입점의 짧은 요약은 담당 본문에 의존한다.** 식별·현재 상태·선택한 작업은 필요한 곳에 요약할 수 있지만, 상세 순서·미정 목록·검사 수치·정정 경위를 여러 입구에서 각각 관리하지 않는다. 판단의 정본을 지정하고 요약이 있는 곳만 의미가 바뀔 때 맞춘다.
- **과거의 요약과 현재 상태를 같은 값으로 맞추지 않는다.** 기록 당시 선택은 역사적 사실로 남고, 현재 문서만 새 선택을 따른다. 폐기된 계획이 여전히 현재처럼 보이는 실제 진입은 정리하되 모든 과거 문서에 새 결론을 덧붙이지 않는다.
- **같은 변경에 모든 문서를 갱신하지 않는다.** 이 역할 분담이 적용돼 있다면 이번 정정은 state·해당 Ticket·정정 기록과 기록 색인을 중심으로 처리할 수 있다. 실제 기존 입구에 오래된 계획이 복제돼 있다면 최초 정리에서 그 복제도 함께 고쳐야 한다. 새 추천을 핑계로 기존 오해 경로를 남기지는 않는다.

## 확인과 다음 판단

Main이 실제 커밋 diff와 정정 대화, 기록·현재 문서의 역할을 대조해 만든 배치안이다. 별도 독자의 재개 성공이나 수정 부담 감소를 실험한 결과가 아니다. state만 읽는 전체 재개, Ticket부터 읽는 한정 수행, records로 돌아오는 재검토에서 필요한 의미를 각각 직접 제공하도록 문안을 비교했다.

먼저 이 장면에서 허용할 요약과 정본의 관계를 논의한다. 이후 작은 작업·장기 작업·완료 후 재검토에서 구조·분량을 비교하고, 필요하면 실제 문서에 적용한 뒤 읽기 경로를 확인한다. 자동 Maintain·Work background·Reference/Noline의 적용 여부는 이 예시만으로 결정하지 않는다.
