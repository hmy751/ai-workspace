# 본문 관리 정책 재적용과 Work 보류의 마무리

사용자가 “그래 그럼 기록할거 하고 커밋 해두고 이번 작업에서 뭐뭐 남겨놧지?”라고 요청했다. 이 기록은 기준 커밋 `33c1fee` 이후의 정책 보완·재적용·후속 정정에서 **현재 남긴 결과와 다음에 논의할 것**을 모은다. 114~116에 적힌 당시의 “커밋을 포함하지 않았다”는 범위와 달리, 이번 요청은 기록 정리와 커밋을 포함한다.

## 남은 논의와 재개 지점

1. **Work의 기존 체계와 형성 맥락의 관계.** 이미 있는 Spec·Ticket·current·source·output·records가 어떤 역할과 갱신 제약을 갖는지 먼저 보고, 의도·배경·선택 근거를 어디서 어떻게 다룰지 논의한다. Work의 영구 제외나 새 폴더 도입을 결정한 상태는 아니다. [116](2026-10-20-116-defer-work-content-policy.md)의 사용자 정정과 복구 결과에서 재개한다.
2. **진입 문서의 역할과 구성.** DEVELOPMENT·Spec·Ticket 작성 기준·Project 관리 진입을 어떤 이름과 위치로 유지할지, 실질 본문과 진입 역할을 어떻게 연결할지 논의한 뒤 변경한다. 일반 본문에 형성 자료를 붙이는 작업이 진입 전체 재편을 자동으로 뜻하지 않는다. [115](2026-10-20-115-complete-body-moves-and-restore-entries.md)의 복구 이유를 보되, 그때 Work에 보조 자료를 유지한 선택은116으로 대체됐다.
3. **Personal·Project의 관리 단위와 내용 충분성.** 관련 계약·가이드가 각각 독립 단위를 가져야 하는지, 지금의 형성 설명과 근거가 실제 수정 판단에 충분한지는 열려 있다. 현재 배치의 적용과 전체 품질 수용은 구별한다. [114](2026-10-20-114-durable-body-policy-and-reapplication.md)의 실제 결과·자료 공백·검토 한계를 참고한다.
4. **후속 워크플로와 스킬 구체화.** 입력 선택·전달, 구현·검토·최종 확인의 책임과 기존 스킬의 관계는 후속 작업이다. DEVELOPMENT의 본체·진입 역할도 그때 함께 구체화한다. [103](2026-10-19-103-prototype-session-checkpoint.md)과 [현재 다음 행동](../current/state.md#다음에-이어갈-일)을 잇는다. 이번 정리를 관련 Ticket 완료나 운영 설치로 올리지 않는다.

## 무엇을 확인했고 어디까지 보존했는가

최종 Work는 기준판과 파일 목록26개가 같고,7개 파일의 Project 링크 목적지15곳 외에는 모든 내용이 같다. Main과 별도 검토자가 직접 대조했다. [대조 결과](receipts/work-policy-deferral-2026-10-20/baseline-check.json)

[최종 표시 검사](receipts/work-policy-deferral-2026-10-20/viewer-check.json)는 문서112개·코드5개의 표시 원문·해시 일치와 내부 링크643개·앵커191개를 확인했고 경로·절 누락은 없었다. 제품 코드와 테스트, 루트·014의 보존 source에는 변경이 없다. 브라우저 렌더링 실측과 제품 테스트 재실행은 하지 않았다.

114의 새 작업자 적용·독립 검토·복사본 변경 실험,115의 진입 복구,116의 Work 복구를 각 단계의 관찰로 남겼다. 정정 전 실험을 현재 배치의 장기 유지 보장으로 해석하지 않는다. 복구 전 Work 자료는 [보류된 구성 사본](receipts/work-policy-deferral-2026-10-20/work-before-deferral.zip)에만 보존하며 현재 독자의 입력으로 연결하지 않는다.

마무리 점검에서는 바깥 작성 기록·진입 문서19개의 로컬 경로567개에 누락이 없음을 확인했다. 보류 사본의45개 파일은 압축 무결성과 보존한 해시가 일치했다. 별도 검토에서 발견한114와 state의 오래된 “현재” 표현은 당시 상태로 바로잡았으며, 변경 범위가014 안에 한정됨을 확인했다. 스테이징한 변경의 공백 검사에서는 보존용 `edits.diff`의 빈 문맥 행 접두 공백14개만 경고했다. 이는 diff 형식에 필요한 원문이어서 보존했고, 해당 근거 파일을 제외한 전체 변경은 검사를 통과했다.

이번 커밋 범위는014 Workspace의 위 결과·작성 기록·검사 근거와 진입 안내다. 기록을 포함하는 실제 커밋과 변경 파일은 Git 이력에서 확인한다. 다음 세션은 [current 진입](../current/index.md)에서 현재 범위를 확인하고, 판단하려는 항목의 실제 본문과 위 기록을 선택해 읽는다.
