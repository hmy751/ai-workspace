# 협업 경험 보존·반영안의 개선 리뷰와 보완

2026-10-27. **개선 리뷰 한 명 완료, 중요한 세 의견을 제안에 반영했다.** 기본 Work·Personal·스킬 배치를 유지하면서 실제 재사용 연결과 사용자 자신의 판단 방법을 보완했다. 당시 결과는 [보완 제안](2026-10-27-ticket05-collaboration-learning-proposal.md)이다. 제안의 개선이며 구조 설치·실제 협업 효과 확인·05 완료는 아니다.

후속 사용자는 Personal의 정의를 넓혀 이번 내용을 그 안에 두기로 정했다. 이 리뷰는 앞선 Work 중심 제안에 대한 것이며 새 배치에 대한 검토 완료로 확대하지 않는다. [최신 합의](2026-10-27-ticket05-interview.md#후속-합의--personal을-넓히고-이번-내용을-둔다)를 따른다.

## 검토 조건과 근거

사용자는 단순 적절성 판정에 머물지 않고 더 잘 작동할 방법까지 찾는 개선 리뷰 한 명을 요청했다. 원문은 [제안의 요청](2026-10-27-ticket05-collaboration-learning-proposal.md#요청과-보존할-기대)과 [인터뷰](2026-10-27-ticket05-interview.md#후속-요청--기존-구조의-반영안과-개선-리뷰)에 보존했다.

- 검토자: `/root/collaboration_learning_improvement`, 부모 대화 전체를 상속하지 않은 새 컨텍스트. 기본 모델·추론 설정을 상속했으며 별도 모델 변경은 지정하지 않았다.
- 대상: Main이 먼저 작성한 협업 경험 보존·반영 제안. 초안 SHA256 `70c248ae61e29c72d83d5167fbbc3f4b7bd18add6f3f7e019800fe045594d545`. 검토자는 동일 해시임을 확인했다. 아래 초안 구절과 리뷰 발췌는 보완 이전 판단을 복원할 최소 근거다.
- 입력: 사용자 최신 요청·직전 정정 원문, 초안, 현재 Work·Personal·USAGE·context-update·스킬 관리·개선 리뷰 계약, automate-me·chief-of-staff 원문, 기존 사용자 인터뷰.
- 권한: 읽기·분석·의견 반환. 저장소 안에서 필요한 원문 범위를 스스로 선택할 수 있으며 Main의 문제 정의와 현재안도 재판단한다. 파일 수정·설치·개인 대화 탐색·네트워크·추가 reviewer 호출은 하지 않는다.
- 반환 목적: 현재안보다 나은 선택의 구체적인 변경·이득·유지 비용을 비교한다. 결함이나 개선 개수를 강제하지 않는다.

검토자는 기본 계약 외에 보존된 DB·인증 원대화와 access 원대화, 현재 explain 본문을 직접 읽었다. Main은 DB·인증 대화 source_line157~216과 explain의 질문·선택·권한 구절을 다시 대조했다. 업계의 일반 인증 동작이나 실제 제품의 타당성을 새로 검증한 것은 아니다.

## 리뷰 결과와 Main의 판단

### 1. 보존한 경험이 다음 실제 작업에 도달하도록 연결

초안은 “다음 적용을 맡은 Main이 실제 사용 여부·결과·사용자의 평가·추가 부담을 원래 Work 기록에 남기고”라고 했으나, 그 Main이 미채택 경험이나 시도를 어떻게 알게 되는지 충분히 설명하지 않았다.

리뷰 핵심 원문:

> 개선 Work의 주제별 기록은 관련 경험을 링크하는 데 그치지 않고, 지금까지 무엇을 배웠고 어떤 조건에서는 판단이 달라지는지 설명한다. current·Ticket에는 그중 현재 다시 보거나 시험할 주제만 남긴다.

> 시험을 선택했다면 실행할 Work가 정해졌을 때 그 Main에게 적용할 상황·바꿔볼 행동·확인할 결과와 근거 위치를 넘긴다. 실행 Work는 이번에 필요한 설명을 자기 current·Ticket에서 이해할 수 있게 유지한다. 실행할 곳이 아직 없다면 개선 Work의 열린 다음 행동으로 남기며, 자동으로 재사용될 것처럼 기록하지 않는다.

근거: [USAGE](prototypes/development-workflow/noline-demo/context/USAGE.md)의 일반 읽기는 다른 Work의 모든 미채택 기록을 자동 발견하는 계약이 아니다. [chief-of-staff](../source/workflow-reference-supplements/2026-10-27-learning-perspectives/repository/skills/skills/in-progress/chief-of-staff/SKILL.md)의 주제 갱신·판단 전 조회는 별도 위키 이름 없이도 가져올 수 있다.

Main 판단: 채택. 주제별 기록에 이해·조건·반례를 종합하고, 선택한 시도는 적용할 Work에 명시적으로 전달·회수하도록 보완했다. 추가 비용은 전달과 회수다. 모든 경험마다 적용하지 않고, 실제 시도로 고른 항목에만 요구한다. 새 중앙 위키와 자동 검색을 이번 안의 선행 조건으로 만들지 않는다.

### 2. 사용자가 잘 활용한 판단 질문도 다시 쓸 결과로 제공

초안은 사람과 AI의 협업을 함께 본다고 했지만 실제 사례의 결과는 AI의 요청 해석·설명 보완에 치우쳤다.

리뷰 핵심 원문:

> 여기서 재사용할 것은 “사용자는 항상 일반적인 방식을 선호한다”가 아닙니다. 추천의 전제와 추가 비용을 드러내는 질문 방식입니다.

직접 확인한 최소 원문 — [DB·인증 개발 대화](../source/noline-evaluation/corpus/01a0b2ee-2d11-7b33-ba80-2ceeb380a0ae/messages.jsonl), source_line178·190·197:

> 사용자: 보통 로그인 화면으로 보내나? 일반적으로?

> 당시 AI: 제가 재시도를 추천한 건 **Noline에서는 오프라인 중 재로그인이 어려울 수 있기 때문**입니다. 일시적인 읽기 오류라면 다시 읽어서 기존 로그인 상태를 복원할 기회를 주자는 추가 UX 선택이었습니다. 필수적인 수정처럼 받아들일 필요는 없습니다.

> 사용자: 일반적으로 가자 근데 로그인화면으로 보내는데 db가 실패 안하면? 그건 있을수 없지?

[사용자 회고](../source/noline-evaluation/reviews/interview-20261012.md)는 이 논의를 중요한 선택과 이해를 위한 과정으로 평가했다. 위 내용은 당시 발화이며 그 기술 주장을 현재 사실로 다시 확정한 것이 아니다.

Main 판단: 채택. 추천이 기본 요구인지 추가 선택인지 불분명한 장면에서 AI가 차이와 이유를 드러내고, 사용자는 추가 이득이 자신의 목적에 필요한지 판단해볼 수 있다는 시도 후보를 추가했다. 개인 선호로 즉시 일반화하지 않는다. 이득은 사용자에게도 다음 선택을 돕는 도구를 돌려주는 것이다. 비용은 비교 설명과 판단 시간이며, 단순 선택에도 항상 비교를 요구하지 않는다. 실제 효과는 후속 적용에서 확인한다.

### 3. 이미 있는 기준은 중복 추가보다 실제 적용을 확인

초안의 access 사례는 “Personal에는 질문을 해석할 판단과 조건, 설명 스킬에는 기존 선택·이유·적절성을 먼저 다루는 수행 연결을 둘 수 있다”를 먼저 제시했다.

리뷰 핵심 원문:

> 현재 explain에는 필요한 판단이 이미 있다. 이번 경험을 이유로 같은 규칙을 Personal·스킬에 추가하기보다, 다음 선택 이유 질문에서 현재 스킬이 실제로 적용되는지 확인한다. 미적용이면 읽기·호출·수행 문제를, 적용했는데도 부족하면 본문의 의미나 설명 방법을 다시 본다.

근거: [현재 explain](prototypes/development-workflow/skills/explain/SKILL.md)의 질문·선택 판단 구별, 의미 있는 대안의 대조, 이해·동의·수정 권한의 구별. [원개발 access 대화](../source/noline-evaluation/corpus/01a0ec21-e59e-7370-8432-8434271aa669/messages.jsonl) source_line2757~2784 및 [사용자 회고](../source/noline-evaluation/reviews/interview-20261012.md).

Main 판단: 채택. 반영 위치 후보를 나열하기보다 기존 기준을 사용해 볼 사례로 바꿨다. 이득은 같은 의미가 Personal과 스킬에 중복해서 늘어나는 것을 막고 실제 부족한 지점을 찾는 것이다. 다음 유사 질문에서 이유·대안·비용과 수정 권한을 구별했는지 보는 제한된 확인을 제안한다. 새 테스트나 스킬 수정은 실행하지 않았다.

## 유지한 부분과 확인의 상한

리뷰는 원문·사용자 평가·AI 해석의 구별, 성공·반례의 보존, 반복 횟수만으로 채택하지 않는 점, Personal과 스킬을 구별하되 함께 바뀔 수 있는 점을 유지할 강점으로 판단했다. Main도 이 책임 구분을 유지했다.

단순 파일 배치 검토를 넘어 실제 다음 작업으로의 전달과 사람의 판단 방법을 보완했다. 현재 결과는 문서·원문 대조에 근거한 제안이다. 다음 Main의 재진입 확인, 실제 협업 시도, 유용성·부담의 관찰은 아직 실행하지 않았다. 제안과 리뷰의 로컬 링크 및 공백 검사는 별도로 확인하며, 이 정적 확인을 실제 효과 확인으로 부르지 않는다.
