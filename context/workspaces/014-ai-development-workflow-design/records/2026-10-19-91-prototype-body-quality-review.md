2026-10-19. 사용자는 다음 업무 연결 논의에 앞서 본문을 더 구체적이고 실제 산출물답게 다듬어야 한다고 지적했다. Main은 새 컨텍스트의 개선 리뷰어에게 원래 산출물과 필요한 원자료 접근점을 제공하고, 본문의 판단 깊이와 사용성을 높이는 제안을 받았다. 이 기록은 사용자 정정·리뷰어 권고·Main의 반영을 구별한다.

## 개선 리뷰에 준 입력과 판단권

`subagent-delegation`을 사용해 `/root/body_quality_review`를 새 컨텍스트로 시작했다. 사용자 최신 발화, 현재 prototype 경로,57·61과 기록 색인의 원자료 접근점, 독립 Personal·Project 책임과 조건별 적용·출처 재접근·새 구체화 구별이라는 기존 제약만 제공했다. Main의 원인 가설·예상 개선안을 주지 않았고 파일 수정 없는 개선 리뷰를 요청했다. 전체 대화나 이전 Main의 설명은 전달하지 않았다.

리뷰어는 실제 문제와 필요한 추가 원자료를 직접 선택했다. 현재 본문,31·45·47·57의 사용자 생각과 사례, Matt·Vercel의 보존 본문, pstack 공개 본문을 대조했다고 보고했다. 검증 체크리스트나 합격 판정 대신 주요 품질 문제, 원자료에서 복원할 것, 실제 재작성 예시와 남은 tradeoff를 반환했다. 이 보고는 사용자 채택이나 효과 확인이 아니다.

## 주요 권고와 Main의 판단

- **리뷰어 해석:** “문장 종결 문제가 아니라 판단을 만들어내는 내용의 밀도 문제다.” Main도 원자료와 대조해, 질문·원칙이 존재한다는 것보다 그 질문으로 무엇을 살피고 어떤 선택을 달리해야 하는지가 부족했다고 판단했다. 평서문을 전부 명령문으로 바꾸는 방식은 선택하지 않았다.
- **잘못 만든 질문:**31은 외부 기능 단위·내부 책임·파일 배치의 구별과 양립을 설명한 대화다. 기존 본문의 “충돌하는지 볼 때”는 Main이 만든 해석이며 제거했다.31을 특정 명명 규칙을 직접 채택한 기록으로 읽지 않고, 이름을 판단하기 위한 책임 구별의 근거로 사용했다.
- **실제 사례의 역할:**45의 isError와47의 공개 오류 의미·숨은 우선순위를 본문에서 설명하도록 권고했다. Main은 당시 사실·사용자 판단을 설명하고, JSX와 반환/throw 예시는 재구성임을 표시했다. 내부 함수·공개 API 같은 일반 대비는 이 사례가 설명하지 못하는 조건을 보충하는 데 사용한다.
- **Project의 고유 기여:** Personal 설명을 Noline 용어로 반복하지 않고, 제품 의미·사건별 상태·소비자의 실제 다음 행동·현재 구현 범위를 나누어 설명하도록 권고했다. 특히 “조회 실패가 인증을 되돌리지 않음”과 “조회 완료를 기다리지 않음”은 별도 선택이라는 구별을 반영했다.
- **출처 배치:** 본문은 판단에 필요한 내용을 직접 제공하고, 작성 지위와 원문은 별도 근거에 모으라는 권고를 채택했다. Main은 새 Personal 운영 폴더를 늘리지 않고 prototype 바깥 해설 층의 `authoring-basis.md`를 선택했다. 제품 계약·개인 기준의 정본을 그 파일로 옮긴 것은 아니다.

Main은 책임 분리 전체 주제로 확장하기보다 현재 이름·완료 본문을 완성도 있게 다듬는 범위를 선택했다. 외부 사용 단위·내부 책임·기존 도구의 설명은 이름을 판단하는 데 필요한 만큼 포함한다. 현재 문장·코드 예시의 정확한 형식은 이번 제안이며 사용자 채택으로 올리지 않는다.

## 확인과 남은 판단

Main은 현행 예제 소스에서 Store 저장 뒤 상태 공개, 서비스의 선행 대기, wrapper의 Query 비대기·동기/비동기 오류 전달, 두 소비자의 안내·이동/닫기 호출을 읽고 Project 본문에 대조했다. 실제 앱의 화면과 네트워크를 새로 관찰한 결과는 아니다. 실제 Noline·전역 기준·skill·Harness·코드 동작은 변경하지 않았다.

본문 보완 후 같은 개선 리뷰어에게 새 본문의 남은 피상성·불필요한 확장·예시 정확성을 다시 물었다. 후속 권고 세 가지를 반영했다.

1. 일반 조회 실패를 저장 실패로 소급하지 않는 것과 이후 인증 거부로 현재 상태가 바뀌는 것을 구별한다. Main은 보존된 Noline 인증 계약의75~85행을 직접 대조하고, demo에는 거부 판정·요청 차단·재인증 전환이 없음을 명시했다.
2. 가독성 본문의 개략 코드에서 생략했던 Query 동기·비동기 오류 전달을 실제 구현대로 복원했다. 이 문서가 설명하려는 완료·실패 경계를 생략하면 코드 자체가 다른 기대를 만들 수 있기 때문이다. 사건 표의 “요청 시작”도 “요청 시작 실패”로 바로잡았다.
3. 최신 데이터가 필요한 소비자가 생겨도 공통 wrapper의 반환 시점을 바로 바꾸지 않는다. 해당 소비자가 기다릴지 공통 계약을 바꿀지, 기존 Login·Reauth에 미치는 영향을 대조하도록 설명했다.

이는 Main이 수용한 구체적인 품질 보완이며 최종 사용자 채택이 아니다. 링크 검사·본문 길이·파일 수를 품질 향상의 증거로 삼지 않는다.

다음 논의는 본문 자체를 읽으며 판단 깊이·구체성·조건별 선택이 충분한지 보는 것이다. 특히 책임 설명이 이름 본문의 범위에 적절한지, Project가 독립적으로 충분한지, 출처가 본문 이해를 대신하지 않는지 본다. DEVELOPMENT.md의 책임·위치와 실제 스킬 연결은 그 다음에 이어갈 미결정이다.01-02·03·04-03의 완료나 사용자 만족을 선언하지 않는다.
