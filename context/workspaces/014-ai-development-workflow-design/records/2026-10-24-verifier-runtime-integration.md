# 검증 합의의 실행 본문 반영과 전체 흐름 대조

2026-10-24. **검증자1~12의 합의를 기존 구현·개선 검토1~15 흐름에 통합했다.** 실행 본문과 형성 자료·진입점을 맞추고, Main이 대표 장면의 책임·인계·종료를 대조했다. 메모리 기반 인증 예제의 기존 검사7개와 정상·조회 실패 실행도 직접 확인했다. 문서 적용·장면 대조와 실제 여러 agent의 전체 개발 수행·운영 설치·효과 검증은 구별한다.

## 요청과 기준

사용자 원문:

> 좋아 그럼 검증자 합의한 내용도 실제 실행 본문에 반영하자. 기존 구현자·개선검토자 흐름이랑 잘 연결되는지 대조하고 전체 흐름까지 확인해줘

[검증 합의](2026-10-24-verifier-workflow-proposal.md)의 후속 확정을 기준으로 [개선 리뷰와 후속 조정](2026-10-24-verifier-workflow-improvement-reviews.md), [기존1~15번 반영](2026-10-23-development-workflow-1-15-integration.md), [단계·층위·책임 관점](2026-10-24-workflow-structure-and-responsibility-guidance.md)을 대조했다. 실제 지침은 prototype 안에서 읽을 수 있게 구성하고 합의 발화를 실행 본문에 나열하지 않았다. 과거 설계안·리뷰 전 사본·원문은 수정하지 않았다.

## 기존 구현·개선 검토와 충돌을 정리한 곳

기존 ‘국소 수정은 Main의 직접 확인으로 닫을 수 있다’는 문장은 개선 의견의 처리와 최종 요구 충족 검증을 한 종료로 읽을 여지가 있었다. **개선 의견의 수정·이득 확인은 Main이 닫되, 별도 요구 검증의 호출·축소 조건은 따로 적용**하도록 고쳤다. 수정의 크기와 검증 책임을 섞지 않는다.

기존1~5의 기준 공유·적용 재판단·의미 있는 대안·Main 조합 책임과 사용자 선택 경계는 유지했다.6의 완성·맥락 이해·독립 기대 결과·인계에 구현 중 기계 검사와 관찰 준비를 연결했다.7~10의 개선 검토 입력·탐색·권한·호출 조건은 보존했다.11~12의 원 구현자 수정·국소 처리·의미 변화 재검토에 검증 반환과 재검증 왕복을 구체화했다.13의 실행 배치에 검증 세션 조건을 추가하고14의 명시 호출·설치 및 호환 조건,15의 Main 갱신과 자동 Maintain 미연결은 유지했다. Personal 기준과 제품 계약을 다시 작성하지 않았다.

예제 해설·스킬 안내·형성 맥락도 새 상세로 연결했다. 특히 형성 맥락의 ‘현재 공통 본문과 검토 상세만 존재’하던 설명을 실제 네 실행 문서와 맞췄다. 이전 DEVELOPMENT 보존판의 검토자 직접 수정은 현재 기본 권한으로 승계하지 않았다.

## 직접 실행한 확인

확인 당시 Git 기준은 `b5187dcb4ed2eaf404507e93f15378034ef8970e`이며 새 실행 본문은 미커밋 변경을 포함했다. 인증 예제의 제품·테스트 코드는 변경하지 않았다. Node.js24.16.0에서 demo 안내의 다음 명령을 실행했다.

- `node --test examples/authentication/tests/*.test.mjs`:7개 통과, 실패·취소·생략0. 저장 전 공개 금지, 저장 실패 보존, 후속 비동기/동기 조회 오류 분리, 인증 실패, 귀속 보존, 두 소비자의 완료·후속 행동을 확인했다.
- `node examples/authentication/src/demo.mjs`: 저장·공개·조회 요청·인증 완료·이동 요청 뒤 조회 완료. 최종 signed-in·보존 여행1개.
- `node examples/authentication/src/demo.mjs --refresh-fails`: 인증 완료·이동 요청 뒤 조회 후속 실패 별도 처리. 최종 signed-in·보존 여행1개.

검사 코드도 실제 기대 결과와 대조했다. 제어된 Promise의 완료 전에 상태·저장값·완료 통지가 변하지 않는지를 보고, 조회 Promise를 끝내기 전에 인증 반환을 기다리며, 실패 때 기존 상태·데이터와 오류 callback을 확인한다. 구현 상수나 소스 문자열 위치만 반복하는 검사가 아니다. 저장 어댑터가 부분 실패 후 이전 값을 유지한다는 가정과 실제 UI·DB·동시성 미구현은 여전히 한계다.

열람 화면 생성은 처음 기본 경로에서 marked를 찾지 못했다. 이미 설치된 번들 모듈을 `MARKED_MODULE`로 지정해 생성·검사를 완료했다. 문서163개·코드5개 원문/SHA 일치, 내부 링크929개·앵커273개, 누락0개, 화면 스크립트 문법 통과. 브라우저 렌더링·클릭은 실행하지 않았다. 변경한 Markdown21개의 로컬 파일 링크를 확인했고 누락은 없었다. development 메타데이터는 기존 Ruby YAML 파서로 이름·설명을 확인했으며 Git 공백 검사도 통과했다. 정확한 링크 수·최종 실행 본문과 예제 입력12개의 SHA는 [정적 확인 기록](receipts/workflow-integration/verifier-2026-10-24.json)에 남겼다. 이 기록은 기존 Verify receipt나 의미 판정이 아니다.

## 다음 작업의 경계
