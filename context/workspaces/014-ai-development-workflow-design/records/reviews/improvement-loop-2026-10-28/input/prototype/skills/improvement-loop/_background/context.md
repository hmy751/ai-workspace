# 경험에서 실제 반영까지 같은 세션에서 잇는 이유

[실행 본문](../SKILL.md)의 목적은 대화에서 배울 것을 모으는 데서 끝내지 않고 지금의 본문·기준·수행을 더 좋게 하는 것이다. 사용자는 기존 기반이 있다는 이유로 외부 자료의 유용한 관점을 좁히지 않기를 원했다. 문서 모양뿐 아니라 내용 자체가 목적과 지침에 맞는지, 사람과 AI의 판단·질문·조사 방식과 수행 환경까지 보자는 범위가 남았다.

문맥을 잘 아는 기존 세션에서 선택한 개선을 바로 반영하는 것이 중요하므로 현재 Main이 전체 흐름을 잇는다. 반복해서 쓸 실행 지침은 improvement-loop로 구분하되 새 상설 담당자를 만들지 않는다. Main은 관찰·대안·추천을 종합하고 사용자는 새 개선을 선택한다. 실제 부작용 권한·검사는 대상의 기존 계약을 따른다. 이 스킬은 모델의 판단을 안내하며 범위 준수나 효과를 코드로 보장하는 장치가 아니다.

Personal에는 개인의 기준뿐 아니라 협업 경험·현재 이해·열린 후보를 둘 수 있게 했다. 경험을 모으기 위해 Work를 억지로 만들거나 선택한 실행을 다시 등록하는 방식을 사용자가 정정했다. 그래서 실제 작업의 기록은 기존 방식에 맡기고, 다시 볼 경험은 Personal의 길잡이·주제·미분류 기록에서 찾도록 했다. Work 전체의 기존 범위를 줄이는 선택이 아니다.

발견·새 개선 선택과 이미 정한 내용의 한정 반영은 다른 판단이다. Personal·Project 반영은 context-update를 재사용하고 코드·스킬·도구 변경은 실제 대상의 수행으로 연결한다. 스킬이 없어져도 Personal의 의미·관리·근거가 남도록 모음의 규칙은 Personal이 소유한다. 채택한 실행 내용은 실제 대상 한 곳에 두며 경험 모음은 그 결과와 이유를 연결한다.

전체 대화를 훑겠다는 합의는 압축 후 요약만으로 충족되지 않는다. 따라서 원문 복구와 접근 공백을 실행 상세로 분리했다. 현재 로컬 Codex에서 같은 세션의 파일과 메시지 구조를 확인했지만 모든 host의 완전성·접근을 증명한 것은 아니다. 새 수집기를 먼저 만드는 대신 실제 환경의 원문 접근을 확인하고 중요한 공백을 표시한다.

효과는 다음 관련 실제 사용에서 살피고 필요할 때 한정 비교한다. 장시간 대화의 전면 재실행을 기본으로 하면 마무리 부담이 커지고 한 번의 생성 결과를 과대평가할 수 있다. 미사용·불충분 적용·불명확한 이득·실제 부작용을 구별해 유지·수정·범위 축소·철회를 고른다. 반복 횟수나 후보 점수는 아직 고정하지 않았고 이번 프로토타입도 이를 새로 정하지 않는다.

이름은 경험 학습만 강조하지 않도록 improvement-loop로 정정했다. 현재 목적은 내용·기준·구조·협업·수행 수단을 살펴 선택한 개선을 반영하는 것이며 학습과 기록은 그 입력과 연결의 일부다. [사용자 원문과 선택](records/2026-10-28-naming.md)을 따른다.
