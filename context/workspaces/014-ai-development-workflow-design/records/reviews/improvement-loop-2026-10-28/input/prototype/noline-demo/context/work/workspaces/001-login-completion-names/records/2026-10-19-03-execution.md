# 실행 확인 — 2026-10-19

> 초기판의 수행 기록이다. 이후 파일 경로를 옮겼으며 링크는 현재 파일로 연결한다. 아래 당시 명령·판단은 그대로 보존한다. 현재 실행 위치와 명령은 [demo 안내](../../../../../README.md#직접-실행한다)에서 읽는다.


대상은 이 Work를 위해 새로 작성한 `noline-demo/src/` 코드다. Node.js 24.16.0의 내장 테스트를 사용했고 외부 의존성 설치는 하지 않았다. 명령의 기준 디렉터리는 `development-workflow/noline-demo/`다.

```bash
node --test tests/*.test.mjs
```

실제 결과: 검사 7개, 통과 7개, 실패 0개, 취소 0개, 건너뜀 0개. 검사는 [authentication.test.mjs](../../../../../examples/authentication/tests/authentication.test.mjs)에 있다.

| 확인한 동작 | 확인 방식 |
| --- | --- |
| 진행 작업과 저장이 끝나기 전 새 상태·완료가 공개되지 않음 | 진행 작업과 저장의 Promise를 각각 멈추고 이전 상태·저장값·호출 기록 대조 |
| 저장 실패 시 이전 인증·여행 데이터 보존 | 저장 오류를 주입하고 이전 저장값·상태, Query·callback 미호출 확인 |
| Query가 계속 대기 중이어도 인증 완료 전달 | 조회 Promise를 끝내기 전에 로그인 반환과 완료 callback 확인 |
| Query 실패가 인증 성공을 되돌리지 않음 | 로그인 완료 뒤 조회를 실패시키고 별도 오류 수신·새 세션 유지 확인 |
| Query 요청의 동기 오류도 후속 실패로 처리 | 요청 함수가 즉시 던지게 하고 인증 성공과 별도 오류 수신 확인 |
| 서버 인증 실패와 다른 계정·귀속 불명 데이터 보호 | 서버 오류 시 후속 미실행, 귀속 불일치 때 저장·삭제 없이 데이터 보존 확인 |
| Login·Reauth의 완료 표현과 각자 후속 동작 | 조회 진행 중 두 소비자의 정확한 안내와 이동·닫기 함수 호출 확인 |

사람이 읽는 실행 예시도 다음 두 명령으로 직접 확인했다. 둘 다 종료 코드 0이었다.

```bash
node src/demo.mjs
node src/demo.mjs --refresh-fails
```

정상 실행은 기기 저장, `signed-in` 상태 확인, Query 요청, ‘로그인 완료’ 안내, 이동 요청, 후속 Query 완료 순으로 출력했다. 실패 실행은 같은 인증 완료·이동 요청 뒤 ‘조회 후속 실패 별도 처리’를 출력했다. 두 실행 모두 최종 상태 `signed-in`, 저장 계정 `demo-user`, 기존 여행 1개 보존으로 끝났다. 이 출력의 이동 요청은 함수 호출이며 UI 전환 결과가 아니다.

이 결과는 작성자가 직접 실행한 검사다. 별도 reviewer가 검토한 결과를 가정해 추가하지 않았다. 테스트는 메모리 어댑터와 주입한 대기 함수의 계약을 확인하며 실제 Noline의 UI·저장소·네트워크와 연결된 결과가 아니다.

남은 범위는 실제 DB·queue 귀속과 조율, 부분 저장 실패·재시작 복구, 동시 세션 변경, callback 자체의 예외다. 현재 완료·오류 callback은 정상 반환하고 저장 실패는 이전 저장값을 보존하는 어댑터 계약을 전제로 한다. 이 전제를 바꾸는 구현에서는 해당 실패 경계를 다시 설계·검사한다.
