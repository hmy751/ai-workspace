# Work를 이어 가는 방법

Main의 일반 재개에서는 사용자가 지정한 Workspace를 우선한다. 지정이 없으면 [Workspace 색인](workspaces/README.md)의 기본 선택을 따른다. 해당 README, `current/memory/index.md`와 관련 Spec·Ticket, `current/state/index.md`, `output/index.md`에서 목표·제약·현재 선택의 이유·실제 결과·남은 행동을 확인한다. 이번 요청이 배경 설명인지 수행인지 판단하고, 과거에 적힌 다음 행동으로 현재 요청을 덮어쓰지 않는다.

범위를 정해 위임받은 담당자는 지정된 작업·판본과 관련 Spec/Ticket·원문을 우선 읽고 판단에 필요한 상태를 추가로 확인한다. 전체 current와 관련 없는 다른 Ticket의 기본 완독을 요구하지 않는다.

[공통 읽기 방법](../USAGE.md)으로 관련 Personal·Project 본문과 필요한 source를 골라 이번 판단에 적용한다. 개발 수행의 역할·시점·반환은 [개발 절차](../../../skills/development/SKILL.md)가 연결한다. 한정 설명이나 읽기 요청 때문에 개발 전체를 시작하지 않는다. 개인 기준을 읽었다는 이유로 제품 약속을 바꾸거나, 기존 예시의 함수명을 모든 작업에 강제하지 않는다.

Main은 이 지침과 실제 Workspace·Project·Personal의 관리 계약을 이해한 뒤 바뀐 의미를 직접 반영하고, 다음 작업이 문서에 의존하면 실제 반영을 확인한다. 담당자의 결과·제안을 검토해 현재 선택과 남은 일을 연결하며, 반영을 제안했다는 사실로 공유 current의 수정 권한이 생기지는 않는다. 별도로 배정한 기록 담당이 있으면 그 범위에서 수행한다.

목표·계약·가정은 memory, 전체 상황·다음 행동은 state, 실행 단위의 결과는 Ticket에 맞춘다. 입력은 source, 결과 위치는 output, 선택·시행착오·검사 이력은 records가 맡는다. 원자료와 과거 기록을 새 결론에 맞춰 덮어쓰지 않는다.

중요한 제안·근거와 채택·조정·미채택의 이유, 실제 반영·확인 결과는 기존 Ticket·records에서 다시 찾을 수 있게 한다. current에는 지금 유효한 의미와 남은 검토·반영·확인만 유지한다. 반영 도중 중단되면 이미 맞춘 곳과 남은 판단·담당·다음 행동을 구별해 이어갈 수 있게 남긴다. 모든 제안·읽기·발화를 기록하거나 새 제안함·필수 상태값을 만들지 않는다. 이 자료는 이후 경험 개선에도 사용할 수 있지만, 일상 유지가 그 단계를 기다리지는 않는다.

결과를 반환할 때는 해당 current·Ticket·output이 실제 최신 결과와 같은 완료 범위를 가리키는지 확인한다. 한정 요청 완료, Work 목표 완료, 대화 중단을 구별하고 핵심 미확인은 남은 수행으로 잇는다. 같은 목표는 같은 Work에서 이어가며 세션 교체만으로 새 Work를 만들지 않는다. 독립 목표 생성·전환이 요청되면 [해당 계약](workspaces/CREATE-AND-TRANSITION.md)을 따른다.

검사는 [실행 안내](../../README.md#직접-실행한다)를 사용한다. 이 demo의 직접 확인 결과와 실제 Noline·화면·저장소의 미확인을 구별한다. 자동 Maintain이나 session activation은 연결돼 있지 않으므로 운영 명령을 임의로 실행하지 않는다.
