# 제약·현재 설계·가정

**지킬 제약:** 같은 계정의 여행 데이터를 유지하고, 저장 실패와 후속 조회 실패를 구별한다. Project 계약을 이름 변경만으로 숨기거나 개인 기준의 예시 이름을 필수 규칙으로 복사하지 않는다.

**현재 선택:** `signInAndRequestRefresh`·`onSignedIn`을 유지한다. 기존 이름 안도 설명을 읽으면 사용할 수 있지만, 이번에는 코드 자체에서 조회 요청과 인증 완료를 더 분명하게 드러내는 방향을 우선한다. 내부 두 소비자이고 공개 호환 계약이 없다는 사실은 그 개선 비용을 낮춘다. 이름 유지안은 남는 설명 의존과 호환·변경 위험을 함께 고려할 절충안으로 비교한다. [동일 코드의 두 안](../../../records/2026-10-19-06-naming-alternatives.md)에서 설명을 같게 둔 비교와 비용을 확인한다. 두 callback은 최신 조회 값을 소비하지 않으므로 새 대기를 넣지 않고 이동·닫기 시점을 보존한다. 이 비교는 현재 선택의 설명을 보완한 것이며 최초 작성 때 수행한 비교로 소급하지 않는다.

**대기와 실패의 구별:** 조회를 기다리더라도 조회 실패를 인증 실패와 별도로 전달할 수 있다. 비대기는 실패 분리의 필수 조건이 아니다. [당시 작성 기록](../../../records/2026-10-19-02-implementation.md)의 비대기 선택 이유는 이 구별이 부족했으며, 이번 보완에서 현재 설명을 바로잡았다. 소비자에게 최신 결과가 필요해지면 그 소비자만 기다릴지 공통 완료 계약을 바꿀지 판단한다. 후속 조회의 동기 요청 오류를 인증 실패와 분리한 처리는 실행 가능한 데모를 만들 때 추가한 선택이며, 초기 가정 코드에 이미 있던 동작으로 소급하지 않는다.

**가정과 한계:** 메모리 어댑터는 성공 시 저장하고 실패 시 이전 값을 유지하며 callback은 정상 반환한다. 진행 작업 대기는 주입한 함수로만 표현한다. 실제 DB·queue의 원자성, 동시 로그인·로그아웃, 화면·네트워크 연결은 확인하지 않았다.

소비자가 조회 결과까지 필요해지거나 공개 호환 요구가 생기면 위 선택을 재판단한다. 기준을 채택한 뒤에도 목적·사용처·비용에 따라 유지·수정·보류를 판단한다는 개인 기준을 여기에도 적용한다.
