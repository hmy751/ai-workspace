# 조회 실패의 분리와 대기 선택을 바로잡은 기록

[인증 계약 본문](../../INDEX.md)의 대기·실패 설명이 형성된 2026-10-19 작성 논의다. 2026-10-20에 보존 자료와 기존 Work 기록을 대조해 재구성했다. 실제 Noline 제품의 오류 발생이나 새 기능 도입 기록이 아니다.

처음 실행 예제를 만들 때에는 제품 자료의 저장 뒤 공개·저장 실패 보존·인증 뒤 조회 실패 분리를 사용했다. 두 내부 소비자, 비대기 조회, 별도 후속 실패 callback은 예시 조건으로 이어받았다. [당시 구현 기록](../../../../../work/workspaces/001-login-completion-names/records/2026-10-19-02-implementation.md)은 이름 유지·설명 보완, 개명·설명 보완, 조회 완료까지 대기의 세 선택을 비교했다.

본문 품질을 보완하는 과정에서 “조회 실패가 인증을 되돌리지 않는다”와 “조회 결과를 기다리지 않는다”를 같은 이유로 다루면 안 된다는 구별을 반영했다. 이후 합의 대조에서는 Work의 비대기 이유에 남아 있던 불충분한 설명도 발견했다. [정확한 발췌](../evidence.md#대기-이유를-바로잡은-작성-논의)에 남긴 것처럼, 기다려도 실패 분리는 가능하며 현재 비대기는 기존 완료·이동·닫기 시점과 최신 값을 직접 사용하지 않는 소비자 조건에서 설명해야 했다.

현재 선택은 소비자별 요구를 먼저 보는 것이다. 최신 결과가 필요하면 해당 소비자만 기다리는 경로를 둘 수 있고, 공통 완료 계약 자체를 바꿀 수도 있다. 후자는 기존 두 소비자의 loading·이동·닫기·실패 처리까지 바꾸므로 별도의 영향 판단이 필요하다. 어느 대안도 이번 문서 정리에서 구현하거나 모든 인증 흐름의 표준으로 채택하지 않았다.

후속 개선에서는 일반 조회 실패와 별도 인증 거부를 구별하고, 가독성 설명의 코드에서도 동기·비동기 조회 오류 전달을 생략하지 않도록 보완했다. 이 선택의 근거는 [작성 논의](../evidence.md#제품-계약과-데모-선택을-구별한-작성-논의)와 [인증 거부 원문](../evidence.md#인증-거부는-별도-사건)이다. 코드 동작은 이 문서 보완 과정에서 바꾸지 않았고, 거부 경로는 계속 미구현으로 남겼다.

향후 소비자의 최신 데이터 요구, callback 예외, 저장 어댑터의 부분 실패·동시 실행 조건이 달라지면 이 당시 전제와 현재 계약을 다시 비교한다. 과거 구현 기록을 새 설명으로 덮어쓰거나 이번 형성 자료의 구성을 신규 제품 합의로 해석하지 않는다.
