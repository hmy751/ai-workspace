# 작업 체계 개선 루프 — 구성과 적용 사례

사용자 요청으로 시작한 개선 검토가 **실행 스킬, Personal 경험 모음, 실제 반영 대상**을 어떻게 연결하는지 보여주는 안내다. 지금 루프를 수행할 때는 [improvement-loop 본문](skills/improvement-loop/SKILL.md)을 읽고, 이 문서에서는 전체 관계와 대표 선택을 살핀다.

Main은 현재 대화의 맥락을 유지하며 대화 전체와 관련 내용을 살펴 선택지를 만든다. 사용자가 고른 가능한 개선은 실제 대상에 반영하고 직접 확인한다. Personal은 다시 볼 경험과 판단을 보존하며, 채택된 기준·제품 내용·실행 지침은 실제 반영 대상이 소유한다.

## 무엇을 이해하거나 고칠 때 어디로 가나

| 질문 | 담당 본문과 역할 |
| --- | --- |
| 언제 시작하고 무엇을 살펴 어떻게 선택·반영·마칠까? | [improvement-loop/SKILL.md](skills/improvement-loop/SKILL.md). 현재 Main의 수행 계약이다. |
| 앞부분이 압축됐거나 원문이 빠졌다면? | [대화 원문 확인](skills/improvement-loop/references/conversation.md). 같은 세션의 입력 범위·원문 접근·공백 처리를 다룬다. |
| 이전 보완을 실제로 썼고 도움이 됐는지 어떻게 볼까? | [사용과 효과 판단](skills/improvement-loop/references/effects.md). 실제 사용·도움·부담에 따라 다음 선택을 구별한다. |
| 개인 기준과 아직 채택하지 않은 경험은 어떻게 다른가? | [Personal](noline-demo/context/personal/README.md). 개인 기준과 경험·해석·열린 후보의 경계를 소유한다. |
| 관련 경험과 열린 질문은 어디서 다시 찾을까? | [경험 길잡이](noline-demo/context/personal/experience/README.md). 주제별 상세와 아직 묶지 않은 기록으로 들어간다. |
| 경험을 저장·갱신하고 채택 결과와 어떻게 연결할까? | [경험 관리](noline-demo/context/personal/experience/MAINTENANCE.md). 근거·현재 해석·후보·실제 반영 대상의 관계를 유지한다. |
| 선택한 실제 대상은 어떤 방법으로 고칠까? | Personal·Project 본문은 [context-update](skills/context-update/SKILL.md), 개발 수행·확인은 [development](skills/development/SKILL.md), 스킬·도구는 각 대상의 계약을 따른다. |

Personal 경험 모음은 루프의 부속 실행 기록이 아니다. 스킬을 교체해도 모음과 관리 기준은 유지할 수 있다. 기존 개발 기준은 그대로 적용할 본문에 있고, 경험 주제의 열린 후보는 사용자 선택만으로 정해진 범위에서 반영한다. 실행 중 자연스럽게 생기는 Work 기록은 기존 작업 방식을 따르며 별도 등록 단계는 없다.

## 한 번의 사용을 따라가면

아래는 수행 관계를 설명하는 흐름이며 실제 운영 실행 이력이 아니다. 세부 판단과 예외는 위 담당 본문을 따른다.

| 흐름 | 연결되는 내용과 결과 |
| --- | --- |
| 사용자가 이번 대화를 돌아보자고 요청한다 | 현재 Main이 대화 전체를 훑고 중요한 입력 공백을 구별한다. |
| 경험과 현재 대상을 대조한다 | Personal 길잡이와 관련 주제, 대상 본문 전체·목적·내용 지침·실제 결과를 함께 살펴 관찰과 해석을 만든다. |
| 개선 선택을 함께 고른다 | 추천과 이유를 먼저 보고 다른 후보·유지 판단·공백도 확인한다. |
| 선택한 가능한 개선을 반영한다 | 실제 대상에서 수행·직접 확인하고 경험의 선택·결과를 연결한다. 한정 시도·남은 실행·미결을 구별한다. |
| 다음 관련 루프를 요청한다 | 관련 경험을 다시 찾아 실제 사용·도움·부담을 살피고 다음 선택을 한다. |

이 연결은 모든 작업의 고정 관문이 아니다. 일상 갱신은 기존 권한과 방법으로 수행하고, AI가 루프 시점을 제안한 것만으로 루프가 시작되지는 않는다.

## 여러 자료가 좋지만 무엇을 가져올지 고르기 어렵다

[설계 논의 주제](noline-demo/context/personal/experience/topics/design-conversation.md)에는 실제 사용자 발화와 당시 진행을 보존했다. 현재 해석은 자료를 더 모으는 것에 더해 대안의 실제 차이와 남은 질문을 연결할 필요가 있다는 것이다. ‘비교 후 질문하기’는 열린 후보이며 매번 도식·인터뷰를 요구하는 기준은 아니다.

다음 대화에서도 선택 기준이 불분명했다면 Main은 새 대화의 실제 비교·질문·사용자 선택, 기존 주제, work-discussion 전체를 대조한다. ‘인터뷰’라는 단어가 같은지만 찾지 않고 같은 어려움을 만든 조건과 실제 수행을 살핀다. 아래는 그 대조에 따라 가능한 다음 선택이며 현재 채택 결과가 아니다.

| 확인한 조건 | 가능한 선택 | 실제로 달라지는 곳 |
| --- | --- | --- |
| 기존 스킬의 비교·질문 방식이 충분하고 실제로도 도움이 됐다 | 현행 유지, 필요하면 경험만 보존 | Personal 주제의 경험·해석 |
| 기존 지침은 충분하지만 이번에 읽거나 적용하지 못했다 | 찾는 경로·적용 조건·실제 수행을 보완 | 확인된 원인에 해당하는 진입 또는 수행 |
| 특정 열린 설계에서는 유망하지만 일반 적용 근거가 부족하다 | 사용자 선택에 따른 한정 시도 | 해당 작업에서 언제 어떤 비교·질문을 할지와 Personal의 시도 범위·기대 변화·반영 대상 |
| 기존 스킬의 조건에 구체적인 부족이 확인됐다 | 사용자 선택에 따른 본문 보완 | 실제 스킬과 필요한 연결·직접 확인, Personal의 반영 결과 |

기존 스킬로 충분한데 인터뷰 단계만 늘리는 안은 제외할 수 있다. 추천할 때 실제 바꿀 문장이나 수행 장면을 보여준다. 한정 시도는 일반 채택과 구별하고, 기준 전문은 경험 주제에 복제하지 않는다. 아무것도 고르지 않거나 미결 이유가 같으면 후보를 유지하며 자동 재권고하지 않는다.

## 좋은 편집 경험으로 관련 본문 전체를 살핀다

[문서 품질 주제](noline-demo/context/personal/experience/topics/document-quality.md)는 첫 11편 편집의 긍정 반응과 조건·순서·예외를 보존한 방식을 담는다. 다음 문서 반영에서는 새 정보 한 줄뿐 아니라 해당 주제 전체와 내용 지침을 대조한다. 같은 설명이 충분하면 무수정 유지, 부족한 적용 조건이 확인되면 기존 본문 통합, 다른 문서에서도 유용한 판단이면 Personal 사례 보완을 추천할 수 있다.

가령 실제 대상에서 같은 의미가 두 곳에 중복돼 독자를 혼동시킨 것이 확인되고 사용자가 통합을 선택했다면, context-update로 실제 본문과 들어오는 참조를 함께 고친다. 읽는 입구에서 조건·예외가 복원되는지 확인한 뒤 반영 결과를 잇는다. 이는 현재 demo에 그 결함이 발견됐다는 주장이 아니다. 이 좋은 경험에서 모든 문서를 표로 바꾸는 기준이 나오는 것도 아니다.

## 이전 보완을 썼는데 이득이 애매하다

[설명 방식의 효과 주제](noline-demo/context/personal/experience/topics/explanation-effects.md)에 보존한 비교에서는 일부 근거가 좋아졌지만 전체 이득이 제한적이었고, 문구를 더하지 않고 현행을 유지한 판단이 있었다. 이것을 이번 루프 스킬의 사용 효과로 옮기지 않는다.

다음 관련 사용에서는 이전 변경의 목적과 실제 사용을 대조한다. 읽지 않은 장면이면 접근·적용 문제를, 사용했지만 효과가 불분명하면 조건과 부담을 살핀다. 작은 이득이 있어도 불필요한 절차가 커졌다면 범위 축소·간소화를 권할 수 있다. 선택을 바꿀 가치가 있을 때만 관련 요청에서 한정 비교한다. 이 판단의 상세는 [effects](skills/improvement-loop/references/effects.md)가 맡는다.

## 적용 범위와 형성 근거

이 prototype은 실행 지침과 Personal의 예시·읽기·관리 연결을 제공한다. 세 경험 주제는 현재 근거에 따른 배치이며 Personal 전체의 고정 분류가 아니다. 후보 점수·반복 횟수·고정 출력 양식·자동 채택 범위를 정하지 않았다.

지침이 존재하는 것과 실제 host에서 읽고 수행한 것, 다음 사용에서 도움이 된 것은 다르다. 운영 설치·세션 원문 전체 확인·후속 사용 효과는 이 안내만으로 확인되지 않는다. 별도 상설 리뷰어·스케줄·hook·자동 수집기는 전제하지 않는다.

루프의 범위와 선택 이유를 다시 볼 때는 [스킬 형성 자료](skills/improvement-loop/_background/README.md), Personal의 경계를 재검토할 때는 [경험 모음의 형성 자료](noline-demo/context/personal/_background/experience-collection/README.md)를 읽는다. 이번 작성·검토 진행 상태는 Workspace의 current와 기록이 관리한다.
