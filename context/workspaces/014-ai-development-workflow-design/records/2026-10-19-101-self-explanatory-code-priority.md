# 코드 자체의 명료함을 우선하는 판단 보완

2026-10-19. 사용자가 A/B 비교의 목적을 물어 Main이 설명한 뒤 다음 관점을 밝혔다.

> 근데 난 되도록 설명이 필요없는 코드가 지향되어야 할 코드라고 생각해

앞선 설명은 A도 가까운 주석으로 사용할 수 있다는 점을 강조하면서, 사용 가능성과 지향할 코드 품질의 차이를 충분히 구별하지 않았다. 가능한 한 코드 자체에서 의도와 동작이 드러나는 방향을 우선하도록 일반 기준과 현재 비교의 판단을 보완했다.

- 개발 공통·이름 일반 기준: 이름·타입·책임 배치·제어 흐름의 명료함을 먼저 보고, 코드에 담기 어려운 이유·외부 제약·비자명한 계약을 설명으로 보완한다. 주석 존재를 개선 불필요의 근거로 삼지 않는다.
- 인증 사례·같은 코드 A/B: 현재 조건에서는 주요 완료 의미를 이름에 담는 B를 권한다. A는 올바르게 사용할 수 있지만 설명 의존이 남으며, 공개 호환성·실제 변경 위험이 클 때의 절충안으로 비교한다. 같은 동작·같은 주석의 비교 조건은 유지했다.
- Project 가독성 가이드·Work 개인 기준 선택·Spec05·walkthrough: 같은 판단이 이어진 문장을 함께 조정했다. 제품의 비대기·오류 계약은 바꾸지 않았다.
- current/memory: 사용자 원문과 지속할 판단을 남겼다. 대상물 본문에 바깥 설계 이력을 연결하지 않았다.

‘되도록’이라는 방향을 모든 주석 제거, 이름에 모든 정보 나열, 기존 공개 API 즉시 개명으로 확대하지 않는다. B도 최선의 이름·구성으로 확정하지 않는다. 이번 비교는 이름의 차이를 보여 주므로 타입·책임·제어 흐름까지 개선·검증했다고 보고하지 않는다.

표시 화면을 재생성하고 원문53개·코드5개의 일치, 링크·앵커·대상물 경계와 A/B의 동일 동작·주석 검사를 통과했다. `git diff --check`도 통과했다. 인증 소스와 입력 source는 수정하지 않았으며 제품 검사나 브라우저 실측을 새로 수행한 것으로 기록하지 않는다.
