# Personal·Project의 독립 책임과 본문 형식 정정

2026-10-19. 사용자는83의 구체 적용 시안에서 Personal의 위치와 Project의 직접 의존을 정정하고,01에서 논의한 사용자 생각·레퍼런스가 본문 형식에 반영됐는지도 확인하라고 요청했다. 이번에는 기록에 있던 전제를 없었던 것으로 고치지 않고, 실제 구조·당시 기록·최신 정정을 대조해 수정한다.

## 기록에 있던 전제와 실제 구조를 구별한다

[루트 README](../../../../README.md)는 ai-workspace를 작업 방식·도구를 쌓는 개인 저장소로, [작업대 context](../../../README.md)는 `workspaces/`와 `source/`를 가진 작업대로 정의한다. [Reference context](../../../../reference-project/context/README.md)는 Project와 Work를 나누며 제품·테스트는 context 밖에 둔다. 어느 현행 계약에도 Personal은 아직 정의돼 있지 않다. `reference-project/`는 실행 가능한 기준 Project이며 작업대 자체와 같은 물리 구조가 아니다.

[79](2026-10-18-79-personal-and-project-layer-discussion.md)는 개인 기준과 Project의 책임 분리·적용 관계에 관한 Main 추천이었다. [80](2026-10-18-80-personal-project-content-allocation.md)은 루트 `personal/development/` 위치와 Project 입구에서 개인 기준을 함께 안내하는 읽기 경로를 제안했다. 사용자 구조 정정 뒤 [81](2026-10-19-81-personal-context-direction-and-next-step.md)은 다음 두 내용을 실제 설계 전제로 올렸다.

> 개인 기준을 별도 지속 맥락으로 두고, 이 저장소의 `context/personal/development/`에서 중앙 정본을 관리하는 방향을 현재 설계 전제로 삼는다.

> Project guidance는 개인 기준을 참조하되 자기 범위의 의미를 이해할 만큼 설명한다.

81에는 이 위치가 기존 규칙의 자동 결론이 아니라 새 책임을 추가하는 설계 선택이라는 설명도 있다. 따라서 기록에 그런 내용이 없었다거나 처음부터 계속 미정이었다고 정리하면 과거 판단이 사라진다. 반대로 기록에 전제가 있다는 사실이 그 구조의 적절성을 증명하지도 않는다.81은 “그래 이정도 정하고 그럼 다음 뭐지?”를 방향 선택으로 기록했지만, 당시 Main의 제안 전체 원문은 이번 조사 자료에 없어 정확한 수락 범위를 독립적으로 다시 확정하지 않았다. 이번 수정의 근거는 위 최신 사용자 정정이다.

82는 Project README가 개인 본문을 선택적으로 안내하는 시안을 만들었고83은 이를 실제 상대 링크로 구체화했다. 수정 전83의 시안 README는 다음과 같이 설명했다.

> 개인 기준은 ai-workspace 쪽에 한 번만 둔다. noline-demo의 가독성 가이드는 그 본문을 실제 링크로 참조하고, 이 Project에 적용할 범위와 인증에서 지킬 차이를 직접 설명한다.

이번에 대체하는 것은 **ai-workspace 내부를 Personal의 정해진 운영 위치로 삼는 전제와, Project 내용 문서가 개인 기준의 참조·채택·갱신 관리까지 소유하는 연결**이다. 개인의 일반 판단과 Project의 구체 계약을 구별하는 방향, 함께 읽는다는 이유로 제품 정책·코드 가이던스 본문을 모호하게 합치지 않는 조건, 실제 설치·전체 기준 채택은 없었다는 경계는 유지한다.

이번 기록은 구조·근거 대조와 수정의 책임·범위를 남긴다. 수정된 전체 문서와 viewer의 확인 결과는 아래에 남긴다. 과거83의 검사 수치와 화면 확인을 이번 수정의 검증으로 재사용하지 않는다. 제품 실행·실제 Noline 적용·운영 설치·새 스킬 구현·개인 기준 전체 채택은 없으며01-02·03·04-03·06도 미완료다. 이번 정리에서 커밋하지 않는다.


## 수정 후 확인

- 수정 시안은 Markdown 19개다. Main이 viewer에 담긴 전체 원문과 각 파일의 SHA-256을 대조해 모두 일치함을 확인했다. 세 열은 Personal 기준·Project 가이드·workflow 연결이며, 예전 ai-workspace 내부 Personal 경로는 화면의 문서 선택·단계 입력에서 제거됐다.
- 현재 미커밋 문서 37개의 로컬 링크 대상 594개를 확인해 누락이 없었고 코드 블록과 변경 형식 검사도 통과했다. Project 본문에 개인 기준 의존 문구·경로가 없으며 Personal 본문에도 Noline 적용처 역링크가 없는 것을 확인했다. 이는 문서 독립성의 기계적 보조 확인이며 의미 판단을 대신하지 않는다.
- 작성과 분리된 검토자가 현행 canonical,57·61·64·65·68·72·73,81~84 및 수정 본문·current를 직접 대조했다. 문서 책임·근거·장면 정합성에서 수정이 필요한 실질 결함을 발견하지 못했다. 사용자 수용이나 실제 작업의 기준 발견·판단 효과까지 판정한 결과는 아니다.
