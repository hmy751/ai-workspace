# 본문·형성 자료를 파일명에서 구별하는 보완

사용자는 `_background/`와 `INDEX.md`·`INDEX.cases.md` 표기를 선택하고 CONTENT-POLICY와 적용된 데모·링크를 함께 맞추도록 요청했다. 폴더가 많아졌을 때 읽는 목적을 이름에서도 구별하려는 보완이다.03의 구성안 완료와 후속 순서는 유지한다.

## 반영 범위

- [CONTENT-POLICY](prototypes/development-workflow/noline-demo/context/CONTENT-POLICY.md)의 파일명·구성 예·읽기와 갱신 안내에 표기를 통합했다. `_`는 형성 자료를 구별하고 `INDEX`는 현재 사용할 본문 묶음을 나타낸다. 중요도·권한·필수 읽기 등급은 아니다.
- 데모의 형성 자료 폴더10곳과 시작·분할 본문11개를 개명했다. README와 기존 체계 지침의 이름·위치는 유지했다. SYSTEM-GUIDANCE도 대문자를 체계 지침 전용 표시로 읽지 않도록 설명을 맞췄다.
- 현재 링크를 새 경로로 맞추고 viewer의 읽기 단계·비교·필수 관계 경로를 수정했다. 바깥014 current·output·records에서 현재 본문을 가리키는 링크도 연결했다. 과거 원문 발췌·당시 경로 표기와 보존 source·receipt는 유지했다.
- Work의 파일명·구성·내용은 유지하며 이동한 Personal·Project 본문으로 가는 링크만 갱신했다. 실제 운영 저장소·제품 코드·테스트는 바꾸지 않았다.

선택 이유·사용자 발췌·전환 기록은 [정책 가까운 형성 자료](prototypes/development-workflow/noline-demo/context/_background/content-policy/README.md)에도 선별해 남겼다. 기존 문서 역할을 바꾸거나 새 viewer 역할 표시·접기 기능을 추가하는 작업은 아니다.

## 확인

로컬 링크1049개를 실제 파일명의 대소문자까지 대조했고, 현재 읽기 경로에서 옛 이름을 가리키는 링크는 없었다. 시작·분할 본문11개는 링크 외 내용이 같으며, Work의 변경 파일10개도 링크 외 내용이 같았다. 기존 형성 자료의 인용문은 보존됐다.

열람 화면을 재생성해 문서118개·코드5개의 원문·해시, 내부 링크684개·앵커204개와 이름 기준의 필수 관계13개를 확인했다. 경로·절 누락은 없으며 모든 로컬 문서 링크가 대상물 안에 있다. 정적 검사·구문 검사는 통과했고 브라우저 렌더링과 제품 테스트는 새로 실행하지 않았다. 전체 변경의 공백 검사도 통과했다.

 대소문자를 구별하지 않는 로컬 파일 시스템에서도 Git이 INDEX 개명을 추적하도록 이동 처리했다. 커밋은 이번 요청에 포함하지 않았다.

사용자는 반영·검사 결과를 확인한 뒤 “그래 커밋 하자”라고 요청했다. 이 후속 요청에 따라 정책·개명·현재 링크·열람 화면·형성 근거와 Workspace 안내를 함께 커밋한다. 실제 커밋과 변경 범위는 Git 이력에서 확인한다.
