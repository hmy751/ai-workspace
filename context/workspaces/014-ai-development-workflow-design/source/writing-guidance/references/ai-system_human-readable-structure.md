# AI 시스템 산출물의 사람용 진입과 본문 구성

AI가 만들거나 관리하는 지속 산출물에서 사람이 현재 상황을 이해하고 검토·수정·다음 지시를 할 수 있는지 판단한다. 사람이 접하는 README, 운영 문서, CLI 출력, UI와 그 아래 상세 자료에 적용한다.

필요한 코드, JSON, schema와 자동화는 실행 목적에 맞게 유지한다. 사람용 설명은 그 의미와 판단할 사항을 드러내고 실제 상태와 근거로 연결한다.

## 필요한 답과 판단을 먼저 찾을 수 있게 한다

먼저 이 산출물에서 사람이 이해하거나 결정해야 할 일을 정한다. 그 일에 필요한 다음 내용을 진입점과 선택한 본문에서 찾을 수 있게 한다.

- 현재 문제, 핵심 답과 유효한 상태
- 확인하거나 결정할 사항과 판단을 바꾸는 조건
- 관련 구성요소의 역할과 관계
- 실제 상태와 상세 근거의 위치
- 수정이나 다음 지시에서 가리킬 대상

모든 산출물에 같은 목차나 항목을 채우는 요구는 아니다. 별도 설명 문서가 없어도 사람이 실제로 접하는 표면에서 필요한 판단을 할 수 있으면 충분하다.

## 핵심과 상세의 비중을 구별한다

핵심 답과 현재 판단을 먼저 드러낸다. 그 판단을 바꾸는 이유·조건·예외는 가까이 설명하고, 일부 작업에만 필요한 상세는 읽을 조건과 함께 뒤에 두거나 별도 근거로 연결한다.

- 현재 기준, 확인된 사실, 미정인 선택이 섞이면 각 지위와 관계를 구별한다. 모두 같은 비중으로 이어 쓰지 않는다.
- 하나의 설명 안에서도 독립적으로 찾아야 할 조건은 구별한다. 문단·목록·표는 전달할 관계에 맞게 선택한다.
- 사례는 기존 설명에 없던 판단을 이해하게 할 때 남긴다. 같은 판단을 반복하는 사례는 통합하거나 근거 기록으로 연결한다.
- 조사 순서, 완료한 작업 목록, 편입 경위는 현재 판단에 필요한 설명으로 선별한다. 과거에 중요했다는 이유만으로 현재 본문의 비중을 유지하지 않는다.

독자가 본문을 이해하는 데 필요한 전제와 조건은 충분히 설명한다. 상세를 분리하더라도 핵심 답을 여러 링크에서 조립해야 하는 상태로 만들지 않는다.

## 실제 상태와 설명을 함께 유지한다

사람용 설명은 기계 상태를 복제하지 않고 의미를 설명한 뒤 정본(canonical)으로 연결한다. 같은 상태를 따로 관리해 설명과 실제 값이 어긋나게 만들지 않는다.

내용은 읽는 대상, 갱신 주체나 유지 기간이 의미 있게 다를 때 나눈다. 분리 때문에 전체 의미를 복원하기 더 어려워지면 합친다.

이 기준은 정본이나 책임 Owner를 새로 정하지 않는다. 지속 컨텍스트의 경계와 소유 관계는 `ai-system_context-ownership-boundary.md`를 따른다. 여기서는 그 관계와 필요한 답이 사람이 사용하는 경로에서도 발견되는지 확인한다. `ai-system_context-ownership-boundary.md: 적용`

## 구조 예시

다음은 한 가지 예시이며 표준 구조가 아니다.

```text
workspace/
├─ README.md              # 목적과 사람이 읽는 순서
├─ current/
│  ├─ context.md          # 계속 유효한 현재 맥락
│  ├─ state.md            # 현재 문제와 상태의 해석
│  └─ status.json         # 기계가 갱신하는 최신 상태
├─ records/               # 상세 과정과 증거
├─ workspace.json         # 기계가 읽는 실행 계약
└─ harness/
   └─ workspace.py        # 실제 실행과 검증
```

이 구조에서 사람은 `README.md`에서 시작해 현재 문제와 판단할 사항을 확인하고, 필요할 때만 `status.json`, `records/`와 실제 구현으로 내려간다.

Python이나 JSON을 사람용 형식으로 바꾸지 않는다. 사람이 현재 상황을 이해하기 위해 그것부터 해석하게 만들지 않는 것이 핵심이다.

작은 작업이라면 하나의 문서가 사람용 진입과 현재 맥락을 함께 맡아도 된다.

## 실제로 읽고 판단해 확인한다

사람이 해야 할 검토나 다음 지시 하나를 정하고 실제 진입점에서 읽어 본다. 작성 중 본 대화나 원자료의 기억으로 본문의 빈칸을 채우지 않는다.

1. 핵심 답과 확인·결정할 사항을 어디에서 찾았는지 확인한다.
2. 판단을 바꾸는 조건을 놓치지 않고, 무관한 사례나 이력을 함께 해석하지 않아도 되는지 본다.
3. 상세 근거로 내려가 실제 상태를 대조하고, 수정이나 다음 지시에서 가리킬 대상을 찾는다.

파일과 링크가 갖춰졌거나 분량이 줄었다는 사실로 이 확인을 대신하지 않는다. 필요한 판단이 묻혀 있으면 내용의 선택·비중·배치를 고친다. 이 과정에서도 기계용 산출물의 실행 계약은 유지한다.
