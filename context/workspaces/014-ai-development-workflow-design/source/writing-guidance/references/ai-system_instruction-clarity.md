# AI 지침의 명확성과 적용 범위

AI가 지침을 읽고 의도한 판단과 행동을 복원할 수 있도록 작성한다. 무엇을 해야 하는지, 언제 달라지는지, 무엇을 지켜야 하는지가 드러나야 한다.

전역·프로젝트 지침, skill, agent 역할, prompt와 운영 계약을 새로 만들거나 행동 의미를 크게 수정할 때 적용한다. 이미 작성된 지침을 사용하는 일반 작업마다 다시 읽는 절차는 요구하지 않는다.

## 현재 요구와 필요한 설명을 선별한다

먼저 이루려는 결과와 중요한 제약을 밝힌다. 본문에는 다음 판단과 행동에 필요한 내용을 남긴다.

- **요구:** 기본 행동, 행동이 달라지는 조건, 제약과 예외를 명시한다. 요구가 충돌할 수 있으면 우선순위를 밝힌다.
- **이유와 배경:** 적용 범위를 이해하거나 상황에 따라 판단하는 데 필요한 설명을 둔다. 조사했다는 이유만으로 모두 싣지 않는다.
- **예시:** 추상적인 규칙만으로 구별하기 어려운 경우를 보여 준다. 적용을 바꾸는 특징을 설명하여 이름·단계 수·파일 배치까지 의무로 읽히지 않게 한다.
- **이력:** 현재 요구를 이해하는 데 필요한 이유는 본문에 남기고, 상세한 변경 과정과 과거 판단은 기록으로 연결한다.

현재 따라야 하는 요구와 이해를 돕는 설명은 제목이나 문장으로 구별한다. 모든 지침에 위 항목을 별도 목차로 만들 필요는 없다.

AI가 확인해야 할 자료와 사용자에게 보여 줄 결과도 구별한다. 조사한 항목을 출력 목차로 옮기지 않는다. 결론을 바꾸는 조건과 근거 한계는 결과에 남긴다.

## 관계에 맞는 형식으로 구성한다

하나의 행동을 정하는 조건과 예외는 가까이 둔다. 가까이 둔다는 이유로 서로 다른 판단을 한 문장이나 문단에 모두 넣지 않는다.

- **문단:** 하나의 이유나 관계를 발전시킨다. 다른 판단으로 넘어가면 문단을 나눈다.
- **목록:** 각각 찾아 적용해야 하는 독립 조건이나 항목을 구별한다.
- **번호:** 실행 순서가 결과를 좌우하는 절차를 표현한다. 방법이 달라질 수 있는 일은 순서 대신 판단 기준과 허용 범위를 제공한다.
- **표:** 같은 기준으로 비교할 대상과 차이를 보여 준다. 제목과 항목만으로 뜻을 이해할 수 있다면 같은 내용을 앞에서 다시 설명하지 않는다.

제목은 독자가 찾을 요구나 질문을 드러낸다. 중요한 요구, 조건부 상세, 참고 설명의 비중을 구별한다. 문장 길이를 줄이거나 목록으로 바꾸는 것만으로 이 구별을 대신하지 않는다.

고정 목차나 모든 형식의 사용을 요구하지 않는다. 분량과 형식은 필요한 의미를 찾고 적용할 수 있는지로 선택한다.

## 기준과 상세의 위치를 정한다

같은 기준은 원칙적으로 한곳에서 정의한다. 다른 위치에서는 적용 관계와 이해에 필요한 짧은 전제를 설명한다. 재서술이 필요하면 같은 의미를 유지하는지 확인한다.

별도 파일은 적용 시점이나 관리 책임이 다르거나, 일부 작업에만 필요한 상세를 분리할 이점이 있을 때 만든다. 나눈 뒤에도 언제 무엇을 읽어야 하는지 알 수 있어야 한다. 해당 지침을 적용하는 데 공통으로 필요한 조건을 여러 링크에서 다시 조립하게 만들지 않는다.

지침과 예시는 의도한 결과에 맞는 구성을 사용한다. 압축된 명사 나열, 이어지는 설명 문단, 과도한 항목화 중 어느 하나를 기본 양식으로 삼지 않는다. 주변 문서와 같은 목차라는 사실은 적절한 구성의 근거가 아니다.

## 작성 예시

다음은 조사 기준과 출력 기준을 구별하는 예시다.

**관계가 불분명한 지침**

> Source·configuration·runtime·test·미완성을 확인한다. 역할·흐름·책임·위치·근거·남은 판단을 설명한다. 모든 항목을 매번 조사하거나 출력하지는 않는다.

마지막 문장이 앞선 요구 전체를 제한하지만, 어떤 항목을 선택해야 하는지는 독자가 다시 추론해야 한다.

**선택 기준이 드러나는 지침**

> 사용자가 이해하려는 동작을 설명하는 데 필요한 코드와 설정을 확인한다. 실제 실행 여부가 질문의 핵심이면 실행 기록도 확인하고, 코드에서 추론한 동작과 구별한다.
>
> 답변에는 질문에 대한 결론과 이를 이해하는 데 필요한 연결을 설명한다. 조사한 항목을 그대로 목차로 옮기지 않는다. 확인하지 못한 부분이 결론을 제한하면 해당 설명 가까이에 밝힌다.

이 예시의 핵심은 문장을 줄이는 데 있지 않다. 무엇을 확인할지 고르는 조건과 무엇을 설명할지 고르는 기준을 각각 드러낸 것이다. 실행 순서나 고정 출력 항목이 실제 요구사항인 작업에는 그 요구를 명시한다.

## 기존 지침을 고치고 실제 적용으로 확인한다

문제가 생기면 기존 표현과 적용 관계를 먼저 확인한다. 해당 부분과 예시를 고치고, 중복·대체된 요구·현재 필요하지 않은 보완 규칙을 정리한다. 금지문과 예외를 끝에 계속 덧붙이지 않는다.

도입 의도는 현재 규칙을 유지해야 한다는 근거가 아니다. 그 규칙이 막으려던 실패와 현재 효과를 확인하여 삭제·통합·대체·적용 범위 변경을 판단한다. 중요한 변경 이유는 기록에 남기고 현재 지침에는 유효한 요구를 일관되게 둔다.

확인은 변경의 의미와 실패 영향에 맞춘다. 중요한 행동 변경은 대표 요청에 적용하여 다음을 살핀다.

- 요구와 행동이 달라지는 조건을 지침에서 직접 찾아 적용했는가?
- 중요한 의미와 제약을 놓치거나 예시를 의무로 확대하지 않았는가?
- 적용하지 않아야 할 상황에서 불필요한 절차를 시작하지 않았는가?
- 필요한 설명을 빠뜨리거나 조사 과정과 중복 설명을 과도하게 출력하지 않았는가?

문서에서 발견한 해석 위험과 실제 실행에서 확인된 실패는 구별한다. 사람이 읽기 좋아졌다는 사실만으로 AI의 수행 신뢰성이 개선됐다고 단정하지 않는다.
