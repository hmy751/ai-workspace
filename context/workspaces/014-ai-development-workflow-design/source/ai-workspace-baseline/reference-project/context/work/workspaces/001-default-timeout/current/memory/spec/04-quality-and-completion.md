# 품질·완료 판단

[제품 기준](../../../../../../project/common/prd.md)의 유효 입력·거부 입력과 실제 loader 결과를 대조한다. 특히 누락 시 `5000`이라는 기본값, 명시값 유지, boolean 거부와 반환값 불변성을 [제품 테스트](../../../../../../../tests/test_config_loader.py)로 확인한다.

변경 전후 코드를 비교해 기본값과 검증 책임이 loader에 일관되게 남는지, 같은 규칙을 호출자마다 반복하거나 핵심 동작을 미뤄 둔 부분이 없는지 확인한다. 테스트 통과는 해당 테스트 범위의 근거이며 전체 목표와 별도로 해석한다.

검증 기록과 현재 상태를 다음 Recover에서 찾을 수 있어야 한다. Durable 제품 증거가 필요한 시점에는 [Verify 계약](../../../verify.json)을 사용한다. 마지막 실행 결과와 현재 snapshot의 일치 여부는 다르며, 사람의 명시적 수락 전에는 Workspace 완료로 간주하지 않는다.

현재 실행 결과·미확인 범위·다음 판단은 [Workspace state](../../state/index.md)에서 확인한다. 이 문서에 최근 실행 상태를 중복 관리하지 않는다.
