# Workspace 내부 읽기본

이 파일은 [보존 원본](<../../../noline-evaluation/reviews/noline-design-basis.md>)의 Markdown 링크를 보존된 내부 사본으로 연결한 파생본이다. 본문 주장은 당시 평가이며 현재 설계의 확정안이 아니다. 사본이 없는 링크는 원래 외부 경로로 남겼다.

# Noline 자체 평가를 위한 설계·설치 근거

기준은 Noline `4fb309d2`다. 이 문서는 07·09 연구가 **기대했던 도움**과 Noline에 **실제로 설치된 규정**을 연결한다. 설치와 정적 계약만으로 호출·사용·효과를 인정하지 않는다. 평가 질문은 연구 당시에도 요구한 개발 결과, 코드 품질과 후속 변경, 사람이 이해·판단하며 결과까지 가는 부담의 세 축이었다([07 평가 구조 47–55행](<../../../noline-evaluation/documents/research/07-tripproof-spec-driven-continuity/09-improvement-evaluation/01-evaluation-structure.md:47>)). 필요한 설계·검토 참여는 제거할 부담으로 세지 않았다. 이는 Noline 평가의 배경이지, 과거 연구의 이력서·포트폴리오 목적을 현재 사용자 목표로 가져오는 근거가 아니다.

판정에 특히 중요한 원문은 다음과 같다.

- 07 연구는 “목표를 저장하고 다시 읽거나 작업을 완료했다고 보고하는 것만으로는, 그 목표가 실제 선택과 완료 판단에 사용된다고 볼 수 없었다”고 명시한다([공동 적용 판단 11–16행](<../../../noline-evaluation/documents/research/07-tripproof-spec-driven-continuity/06-judgment-and-understanding-application/01-joint-application-decisions.md:11>)). 따라서 연속성은 관찰할 기제이며 유일한 성패 기준이 아니다.
- 연구의 Spec은 “Work의 결과와 공통 판단 기준”, Ticket은 “확인 가능한 결과를 만드는 실행 단위”다([정의 3–5, 11–21행](<../../../noline-evaluation/documents/research/07-tripproof-spec-driven-continuity/08-skills-spec-ticket-integration/03-spec-ticket-definition-and-scope.md:3>)). Ticket의 네 부분 중 마지막은 **현재 상태와 실제 결과**이며 계획한 확인과 실제 수행을 구분한다([구성 3–7, 25–39행](<../../../noline-evaluation/documents/research/07-tripproof-spec-driven-continuity/08-skills-spec-ticket-integration/04-ticket-components-and-rationale.md:3>)). Noline은 이를 [SPEC.md 34–52행](<../../../noline-baseline/context/work/workspaces/spec-and-tickets/SPEC.md:34>), [TICKET.md 31–49행](<../../../noline-baseline/context/work/workspaces/spec-and-tickets/TICKET.md:31>)에 반영했다.
- 09 연구는 “사람이 필요한 이해와 판단을 유지하고, 나중에 다시 복구해야 할 인지부채를 줄이는 것”을 목표로 두되, 이해 지원을 제품·코드 적합성 판정으로 키우지 않는다([현재 설계 3–7행](<../../../noline-evaluation/documents/research/09-tripproof-cognitive-debt/05-current-solution-design.md:3>), [README 1–5행](<../../../noline-evaluation/documents/research/09-tripproof-cognitive-debt/README.md:1>)). “사용자의 내적 이해 완료를 판정하는 것은 아니다”라는 한계도 명시한다([현재 설계 92–100행](<../../../noline-evaluation/documents/research/09-tripproof-cognitive-debt/05-current-solution-design.md:92>)).
- 구조 표현은 설명의 가설이지 검증된 효능이 아니다. 연구는 화살표·묶음의 의미까지 근거를 요구하고, 정적 Markdown 구조도가 외부 영상의 interactive 탐색과 같은 효과를 낸다는 주장은 배제한다([시각화 분석 13–23, 120–132, 151–157행](<../../../noline-evaluation/documents/research/09-tripproof-cognitive-debt/06-work-artifact-briefing-visual-structure-analysis.md:13>)).

시간 경계도 평가에 필요하다. 07·09의 README는 해당 준비본이 **미설치**이고 실제 효과는 미확인이라고 밝힌다([07 README 9–13, 53–57행](<../../../noline-evaluation/documents/research/07-tripproof-spec-driven-continuity/README.md:9>), [09 README 1–5, 38–40행](<../../../noline-evaluation/documents/research/09-tripproof-cognitive-debt/README.md:1>)). Noline의 `aa2314cd`는 그 뒤의 실제 설치 근거이지만, 연구 자체가 Noline에서 효과를 검증했다는 뜻은 아니다. `b4ed41f6`의 첫 Work 구조에 9월 10일 스킬, 12일 Spec·Ticket 기준, 14일 Project Owner·읽기 기준을 소급하지 않는다([Git 경계](<../../../noline-evaluation/inventory/git-provenance.md:5>)). `4fb309d2`의 문서가 Maintain을 여전히 언급하는 것은 설치판의 역사적 계약을 보여 준다. 이번 자체 평가에서는 중단된 Maintainer 하네스의 작동·개선·재개를 평가 대상으로 삼지 않고, Work의 `current`·output·records와 실제 제품 결과는 계속 본다.
