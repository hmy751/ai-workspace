# 검증 결과와 현재 선택 근거

2026-09-10 기준, Codex 이식 설정은 **`gpt-5.6-sol` + `medium`**이다. 현재 지침 주입 구성에서 합성 장면 8건을 한 번씩 실행해 8건 모두 형식·자료 ID 검사를 통과했고, 원문 대조에서는 7건의 핵심 관계가 보존됐다. 한 건에서는 검토 중 한 행동이 장면 요약에서 빠졌다. 모델이 실제로 자료를 수집·저장하는 장치 검사와, 생성한 문장이 원문에 충실한지의 검토를 구별한다.

실제 프로젝트 자동 수집, Main과 동시 작업할 때의 간섭, 사람의 사후 회고에 얼마나 도움이 되는지, 개발 개선 효과는 이 시험으로 확인하지 않았다. 이 문서는 현재 선택에 필요한 결과와 한계를 소유하고, 원자료·당시 판본·개별 시험 보고서는 013의 작업 기록에 둔다.

## Sol medium을 선택한 근거

초기 역할은 당시 장면을 짧게 연결하라는 요구가 중심이었고, 사용자 반응과 경험의 한정을 반복해서 빠뜨렸다. 초기 세 장면 시험에서 Terra medium·high·xhigh와 Sol medium·high 모두 B의 일부 회고 단서를 놓쳤으며, Astra medium은 두 번 모두 핵심 관계를 남겼다. 이때의 Astra 우선 판단은 초기 역할에 대한 결과다.

이후 역할에 기록의 용도, 생략하면 의미가 달라지는 조건·한정, 자기보고와 관찰의 구별, 선택한 의미를 유지하는 압축과 원문 대조를 반영했다. 수정한 역할을 고정하고 기존 A~C와 새 D~E를 각각 두 번씩 Terra·Sol의 medium·high로 비교했다. 입력과 사전 검토 기준을 고정했고 기대 답변은 모델에게 주지 않았다. 두 검토자가 모델·시간·사용량을 가린 응답을 나눠 원문과 대조한 뒤 Main이 설정을 연결했다.

다음은 **각 설정의 10개 출력**에서 중요한 관계가 남았는지 확인한 결과다. 일반 정확도가 아니며 가벼운 표현 보완까지 없는 완벽한 응답을 뜻하지 않는다.

| 지정 설정 | 핵심 관계 보존 | 중요 맥락 누락 | 누락 내용 |
|---|---:|---:|---|
| Terra medium | 7/10 | 3/10 | B의 초기 반응·날짜 재입력·시간 한정 두 번, D의 저장 안내 유지 요청 한 번 |
| Terra high | 9/10 | 1/10 | B의 초기 반응·재입력·시간 한정 한 번 |
| Sol medium | 10/10 | 0/10 | 이 표본에서 중요 누락 없음 |
| Sol high | 10/10 | 0/10 | 이 표본에서 중요 누락 없음 |

Terra는 당시 호출에서 더 빠르고 참고 비용도 낮았지만 위 단서를 일부 놓쳤다. Sol high는 medium보다 추가 품질 이점을 확인하지 못했다. 이 근거를 보고 사용자가 Sol medium을 선택했다. 현재 역할·주입 구성으로 모든 다른 모델을 다시 비교한 것은 아니므로 최저 비용 설정이나 Astra와의 현재 우열을 확정하지 않는다. 모델은 역할 본문에 고정하지 않고 이식 설정에서 지정한다.

B의 구체적 원문은 “우선 화면은 두자”는 반응 뒤 “날짜를 몇 번 다시 넣어서 좀 손이 가긴 했는데, 오래 걸린 건 아니고”라고 보고하고 날짜 기준을 다시 묻는 흐름이었다. 기술적인 날짜·CSV 관계와 최종 명칭 변경만 남으면 당시 검토 경험이 빠진다. 수정 역할의 Sol은 재입력 행동과 오래 걸리지는 않았다는 한정을 함께 남겼다. 이는 부담이 실제로 개선됐다는 판정이 아니라 자기보고의 의미 보존이다.

당시 40회 전체 출력·익명 검토·사용량은 [역할 보완 후 비교 기록](../../../../../workspaces/013-tripproof-pre-application-evaluation/records/2026-09-10-evidence-collection/before-organization/10-revised-role-parallel-comparison.md)에 있다. 다른 시점의 초기 역할 결과와 비교한 것이므로 지침 변경 하나의 인과 효과나 일반적인 성공률로 확장하지 않는다.

## 현재 구성에서 확인한 여덟 장면

현재 공통 지침과 수집 역할을 고정하고, 직전 시험과 bytes가 같은 입력 8개를 Sol medium에 한 번씩 전달했다. 원자료·manifest·사건·최근 기록만 주고 사전 평가 메모와 이전 출력은 주지 않았다. 각 호출은 새로운 세션이고 동시 2건으로 실행했다. 아래 결과는 Main이 입력과 출력의 전체 필드를 대조한 것이며 독립·블라인드 검토가 아니다.

| 장면 | 구별해야 할 내용 | 현재 결과 |
|---|---|---|

## 남아 있는 G의 누락

사용자는 같은 CSV를 오늘 처음 전체 검토했다며 다음과 같이 말했다.

> 메일하고 왔다 갔다 하긴 했지만 이미 메일에 표시가 돼 있어서 어렵진 않았어.

출력은 다음 부분을 남겼다.

> 메일에는 이미 표시가 되어 있어 대조가 어렵지는 않았다고 했으며

메일과 표를 대조했다는 대상, 어렵지 않았다는 체감, 메일에 표시가 있었다는 이유는 남았다. **메일과 표를 오가며 확인했다는 행동은 어느 필드에도 남지 않았다.** 그 행동을 ‘부담이 컸다’고 평가해 넣어야 한다는 뜻은 아니다. 나중에 당시 경험을 떠올릴 구체적인 과정이 하나 빠진 것이다. 원문은 입력·접수 자료에 보존돼 있어 데이터 소실과는 구별된다.

같은 누락은 공통 지침 추가 전·후와 현재 주입 대체 후에 이어졌다. 현재 지침에는 조건과 경험을 남기라는 원칙이 있지만, 출력에서는 체감과 이유를 남기며 행동을 부수적인 설명으로 압축한 형태가 보인다. 모델의 내부 원인을 확정할 수는 없다. 지침 주입을 대체한 마지막 변경은 본문을 그대로 둔 시험이므로 이 누락을 직접 고치는 변경의 검증도 아니다.

사용자와는 ‘한 행동과 그에 대한 느낌·판단을 서로 대신하는 정보로 취급하지 않는다’는 일반적인 보완 방향까지 논의했다. **이 문서 정리에서 그 방향을 에이전트 본문에 새로 구현하거나 재시험하지 않았다.** 현재 상태는 누락이 남은 준비본이다. 필요하면 짧은 원발화 전체를 보존하는 것도 가능한 표현이며 특정 단어의 포함 여부만으로 채점하지 않는다.

## 실제 입력량과 호출 시간

현재 Codex 어댑터는 선별한 두 본문으로 기본 개발 지침을 대체하고 스킬·프로젝트 문서 주입을 끈다. 별도 macOS 프로세스의 추가 읽기 제한으로 전역 AGENTS 두 후보와 symlink 대상을 가린다. 원본 글로벌 파일·인증·HOME·CODEX_HOME은 바꾸지 않고 read-only/never 권한을 유지한다. 구현과 이식 조건은 [실행 안내](v0/README.md#codex와-claude의-실행-격리)에 있다.

모델 호출 전 인증 없는 localhost에서 같은 어댑터 명령의 요청을 받았다. 선별한 공통·역할 본문은 각각 1회였고 전역 AGENTS·스킬 목록·도구 정의는 0개였다. 관리 문서는 없고 권한 지침은 남았으며 인증 헤더도 없었다. 수신기는 의도적으로 HTTP 400을 반환해 추론을 하지 않았다. 로컬 메시지 텍스트 계산은 16,133 → 4,038토큰이지만, provider·schema·서버 렌더링이 다른 진단값이므로 아래 실제 토큰으로 대체하지 않는다. [요청과 확인값](../../../../../workspaces/013-tripproof-pre-application-evaluation/records/2026-09-10-evidence-collection/before-organization/validation/2026-09-10-instruction-replacement/request-composition/findings.json)

이전에는 전역 주입 위에 공통 지침을 추가해 호출당 입력이 650토큰 늘었다. 그 추가 구성의 8건을 기준으로 실제 주입을 대체한 현재 8건과 비교했다. 두 지침과 사건 입력은 bytes가 같다. 아래 입력·캐시·출력·추론은 **호출당 평균 토큰**, 시간은 CLI 경과시간 중앙값이다.

| 측정 | 이전 추가 구성 | 현재 대체 구성 |
|---|---:|---:|
| 입력 | 19,467.125 | 5,912.625 |
| 그중 캐시 입력 | 1,488 | 496 |
| 출력 | 591 | 542.625 |
| 그중 추론 출력 | 27.25 | 39.75 |
| 호출 시간 중앙값 | 21.512초 | 21.890초 |

평균 입력은 **69.63% 감소**했다. 현재 8회 합계는 입력 47,301토큰·출력 4,341토큰이다. 캐시 입력과 추론 출력은 각각 입력·출력의 일부로 집계했으며 다시 더하지 않는다. 실제 모델명과 청구액은 CLI 메타데이터에 없었으므로 지정한 모델·추론 옵션과 보고 토큰만 기록했다. 과거의 크레딧 환산은 당시 가격과 가정에 따른 참고값이고 실제 차감 영수증이 아니다.

이전 시험은 순차, 현재 시험은 동시 2건이었고 시점·캐시도 달라 시간 차이를 성능 개선으로 해석하지 않는다. 입력 감소율을 전체 청구액 감소율로 바꾸지 않는다. 이 수치는 한정된 합성 입력의 관찰값이며 긴 세션·다른 자료의 호출 비용 상한이 아니다. [계산과 비교 조건](../../../../../workspaces/013-tripproof-pre-application-evaluation/records/2026-09-10-evidence-collection/before-organization/validation/2026-09-10-instruction-replacement/metrics.json)

사건 JSON의 정확한 중복을 접는 처리도 이미 구현돼 있다. 원문 문자열과 원자료 bytes는 유지하고, 동일한 첨부 상세·session_id·경로·크기·미리보기를 참조로 바꾼다. 앞선 다섯 장면에서는 사건 JSON이 평균 2,027.4 → 1,666.4 로컬 토큰으로 줄었지만 전체 CLI 입력의 감소는 훨씬 작았다. 이 사실이 실행 환경의 추가 주입을 확인하게 한 근거다. 현재 중복 해석 규칙은 [실행 안내](v0/README.md#모델-입력에서의-중복-표현)에 본문으로 유지한다.

## 장치 검사와 미확인 범위

마지막 실행 구성 변경 후 모델 없는 검사 **47개**가 통과했다. 어댑터 18개는 지침 전달·판본 보존·세션 분리·명령과 도구 경계, runtime 21개는 복사·중복·허용 경로·크기·부분 보존·재시도·시간순 맥락·회고 보존, 예제 8개는 입력 고정·동시 시험·실패 보존을 확인했다. JSON 형식 검사는 G 같은 의미 누락을 검출하는 검사가 아니다.

- Codex는 `codex-cli 0.153.4`에서 검증했다. 전역 지침 격리는 macOS용이며 다른 OS나 CLI의 로딩 변경은 새 요청 검사가 필요하다. 일부 이전 실행은 CLI 상태 DB·초기화 권한 오류로 모델 시작 전에 실패했으며 실패 기록도 보존돼 있다.
- Claude는 같은 두 지침·schema 연결과 fake CLI 검사까지 확인했다. 실제 Haiku 호출은 `authentication_failed`·미로그인으로 시작하지 못했고 후속 호출을 중단했다. 인증 후 문장 품질은 미검증이다.
- 앱·logger의 생성 지점 연결, 전달되지 않은 사건의 포괄성, 실제 세션 ID·대화/코드 접근점의 유효성은 이식 환경에서 확인해야 한다. fixture가 실제 자동 수집 완료를 입증하지 않는다.
- 현재 binary·이미지는 사본과 metadata만 보존하며 모델이 내용을 읽지 않는다. 큰 자료는 복사 한도를 넘거나 preview가 잘릴 수 있다. 사라진 뒤 전달된 자료를 복구하는 기능도 없다.
- 총 저장량·대기 사건 수의 상한, 장기 검색 성능, 정전 내구성, 강제 종료 후 외부 자식 프로세스 자동 회수는 제공·보장하지 않는다. CLI 자체의 공용 DB·인증·캐시 사용도 별개다.
- 실제 사람의 회고 효용과 이해·부담의 변화, 개발 결과의 개선은 이후 원자료와 사용 경험을 가지고 평가해야 한다.

재검증 명령과 입력 고정 방법은 [실행·검사 안내](v0/README.md#고정-입력으로-모델추론-강도-비교)에 있다. 변경할 때마다 현재 결과를 이 본문에 반영하고 개별 실행의 고정 입력·원출력·판본·실패는 Workspace records에 남긴다.

## Workspace 연결 재설치 검증 — 2026-09-10

Noline에 독립 어댑터를 연결했다. Main의 목적·활성 조건·운영 접근점은 `context/work/AGENTS.md`에, Work와 수집기의 관계는 Work README에 둔다. 루트에 추가했던 수집기 전용 문구는 제거했고 상세 운영은 수집기 README가 소유한다. 사건별 호출·대기·오류 처리는 별도 worker가 맡는다. macOS 서비스는 등록하지 않았으며 사건 수신 시 시작하는 부모 프로세스의 자료 전송·worker 재시작·idle 종료는 유지했다.

수집 runtime 21개·adapter 18개·예제 8개·패키징 3개·연결 13개 검사는 앞선 재설치에서 통과했고, 설치본 Sol medium의 임시 사건 한 건도 원자료 보존부터 기록 저장까지 완료했다. 안내 위치 보완 뒤에는 이전 루트 안내를 Work로 옮기는 검사까지 포함한 연결 검사 14개를 다시 실행해 통과했다. 이 이동은 실행·모델 설정을 바꾸지 않으며 제거 receipt도 함께 갱신한다. Adapter의 최초 sandbox 내 검사 실패와 호스트 재실행 통과는 구분해 보존했다.

Noline 정적 검사와 Maintain 관련 검사는 통과했다. 전체 Harness 122개 중 기존 Verify의 자식 프로세스 timeout 사례 한 건은 실패했고 단독 재실행은 통과했다. 이 실패를 해결했다고 하지 않는다. 실제 사용자 host의 Workspace 작업, 동시 개발 지연, 인증된 Sonnet 실행은 이번 검증에 포함하지 않았다. 수집 모델 지침이나 앞선 의미 누락 사례는 이번 연결 작업에서 바꾸거나 재평가하지 않았다.

후속으로 별도 임시 프로젝트·Workspace·CLI session에서 실제 hook 전달을 확인했다. 연결된 두 요청에서 각각 요청·도구 실행 전후·최종 응답을 포착했고 Sol medium이 기록 두 건을 저장했다. 마지막 요청은 실제 `read-only`·`never` 권한을 확인했으며 원래 session·turn·Workspace·generation과 `PAGE_COUNT=20`, `TOTAL_COUNT=153`이 기록에 남았다. 같은 hook 조건의 미연결 session에서는 수집 원자료가 늘지 않았다. 최초 fixture의 Git·Project trust 누락과 명시적 sandbox 재검증은 실패·조건 변경으로 별도 보존했다. 시험 뒤 수집기 종료와 Maintain 미처리 0개도 확인했다.

실제 Noline은 Project 신뢰와 hooks feature가 켜져 있지만 새 hook 정의의 실행 승인은 없다. Noline에서 Codex CLI의 `/hooks`로 최초 검토·승인이 필요하며 설치기는 전역 보안 설정을 변경하지 않았다. 승인된 CLI fixture의 전달 성공을 현재 열린 Desktop·실제 사용자 세션·Claude의 동작 보장으로 확장하지 않는다. 이 조건은 현재 설치 안내에도 반영했다.
