## 1. 문서는 지속되는 주제와 관련 작업을 중심으로 구성한다

Ticket이나 조사 결과마다 문서를 만들지 않고, 다음 관련 작업에서 반복해서 이해하고 판단해야 할 주제로 구성한다.

특히 guidance는 단순 조언이나 수행 순서가 아니라 **계약·이유·구체적인 적용·판단·검증을 제공하는 작업 가이드**다. API 가이드라면 공통 원칙만 적지 않고 Schedule 등에 어떻게 적용되는지도 설명한다.

`common`은 제품·데이터·시스템의 의미를, `guidance`는 관련 작업에서 그 의미를 적용하고 변경하는 기준을 맡는다. 둘의 차이는 추상적이냐 상세하냐가 아니다.

## 2. 함께 이해할 내용은 모으고, 따로 읽을 이유가 있을 때 나눈다

한 개념의 정의·규칙·예외·주의점을 여러 파일에 흩뜨리지 않는다.

- 해당 주제를 읽는 작업에 공통으로 필요한 내용은 본문에 둔다.
- 일부 작업에서만 필요한 상세는 읽을 조건을 밝히고 분리한다.
- 책임 종류나 문서 길이만으로 기계적으로 쪼개지 않는다.

기준 본문은 하나로 유지하되, 다른 문서를 이해하는 데 필요한 전제를 짧게 다시 설명하는 것은 허용한다. 링크는 상세 확인 경로이지, 본문의 의미를 독자가 조립하게 맡기는 수단은 아니다.

## 3. 남길 가치는 판단하되, 코드에 있다는 이유만으로 제외하지 않는다

설정이나 코드 한 곳에서 바로 확인할 사실을 계속 복제하는 것은 관리비용에 비해 가치가 작은 경우가 많다.

반면 다음 내용은 남길 가치가 있다.

- 선택 이유와 코드에 드러나지 않는 관례
- 오해하기 쉬운 조건과 예외
- 여러 구현 경로를 연결해야 이해되는 관계
- 다음 작업의 판단을 바꾸는 적용 범위나 현재 차이

다만 **남길 가치가 있다는 것과 독립 문서가 필요하다는 것은 별개**다. 가이드 안에서 충분한지, 별도 `current`가 필요한지는 이후 테스트에서 확인한다.

## 4. ‘언제 읽는가’도 문서와 함께 관리한다

물리적으로는 `common/current/guidance`를 유지하지만, 실제 읽기는 Project 진입점에서 **작업·주제별로 시작**하게 한다.

각 문서는 무엇을 설명하며 어떤 작업에서 읽어야 하는지 밝히고, 추가 링크에도 필요한 이유를 제공한다. 모든 작업에서 모든 층을 읽도록 만들지는 않는다.

새 읽기 스킬은 이 경로를 따라 필요한 본문을 선택하고 작업에 적용하도록 돕는다. 문서별 읽기 조건이나 제품 계약을 스킬에 다시 복제하지 않는다.

`summary/read_when` 같은 형식이나 자동 목록 도구는 아직 채택하지 않는다. 먼저 읽기 조건과 실제 사용이 잘 연결되는지 확인한다.

## 5. 갱신은 바뀐 의미와 실제 영향을 따른다

변경된 의미를 소유한 본문부터 갱신하고, 그 변화로 설명·적용·판단·읽기 경로가 달라지는 문서만 함께 맞춘다.

링크로 연결됐다는 이유만으로 전부 갱신하지 않고, 작업이 끝났다는 이유만으로 Project 문서를 새로 만들지도 않는다. 반대로 지속할 변화가 명확해졌다면 작업 종료까지 기다리지 않는다.

## 실제 지침 작업에 연결하면

수정·구성할 대상은 이렇게 잡으면 돼.

- **기준 reference:** 내용 선별, 주제 구성, 분리, 읽기, 갱신의 판단 기준과 대비 사례를 설명한다. 고정 양식 모음으로 만들지 않는다.
- **Project README와 관련 진입점:** 구조·권위 관계를 유지하면서 주제별 읽기 경로를 제공한다.
- **MAINTENANCE.md와 `update-project-context`:** 위 기준에 맞춰 작성·갱신 책임과 수행 방식을 조정한다.
- **새 읽기 스킬:** 관련 본문을 선택하고 이해·적용하는 역할을 구성한다.

Reference의 위치와 파일 분리, 스킬 이름·발동 조건은 구체적인 설계에서 정하면 된다. 기준 본문과 스킬의 중복 소유는 피하고.

그다음 기존 문서는 **원복 범위를 먼저 확인한 뒤** 새 지침으로 다시 구성해 보는 거야. 그 결과로 본문의 충분성, 읽기 부담, 갱신 부담을 보고 `current`의 독립적인 역할을 다시 판단하면 돼. 지금은 원복이나 문서 수정 없이, 여기까지를 반영 방향으로 정리한 상태야.
