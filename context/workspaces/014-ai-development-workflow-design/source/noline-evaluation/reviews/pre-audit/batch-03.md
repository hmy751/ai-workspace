# batch-03 장면 색인

15개 part의 공개 발화를 모두 읽었다. 아래는 평가 후보의 위치를 찾기 위한 색인이다. 코드·테스트·커밋 결과는 대화 속 보고만으로 확정하지 않았다. 상세 근거와 반대 설명은 `batch-03.json`에 있다.

| 장면 | 원문 위치 | 관찰된 전환과 남은 판단 |
| --- | --- | --- |
| B03-S01 첫 사용 버그 조사의 완료 기준 | `01a09951…:124–725` | 사용자는 로그인 결함의 깊이보다 첫 사용의 주요 기능 카테고리를 충실히 조사했는지 물었다. 티켓 이전에 확대 조사를 요구했고 assistant는 범위 부족을 인정했다. 실제 실험 타당성은 미확인. |
| B03-S02 티켓을 앱 장면 순서로 배치 | `01a09951…:732–1081` | 기술 착수 우선순위와 별개로 티켓 번호를 사용자 경험 순서에 맞췄다고 보고했다. 커밋 메시지는 한국어와 저장소 관례를 모두 고려하라는 정정이 있었다. |
| B03-S03 Project 기준 본문의 소유권 | `01a09e0a…:618–930` | 002 Ticket 01–05와 기존 `.claude` 자료를 합치는 범위를 정했다. 첫 산출물이 기록 같고 링크에 기대었다는 사용자 지적 뒤, 이번 주제의 기준 본문을 `context/project`가 소유하되 전체 개편은 유보했다. |
| B03-S04 Project 층과 읽기 경로 | `01a09e0a…:1528–2054` | 사용자는 `current`의 유지비용과 guidance의 실제 역할을 물었다. API 적용 예시에는 긍정했지만 `current` 존폐는 재구성 시험 뒤 판단하기로 했다. 읽기 스킬·reference와 기록 작성 요청으로 이어졌다. |
| B03-S05 구성 시험의 판정 수정 | `01a09e0a…:2179–3052` | 지침 정비 뒤 서브에이전트 재시험을 '성공'으로 보고했지만, 사용자 질문 뒤 티켓 순서가 남은 본문·중복·편입 이력을 다시 발견했다. 지침을 보완하고 시험 산출물을 되돌린 후 다른 세션용 재시험 지시문을 만들었다. |
| B03-S06 원천 context-harness로 역반영 | `01a09e48…:13–1053` | 사용자가 Noline 내부와 별도 원천 저장소를 구별하고, 제품 상세가 아닌 재사용 가능한 이관·구성·읽기 기준을 원천에 반영하게 했다. 뒤에는 Noline 후속 커밋을 근거로 원천 기준을 다시 넓혔다. 실제 이식 효과는 미확인. |
| B03-S07 독립 갱신의 교차 검토 | `01a09f1f…:9–555`, `01a09e0a…:3059–3137`, `01a09f8a…:9–667` | 별도 세션의 갱신 결과가 복사·검토되었다. 검토에서는 기존 의미 누락, 날짜 사실 범위, 실행 기록, runbook 연결 부족을 지적했고, 일부는 후속 독립 실행에서 다르게 나타났다. 복사된 user 역할의 보고는 사람의 승인과 구별해야 한다. |
| B03-S08 큰 게이트에서 최소 수정으로 | `01a09f46…:728–1279` | 문서 전환 누락 뒤 assistant는 여러 완료 게이트를 제안했다. 사용자가 과도함을 지적하자 기존 Owner·작업 진입점에서 재확인하는 한 문장과 현재 문서 직접 보완으로 줄였고, 적용·커밋을 보고했다. 재발 방지 효과는 열려 있다. |
| B03-S09 Ticket 06의 네트워크 문제 재정의 | `01a0a417…:9–401` | startup의 기본 `online` 값을 설명받은 사용자는 Noline의 선택적 라우팅을 상기시켰다. assistant는 Router·Policy·Sync·UI 소비 관계를 다시 조사해 `unknown`만 추가하면 위험하다고 보고했다. 사용자는 정보량을 언급하며 정책 인터뷰를 요청했다. |
| B03-S10 화면 모형에서 코드 재조사까지 | `01a0a417…:416–1263` | 비활성 여행의 오프라인 UX를 인터랙티브 모형으로 논의했다. 모형에 있던 동작을 다시 미정으로 묻는 혼선, `unknown`·약한 연결·쓰기 경계의 설명 수정이 이어졌다. 마지막 넓은 코드 위험 보고에 대한 사용자 후속 반응과 구현 결과는 이 batch 밖이다. |

평범한 진행 표본은 JSON의 `ordinary_spans`에 세 곳 남겼다. 가장 중요한 후속 확인은 Project 본문·기존 진입점·Workspace Recover가 최종 상태에서 실제로 일치했는지와, Ticket 06 정책이 코드·기기에서 어느 범위까지 검증됐는지다.
