## 대표 본문에서 실제로 바뀐 것

### 기기 세션: 같은 계약을 비교 가능한 조건과 결과로 배치

수정 전 원본 L2259의 `common/device-session.md`는 인증 다섯 상태를 목록으로, 재로그인·종료 실패는 여러 문단으로 설명했다. 재로그인 부분의 핵심 원문은 다음과 같다.

> 같은 계정으로 재로그인하면 기존 DB와 미전송 queue를 유지한다.
>
> 서버 인증 성공만으로 재로그인이 완료되지는 않는다.

10월 1일 편집 이후 본문은 같은 계정 성공·다른 계정·취소/실패·저장 뒤 캐시 실패를 `재로그인 결과 | 유지·적용할 상태` 표로 나누었다. 후속 수정본의 핵심 행은 다음과 같다.

| 재로그인 결과 | 유지·적용할 상태 |
| --- | --- |
| 같은 계정으로 인증하고 기기 저장·세션 적용까지 성공 | 기존 DB·미전송 queue를 유지하고 보호 요청을 다시 허용한다. 나머지 조건도 맞으면 sync를 재개한다. |
| 기기 저장·세션 적용 뒤 캐시 갱신 실패 | 이미 완료된 인증 저장을 실패로 되돌려 표현하지 않는다. |

종료 부분은 “정상 로그아웃은 Local DB·queue·기기 인증·선택·조회 캐시를 비운다”를 먼저 드러낸 뒤, 실제 순서가 데이터 손실 판정에 영향을 주는 세 단계와 실패 위치별 결과 표를 유지했다. 서버 로그아웃 실패와 계정 삭제 실패의 서로 다른 결과, DB를 비운 뒤 인증 삭제가 실패하면 DB가 복구된 것이 아니라는 예외도 남았다. 의미를 일괄 축약한 변화가 아니라 조건·순서·실패 결과의 발견 경로를 바꾼 편집이다.
