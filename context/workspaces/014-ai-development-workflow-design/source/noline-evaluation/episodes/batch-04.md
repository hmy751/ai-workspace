# batch-04 장면 색인

inventory의 batch-04 part-01~13을 순서대로 모두 읽었다. part-02·05·07·13의 한 번 출력이 잘려 해당 구간을 sed로 재독해했다. 패킷의 공개 발화 전체를 대상으로 했고 도구 출력·실행 결과·내부 리뷰어 원문은 열지 않았다. 마지막 part-13은 사용자 선택 설명 직후 끝나므로 후속 구현은 미확정으로 둔다.

현재 JSON에서 생성한 색인이다. 독립 검토가 적용된 장면은 승인 경위·보고 주체·미확정을 보강했다. 원문 인용과 대안은 상세 링크에서 함께 읽는다.

## B04-S01 · 온라인 비활성 여행 지원을 새 정책으로 오인한 설명 복구

assistant가 조사 중 찾은 경로 결함과 이번 unknown 정책을 넓게 묶어 설명하자 사용자가 범위를 물었다. 코드 흐름 설명 뒤 정상화에는 동의했지만, 이후 온라인 비활성 수정·삭제가 본래 지원할 동작임을 지적했다. assistant가 새 정책처럼 표현한 점을 정정하고 초점을 unknown 쓰기 제어로 되돌렸다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s01)

## B04-S02 · unknown 의미를 빈도 우려와 함께 결정

사용자가 unknown이 초기 상태만인지 재관측의 미확정도 포함하는지 확인했다. assistant는 새 제안임을 구별했고, 사용자는 값의 흔들림과 화면 전환 빈도를 따졌다. NetInfo 구현에 대한 assistant 설명 뒤 사용자는 실기기 측정을 선행 조건으로 둘 수 없다며 현재 판단을 요구했고, 이후 판정 불가를 unknown에 반영하고 10초 안내를 선택했다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s02)

## B04-S03 · 버튼별 검사 대신 Router 차단과 화면 안내로 경계 정리

사용자는 입력을 유지하면서 쓰기 실행을 막는 방식을 논의했고 버튼마다 unknown 조건을 두는 관리 부담을 제기했다. Router가 실행 시점에 오류로 차단하고 UI가 안내하는 방식으로 좁혔다. 캐시 삭제 없이 제한 화면을 보이기로 했고, 실행 환경 격리가 확인되지 않아 debug override를 화면 중심으로 두고 쓰기·새 sync 전송은 차단하기로 했다. 전송 후 응답 유실은 이번 큰 정책 인터뷰에서 일반 서버 요청 처리로 되돌렸다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s03)

## B04-S04 · Maintain 실패 뒤 결정 기록을 직접 복구하고 보존성 확인

Maintain 재연결 요청에서 문서 해시 충돌과 누락 합의를 확인했다는 보고가 있었다. 이후 사용자가 대화 전체를 바탕으로 Work 문서 갱신을 요청했고, assistant가 Ticket 06·Spec·기록 등을 직접 갱신했다고 보고했다. 사용자는 나중에 다시 판단할 수 있을 만큼 앞선 논의도 보존됐는지 두 차례 확인했다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s04)

## B04-S05 · 가독성 요구가 독립 리뷰의 판정 기준과 테스트 검출력으로 구체화

첫 Network Store 단계 후 사용자는 원래 목표가 코드 가독성임을 재강조했고 제품 코드와 테스트 전체를 다듬게 했다. 첫 독립 리뷰에서는 현재 개선을 평가했으나, 사용자는 리뷰어가 스스로 개선 목표·구체 기준을 제시해야 한다고 정정했다. 두 번째 리뷰는 Router 테스트의 구별력, sync 시작 책임, 재확인 요청 수명을 제안했고, assistant는 작업자 구현과 변이 검사 결과를 보고했다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s05)

## B04-S06 · 전문가 리뷰의 미해결 문제를 인계하고 새 세션에서 재현

사용자는 Store 변수 노출 우려에서 종합 코드 전문가 리뷰를 요구했다. assistant는 private closure라는 판단과 debug 수동 sync 우회·중복 sync 문제를 미해결로 보고했다. 사용자 요청에 따라 인계 기록·Ticket·state를 갱신했다고 했고, 다음 세션은 해당 티켓과 기록을 읽어 코드에서 두 문제와 여타 잔여 경로를 다시 확인했다고 보고했다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s06)

## B04-S07 · 동작 개선으로 넓어진 품질 작업을 철회하고 목표를 다시 좁힘

사용자는 작업 중 코드 전체의 품질 리뷰와 worker·독립 검증을 요청했다. 구현 전 리뷰가 티켓·합의에 맞는지 묻고, 그 채택 판단은 Main이 해야 한다고 정정했다. assistant가 sync·startup·Router·화면 연결의 채택·제한을 제시하고 관련 기록과 코드를 읽었다고 답한 뒤 사용자는 진행을 지시했다. 이후 assistant는 확대된 소비 연결 구현과 205개 테스트 통과를 보고했다. 결과 설명을 본 사용자는 원래 원한 가독성·응집도·파악 용이성에 비해 동작 개선 범위가 커졌다며 작업 전 코드로의 복구를 요청했다. assistant는 복구·90개 테스트 통과를 보고했고, 사용자는 이미 남은 기록을 철회 표시와 함께 보존하기로 선택했다. 이후 동작 보존 중심의 좁은 품질 리뷰와 5개 파일 정리 결과가 보고됐다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s07)

## B04-S08 · 코드 위치와 동작 질문을 통해 사용자가 판단을 이어감

Network Store 설명 뒤 사용자는 session 수명을 자기 말로 재구성했고, 이후 소크라테스식 질문에서 앱 진입·sync 차단, 활성 여행 저장, ref 잠금 등을 답했다. Promise 대기 의미에서는 두 번 혼란을 표시해 assistant가 코드로 풀었고, 실제 파일·줄 위치를 요구했다. 후속 network 타이머 설명에는 이해했다고 말했으나 늦은 응답 우선순위는 모르겠다고 했다. assistant가 sync engine 질문까지 확장하자 사용자는 작업 범위를 다시 물은 뒤 질문을 멈추고 작업 부분 설명을 요청했다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s08)

## B04-S09 · 커밋 범위를 두 차례 정정하고 코드 검토 순서를 정함

assistant가 네트워크 관련 코드 11개와 테스트 4개를 커밋했다고 보고하자 사용자는 검토된 Network Store·테스트·필요한 호출부만 뜻했다고 정정했다. assistant는 부분 커밋으로 고쳤다고 했지만, 후속 설명을 본 사용자가 Provider·Router 등도 제외하라고 재지시했다. assistant는 더 좁은 커밋으로 재구성하고 남은 변경을 작업 폴더에 보존했다고 보고했다. 이후 사용자가 Policy·Router·Provider 세 파일을 별도 커밋하게 하고 대응 테스트 누락을 바로잡았다.

[원문·해석·대안·미확정](../scene-evidence.md#b04-s09)

## B04-S10 · Layout과 DB·인증 초기화의 책임을 재구성하되 선택 경계는 보류

앞 세션에서는 사용자가 Layout 파일 분리 위치와 FSD 책임을 따져 최종적으로 Layout 안 유지를 택했고, assistant는 테스트·커밋·결정 기록을 보고했다. 새 세션은 그 티켓/기록을 출발점으로 DB·인증 실패 처리를 다음 작업으로 골랐다. 사용자는 DB 실패 재시도와 인증 읽기 실패 시 로그인 흐름을 구분한 뒤 시나리오 테스트 선행을 요구했다. 구현 보고 후 preparation/auth 중복과 Spec의 응집도 목표를 지적해 Root 중심으로 정리시켰고, 다시 모듈 경계를 물었다. 독립 리뷰 뒤 새 `application` 위치는 수용했지만 파일 세 개가 리뷰어 권고인지 assistant 안인지 확인했다. 마지막에는 여행 선택·cleanup 경계에 대한 질문 중 하나는 설명을 요청했고 하나는 선택했다.
