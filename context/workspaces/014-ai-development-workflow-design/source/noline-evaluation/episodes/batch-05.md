# batch-05 장면 색인

inventory의 batch-05 전체 10개 part(두 세션, 206,930자)를 순서대로 읽었다. part-01의 최초 cat 출력은 중간이 잘려 해당 줄을 다시 읽었고, 나머지는 part별 줄 구간으로 나눠 잘림 없이 읽었다. 원본 corpus 인접 발화 추가 조회는 하지 않았다. 도구 출력·실제 diff·테스트 로그는 열지 않았으므로 assistant 보고로 표시했다. part-08:2308의 user 역할 내용은 과거 기록 복사본이며 사람의 새 정책 발화로 취급하지 않았다.

현재 JSON에서 생성한 색인이다. 독립 검토가 적용된 장면은 승인 경위·보고 주체·미확정을 보강했다. 원문 인용과 대안은 상세 링크에서 함께 읽는다.

## B05-S01 · 앱 준비와 여행 데이터의 구분을 브리핑 뒤 확인

사용자는 서버가 선택 여행의 삭제를 확인했을 때 다른 여행으로 전환하는 선택을 했다. 초기화·선택·cleanup 변경 보고 뒤 코드 읽기 순서와 도식을 요청했고, 브리핑 다음에는 여행이 없으면 DB도 없는지 물었다. assistant는 DB 준비와 여행 row 존재를 구분해 답했다.

[원문·해석·대안·미확정](../scene-evidence.md#b05-s01)

## B05-S02 · 코드 스타일 불안을 독립 기준과 적용 결과로 연결

사용자는 개행과 코드 품질을 우려하며 변경 파일만 독립 리뷰어에게 보낼 것을 요구했다. assistant는 리뷰 기준을 주석·로그·이름·비동기 표현·테스트 대기까지 확장해 보고했다. 사용자가 적용을 요청하자 정리와 154개 테스트 통과를 보고했고, 이어 records·Ticket·state 갱신 및 8a1a3ea 커밋을 보고했다.

## B05-S04 · 인증 논의에서 예시가 논점으로 바뀌자 판단을 철회

## B05-S05 · 세션 상태의 모호함을 저장·복원 계약으로 구체화

사용자는 토큰·ID·로컬 소유권·서버 인증을 프로그램 상태로 어떻게 표현할지 반복해 물었다. assistant의 세 상태, 플래그, 다시 세 상태 제안은 토큰 누락과 복원 실패 반례에서 수정됐다. 이후 세션 기록을 SecureStore에 한 묶음으로 저장하고, 세션 없음·복원 오류·재인증 필요를 구분하는 안이 정리됐다. 사용자는 초기화 상태 이름, 무기한 로컬 이용, 다른 계정 전환 시 폐기, 로그아웃 중 앱 종료 복구 제외를 정했다. 장기 기록은 source 원문 복사 대신 records/current에 넣도록 정정했고, assistant는 정책 문서 커밋 10960e9와 구현·235개 테스트 통과를 보고했다.
