사용자가 **회고(retrospective)**를 요청했습니다. 코딩 에이전트의 **환경**을 개선해 다음 실행을 나아지게 할 방안을 제안합니다.

## 단계

1. 작성 스타일 지침을 확인하기 위해 `writing-for-agents` Skill을 호출합니다.

2. 사용자가 지정한 세션의 주요 원자료를 읽습니다. 이 자료는 이 컴퓨터의 세션 로그 검색을 포함할 수 있습니다. 세션을 지정하지 않았다면 현재 세션을 기본으로 합니다.

3. 다음 범주에서 개선 후보를 찾습니다.

- **탐색**: 에이전트가 올바른 파일을 찾기 쉬웠나요? 파일 간 숨은 의존성이 있나요? 탐색 포인터를 두면 도움이 되나요? 정보를 찾는 데 오래 걸렸을 때 살펴봅니다.
- **자동 검사**: 린트, 타입 검사, 테스트, 파일 시스템 린터 등 에이전트가 한 실수를 잡을 자동 검사가 있나요? 새 검사를 제안하기 전에 저장소 자체의 검사 명령부터 읽습니다(`package.json`, 빌드 도구의 `lint`/`check` 스크립트, CI 워크플로). 이미 존재하지만 연결되지 않았거나 조용히 고장 난 검사가 발견 사항입니다. pre-commit hook도 없고 CI에서 lint/typecheck/test도 실행하지 않는 저장소는 그 자체로 개선 기회입니다. 자동 검사가 잡을 수 있는 실수를 에이전트가 했거나 저장소에 guardrail이 전혀 없을 때 살펴봅니다.
- **코딩 표준**: reviewer 에이전트에 새 규칙을 추가해야 하나요? 기존 규칙을 제거하거나 명확하게 해야 하나요? 먼저 위반을 분류합니다. 고정된 문법 형태, 금지 API, import 형태, 파일 위치 규칙처럼 **기계적으로 판별 가능한 것**은 결정론적 검사로 처리합니다. 저장소 자체의 린터에 사용자 규칙을 추가하거나, pre-commit hook 또는 CI 작업을 추가합니다. 기존 guardrail에 가장 저렴하게 붙일 수 있는 방식을 택합니다. 규칙을 문서에 쓰기보다 검사를 만드는 것을 기본값으로 합니다. 어떤 guardrail로도 대체할 수 없는 파일 간 일관성, “주변 스타일과 맞음”처럼 실제 판단이 필요한 경우에만 `CODING_STANDARDS.md`를 사용합니다. reviewer 에이전트가 실수를 놓쳤을 때 살펴봅니다.
- **전역 AGENTS.md**: 저장소 또는 사용자 전역 범위의 `AGENTS.md`가 특히 크다면, 지시 중 코딩 표준이나 자동 검사로 옮겨야 할 것이 있나요?
- **도구 효율**: 비싼 도구 호출을 줄일 수 있었나요? 토큰 효율이 특히 낮은 사용자 정의 도구(CLI, MCP 등)가 있나요? 에이전트가 비용이 큰 도구 호출을 했을 때 살펴봅니다.
- **효과 없는 지시(No-ops)**: steering 파일에 에이전트 행동을 바꾸지 않는 지시가 있나요? 지침 파일이 크고 다루기 어려울 때 살펴봅니다.
- **정보 접근**: 에이전트가 정보에 더 쉽게 접근할 방법이 있나요? 개발 서버 로그를 미리 연결하거나 외부 서비스에 읽기 전용 접근을 주는 방식이 예입니다. 중요한 정보에 접근할 수 없었던 경우 살펴봅니다.

4. 후보를 심각도 순으로 사용자에게 제시합니다.

## 참고

### 구현과 검토

모든 작업에는 구현과 검토의 두 단계가 있습니다. 구현 에이전트는 가장 큰 문맥 부담을 가집니다. 탐색, 코드 작성, 실패 디버깅을 담당합니다.

검토 에이전트는 diff만 받으므로 문맥 부담이 가장 적습니다. 탐색이나 코드 작성, 디버깅이 필요하지 않은 경우가 많습니다.

따라서 코딩 표준을 적용하는 책임은 구현 에이전트가 아니라 검토 에이전트가 맡아야 합니다.

### 파일

저장소에는 다음 파일이 있습니다.

- `CLAUDE.md`/`AGENTS.md`: 저장소에서 작업하는 모든 에이전트의 문맥에 자동으로 들어갑니다. 매우 아껴 써야 하며, 보통 다른 파일을 가리키는 탐색 포인터만 둡니다.
- `CODING_STANDARDS.md`: 구현 단계가 아니라 검토 단계에서 읽습니다. 1,000줄을 넘으면 docs 폴더를 가리키는 탐색 포인터를 추가합니다.
- 문서: 다른 문서가 가리키는 참고 자료로 사용합니다. 새 문서를 만들기 전에 기존 문서를 찾습니다.
- Skill: 설명이 에이전트 문맥에 자동으로 들어가는 문서나 사용자가 직접 호출하는 절차에 사용합니다. 작성 방식은 `writing-for-agents` Skill 지침을 따릅니다.
