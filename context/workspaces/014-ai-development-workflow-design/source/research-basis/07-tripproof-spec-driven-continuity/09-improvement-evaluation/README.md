# 스킬·레퍼런스 개선안의 평가 준비

05·07 문제 분석을 바탕으로 개선한 스킬·레퍼런스·작업 구성을 여러 개발 작업에서 평가하고, 그 변화와 개발자의 기여를 설명하기 위한 연구 묶음이다. 현재 사용할 내용을 목적별 본문으로 구성하고, 연구의 이전 판본은 archive에, 작업·정리 이력은 Workspace records에 보존한다.

## 현재 문서와 읽는 방법

**평가안의 구체화 결과는 [06 확인할 성과와 평가안](06-outcomes-and-evaluation-plan.md)이다.** 선정한 성과별로 전후 차이·판정 조건·비교 근거·업무 의미·개발자 기여를 채웠다. 서브 작성 뒤 별도 리뷰와 Main 보완을 거친 제안이며, 아래 01~05는 구조와 방법·근거를 상세히 확인할 때 사용한다.

**사후 평가를 위한 자료 수집 준비본은 [07 증거 수집](07-evidence-collection/README.md)에 있다.** 현재 사용할 수집 대상·시점·기록 형식, Main 밖에서 실행하는 에이전트와 runtime, 이식 방법·검증을 본문에 담는다. 제작 논의와 모델 시험 원자료는 [013의 수집기 기록](../../../../workspaces/013-tripproof-pre-application-evaluation/records/2026-09-10-evidence-collection/README.md)에 보존한다. 코드·대화 원본을 재사용하면서 당시 자료와 회고 단서를 보완한다. 수집 기록에서 성과를 판정하지 않으며, 실제 프로젝트의 자동 수집 연결은 이식할 곳에서 정한다.

[01 전체 평가 구조](01-evaluation-structure.md)는 평가 대상·기존 세 기준·성과 항목·판정과 근거·해석 관점이 어떻게 이어지는지 보여 준다. 전체 관계를 확인할 때 여기서 시작한다.

[02 평가 방법](02-evaluation-method.md)은 실제로 평가를 진행하며 참고할 본문이다. 개선 대상과 기대 행동의 대응, 설계 이유와 대안·비용, 설계·행동 확인, 세 기준의 관찰 질문과 판정 조건, 충족과 개선의 구분, 기여·비교·기록 방법을 다룬다.

[03 외부 자료 분석](03-external-reference-analysis.md)은 회사·연구별로 무엇을 어떻게 비교했는지, 수치가 무엇을 의미하는지, 이번 평가에서 어떤 방법을 쓰고 어디까지 해석할지를 설명한다. 외부 출처 목록과 접근 상태는 기존 source가 소유한다.

[04 실제 평가 기록과 사용 예](04-worked-evaluations.md)는 과거 리팩터링의 원문·전후 코드·대조 명령·판정·다른 해석을 담는다. 미구현을 보고한 사실과 요구 충족을 구분하는 실제 장면, 일반 개발 장면의 예, 판단이 갈리는 조건, 다음 확인과 다른 사람에게 보여 줄 근거도 본문에서 읽을 수 있다.

[05 문제·개입·검증 근거](05-problem-and-intervention-basis.md)는 05·07의 원래 문제, 당시 체계의 강점, 개선한 구성, 판본과 검증 상한, Before 자료의 해석을 다룬다. 적용 범위와 비교 시작 상태를 정할 때 참고한다.

실제 평가를 준비할 때는 02와 04를 함께 사용하고, 외부 비교 방법은 03, 출발 문제와 판본·검증 상태는 05에서 확인한다. 번호 전체를 순서대로 다시 읽는 절차는 아니다.

## 구체화한 내용과 다음 판단

전체 구조를 문서로 남기고 09~13에서 유효한 내용을 위 다섯 본문에 재구성한 뒤, 다음 세 작업을 06에서 연결했다.

1. **확인할 성과를 구체적으로 정하기**: 핵심 누락에 따른 작업 재개, 후속 변경의 어려움, 반복 설명 부담 등이 어떻게 달라지는지.
2. **각 성과의 판정 기준과 근거를 연결하기**: 어떤 경우에 개선됐다고 인정할지, 코드·실행·작업 기록 등 무엇을 비교해서 판단할지.
3. **그 성과의 의미와 개발자의 기여를 연결하기**: 업무적으로 왜 중요한지, 개발자가 어떤 문제를 발견하고 판단·개선했는지.

기존 세 평가 기준은 위 작업에서 사용하는 큰 질문이다. 위 세 가지는 수행한 구체화 작업이며, 새 평가 기준 세 개를 추가한 것이 아니다. 06은 네 성과를 선정하고 각 성과에 위 세 작업의 내용을 채웠다. 다음 판단은 제안한 성과와 판정 조건의 수용·보완이며, 실제 적용할 때에는 작업·시작 상태·개입 판본·관찰할 장면을 선택한다.

평가 대상은 이번 개선안이고, 범용성은 기능 개발·리팩터링·버그 수정 등 다른 프로젝트와 작업에도 평가 방법을 해석해 사용할 수 있다는 뜻이다. TripProof는 출발 근거, Noline 등은 적용 사례 후보다. 이력서가 우선 사용처이며 업무·비즈니스 의미와 AI-native 역량은 개선 과정과 평가 결과에 연결해 해석한다.

이번에는 성과별 세부 구체화와 그 검토까지 진행했다. 관련 원자료와 외부 방법을 필요한 범위에서 재확인했고, 실제 프로젝트 적용·설치·효과 실험은 수행하지 않았다. 작성·검토·보완 범위는 [Workspace 검토 기록](../../../../workspaces/013-tripproof-pre-application-evaluation/records/2026-09-09-05-outcome-concretization-review.md)에 있다.

## 현재 본문·연구 과거 판본·작업 이력의 관계

```text
09-improvement-evaluation/
├─ README.md                         목적·범위·읽는 방법
├─ 01-evaluation-structure.md         전체 구조와 개념의 관계
├─ 02-evaluation-method.md            상세 평가 방법
├─ 03-external-reference-analysis.md  회사·연구 사례의 상세 분석
├─ 04-worked-evaluations.md           실제 평가·개발 예·다음 확인
├─ 05-problem-and-intervention-basis.md 문제·구성·검증의 근거
├─ 06-outcomes-and-evaluation-plan.md 선정한 성과·판정·근거·의미와 기여
├─ 07-evidence-collection/            현재 수집 계약·실행 패키지·검증 결과
└─ archive/                          연구의 이전 초안·분석·리뷰 판본
```

현재 본문은 작업과 판단에 필요한 설명·표·사례·코드·근거를 소유한다. [archive](archive/README.md)는 원래 09~13의 분석·초안·리뷰 전체 판본을 보존한다. 유효한 상세를 확인하려면 과거 판본부터 읽어야 하는 구조로 만들지 않는다. 당시 분석의 표현·검토 대상·근거를 재검토할 때 archive를 사용한다.

[Workspace 013의 records](../../../../workspaces/013-tripproof-pre-application-evaluation/records/README.md)는 작업 요청·정정·선택·정리·검사의 시간 이력을 소유한다. 이번 정리 기록과 첫 요약안도 그곳에 있다. 연구 본문을 Workspace에 복제하지 않고 두 위치를 연결한다.

내용이 바뀌면 그 내용을 소유한 현재 본문을 갱신한다. 같은 내용을 여러 현황·후속 초안에 계속 복제하지 않고, 필요한 지위·독자·수명이 달라질 때 문서를 나눈다. 원래 09~13의 이동 위치와 해시·링크 보정은 [정리 기록](../../../../workspaces/013-tripproof-pre-application-evaluation/records/2026-09-09-03-evaluation-organization.md)에 있다.

연구 내용의 정본은 이 `context/analysis` 묶음, 외부 출처 목록과 접근 기록의 정본은 [source 09](../../../source/09-ai-native-engineering-evaluation/source.md)다. [Workspace 013](../../../../workspaces/013-tripproof-pre-application-evaluation/README.md)은 진행 상태와 자료·산출물 지도를 소유한다. Main이 연구 내용과 연결을 관리하고 사용자가 평가 목적·범위·중요 선택과 수용을 판단한다. 파일 검사나 Maintain 갱신이 연구의 타당성이나 실사용 효과를 대신 판정하지 않는다.
