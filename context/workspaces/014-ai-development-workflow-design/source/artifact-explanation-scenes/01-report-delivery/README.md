# 01 — 네 보고서 작성 요청 전후의 원문

2026-10-22 자료 보강: [당시 코드·도구 기록과 출처](historical-materials/README.md)를 추가했다. 공개 발화 원본은 유지하고, 압축 rollout에서 확인한 자료와 시점별 한계를 분리했다.

## 먼저 읽을 원문

[input/conversation.txt](input/conversation.txt)는 세션 `01a1052a-4e61-7072-9b81-ff44449e5b85`의 source_line **12~619**, 사용자·AI 공개 메시지 **30개**다. 시작은 Ticket 06 재개 요청이고 끝은 아래 실제 사용자 답변을 포함한 원래 레코드다.

> 네, 앞서 설명한 2~5번

마지막 발화는 원래 로그의 질문 응답 wrapper까지 그대로 보존한다. 바로 앞603에는 네 보고서를 작성하라는 요청이 있고608에는 AI의 대상 확인이 있다. 원문의 오타·띄어쓰기·Markdown·자동 삽입된 브라우저 문맥도 수정하거나 삭제하지 않았다. 원래 corpus가 공개 메시지로 추출해 둔 범위를 유지하며 전체 도구 trace나 내부 추론을 포함한 로그 전문이라고 주장하지 않는다.

**선택한 재개 지점은619 다음이다.** 이때부터 보고서 작성 작업을 이어가는 조건이다. 자료 수집이 끝난 직후의 첫 보고 문장만 생성하는 조건과 다르다. 새로 만든 자연어 과제를 덧붙이지 않는다.

## 이후 원문

[evaluation/conversation.txt](evaluation/conversation.txt)는 **634~1119**, 메시지 **14개**다.619 이후 조사·첫 보고·사용자 정정·추가 조사와 재작성·후속 사용자 반응까지 이어지는 원문이며 구간 안의 메시지는 생략하지 않았다.779의 첫 보고와789의 사용자 교정은 모두 이쪽에 있다. input을 보고 수행하는 주체에게 이 원문을 함께 주면 안 된다.

두 파일을 순서대로 이으면 원 corpus의12~1119 공개 발화 전체가 된다. 이 사건의 이후 메시지와 나머지 세션은 포함하지 않았다. 범위 선정 이유와 한계는 [구성 기록](../../../records/2026-10-21-ticket04-02-source-scene-assembly.md)에 둔다.

- [observed-artifacts](observed-artifacts/README.md): 현재 Noline에서 발견한 관련 파일41개를 별도 보존했다. 최초 보고서와 재작성본이 같은 경로에서 덮어써졌을 수 있어619 시점 자료로 자동 제공하지 않는다.
- [manifest](manifest.json): 각 메시지 범위·파일 해시·Git 기준·현재 사본의 원래 경로·확보하지 못한 범위를 담는다.

같은 원 경로의 `.jsonl.zst`에서 당시 도구 읽기·관찰·최초 보고서 생성 명령을 추가 확보했다. 압축 해제 해시는 기존 meta와 일치한다. 초판 HTML 전체 바이트·전체 워커 내부 실행·DB·시뮬레이터 상태는 완전히 복원하지 않았다. **원자료 확보와 역사 실행 전체 재현을 구별한다.**
