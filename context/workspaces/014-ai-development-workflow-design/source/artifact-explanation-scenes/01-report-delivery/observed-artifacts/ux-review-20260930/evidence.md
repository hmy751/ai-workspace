# Ticket 06 UX 판단용 1차 증거 — 2026-09-30

수집 담당이 기존 자료를 색인하고 실제 화면의 빈 부분을 보완한 묶음이다. UX 수락, 결함 원인, 수정 우선순위는 이 문서에서 결정하지 않는다. 재사용 3묶음과 신규 2묶음을 구성했다. 기존 증거를 이번에 새 실행한 것처럼 해석하지 않는다.

## 환경·변경 범위

- iPhone 15 Pro / iOS 26.0 / simulator `D22939DA-F2A4-4F24-B286-197DC62F415C` / 개발 앱 `com.noline.dev`.
- 시작: 홈, 온라인, 파리 9월30일~10월2일, 온라인 전용(비활성), 일정 2개, 경비 EUR 25.00. 하단에 기존 Controller/CreateScheduleScreen 개발 경고가 있었다.
- MobileBuildMCP의 이 subagent 세션 defaults는 비어 있었다. simulatorId/bundleId를 세션에만 설정(`persist:false`)했다. 빌드·앱 재설치·프로젝트 설정 변경은 하지 않았다.
- 신규 수집에서 네트워크 override를 바꾸지 않았다. 읽기 화면만 이동했고 데이터 생성·수정·삭제·로그아웃은 하지 않았다.
- 신규 캡처와 원문 발췌만 이 폴더에 추가했다. 제품 코드·Workspace 문서·기존 자료는 수정하지 않았다.

## 검토 질문별 증거 색인

### 1. 홈의 연결 상태·제한 안내·복귀 표시를 함께 읽을 수 있는가 — 재사용

근거: [기존 화면 색인](../index.html), [온라인 활성 홈](../01-online-home.jpg), [활성 offline 홈](../02-active-offline-home.jpg), [비활성 offline 홈](../04-inactive-offline-home.jpg), [비활성 unknown 홈](../06-inactive-unknown-home.jpg), [온라인 복귀 홈](../07-online-restored-home.jpg).

조건·행동: 앞선 검증에서 활성/비활성 여행과 Debug override offline/unknown을 비교하고 override를 해제했다. 이번 수집에서는 04·06·07을 직접 열어 화면을 확인했고 홈 제한을 다시 재현하지 않았다.

관찰:

- 04의 상단은 ‘오프라인’, 여행 카드에는 ‘온라인 전용’이다. 일정·경비 숫자 각각의 자리에서 동일한 ‘인터넷에 연결되어 있지 않아요. 오프라인에서는 활성 여행을 선택해주세요.’ 문장을 표시한다. 캡처에서 문장은 좁은 두 영역 안에서 여러 줄로 나뉜다.
- 06의 상단은 ‘확인 불가’이다. 일정·경비 자리 각각에 아이콘과 ‘다시 확인’ 버튼이 보인다. 이 캡처에서 원인 설명 문장은 시각적으로 보이지 않는다.
- 07은 상단 ‘온라인’, 같은 여행 카드, 일정 2개·EUR 25.00을 표시한다. 제한 카드 대신 숫자가 보이는 비교 근거다.
- 02의 기존 캡션은 활성 여행의 offline 상태에서 로컬 데이터 숫자가 유지됐다고 기록한다.

전/후: 04 또는 06 → 07. 한계: Debug override 기반의 정지 화면이며 실제 단절·실제 통신 재접속·조회 성공 시각·사용자가 복귀를 알아차린 시점을 보여주는 영상은 없다. 07 제목의 ‘실제 온라인 복귀’는 override 해제 후 실제 관측 상태로 돌아왔다는 앞선 기록이며 실제 네트워크 단절을 새로 검증한 근거는 아니다.

### 2. 상세에서 활성/비활성 여행의 제한 범위를 이해할 수 있는가 — 재사용

근거: [활성 offline 일정 상세](../03-active-offline-detail.jpg), [비활성 offline 일정 상세](../05-inactive-offline-detail.jpg).

조건·행동: 앞선 검증의 여행 활성 상태 차이와 offline override. 이번 수집에서 05를 직접 열었다. 03은 기존 캡션을 재사용한다.

관찰: 05는 ‘일정 상세’ 제목과 하단 탭을 유지하고 중앙에 ‘작업을 수행할 수 없습니다’, ‘인터넷에 연결되어 있지 않아요. 오프라인에서는 활성 여행을 선택해주세요.’를 표시한다. 일정 A 내용은 보이지 않는다. 03의 기존 캡션은 일정 A와 연결 경비 1개가 표시됐다고 기록한다.

전/후: 같은 소비자의 활성/비활성 조건 비교이며 연속 전환 증거가 아니다. 05의 우측 상단에는 연결 상태 아이콘과 ‘오프라인’ 라벨이 보인다. 한계: 현재 온라인 상세는 아래 신규 5번과 비교할 수 있지만 촬영 시점·하단 개발 경고가 달라 단일 전환 영상으로 취급하지 않는다.

### 3. 작성 중 제한·복귀와 입력 유지가 어떤 흐름을 만드는가 — 재사용

근거: [앞선 폼 검증 원문](../form-verification.md), [수동 일정 작성](../08-manual-schedule-offline.jpg), [online 복귀로 폼 숨김](../09-manual-schedule-online-hidden.jpg), [장소 선택 후 offline](../10-selected-schedule-offline.jpg), [취소 개발 경고](../11-schedule-cancel-warning.jpg).

조건·행동: 앞선 실제 화면에서 미저장 입력을 둔 채 기존 networkStore override를 전환했다. 이번 수집에서 폼 입력보존이나 알려진 일정 생성 문제를 반복하지 않았다.

관찰은 원문에서 재사용한다:

- 경비 생성은 제한 중 안내 화면으로 교체되고 복귀 후 제목·금액·선택 일정이 유지됐다.
- 경비 수정과 일정 수정은 Drawer 안에 제한 안내가 표시됐고 복귀 후 미저장 제목과 기존 값이 유지됐다.
- 수동 일정 입력 중 online 복귀하면 검색 단계가 보였고 unknown에서 입력값이 다시 보였다. 08→09는 작성 화면 표시가 바뀐 근거다.
- 장소 선택 후 offline에서 접근성 트리에 일반·수동 폼이 함께 존재했다. 10 한 장에 두 폼이 모두 선명하게 보인다고 해석하지 않는다.
- 일반 폼 취소 뒤 Controller/CreateScheduleScreen 경고가 표시됐다. 11은 앞선 재현 근거다.

한계: 경비·일정 수정의 입력보존은 원문 관찰 기록을 근거로 하며 해당 전/후 신규 이미지가 없다. 실제 단절·저장 성공·키보드/팝업 조합은 미확인이다. 알려진 문제의 코드 원인·이번 변경과의 관계는 앞선 원문에 조사 내용이 있으나 수집 담당이 새로 판정하지 않았다.

### 4. 정상 일정 목록의 여행·상태·내용·추가 동작 배치는 어떤가 — 신규

근거: [12 온라인 일정 목록](12-online-schedule-list.jpg), [실제 UI 발췌](ui-excerpts.md).

조건·행동: 시작 홈에서 기존 개발 경고 상세 overlay를 Minimize하고 ‘일정’ 탭을 눌렀다. 여행과 Debug 상태는 변경하지 않았다.

관찰:

- 헤더 ‘일정’, 우측 ‘온라인’과 지도 보기 버튼, 그 아래 ‘파리, 프랑스 / 메인’ 여행 선택 영역이 보인다.
- 첫 날짜 구간은 `2026-09-29`, `0개`, ‘이 날의 일정을 추가해보세요’와 ‘추가’이다. 이어 `2026-09-30`, `2개`, 일정 A(루브르/17:00), 일정 B(오르세/21:00)가 보인다. 아래에는 `2026-10-01`, `0개`가 보인다.
- 시작 홈의 여행 카드 기간은 9월30일~10월2일이었다. 목록 첫 구간에 9월29일이 표시되는 사실만 기록하며 원인은 확정하지 않는다.
- 기존 개발 경고가 하단 영역을 일부 덮고 있다. 제품 UX의 일반 상태와 개발 경고가 섞인 캡처임을 고려해야 한다.

전/후: 시작 홈의 원문 발췌 → 12. 한계: 목록의 offline/unknown 표시, 지도 보기, 추가 버튼 진입, 날짜 전체 범위와 스크롤은 이번에 확인하지 않았다.

### 5. 정상 상세의 연결 상태·내용·연결 경비는 어떤가 — 신규

근거: [13 온라인 일정 A 상세](13-online-schedule-detail.jpg), [실제 UI 발췌](ui-excerpts.md).

조건·행동: 12의 기존 ‘검증 일정 A’ 카드를 눌렀다. 데이터 수정은 하지 않았다.

관찰: ‘일정 상세’와 뒤로 가기, 우측 ‘온라인’이 보인다. 일정 A/루브르/Paris/2026-09-30/17:00, 총 경비 EUR 25.00(1개), ‘지도에서 보기’, ‘경비 추가’, 경비 내역 1개와 ‘검증 입장료 / EUR 25.00 / 기타’가 표시된다. 하단 기존 개발 경고도 남아 있다.

전/후: 12 → 13. 05와 13으로 제한 상태의 내용 가림과 정상 상태의 내용 영역 차이를 비교할 수 있다. 한계: 상세에서 제한→복귀를 이번에 새 실행하지 않았고 경비 상세로 이동하지 않았다.

## 수집 중 장애와 범위 종료

첫 MobileBuildMCP 일정 탭 ref 조작은 기존 개발 경고 상세 overlay를 열었다. runtime snapshot에 Dismiss/Minimize가 tap target으로 나오지 않았다. 이 overlay는 신규 결함 재현이라고 주장하지 않는다. native Simulator AX에 보이는 Minimize를 한 번 눌러 홈으로 돌아왔고 이후 정상 목록·상세 이동이 가능했다. CUA 초기화 호출 자체가 약 114초 걸렸다. 긴 runtime 우회·새 harness 설치·오류 상태 주입은 하지 않았다.

Main의 1차 수집 종료 지시에 따라 일정 목록·상세 2장으로 신규 수집을 마쳤다. 경비 목록·경비 상세, 최초 조회 실패·갱신 실패와 재시도, 시작/인증/foreground 재확인, mutation 제한 이유, 실제 통신 단절·재접속·저장 성공은 이번 1차 수집에서 미확인이다. 위 범위를 기존 자료가 입증한 것처럼 확장하지 않는다.

## 최종 UI 상태와 제어 반환

홈 탭으로 돌아가 native AX로 복구를 확인했다: 온라인, 파리 9월30일~10월2일, 온라인 전용, 일정 2개, 경비 EUR25.00. 기존 개발 경고는 시작과 같은 하단 Minimize 상태이다. override·활성 여부·서버 데이터를 변경하지 않았다. 이후 추가 조작은 하지 않으며 시뮬레이터 제어를 Main에 반환한다.

현재 복구 토스트를 추가하지 않는 결정은 [작업 기록](../../../context/work/workspaces/002-code-readability-refactoring/records/2026-09-30-02-recovery-toast-and-ux-review.md)에 있다. 이 증거 묶음은 그 결정의 종합 UX 검증 완료를 뜻하지 않는다.
