③ 목록·상세·폼 종합 UX

9월 30일 보고서는 연결이 바뀌면 작성 화면이 사라지거나 제한 안내로 교체되는 문제를 남겼습니다. 이후 작성 흐름을 개선했고, 이번에는 남아 있던 비활성 목록의 제한·복귀를 추가 확인했습니다.

비활성 목록의 제한·복귀와 선택창을 닫은 뒤 입력 보존은 확인됐습니다. 선택창에서 기존 날짜·시간이 처음부터 보이지 않는 문제를 추가로 확인했습니다.
목록은 이 대표 흐름에서 추가 수정이 필요하지 않습니다. 작성 흐름은 기존 개선을 유지하고, 날짜는 현재 값을 전달하고 시간은 선택된 값이 보이도록 열면 됩니다.

수동 일정 작성 중 online이 되면 검색 화면으로 밀림, 폼 두 개가 함께 생김단일 초안·단일 폼으로 변경. 연결 전환 때 제목·장소와 작성 단계를 유지하는 자동 검사 있음옛 캡처를 현재 결함으로 다시 올리지 않습니다.
경비 작성 중 제한 안내가 폼 전체를 대신함폼을 유지하면서 후보·저장을 제한하도록 개선. 10월 2일 실앱에서 입력 보존·복귀 후 명시적 저장 확인이미 개선한 동작입니다. 전체 경비 폼을 다시 만들 필요 없습니다.
목록·상세의 제한·복귀 경험은 덜 확인됨이번에 기존 비활성 여행에서 online→확인 불가→offline→실제 상태 복귀를 실행아래 대표 목록에서는 안내 중복이나 복귀 후 내용 유실을 발견하지 않았습니다.

작성 화면에서는 무엇을 확인했나

일정 직접 입력에서 제목 REPORT-1004를 적고 날짜·시간 선택창을 각각 열었다 닫았습니다. 닫은 뒤 제목·9월 30일·09:00은 그대로였고, 마지막에는 저장 없이 취소했습니다.

추가로 선택창의 초기 표시를 코드와 대조했습니다. 날짜창에는 현재 폼 날짜를 전달하지 않아 9월 30일을 보여주지 않았습니다. 시간은 09:00을 내부적으로 선택하고 있지만 그 위치로 스크롤하지 않아 처음에는 위쪽 00부터 보였습니다.

보완할 것은 명확합니다. 날짜창에 현재 날짜를 연결하고, 시간창은 선택된 시간이 처음부터 보이도록 엽니다. 시간 값이 00:00으로 바뀌거나 입력이 유실된 문제는 아닙니다.

어디서 추가 확인을 멈췄나

비활성 기존 경비에는 연결된 일정이 없었습니다. 그래서 “이미 연결된 일정이 있는 비활성 수정 초안에서 제한·연결 해제” 조건을 확인하려고 새 데이터를 만들지는 않았습니다. 이 조건은 현재 자동 검사 근거를 사용하고, 실제 해당 데이터가 있는 다음 폼 검증에서 확인하면 됩니다.

열린 작성 폼에는 Debug로 가는 경로가 없어 그 폼을 유지한 채 강제 상태를 바꾸는 수집은 하지 못했습니다. 앞선 10월 2일 입력 보존 관찰과 현재 자동 검사를 유지하며, 이번 선택창 확인을 그 전환 검사로 대신하지 않습니다.

첫 실패·재조회 실패 안내는 기존 자동 검사에 있습니다. 이번에는 정상→제한→복귀라는 원래 질문을 확인했으며 서버 중단과 실패 주입까지 새로 확장하지 않았습니다.
