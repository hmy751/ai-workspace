② 앱 복귀와 네트워크 재확인

06번은 연결이 달라져도 현재 화면을 올바르게 제한하고 복구하는 작업입니다. 앱 밖에 있는 동안 연결이 바뀐 경우까지 이어지는지 확인하려고 이 항목을 봤습니다.

수동 재확인은 구현됐지만, 앱으로 돌아올 때 그 재확인을 호출하는 연결은 아직 없습니다.
다음 작업은 기존 재확인 함수를 앱 복귀 시 한 번 호출하도록 연결하는 것입니다. 네트워크 감지 전체를 새로 만들 필요는 없습니다.

왜 확인했나

9월 30일 보고서는 주로 앱을 열어 둔 상태에서 제한·복구되는 화면을 봤습니다. foreground 항목은 그 보고서에서 새로 발견한 화면 버그가 아니라, 06번 티켓에 남아 있던 “다른 앱에 갔다 돌아왔을 때도 현재 연결을 다시 확인한다”는 연결 작업입니다.

그래서 정상 홈 사진만 추가해서는 답이 되지 않습니다. 복귀 시점에 실제로 재확인을 요청하는 코드가 있는지 확인해야 했습니다.

되는 것과 빠진 것

대상판단
기존 연결 감지·화면의 다시 확인 버튼구현됨. 연결 감지는 계속 작동하고 버튼은 기존 refresh 함수를 호출합니다.
앱 복귀 시 한 번 재확인앱과 설치된 NetInfo 11.4.1 소스에서 해당 연결이 없습니다.
왜 이것이 필요한가설치 라이브러리의 안내도 iOS에서 백그라운드 중 Wi-Fi 변경을 놓칠 수 있어 복귀 시 재확인을 권합니다.
기존 감지를 모두 실패로 봐야 하나아닙니다. native 이벤트와 주기적인 인터넷 확인은 존재합니다. 복귀 순간 확인을 요청하는 연결이 빠진 것입니다.

그래서 무엇을 하면 되나

  1. 앱의 복귀 이벤트에서 기존 refresh를 호출합니다. 복귀할 때마다 화면을 강제로 unknown으로 바꾸거나 초기화를 반복하지 않습니다.
  2. 복귀 이벤트가 호출을 만드는지, 연속 복귀·수동 확인이 겹쳐도 중복 요청을 공유하는지 검사합니다.
  3. 연결이 바뀐 뒤 돌아오는 대표 흐름을 한 번 확인합니다. 조회나 sync는 갱신된 상태를 기존 경로로 소비하게 둡니다.
판정: 구현할 연결이 남아 있습니다. 이번에는 소스와 설치 라이브러리의 동작 범위를 더 확인했으며 제품 코드는 바꾸지 않았습니다.

실제 화면에서 확인한 범위

Home 버튼으로 나갔다 앱 아이콘으로 돌아오는 동작은 정상입니다. 이 사진은 복귀 자체의 참고 자료이고, 자동 재확인 호출의 증거는 아닙니다.
