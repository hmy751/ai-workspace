⑤ 보류·후속 작업과 06번의 종료 경계

이 보고서는 새 버그를 찾기 위한 검사가 아닙니다. 앞선 개선과 남은 문제를 보고 “06번에서 지금 끝낼 일”과 “다른 작업으로 남겨 둘 일”을 정리한 것입니다.

지금은 홈 안내와 앱 복귀 연결을 정리하고, 대표 화면 전환 확인을 마치는 데 집중하면 됩니다.
날짜 차이는 원인을 확인했으므로 날짜 작업으로 연결합니다. 이미 보류한 경비 두 문제와 다른 티켓 전체를 다시 06번의 할 일로 가져오지 않습니다.

기존 작업과 연결작업 선택보류 내용종료 기준참고 화면전체 보고서
전체 보고서9월 30일 원래 보고서① 홈 안내② foreground 복귀③ 목록·상세·폼 UX④ 날짜 표시 차이⑤ 보류·후속 범위

왜 이 정리가 필요한가

9월 30일 보고서에서 일정 작성 화면이 사라지거나 두 폼이 생기는 문제가 발견돼 일정 작성 흐름을 고쳤고, 이어 경비 작성·연결·실패 안내까지 개선했습니다. 지금은 그 결과를 확인하면서 06번의 남은 범위를 정하는 단계입니다.

처음 만든 ⑤ 보고서는 후속 티켓과 내부 구현을 길게 나열해, 당장 무엇을 하자는지 흐렸습니다. 아래 네 가지로 정리합니다.

이번에 할 일과 남겨 둘 일

판단구체적인 행동
06에서 지금 처리홈의 중복·읽기 어려운 제한 안내 개선, 앱 복귀 시 재확인 연결, 목록·작성 대표 전환 결과 확인
이미 고친 것을 재사용일정 단일 초안·단일 폼, 경비 폼 유지·일정 연결·저장 실패 안내. 옛 스크린샷의 문제를 그대로 다시 수정 목록에 넣지 않음
다른 작업으로 연결홈·목록 날짜 기준 차이는 날짜 작업(08). 이번에 확인한 날짜·시간 선택창의 초기 표시는 일정 폼 작업(10)에 좁혀 연결. 저장 후 경로·전체 sync·cleanup은 각 기존 담당에서 계속.
기존 결정 유지경비 삭제 실패 이유 유실·특수 Debug 재시도는 보류. 복구 토스트도 현재는 추가하지 않음

보류 두 문제는 무엇인가

경비 삭제가 실패했을 때 이유를 충분히 전달하지 못하는 문제, 그리고 Debug 표시만 online이고 실제 연결은 끊긴 특정 상세 오류 상태에서 재시도 버튼을 눌러도 요청이 나가지 않는 문제입니다. 사용자가 10월 2일 이번에는 넘기기로 했으므로, 이번 점검에서 다시 착수할 이유는 없습니다.

복구 토스트는 보류된 구현이 아니라 “지금은 추가하지 않는다”는 선택입니다. 실제 복귀 화면에서 사용자가 상태 변화를 알아보기 어렵다는 근거가 생길 때 다시 검토하면 됩니다.

언제 06번을 마쳤다고 볼 수 있나

남은 홈 안내·복귀 연결을 처리하고, 원래 불편을 대표 화면 흐름에서 다시 확인한 뒤 결과를 정리하면 됩니다. 실제 통신 단절 저장이나 모든 날짜 선택 조합을 검증했다고 확대하지 않되, 그런 전체 검증을 이유 없이 이번 완료의 필수 조건으로 추가하지도 않습니다.

보고서는 다음 행동을 정하기 위한 것입니다. 현재 제품 수정은 아직 하지 않았으므로, 이 보고서 작성 자체가 06번 작업 완료는 아닙니다.
