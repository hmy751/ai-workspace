## 복원과 확인

부모 압축 로그를 해제한 SHA-256은 기존 corpus 메타와 일치한다. 당시 임시 백업 디렉터리는 현재 남아 있지 않아, Git HEAD·작업 전 diff·원 코드 읽기 출력·워커별 수정 기록을 시간순으로 대조했다. 현재 Noline working tree나 철회 뒤1209 코드는 사용하지 않았다.

69개 중33개는 당시 전체 파일 읽기 출력과 동일하고26개는 당시 diff를 HEAD에 적용한 결과가 기록된 Git blob 해시와 일치한다. 나머지10개는 당시 기록된 파일 생성·치환·patch·포맷 순서를 따라 복원했다. 이10개를 원 파일 바이트 사본으로 부르지 않는다. Root·두 상세 화면·일정 화면의 최종 주요 구간은 독립된 후속 읽기 출력과도 일치한다.

전후 diff를 별도 작업 전 사본에 재적용한 결과69개 모두 작업 후 사본과 일치한다. 이는 묶음의 전후 관계 확인이지 제품 테스트 재실행이나 모든 줄의 역사적 동일성 증명은 아니다. 실제 도구·DB·native·서버 실행 환경은 복원하지 않았다.

복원 중 두 공백을 지위별로 처리했다. Policy 워커의 첫 편집 스크립트에는 문법 오류가 있었고 바로 뒤 보존된 수정 스크립트와 후속 diff로 최종 코드를 확보했다. Main의 문서 갱신 중 state/output의 선행 dirty 전문은 완전히 복원하지 못했으므로 그 문서를 현재 자료로 내보내지 않았다. Ticket 전문·해당 Ticket 갱신과 최종 작업 기록은 별도 확보했다. `provenance/replay-issues.json`은 이 중간 복원 이력이며 최종 파일 공백과 동일하지 않다.

원자료의 당시 주장과 사용자가 뒤에 내린 범위 판단을 구별한다. Main/검토자의 “합의 범위 충족”은 원문대로 남기되 시험의 기대 답으로 쓰지 않는다. 이후 수정·철회 발화는 이 자료에 포함하지 않았다.
