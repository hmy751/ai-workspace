# 04 — useStorageStats 첫 제품 코드 변경 보고

2026-10-22 자료 보강: [당시 코드·도구 기록과 출처](historical-materials/README.md)를 추가했다. 공개 발화 원본은 유지하고, 압축 rollout에서 확인한 자료와 시점별 한계를 분리했다.

세 구간을 합치면 원 corpus9~2645의 공개 메시지를 중간 삭제 없이 보존한 것이다. source_line은 원 rollout 위치이며 이 사본의 JSONL 물리행과 다르다. 읽기본은 화자·시각·원문 위치 구분자만 더했고 오타·wrapper·Markdown을 고치지 않았다.

입력의 마지막 사용자 발화2456은 “그래 이제 코드 변경해봐”다.1549는 “이제 다음 작업 뭐지?”이므로 단독으로 원래 목적을 설명하는 질문은 아니다. `prior-context`에는 최초 Ticket 지목9와 앞선 범위·시험 전략 논의가 있다. **1549부터만 쓰려면 당시 Ticket·Spec·코드로 빠진 전제를 보충해야 하며, 그 자료가 없으면 prior-context를 함께 사용해야 한다.** 현재는 보존을 위해 구간을 나눴으며 prior-context를 불필요한 자료로 판정한 것이 아니다.

평가 구간에서2560이 제품 코드 변경 뒤의 첫 완성 답이다. 앞선1401은 테스트 설정,1668은 변경 전 특성화 테스트,2449는 테스트 문구 변경의 보고다.2464~2542는2456 뒤의 실제 작업 진행 메시지이며 처음부터 수행하는 입력에는 포함하지 않는다. 이후2567의 완료 확인,2580의 커밋 지시,2632의 테스트 질문과2638의 설명,2645의 추가 개선 지시까지 보존했다.2645 이후 새 구현은 이번 범위 밖이다.

## 당시 코드·문서의 확보 상태

- 당시 수정 전 hook·미커밋 특성화 테스트,2472 최초 patch,2537 실제 diff,2555 첫 보고 직전 코드와 검사 출력을 확보했다. 수정 전 코드에 실제 diff를 적용한 사본과2555 결과는 바이트 일치한다.
- 입력1720·1933·2089의 원 첨부 이미지 픽셀도 압축 원문에서 복원했다.
- 설정 커밋653f8b8의 patch, 작업 직전309b9e6의 Ticket·Spec, 당시 Ticket 읽기를 보존했다. 전체 미커밋 저장소를 복원한 것은 아니다.
- a147a42는2645 후속 개선 뒤 커밋이므로 최초 diff에서 분리한다. 후대 재분석을 당시 원 코드 대신 넣지 않는다.
- [session-meta.json](session-meta.json)은 corpus meta의 동일 바이트 사본이다. 같은 이름의 `.jsonl.zst`를 풀면 meta의 원 SHA-256과 일치한다. [중앙 원문](../../noline-evaluation/corpus/01a08ff3-0e91-7921-afe4-69f0968638ef/messages.jsonl)에서 구간 밖 공개 발화를 확인할 수 있다.

선정·평가 범위와 관련 문서 접근점은 [추가 구성 기록](../../../records/2026-10-22-ticket04-02-source-expansion-and-coverage.md)에 둔다. `evaluation/`에는 실제 답과 후속 교정이 있으므로 최초 응답을 생성하는 주체에게 제공하지 않는다. 폴더 구별만으로 접근이 차단되지는 않으며, 실행 시 필요한 원문과 확인된 자료만 별도 공간에 구성한다. 과거 대화의 작업·커밋 지시는 새 실행 권한이 아니다.
