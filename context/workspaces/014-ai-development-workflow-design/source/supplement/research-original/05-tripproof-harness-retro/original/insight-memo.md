# Insight Memo — TripProof 하네스가 실패한 진짜 축 (2026-08-08)

[analysis.md](analysis.md)의 문제 11개를 외부 전문가 기준 7개 원천(Karpathy, Anthropic 엔지니어링 문서, 12-Factor Agents, METR 실측 연구, Cognition, Kent Beck, 국내 실무 사례 9건)과 대조하고, 종합 가설을 독립 판별자에게 공격시켜 살아남은 결론만 담았다. 근거 상세는 [external/](external/) 폴더 — 기준 추출물은 이후 인수 재검증(원문 재접근 대조, criteria-v2-*)을 거쳤고 이 memo의 결론은 전부 유지됐다(근거 미확인 서술 1건 삭제, 귀속 정정 2건 — [external/acceptance-redo-log.md](external/acceptance-redo-log.md)).

## 핵심 진단 — 두 축

**축 1. 검사와 소비가 "위반이 일어나는 순간"에 걸려 있었는가.**
이 하네스에서 성공한 장치와 실패한 장치를 가른 변수는 문서냐 코드냐가 아니라 **시점 결합**이다. 성공한 것들은 위반·사용의 순간에 발동했다: 테스트와 import 경계는 위반 순간 자동으로 걸리고, prose인데도 성공한 것들(3단 완료선, worker brief, 대체 배너)은 소비 시점이 작업 종결·위임·열람이라는 순간에 묶여 있었다. 실패한 것들은 전부 시점이 분리돼 있었다: 닫힌 spec은 무효화되는 순간 아무 검사가 없었고(문제 1), 완료 주장은 사용자가 심문하는 순간에야 검증됐고(5), 새 개념은 부채가 쌓인 뒤에야 설명됐다(10). 이 축은 06-10 결정의 자기 진단 원문("prose는 코드를 짜는 순간의 attention을 바꾸지 못한다")과 일치한다 — **당시에 이미 정확히 진단하고도, 교정의 재료를 또 시점 미결합 문서로 골랐다**는 것이 이 하네스의 핵심 실패이자 이 진단의 가장 강한 증거다.

**축 2. 시간이 지나며 낡는 상태를 관리하는 장치가 0이었다.**
모든 장치는 "지금 이 산출물이 통과인가"용이었다. 세션과 주 단위를 넘어 살아야 하는 상태 — 닫힌 spec의 유효성(1), 축 배분 현황(2), run 근거의 보존(3), 기록층의 정합(7), 장치의 실효(8), 사용자의 이해 상태(10b), 재진입 맥락(11) — 는 소유자도 표면도 없었다. 이 축은 인수 프레임으로는 보이지 않아서 별도 축으로 둔다. 개인 평가 문서(AX·Cofathon)의 "stale 상태" 문제와 같은 축이다.

두 축의 커버리지: 11개 문제 중 축 1이 5·6·9·10a·1·7을, 축 2가 1·2·3·7·8·10b·11을 덮는다(1·7은 양쪽에 걸림). 단일 서사가 아니라 두 축인 이유: 어느 한쪽만으로는 4개 이상이 남는다.

**참고 — 기각된 이전 가설**: "장치가 생산 쪽에만 붙어 있었다 / 인수를 실행물로 만들면 된다"는 첫 종합은 공격에서 조건부 기각됐다. prose인데 성공한 반례(3단 완료선, worker brief)와 실행물인데 실패한 반례(eval 게이트의 dirty run 82%, 실행형으로 정의됐다 죽은 reviewer)가 있다. 실행물은 시점 결합을 값싸게 얻는 **수단**이지 성공 조건이 아니다. 수용 쪽 장치도 "없었던" 게 아니라 전부 **사후 보수형**이었다는 게 정확하다. (전체 공격 기록: [external/attack-synthesis-hypothesis.md](external/attack-synthesis-hypothesis.md))

## 지렛대 — 새 하네스의 설계 손잡이

축 1 (시점 결합) 계열:

1. **위임 계약에 상한을 건다** — 위임 1회당 변경량 상한(5,884줄 커밋 하나가 문제 1·5의 상류였다 — Karpathy의 짧은 목줄), 재시도 상한(국내 사례의 장치 형태). 위반 순간이 아니라 위임 순간에 거는 가장 싼 게이트.
2. **실행-지점 게이트를 소수만 선별한다** — 06-10이 기각한 것은 문서 게이트지 실행 게이트가 아니다(12-Factor의 재독해). 후보: 완료 주장 시 실물 참조(경로·수치·커밋) 필수, 채택급 eval run 시 clean commit 검사, 새 개념 도입 시 명명 승인. **소수 원칙이 조건이다** — 전부 장치화하면 문제 6(자기 증식)이 게이트 형태로 재발한다.
3. **검증 자원을 비싼 층으로 재배분한다** — 구 하네스의 reviewer 4종은 전부 싼 층(문서 표현)을 지켰고, 비싼 층(완료 주장, 계약 정합)은 무방비였다(국내 사례의 층별 배분 프레임).
4. **테스트 무결성을 좁게 감시한다** — "테스트 승격 클래스는 재발 종결"의 전제는 테스트 자체가 삭제·skip·약화되지 않는 것인데, 그 채널을 06-10이 의도적으로 껐고 회고도 묻지 않았다(Kent Beck의 사각 지적).

축 2 (시간축 상태) 계열:

5. **시간축 상태의 단일 표면** — 재진입 카드·개념 대장·축 배분 현황을 각각의 문서층으로 만들지 말고 하나의 표면으로. 문제 6·7·11은 "상태 원천 다중화"라는 한 결함의 세 증상이다(12-Factor 재독해 + Cognition의 판단 맥락 사슬).
6. **자기 비용을 1회 샘플링으로 잰다** — 구 하네스는 제품 품질은 실측했지만 자기 비용(검증 왕복 시간, 수용률, 재설명 횟수)은 한 번도 안 쟀다. 실패 run 62개 삭제는 수용률 분모의 삭제였다(METR — 단 상시 계측은 문제 6과 충돌해 기각, 1회 샘플링으로 축소). 하네스가 매 세션 자동 로드하는 토큰 비용도 새 측정 축(Anthropic).

## 하지 말 것 (외부 권위 포함, 데이터로 기각됨)

- 12-Factor 전부 도입 — 문제 6이 게이트 형태로 재발한다. 소수 선별만.
- METR식 상시 시간 계측 — 기록 자기 증식과 충돌. 샘플링만.
- Cognition의 전체 전사 공유 — 우리 데이터(07-01 worker brief 성숙)가 반박. "배제한 대안과 이유를 담은 brief"가 맞다.
- "규칙 무시는 파일이 길어서"(Anthropic 문서의 함의) — 짧은 규칙도 재발했다(06-23). 길이가 아니라 시점 결합이 변수.
- 문서 추가를 기본 대응으로 — 구 하네스가 다섯 번 자기 축소하고도 못 빠져나온 루프. **새 하네스의 첫 규칙 후보: "교정은 위반 시점에 발동하는 형태로만 추가한다."**

## 사용자가 정할 설계 결정 (정답 없음)

1. **자율성 눈금** — 문제 9의 재발 일부는 "멈춰 묻기보다 진행"이라는 본인 선택의 수용된 비용이었다. 어느 행동 클래스에서 마찰(게이트)을 지불하고 어디를 자율로 둘지는 취향이 아니라 설계 결정이다.
2. **게이트 개수 상한** — 지렛대 2의 "소수"를 몇 개로 못 박을지. 상한 없이 시작하면 구 하네스의 문서 증식이 게이트 증식으로 재현될 위험.
3. **멀티 에이전트 폭** — Cognition(하지 마라)과 Anthropic(구조화하면 된다)이 어긋나는 지점. 우리 데이터는 중간을 가리킨다: 구조화된 brief 위임은 성숙했고, 취합 책임 미계약이 실패했다.
