# 06 — Reference 적용과 Noline 재적용

014에서 구체화한 개발 작업 체계를 먼저 `reference-project/`에 반영하고, 그 결과를 Noline의 기존 설치에 맞춰 다시 적용한다. 공통 기준을 실행 가능한 Reference로 만드는 일과, 제품 맥락·기존 변경이 있는 대상에 적응하는 일을 아래 두 결과로 나눈다.

2026-10-29 사용자 요청으로 기존 전환 설계 티켓을 분할했다. 두 하위 Ticket의 목표는 설계·적용·직접 확인까지다. [분할 이유·기존 내용 대조](../../../records/2026-10-29-ticket06-split.md)에 당시 요청과 변경 범위를 남겼다. 후속 요청으로06-01의 [유지·교체·제거 검토안](../../../records/2026-10-29-ticket06-01-reference-transition-proposal.md)을 작성했다. **후속 승인으로 독립적인 context·설명·한정 반영의 [첫 적용·직접 확인](../../../records/2026-10-29-ticket06-01-reference-partial-application.md)을 마쳤다.** Maintain·Work 기록/전환은 현행을 유지하며 전체 workflow 적용·새 host 확인은 남아 있다. 상세 선택·상태는06-01을 따른다.

06-01의 독립 묶음 반영과 확인 범위를 입력으로, 후속 사용자 승인에 따라06-02의 Noline 부분 반영과 정적·읽기 전용 확인을 마쳤다. 전체06-01·06-02 완료나02의 통합 테스트를 앞당겨 완료 처리하지 않는다. 상세 상태·선택·완료 조건은 각 하위 Ticket이 소유한다.

## 이어받는 현재 합의

- Personal은 로컬 `context/personal/`, Project는 제품의 의미·계약·지속 규약·현재 사실, Work는 이번 작업의 선택·진행·결과를 맡는 구상을 사용한다. 전역 Personal 설치안은 현재 선택이 아니다. 실제 대상의 배치와 기존 Owner 연결은 하위 Ticket에서 구체화한다.
- 개발 실행 정본은 prototype의 `skills/development/`와 그 상세다. Personal의 개발 판단 기준과 실행 workflow는 서로 다른 책임이다. 과거 `DEVELOPMENT.md`의 위치·스킬 전환을 미정으로 다시 열지 않는다.
- 공통 읽기 `USAGE`, 한정 반영 `context-update`, 생성·전환과 `create-context-workspace`, 통합 설명 `explain`, 경험 개선 `improvement-loop`의 현재 본문을 입력으로 사용한다. prototype에 연결한 사실과 실제 host의 발견·실행·효과를 구별한다. USAGE/context-update의 사용감 유보도 유지한다.
- 자동 Maintainer를 재개하지 않고 장치를 걷어내되 기록 원칙을 남기려던 방향과 의존 조사는 보존한다. **2026-10-29 후속 요청으로 Maintain 관련은 현행대로 두고02와 함께 다룬다.** 이번06-01의 첫 적용 범위에서 코드·설정·기록 담당·activation·관련 이식 계약을 바꾸지 않는다. Recover·Verify의 유지·단순화·제거 선택도 현재 선행 과제로 요구하지 않는다. 영구 존치를 채택한 것은 아니다.
- Work의 새 background 구성·본문 재배치는 [116의 보류](../../../records/2026-10-20-116-defer-work-content-policy.md)를 따른다. [02 기록 운영](../02-work-records.md)은 다른 쪽에서 병렬 진행한다.06은02를 대신 설계하지 않고 실제 반영에 영향을 주는 합의와 미정을 연결한다.

## 관리와 완료

이 상위 문서는 전체 목적·공통 경계·두 하위 결과의 관계를 소유한다. 하위 Ticket은 상세 결과·진행·완료 조건을, [Spec](../../spec.md)은 전체 작업의 선택과 미정을, [state](../../state.md)는 현재 재진입 위치를 소유한다. 적용안 작성, 실제 반영, 직접 확인, 실제 host 동작, 반복 사용 효과와 사용자 수락을 확인한 범위대로 구별한다.

06 전체 완료는 두 하위 결과와 남은 대상별 차이를 종합해 판단한다. 폴더 생성이나 티켓 분할은 완료 근거가 아니다. 당시 전환 설계의 입력과 판단은 날짜별 기록에서 보존하며, 새 문서를 구성한 사실로 유지·교체·제거 세부안을 채택하지 않는다.
