# 01-02 — 코드·설계 품질과 검토·수정 방법을 구체화한다

상위 과제: [01 개발 작업 방식](README.md)

상태: **분해 정리 완료 · 설계 작업 미착수**. 전체 기준은 [Spec](../../spec.md)에 있다.

## 맡은 결과와 범위

실제 코드·구조의 전후 또는 대비안을 바탕으로 **좋은 설계를 판단하는 방법과 검토 지적을 수정으로 잇는 안**을 만든다. 책임·중복·응집도·인터페이스·변경 부담과 코드가 후속 개발의 패턴이 되는 역할을 다룬다. 요구 충족과 구조 품질을 각각 판단한다.

개발 자체의 질과 사용자 스타일·배경지식에 맞는 개발을 실제 개선 방향으로 구체화한다. 과거 설명 혼란의 원인이 전부 코드 품질이었다고 입증할 필요는 없다. 사용자가 추상적 품질 기준을 먼저 완성하도록 요구하지 않고, AI가 근거 있는 대비안을 제시한다.

## 처음 만들 결과와 근거

변경이 흩어지거나 호출자가 순서·설정·오류 처리를 많이 알아야 하는 좁은 구조 사례를 골라 현재 방식과 개선 후보를 비교한다. 같은 동작을 보존하는 개선과 제품 동작을 바꾸는 선택은 구별한다. 대상 코드는 착수 시 보존 근거와 필요한 현행 상태를 확인해 고른다.

- [codebase-design](../../../source/lectures/codebase-design.ko.md): module·locality·seam, 호출자 부담과 테스트 경계.
- [PR 병목 강연](../../../source/lectures/01_PR_병목_강연_전체번역.md), [code-review](../../../source/lectures/code-review.ko.md): 표준·명세 검토, reviewer 수정 제안과 제공 스킬의 보고 종료 사이의 차이.
- [Agent 신뢰 강연](../../../source/lectures/03_Agent_신뢰_강연_전체번역.md): 코드 패턴·기계적 검사·규칙과 사람 판단.
- [기존 실행 기준](../../../source/ai-workspace-baseline/reference-project/context/work/workspaces/spec-and-tickets/EXECUTION-CRITERIA.md): 이미 요구하는 구조 개선과 필요한 구체화의 구별.

## 다른 Ticket과 주고받을 것

[01-01](01-01-development-flow.md)은 전체 진행·책임 연결, 이 Ticket은 설계 품질의 판단·검토·수정 방법, [01-03](01-03-behavior-verification.md)는 테스트와 실제 동작 근거를 맡는다. 검토의 기준 diff·미커밋 변경 범위, 지적을 누가 판단·수정하고 언제 다시 확인하는지를 01-01과 맞춘다.

선택한 내용 중 코드·검사·개발 가이드·스킬에 둘 것을 비교하고 [03](../03-project-context.md)·[04-01](../04-skill-improvements/04-01-work-decision-skills.md)·[06](../06-framework-transition.md)에 영향을 전달한다. reviewer에게 세부 기준을 집중한다는 강연의 제안을 구현자에게 필요한 제품·구조 맥락까지 생략하는 규칙으로 확대하지 않는다.

## 완료 조건과 확인 방법

- 실제 대비안에서 호출자가 알아야 할 지식·순서·오류 부담과 변경의 분산 정도, 유지할 동작·제품 계약이 드러난다. 줄 수나 파일 수만으로 품질을 판정하지 않는다.
- 현행 기준의 부족, 이미 있는 기준의 수행 문제, 코드·도구·검사 보완의 필요를 근거에 따라 구별한다.
- 표준 준수와 요구 충족의 차이, 근거가 충분한 지적과 판단이 필요한 후보, 유지·수정·보류 이유를 보여 준다.
- 검토 결과의 판단·수정·재확인 방법과 종료 조건, 다른 책임에 미치는 영향이 01-01·01-03과 연결된다. 역할 수나 reviewer의 직접 수정 권한을 미리 고정하지 않는다.
- 대안의 적용 조건·비용·사용자에게 필요한 선택과 실제 적용 뒤 관찰할 효과가 있다. 코드 예시만으로 제품 개선 효과를 인정하지 않는다.

현재는 분할된 설계 과제다. 구체적인 품질 대비안·검토 방식 채택이나 제품 코드 수정은 수행하지 않았다.
