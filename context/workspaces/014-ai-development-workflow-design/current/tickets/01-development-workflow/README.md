# 01 — 개발 작업 방식

이 과제는 목표를 충분한 개발 결과로 만들고 사람이 이해·판단할 수 있게 하는 작업 방식을 설계한다. 개발 진행, 코드·설계 품질, 동작 검증을 아래 세 하위 Ticket으로 나눈다.

## 하위 Ticket

| Ticket | 맡는 결과 |
| --- | --- |
| [01-01 개발 진행과 사람의 판단](01-01-development-flow.md) | 목표·Spec·Ticket부터 조사·개발·검토·수정·첫 보고까지의 진행과 판단 책임 |
| [01-02 코드·설계 품질과 검토·수정](01-02-code-design-quality.md) | 실제 구조 대비안, 품질 판단과 지적의 수정·재확인 방법 |
| [01-03 동작 검증과 도구](01-03-behavior-verification.md) | 사용자 흐름의 증거, 자동 검사·앱 관찰·도구 선택 |

01-01에서 전체 연결 초안을 만들고 01-02·01-03의 구체 결과로 보완한다. 기록·Project의 내용은 [02 기록](../02-work-records.md)·[03 Project](../03-project-context.md)와 함께 설계한다. 개발 진행의 책임과 [04 스킬 보완](../04-skill-improvements/README.md)의 실제 호출·동작을 구별해 맞춘다.

이 상위 문서는 과제의 범위와 하위 결과의 관계를 소유한다. 각 하위 Ticket이 상세 범위·완료 조건·진행·실제 결과를 소유하며, 그 상태를 이 문서에 별도로 복제하지 않는다. 관리 책임과 공통 기준은 [Spec](../../spec.md) 및 [Workspace](../../../README.md)를 따른다. 범위를 바꾸면 영향을 받는 하위 Ticket과 이 연결을 함께 갱신한다.

현재 비교안과 남은 작업은 각 하위 Ticket 본문에서 확인한다. 문서 분할과 진행안·역할 배치의 채택, 실제 개발 수행을 구별한다.
