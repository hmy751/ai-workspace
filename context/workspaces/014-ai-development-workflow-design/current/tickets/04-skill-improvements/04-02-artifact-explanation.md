# 04-02 — 작업물 브리핑·설명 복구 스킬을 보완한다

상위 과제: [04 기존 스킬 보완](README.md)

상태: **접근법 재검토 후 원문 중심 source 1건 구성 · 기존 수정안 보류 · 당시 전체 실행 재현 준비는 미완료**. 전체 기준은 [Spec](../../spec.md)에 있다.

2026-10-20 사용자 요청으로 이 Ticket을 시작했다. [스킬 대조와 응답 제안](../../../records/2026-10-20-ticket04-02-skill-comparison-and-response-proposals.md)에 보고서·인증 브리핑·access·Promise 장면을 현행 두 스킬과 대조하고, 유지할 요구·구체화할 문구·실제 응답 예시·비적용 조건을 제시했다. 첫 보고의 조사·결과 책임은01-01에, 선택과 후속 행동의 재판단은 병렬 진행 중인04-01에 연결하는 후보로 두었다. 실제 스킬·글로벌 기준·제품 코드에는 적용하지 않았으며 사용자 채택·별도 실행 비교·이해 개선 효과는 미확인이다.

이후 사용자가 “동작보다 근본 역할 먼저”라는 발화를 찾아 대조하고 다른 오해도 재검토하도록 요청했다. 같은 제안문의 **대화를 다시 읽고 바꾼 판단**에 기존 네 장면과 일정 작성·여행 목록·시간 선택창·질문식 학습을 재대조한 근거를 남겼다. 근본 역할을 먼저 이해시키고 구체적 코드·흐름으로 잇도록 보완했으며, 보고서 예시에 이전 문제·수정의 연결을 추가했다. Promise를 일방적인 설명 실패로 읽은 판단은 낮췄고, 설명 가능한 구조와 적절한 설계의 구별, 요청한 질문식 학습의 허용을 명확히 했다. 당시 AI의 자기해석을 사용자 요구나 실제 효과로 취급하지 않는다.

후속 요청에 따라 같은 문서의 **실제 본문을 고친다면 넣을 문구와 위치**를 정확한 교체안으로 구체화했다. briefing의 문서 조사 항목·결과 첫 문단·선택 판단 문단, recovery의 원인 파악 도입·작은 복구3번·Quiz 항목을 교체하는 후보이며 나머지 근거·권한·종료 조건은 유지한다. 문구와 응답 예시는 검토용으로 제시했으며 실제 SKILL.md는 변경하지 않았다.

사용자가 응답 예시가 서술적이라 한눈에 들어오지 않는다고 지적한 뒤, 보고서·일정 작성·인증·access·Promise 예시를 핵심 답과 역할·조건 비교·코드·확인 범위가 구별되도록 다시 구성했다. 기존 구성 기준을 실제 예시에 적용한 보완이며, 표·목차를 모든 응답에 강제하는 스킬 규칙을 추가하지 않았다. 새 예시의 사용자 수용·실제 스킬 효과는 아직 확인하지 않았다.

2026-10-21 사용자 요청에 따라 [두 스킬의 본문 통합 수정안](../../../records/2026-10-21-ticket04-02-integrated-skill-drafts.md)을 작성했다. 기존 호출·조사·근거·권한·종료 조건을 유지하며 부분 교체안을 전체 본문에 통합했고, 중복 결과 목록과 별도 금지 목록은 해당 행동 문단으로 합쳤다. 운영 파일은 변경하지 않았으며 전체 문구의 채택·실제 적용·효과 확인은 남아 있다.

사용자 후속 요청으로 [프로토타입의 두 스킬 파일과 변경점](../../../records/prototypes/development-workflow/skills/README.md)을 만들었다. 공통 기준 의존 자료와 읽는 경로를 함께 배치했으며 실제 운영 설치는 아니다.

[세 장면 익명 응답 비교](../../../records/2026-10-21-ticket04-02-blind-response-comparison.md)에서 기존판·수정안 각 한 번씩 총 여섯 응답을 만들고, 두 평가자가 순서를 반대로 받아 비교했다. 일정 브리핑·access는 두 평가 모두 실질 동등, Promise는 판본 선호가 갈렸다. 개선 우세는 확인하지 못했고 실제 제품 조사·사용자 이해 효과·반복 일관성은 미검증이다. 최초 응답·입력·판본·평가를 보존했으며 이번 결과로 스킬을 추가 수정하지 않았다.

2026-10-21 후속 정정으로 보완·검증 기준 자체를 다시 검토했다. 사용자가 지정한 외부 연구의 원래 설계·공동 적용 판단과 Noline 실제 대화를 대조하고, [원래 구성 의도 반영 재수정안](../../../records/2026-10-21-ticket04-02-original-intent-revision.md)에 두 스킬 전체 문구와 변경 이유를 제시했다. 역할·흐름을 포함하는 것과 이해에 연결하는 것을 구별하고, recovery를 일반 설계 재판단으로 넓히는 제안은 제외했다. 구조 이해 자체가 충분한 결과인 경우를 유지한다. 기존 prototype 본문은 아직 이전 제안이며 이번 재수정안으로 교체하지 않았다.

사용자가 지정한 GPT-6.1-sol, medium으로 인증 브리핑·이전 설명 재평가의 두 장면에 기존판·수정안 각1회, 총4개 응답을 생성했다. 기대 답·수정 의도·후속 사용자 평가는 입력하지 않았다. Briefing은 보존된 전체 조사·설명 기록의 재구성 비교이고 실제 제품 코드 조사가 아니다. Recovery는 원문 대화를 사용했다. 두 판본 모두 역할·근거 한계와 앞선 평가의 정정을 수행했고 수정안 우세는 확인하지 못했다. main이 원문을 대조했으며 독립 평가자를 추가한 실험은 아니다. 입력·판본·최초 응답·해시와 검증 한계는 위 재수정안에서 연결한다.

2026-10-21 사용자 요청으로 [UTC 설명 복구 두 판본 비교](../../../records/experiments/artifact-explanation-utc-2026-10-21/comparison.md)를 추가했다. GPT-6.1-sol medium의 새 서브 두 개에 질문 시점까지의 동일 대화와 판본별 스킬을 제공하고 각1회 생성했다. 기대 답·수정 의도·후속 대화는 제공하지 않았고 최초 응답 전체를 보존했다. 두 응답 모두 UTC 저장과 화면별 날짜 해석을 구별했으나 우세·사용자 이해 개선은 확정하지 않았다. 당시 제품 코드 재조사나 최초 합의 전체의 독립 검증은 아니다. 수정안 채택·prototype 반영 상태는 유지한다.

2026-10-21 UTC 비교 뒤 사용자 정정으로 평가 범위를 바로잡았다. 사용자는 “다시 묻기전에 제대로 설명했으면 된거아니야”, source의 “시점 문제… 늦게 발동된다”를 지적했다. 독립 self-check와 원문 대조 결과, [source 대화](../../../source/discussion/conversation.md)의 사용자 L1823은 첫 검토·설명의 부족을 이미 지적했고 같은 대화의 첫 보고·기존 설명 스킬 관계 제안은 개발 보고와 별도 briefing·recovery를 구별했다. [개선 방향](../../../source/noline-evaluation/improvement-directions.md)의 첫 검토·첫 설명도 동일한 검토 대상이다. 이는 새 요구가 아니다. 이번 UTC 시험은 스킬을 지정하고 재질문 이후 답을 생성한 비교여서 최초 전달·실제 스킬 선택 시점을 검증하지 않았다. 따라서 main의 “기존판 유지 쪽에 무게” 판단은 철회한다. 재설명 비교 결과는 해당 범위의 관찰로 유지한다. 다음 판단은 첫 결과에서 필요한 조사·설명 책임과 기존 실행 기준·설명 스킬 연결의 누락을 대조하는 것이며, 곧바로 추가 실험·자동 조기 호출·새 스킬 문구를 확정하지 않는다.01-01과 연결할 책임을04-02 검토 밖으로 밀어내지 않으며, 기록 지연 가설은 설명 시점과 구별한다.

2026-10-21 추가 정정으로 [접근법·검증 재검토](../../../records/2026-10-21-ticket04-02-approach-and-evaluation-reset.md)를 수행했다. 원자료·시험 방법을 독립 검토하고 접근 자체에 제3자 조언을 구했다. 문제를 두 스킬 문구 부족으로 먼저 좁힌 접근, 사용자 교정 뒤 입력과 완성 설명을 사용한 시험, 평가자에게 사용자 의도 근거를 가린 판단을 바로잡았다. 일정의 근본 역할 요구는 첫 완성 브리핑 전이었고 인증에는 AI의 자발적 briefing 선택도 있어 모든 문제를 늦은 발동으로 묶지 않는다. 기존 비교는 안내받은 후속 응답 작성의 관찰로 보존하며 첫 전달·자율 적용·사용자 이해의 증거로 쓰지 않는다. 다음은 사건의 원래 판단 목적·첫 결과의 공백·당시 자료와 기준을 연결해 개입할 책임을 선택하는 것이다. 기존 스킬의 자연스러운 수행, 필요할 때 명시 적용·사실 제공을 원인 구분에 사용하고, 그 뒤 선택한 최소 변경을 검증한다. 당시 제품 자료 부족을 완성 해설로 대신하지 않는다. 추가 시험·스킬 수정은 이번에 수행하지 않았다.

2026-10-21 사용자는 main의 사건 요약을 시험 입력으로 주지 말고 적정 범위의 원문을 발췌해 새 source를 구성하도록 요청했다. [보고서 사건 원자료](../../../source/artifact-explanation-scenes/README.md)에12~619 공개 발화30개와634~1119 이후 발화14개를 원문 그대로 분리하고, 원문84가 보고한 HEAD의 Git archive·작업 기록과 현재 남은 보고서41개를 지위별로 보존했다. [구성 기록](../../../records/2026-10-21-ticket04-02-source-scene-assembly.md)에 경계·출처·동일성 확인·남은 자료 공백을 남겼다. 현재 사본을 당시 HTML로 확정하지 않았고 뒤의 교정·완성 답을 입력에 넣지 않았다. 새 응답 시험·스킬 수정은 하지 않았다. 원문·Git·사본의 동일성과 발췌 경계는 직접 확인과 독립 검토를 마쳤다. 다음은 당시 홈 보고서·도구 반환·실행 상태의 공백이 어떤 검증을 제한하는지 구별하고 첫 전달에서 빠진 책임과 개입 대상을 판단하는 것이며, source 구성만으로 역사 재현이나 개선 효과를 완료로 올리지 않는다.

2026-10-21 새 source를 기준으로 [첫 보고의 책임 공백](../../../records/2026-10-21-ticket04-02-first-report-responsibility-review.md)을 재판단했다. 첫 보고 전의 목적·수집과 판단 분담, 사용자 지적, 후속 추가 확인을 대조하면 목적 연결·관찰 충분성 대조·추가 확인 판단·main의 결과 종합이 부족했다. 초판 HTML·전체 실행 로그 부재로 정확한 실패 단계와 스킬 문구·호출 시점의 원인은 미확정이다. 수정안이나 새 시험은 만들지 않았다.

2026-10-21 후속 작업 전 사용자 요청으로 [두 스킬의 원래 형성 자료](../../../records/2026-10-21-ticket04-02-original-skill-background.md)를 prototype의 각 _background에 구성했다. 원래 이해 지원 설계·품질 보강·공동 적용·Spec/Ticket 연결을 근거와 함께 복원했으며 현재 보류 후보의 채택 이유와 구별했다. 본문은 배경 읽기 안내 외에 유지했다.

## 맡은 결과와 범위

work-artifact-briefing과 explanation-recovery의 **구체적인 설명·조사·판단 대응과 본문 보완안**을 만든다. 첫 결과를 충분히 전달할 책임, 요청에 따라 기존 작업물을 조사해 이해시키는 책임, 앞선 설명의 끊긴 뜻과 전제를 복구하는 책임을 구별한다.

사용자가 이유를 물으면 기존 선택의 적절성을 판단해 설명할 수 있어야 한다. 의미 질문·이의 제기·실제 변경 요청이 섞인 경우도 다룬다. 첫 보고마다 전체 브리핑을 강제하거나 모든 질문을 수정·recovery 호출로 바꾸지 않는다.

## 처음 만들 결과와 근거

보고를 다시 써 달라고 해 조금 나아진 장면과, access 선택의 이유를 물었는데 바로 바꾸려 한 장면에서 기존 응답과 보완 응답을 나란히 제시한다. 판단에 필요한 핵심·사례·구조 표현의 충분함을 비교하되, 사용자의 기준과 당시 만족·보류 동기가 불명확한 부분을 유지한다.

- [Noline 스킬 기준판](../../../source/noline-baseline/.claude/skills/README.md), [Reference 스킬](../../../source/ai-workspace-baseline/reference-project/.agents/skills): 두 스킬과 연결한 설명·근거 기준.
- [사용자 인터뷰](../../../source/noline-evaluation/reviews/interview-20261012.md): 첫 보고·질문 의도·개선 강도의 직접 근거.
- [인지부채 연구](../../../source/research-basis/09-tripproof-cognitive-debt/README.md): 사람이 이해하고 자기 판단으로 다음 지시를 내리는 문제와 제품·코드 적합성 검토의 구별.
- [문서 개선 후속 비교](../../../source/noline-evaluation/reviews/document-guidance-followup.md): 기준 적용·실제 변경·사용자 평가의 시점과 범위.

## 다른 Ticket과 주고받을 것

[01-01](../01-development-workflow/01-01-development-flow.md)은 첫 보고가 작업 흐름에서 맡는 책임을, 이 Ticket은 실제 설명과 스킬 적용 방법을 구체화한다. 선택 자체를 재판단해야 하면 [04-01](04-01-work-decision-skills.md)과, 반복 경험에서 기준을 발전시키는 일은 [05](../05-learning-loop.md)와 연결한다.

설명의 부족을 전부 스킬 탓으로 확정하지 않고 [01-02](../01-development-workflow/01-02-code-design-quality.md)의 작업물 품질과도 대조한다. 글로벌 recall-document-guidance와 설명 관련 기준은 참고하며, 실제 글로벌 변경은 이 설계 Ticket의 실행 범위에 포함하지 않는다.

## 완료 조건과 확인 방법

- 두 스킬의 조건·입력·행동·산출물·기록 연결을 확인하고 현행 조항과 장면을 근거로 유지·보완안을 제시한다.
- 첫 보고, 별도 브리핑, 설명 복구에서 필요한 조사와 보여 줄 내용을 실제 응답 예시로 구별한다.
- 설명으로 충분한 질문, 선택 재검토가 필요한 질문, 변경 요청에 대한 대응을 비교한다. 잘못된 주장을 쉽게 풀어 유지하거나 앞선 발화의 뜻을 현재 코드 의미로 바꾸지 않는다.
- 구조 표현·사례·상세 근거가 사용자의 이해와 다음 판단에 어떤 차이를 만드는지, 과도한 읽기·설명 비용과 함께 검토한다.
- 침묵·진행·재질문만으로 성공·실패를 확정하지 않으며, 사용자 선택과 실제 사용에서 확인할 부분을 구별한다.

기존 재수정안과 이전 prototype은 검토 이력·후보로 보류한다. 현재 판단과 다음 행동은 [접근법 재검토](../../../records/2026-10-21-ticket04-02-approach-and-evaluation-reset.md)를 따른다. 개입할 책임과 검증 가능한 주장을 먼저 정하며, 두 스킬 수정·기존판 유지 어느 쪽도 결과로 미리 정하지 않는다. 사용자의 필요한 학습·설계 질문을 실패 횟수로 세지 않고, 추가 교정 없이 필요한 조사와 설명을 수행했는지와 실제 이해 효과를 구별한다. Ticket은 완료하지 않는다.
