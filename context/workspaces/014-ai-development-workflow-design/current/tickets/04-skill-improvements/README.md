# 04 — 기존 스킬 보완

현재 workflow와의 연결: development가 전체 수행을 조율하고,04는 각 스킬의 실제 발동 조건·본문·입출력·기록 관계를 완성한다.01-01·01-03은 [완료 조건 대조](../../../records/2026-10-24-ticket01-01-03-closeout-and-next-scope.md)로 설계 마감했다. 그 결과를 사용해04-03 개별 맥락 스킬을 구체화하며,04-02의 응답 판단과04-01의 기존 마감은 각 하위 Ticket을 따른다. 전체 workflow의 책임 정의와 개별 스킬의 보완·설치를 중복 완료로 처리하지 않는다.

이 과제는 이식해 사용한 기존 스킬 일곱 개의 실제 조항·호출·수행과 인터뷰 장면을 대조하고, 유지·구체화·관계 수정·통합 등의 보완안을 만든다. 아래 세 하위 Ticket으로 구체적인 보완 결과를 나눈다.

## 하위 Ticket

| Ticket | 다룰 스킬과 결과 |
| --- | --- |
| [04-01 작업 정의·재판단](04-01-work-decision-skills.md) | work-discussion·reconsider-work의 조건·동작·본문 보완 |
| [04-02 설명 구성·적용](04-02-artifact-explanation.md) | explain 본체·실행 상세·형성 자료와 기존 두 스킬 연결 통합 |
| [04-03 맥락 읽기·갱신·Workspace 생성](04-03-context-skills.md) | read-project-context·update-project-context·create-context-workspace의 실제 적용·관리 연결 |

각 스킬의 전체 재작성을 전제하지 않는다. 같은 장면의 근거를 재사용하고, 작업 정의·설명·맥락 관리 사이에 책임이 겹치거나 비는지 대조한다. 글로벌 문서·설명 기준은 연결을 확인하는 참고 범위이며 여기서 실제 글로벌 개편을 수행하지 않는다.

[01 개발 작업 방식](../01-development-workflow/README.md)은 일반 수행·품질·검증 방법을, 이 과제는 그 방법을 스킬의 실제 조건·입력·행동·산출물·기록 인계로 잇는 일을 맡는다. Project·Work의 내용과 관리 원칙은 [02](../02-work-records.md)·[03](../03-project-context.md), 기존 장치 제거 이후 연결은 [06](../06-framework-transition.md)과 맞춘다.

이 상위 문서는 과제의 범위와 하위 결과의 관계를 소유한다. 각 하위 Ticket이 상세 범위·완료 조건·진행·실제 결과를 소유하며, 그 상태를 이 문서에 별도로 복제하지 않는다. 관리 책임과 공통 기준은 [Spec](../../spec.md) 및 [Workspace](../../../README.md)를 따른다. 범위를 바꾸면 영향을 받는 하위 Ticket과 이 연결을 함께 갱신한다.

보완안의 채택·반영·확인 범위와 남은 일은 위 각 하위 Ticket에서 확인한다.
