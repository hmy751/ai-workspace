# 04-01 — 작업 정의·재판단 스킬을 보완한다

상위 과제: [04 기존 스킬 보완](README.md)

상태: **설계 결과 완료 — work-discussion 최소안 채택·prototype 반영, reconsider-work 유지**. 전체 기준은 [Spec](../../spec.md)에 있다.

2026-10-21 [최소안 반영과 두 조건 확인](../../../records/2026-10-21-ticket04-01-minimal-update-and-two-checks.md): 사용자가 승인한 기존 정의·보완 후보 대조와 요청별 반환을 prototype의 work-discussion에 통합하고 겹치는 문구를 정리했다. 각 조건1회, 총2회만 실행했다. 충분한 Ticket에서는 새 반올림 관찰만 기존 검사에 연결했고, 표시 통일 기준이 미정인 조건에서는 필요한 선택을 제안했다. 별도 평가자 없이 Main이 원응답을 확인했다. 기존판 대비 향상·새 Work 전체·장기 효과의 보장은 아니다. 사용자 위치 정정에 따라 Reference의 이번 수정은 원복했다. reconsider-work는 유지하며, 스킬의 운영·반영 책임 변경은 기존01-01·04-03 후속으로 남긴다.

2026-10-20 [사후 정정 없는 실행 비교](../../../records/2026-10-20-ticket04-01-blind-skill-comparison.md): 두 사례와 가상 반대 조건을 기존판·보완판으로 각2회, 총16회 실행했고 버전을 가린 독립 검토도 모두 충분으로 봤다. work-discussion 보완판은 충분한 Ticket의 재서술 제안을 줄였지만 기존판도 새 선택을 잘못 열지는 않았다. reconsider-work는 기존판도 필요성을 가를 UX 확인을 먼저 제안해 다음 행동의 개선이 드러나지 않았다. 정리된 조사 사실을 선제공한 제한적 비교이며 원래 긴 작업의 실패 재현·일반 성능 검증은 아니다. 반환 범위 조정은 후보로 유지하고 재판단 본문 교체 필요성은 미입증으로 둔다. 실제 스킬은 변경하지 않았다.

2026-10-20 [구체 교체안](../../../records/2026-10-20-ticket04-01-skill-behavior-proposal.md): 사용자는 기존 기준·사례 추가를 넘어 실제 판단을 바꾸는 안을 요청했다. 기존 Work의 추가 구체화는 보완 후보와 현행 정의를 대조한 뒤 실제 부족분만 반환하고, 조건이 바뀐 예정 작업의 재판단은 원래 상황에서 추가 전후 결과를 비교한 뒤 방법을 고르는 안을 제시했다. 기존 문구의 교체·통합 위치와 실제 응답 차이, 반대 조건의 확인안을 포함한다. 현재 Reference 두 스킬과 보존판의 일치는 확인했으나, 스킬 변경·비교 실행·효과 검증은 하지 않았다.

2026-10-20 [사례 재선별](../../../records/2026-10-20-ticket04-01-definition-reconsideration-cases.md): work-discussion에서 이미 정의된 경비 합계 기준을 새 보강사항으로 제시한 장면과, reconsider-work에서 복구 토스트의 필요성보다 작은 구현 방법만 재검토한 장면을 확인했다. 기존 조항의 수행 부족이 먼저이며, 기존 정의의 충분성 판정과 변경된 조건에서 예정 작업의 필요성 재판정을 시작·반환 동작에 연결하는 보완은 미채택 후보다. 스킬 본문 변경·수행 효과 확인은 하지 않았다.

사용자는 앞선 [DB·인증 구조 개선 대조](../../../records/2026-10-20-ticket04-01-db-auth-comparison.md)를 **이후 워크플로 설계에서 다루기로 정했다.** 구현·검토·완료 판단의 문제를04-01의 사례 추가로 해결할 근거는 부족하다는 재검토를 반영한다. 당시 비교 사실과 한계는 보존하되, 그 사례를 이 Ticket의 주된 보완 근거로 계속 사용하지 않는다.01-01·01-02에서 연결을 판단한다.

2026-10-20 사용자 요청으로 기존01-01·04-03의 후속과 병렬로 이 Ticket의 논의를 시작했다. [source 재확인](../../../records/2026-10-20-ticket04-01-source-review.md)에 DB·인증 작업에서 work-discussion의 제품 선택 뒤 reconsider-work로 구현 결과를 다시 본 연결, access 질문의 오독, 기록을 읽고도 중심을 잘못 잡은 재개, 동작 개선의 승인·철회·후속 채택을 연결했다. 당시 개발 원문·사용자 회고·후속 비교와 미확정을 구별하며, 이미 확인한 판단을 새 인터뷰로 되묻거나 모든 마찰을 스킬 결함으로 분류하지 않는다.

## 맡은 결과와 범위

work-discussion과 reconsider-work의 **유지·구체화·관계 수정 후보와 실제 본문·동작 보완안**을 만든다. 구현 전 원하는 결과·보존할 경계·사람의 선택을 정리하는 책임과, 실제 결과·새 조건·누적 부담 때문에 가정과 후속 작업을 다시 보는 책임을 구별한다.

work-discussion은 현행 직접 호출 조건에서 출발하고 일반 작업 대화의 목표 이해와 관계를 살핀다. reconsider-work는 판단 변경이 기존 결과·의존 작업·Spec·Ticket에 미치는 영향까지 잇는다. 모든 대화에 인터뷰를 붙이거나 매 Ticket 종료를 자동 발동점으로 만들지 않는다.

## 처음 만들 결과와 근거

경비 합계의 기존·신규 보강 구별과 복구 토스트의 필요성 재판단 장면으로 현재 스킬의 요구·실제 대응·보완 대응을 비교한다. 두 실패에만 맞춘 답이 아니라, 새 Work를 적극적으로 구체화하는 경우와 유효한 기존 합의를 유지하는 경우에도 적절한지 살핀다. 기록 재개·승인 뒤 철회는 원인과 책임을 가를 때 보조 자료로 사용하고, “왜 이렇게 했나”의 설명·재판단 경계는 [04-02](04-02-artifact-explanation.md)과 대조한다.

- [Noline 스킬 기준판](../../../source/noline-baseline/.claude/skills/README.md), [Reference 스킬](../../../source/ai-workspace-baseline/reference-project/.agents/skills): 두 기준판의 실제 조항과 호출·기록 연결.
- [사용자 인터뷰](../../../source/noline-evaluation/reviews/interview-20261012.md): 작업 중심·질문 의도와 회고의 불확실성.
- [기록 시점·재개 비교](../../../source/reading/noline-evaluation/reviews/record-timing-followup.md), [철회·후속 구현 비교](../../../source/reading/noline-evaluation/reviews/withdrawal-followup-comparison.md): 원인 단정 없이 비교할 실제 사례.

## 다른 Ticket과 주고받을 것

[01-01](../01-development-workflow/01-01-development-flow.md)은 일반 개발 진행과 판단 책임을, 이 Ticket은 그 중 두 스킬의 조건·입력·행동·반환·기록 연결을 맡는다. [02](../02-work-records.md)의 기록 운영, [03](../03-project-context.md)의 맥락, [06](../06-framework-transition.md)의 Maintainer 제거 이후 인계와 맞춘다.

[04-02](04-02-artifact-explanation.md)·[04-03](04-03-context-skills.md)과 같은 현행 스킬 근거를 재사용한다. 한 스킬의 개선으로 다른 스킬의 책임을 중복하거나 비우는지 함께 확인한다.

## 완료 조건과 확인 방법

- 두 스킬의 실제 책임·호출 조건·입력·결과·기록 연결을 확인하고, 유지할 조항과 보완할 후보를 근거에 연결한다.
- 이미 있는 기준의 수행 부족, 기준의 구체성 부족, 맥락·코드·도구·책임 배치 문제를 구별하며 가를 수 없는 부분을 남긴다.
- 실제 장면에서 작업 정의와 재판단 전후의 대응, 바뀐 선택이 관련 결과에 미치는 영향을 보여 준다.
- 적용·생략할 경우와 과도한 질문·조사·기록이 생길 경우를 비교한다. 스킬 이름이나 설명 문구만 바꾼 안으로 끝내지 않는다.
- 본문·동작 보완안, 사용자 선택이 필요한 차이, 다른 Ticket의 영향과 후속 관찰을 제시한다. 기존 유지도 근거 있는 결과가 될 수 있다.

2026-10-21 사용자 승인으로 설계 결과를 마감했다. [완료 조건 대조와 후속](../../../records/2026-10-21-ticket04-01-minimal-update-and-two-checks.md#완료-조건-대조와-마감)에 다섯 조건의 근거를 연결했다. 실제 설치·장기 효과를 완료한 것은 아니다. 호출·실행 연결은01-01·04-03, 기록 인계는02·06, 실제 이식과 통합 확인은06·07에서 판단한다. DB·인증 사례는01-01·01-02의 입력으로 유지한다.
