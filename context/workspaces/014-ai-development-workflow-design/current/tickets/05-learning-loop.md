# 05 — 작업 경험을 다음 방식에 반영하는 개선 루프를 설계한다

상태: **분해 정리 완료 · 설계 작업 미착수**. 전체 기준은 [Spec](../spec.md)에 있다.

2026-10-26 사용자 후속 방향: 루프를 명시적인 단계로 만들 예정이며, 매 작업마다 수행하기보다 **대화를 기준으로 하는 방향**을 제시했다. 스킬을 통한 수행은 후보이고, 대화의 경계·발동 시점·담당·호출 방식은 후속 구체화 대상이다. 매 응답·모든 대화 종료의 자동 실행으로 확정하지 않는다. [04-03 후속 논의](../../records/2026-10-26-context-03-goal-improvement-review.md#사용자-후속--project-내용-선별과-대화-기준-루프)와 항목3의 반영 책임을 입력으로 받는다.

이 단계에서 채택한 변경을 실제 반영할 때도 각 영역에 지속할 내용인지 먼저 판단하고, 해당 정본·필요한 설명과 읽기 경로를 맞춘 뒤 확인 범위·남은 영향을 연결한다. 당시 제안·판단·이미 반영한 결과를 재사용하며 모든 후보를 다시 쓰거나 원 구현자를 일괄 재호출하지 않는다. 루프의 경험 판단·채택과 반영 방법의 책임을 구별하고, 일상 Work 유지나 이미 정한 의미의 필요한 반영을 이 단계까지 미루지 않는다.

Noline 평가에서는 기록의 효용, 반복 교정, 부분적으로 나아진 보고, 중요한 선택을 이해하기 위한 질문이 함께 드러났다. 이런 경험을 다시 볼 때마다 전체 대화를 수집하거나 규칙을 늘리는 방식은 부담이 크다. 작업 중 생긴 어떤 경험을 어느 크기와 시점에 검토해 다음 방식으로 연결할지 설계한다.

이 티켓의 결과는 **경험을 선택하고 근거와 대안을 검토해 개선 후보를 다루며, 채택 뒤 효과까지 관찰할 수 있는 운영안**이다. T02의 현재 맥락·과정 기록 갱신과 연결되지만, 기록한 내용을 근거로 작업 방식 자체를 유지하거나 바꿀지 판단하는 별도 책임을 맡는다.

## 04-02에서 이어받은 개선 판단 사례

2026-10-26 [04-02 마감](../../records/2026-10-26-ticket04-02-closeout-and-followups.md)과 [배경·응답의 종합 판단](../../records/experiments/explain-choice-investigation-60medium-revised-2026-10-26/comparison.md#배경과-함께-본-다음-행동의-권고)을 이후 운영안의 사례로 받는다. 기준이 이미 있는데 실제 판단에 충분히 적용되지 않은 경우, 일부 근거 확인은 좋아졌으나 최종 답의 큰 변화는 없는 경우, 지침을 더하지 않고 현재판을 유지한 선택을 함께 다룬다.

07의 실제 적용 관찰에서 중요한 판단 누락이 서로 다른 장면에 반복되거나 지침의 충돌·요구 누락이 확인되면 원요청·근거·실제 응답과 영향을 대조해04-02의 필요한 부분을 다시 연다. 명확한 결함은 반복을 기다리지 않는다. 한 답에 항목을 더 넣을 수 있다는 사실이나 취향 차이만으로 범용 문구·새 역할·반복 시험을 자동 추가하지 않는다. 제품 선택·가능한 조사 누락은 우선 해당 작업의 수행 책임과 대조한다. 이 입력을 받았다는 사실로05 운영안 설계나 효과 확인이 완료된 것은 아니다.

## 맡은 결과와 범위

04-03의 [제안·검토 후 반영 구체화](../../records/2026-10-26-context-proposal-review-apply-design.md)는 담당자의 제안·근거, Main의 판단·실제 반영과 결과를 이후 경험 검토에서 선택할 입력으로 남긴다. 이미 확보한 유효한 근거를 재사용하고, 중요한 공백·충돌·대상 변경에 필요한 부분만 추가 확인한다. 미반영 후보뿐 아니라 이미 반영한 선택의 효과·유지 이유도 대상이 될 수 있다. 일상 사실 정정을 이 티켓까지 미루지 않으며, 이 입력이05의 담당·시점·독립 검토 구성이나 효과 관찰 방법의 확정은 아니다.

검토할 경험의 후보에는 반복 교정, 잘된 경험, 새로 드러난 기준, 도구·자료 접근의 부족 등이 있다. 이는 닫힌 목록이나 자동 발동 규칙이 아니며, 단발 사건도 이후 판단을 바꿀 수 있으면 살필 수 있다.

운영안에는 다음 관계를 담는다.

- 어떤 장면을 검토 후보로 삼고 어느 범위의 원문·결과·후속 변경을 근거로 보존할지.
- 즉시 확인할 일과 경험이 더 쌓여야 판단할 일을 어떻게 나누고, 검토 비용에 맞는 크기·시점·담당을 어떻게 정할지.
- 이미 기대한 기준을 반복해서 적용시키는 교정, 필요한 학습·제품 선택, 새 기준을 찾는 논의를 어떻게 구별할지.
- 코드·구조, 도구, 자동 검사, 문서, 스킬·역할 배치 중 무엇을 바꾸거나 유지할지와 선택 이유.
- 후보 제시·채택·반영·효과 관찰을 구별하고, 미채택·보류·추가 근거 요청도 다음 경로로 남기는 방법.

매 대화의 전체 회고, 세션 종료 고정 호출, 반복 횟수만으로 새 규칙 생성, 모든 후보에 인간 인터뷰를 붙이는 방식은 전제가 아니다. 실제 참여가 필요한 판단을 줄이려 하지 않되, 이미 확인한 사실을 사용자가 계속 다시 설명하게 만들지 않는 대안을 다룬다.

## 실행 맥락과 접근

이미 보존한 사례로 검토 흐름을 구성한다. 예를 들어 재개에서 중심을 다시 잡은 경험과 잘 복구한 경험을 비교하고, 첫 보고의 재작성과 중요한 DB·인증 선택을 위한 질문을 같은 실패로 세지 않는지 확인한다.

경험을 해석할 때 사용자 발화, 실제 산출물·변경, AI의 해석과 미확인을 구별한다. 침묵·진행·커밋 요청만으로 만족이나 개선 효과를 추정하지 않는다. 재설명 부담이 줄었다는 전체 평가는 유지하되 수치나 특정 장치의 인과 효과를 만들어내지 않는다.

AI가 확인할 수 있는 원문·코드·문서·도구 사실은 먼저 확인한다. 개인의 이해·선호·감수할 비용이 보완 선택을 가르는데 기존 근거로 알 수 없다면 구체 장면과 대비안을 제시해 필요한 부분만 묻는 방법을 설계한다. 전체 재수집이나 새 인터뷰를 선행 조건으로 두지 않으며, 설계 중 사용자 판단이 필요한 부분은 해당 사례로 좁혀 논의한다.

자료의 참고 범위는 나누어 사용한다.

- 강연의 `retro`는 세션 원자료에서 탐색·검사·표준·도구 비용·정보 접근 등의 환경 개선 후보를 찾는 방법이다. 채택부터 다음 작업의 효과 확인까지 완결한 운영 결과로 보지 않는다.
- Vercel 자료는 수집과 판단을 나누고, 후보·기각·열린 질문을 사람이 검토하며 좁은 위치에 반영하는 방법을 제공한다. 주간 주기나 collector·judge 분리를 그대로 채택하지 않는다.
- Vercel의 공개 eval은 copywriting 범위다. 기대 수정을 숨긴 사례나 skill 없는 실행과의 비교는 참고하되 전체 개발 방식의 효과가 입증됐다고 확대하지 않는다.

대안을 비교할 때 새 지시를 추가하는 방법뿐 아니라 기존 지시의 정리, 코드 구조 개선, 이미 있는 검사의 연결, 자료 진입 경로 보완, 변화 없이 더 관찰하는 방법도 검토한다. 원인을 하나로 닫을 근거가 부족하면 선택을 가를 관찰과 보류 이유를 남긴다.

02는 경험의 근거와 현재 상태를 어디에 남길지, 03은 Project 맥락, 01-01·01-02·01-03는 개발 방식·품질·검증, 04-01~04-03은 스킬 설계를 맡는다. 경험을 공통 기반 개선으로 다룰지 프로젝트 안에서 해결할지도 판단한다. 근거 보존은 02, ai-workspace로 전달하고 대상에 다시 반영하는 방법과 비용은 06과 연결한다. 실제 적용 위치와 전환은 06에 연결하고, 07이 전체 대표 사례 대조와 후속 관찰 계획을 구성할 수 있게 필요한 관찰을 넘긴다.

## 완료 조건과 확인 방법

운영안 문서를 만들었다는 사실만으로 완료하지 않는다. 다음 내용을 기존 사례에 대입해 판단할 수 있어야 한다.

- 반복 교정, 잘된 경험, 필요한 사람의 선택, 도구·자료 부족처럼 성격이 다른 사례에서 검토하거나 지나갈 이유와 범위·시점이 드러난다. 해당 사례에 없는 사실은 만들지 않는다.
- 한 개선 후보에서 근거, 문제 해석, 적절한 반영 대상, 유지·변경 대안, 비용과 사람의 선택을 따라갈 수 있다. 기준 추가만으로 끝나지 않는다.
- 미채택·보류 후보가 사라지거나 확정 규칙으로 바뀌지 않고, 다시 볼 조건 또는 추가 근거의 필요로 연결된다.
- 채택할 경우 무엇이 달라져야 하는지와 다음 유사 작업에서 무엇을 관찰할지 정한다. 규칙 준수, 개발 결과, 사용자 부담의 변화와 미확인을 구별한다.
- 대표 사례를 보완안의 예시로 반복한 확인과 아직 보지 않은 유사 상황에서 확인할 계획을 구별한다. 후속 관찰의 범위·시점·책임과 효과가 없을 때 수정·철회할 판단을 07에 연결한다.

이 티켓의 설계 완료는 운영안을 비교·판단할 수 있는 상태다. 채택, 코드·도구·문서·스킬에 실제 반영, 이후 효과 확인은 별도로 기록한다. 관찰하기 쉬운 결과가 좋아졌다는 이유만으로 전체 작업 경험이 개선됐다고 판정하지 않는다.

## 현재 상태와 실제 결과

현재는 분해 초안이며 운영안의 대안 비교나 채택은 하지 않았다. 새로운 회고 장치·자동화·규칙·인터뷰를 실행하지 않았고, 경험 반영 주기나 담당 주체도 아직 정하지 않았다.

설계할 때 필요한 근거는 다음에서 선택한다.

- [평가·인터뷰 연결 기록](../../records/2026-10-12-01-background-and-evaluation.md): 효용과 마찰, 필요한 질문을 구별할 기존 사례.
- [사용자 인터뷰](../../source/noline-evaluation/reviews/interview-20261012.md): 만족·부담·선호의 확인과 회고가 불확실한 부분.
- [기록 시점과 재개 후속 비교](../../source/noline-evaluation/reviews/record-timing-followup.md): 기록 보존·열람·적용을 나누어 봐야 하는 근거.
- [retro 기준판](../../source/lectures/retro.ko.md): 환경 개선 후보를 찾는 관점과 제안 단계의 한계.
- [Vercel 제품 설계 자료](<../../source/lectures/vercel-product-design (1).md>): 근거 수집·판단·미채택 경로와 eval의 범위.
