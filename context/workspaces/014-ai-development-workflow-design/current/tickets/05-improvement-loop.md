**05 설계 완료 — 2026-10-29:** [마감 결과·열린 기준·후속 범위](../../records/2026-10-29-ticket05-closeout.md). 네 묶음 합의와 두 실행 보완을 prototype에 반영하고 완료 조건을 대조했다. 실제 운영 설치·사용 효과와 Workspace014 전체 완료는 별도다.

상태: **설계 완료 — 2026-10-29**. 네 묶음 합의·실행 prototype·기존 독립 검토 후 정정과 두 실행 보완을 마감했다. [완료 조건 대조](../../records/2026-10-29-improvement-loop-means-comparison-adoption.md#05-완료-조건과-대조)와 [마감·후속 경계](../../records/2026-10-29-ticket05-closeout.md)를 따른다. 실제 운영 설치·효과 확인은 아니다.

## 마감 결과와 후속 경계

[실행 스킬](../../records/prototypes/development-workflow/skills/improvement-loop/SKILL.md)과 적용 사례·원문 확인·효과 판단 상세, Personal 경험 구조를 현재 결과로 유지한다. 사용자 요청의 현재 세션 수행, 대화 전체·관련 본문 검토, 추천 후 공동 선택, 가능한 개선의 즉시 반영과 후보·사용 경험 재조회를 구체화했다. 한정 시도 연결·종료와 동일 목적의 수행 수단 비교 사례도 반영했다.

기존 검증·개선 리뷰를 받은 뒤 관리 단위와 근거를 정정했고, 두 실행 보완은 사용자와 구체 범위를 논의해 반영했다. 다섯 완료 조건은 Main이 현재 본문·대표 사례·후속 연결에서 대조했다. 이 마지막 대조는 새 독립 리뷰나 실제 운영 실행이 아니다.

[06](06-framework-transition/README.md)은 실제 배치·원문 접근·활성화/복구를, [07](07-integrated-rehearsal.md)은 실제 요청·재조회·한정 시도 종료·사용 효과를 이어받는다. 고정 분류·점수·자동 반영 확대는 아직 정하지 않았고 [기타-01](misc-01-improvement-review.md)은 보류한다. 새로운 근거가 현재 설계와 충돌하면 필요한 부분만 다시 연다.

합의·사용자 발화의 원천은 [인터뷰](../../records/2026-10-27-ticket05-interview.md)이며 [전체안](../../records/2026-10-27-ticket05-integrated-proposal.md)과 보존 검토판은 형성 경과다. 당시 미정·미반영을 현재 상태로 가져오지 않는다.

[설명과 수용 기록](../../records/2026-10-27-ticket05-interview.md#2026-10-28--1번-발견의-반영-방향-합의)을 따른다.

- **검토 범위(2026-10-28):** 이번 세션 대화를 처음부터 현재까지 전체 흐름으로 훑어 목표·판단의 변화, 마찰·성공·아이디어·미결을 찾는다. 관련 본문·결과·기준 전체를 깊게 살피고 의미 있는 판단과 개선 기회에 따라 다른 자료로 확장한다. 모든 발화를 같은 깊이로 분석하거나 무관한 전체 자료를 전수 검사하지 않는다. 유효한 기존 이해는 재사용하고, 근거·반대 조건·변경 대상·공백을 설명할 수 있으면 후보 제시로 넘어간다. 고정 시간·문서 수 상한은 두지 않았다. [설명·확인·수용](../../records/2026-10-27-ticket05-interview.md#2026-10-28--2번-검토-범위와-대화-전체-훑기-합의)을 따른다.
- **선택 후 처리·종료 방향(2026-10-28):** 추천·이유와 실제 변경을 제시하고 함께 선택한 가능한 개선은 바로 반영·직접 확인한다. 한정 시도, 채택했으나 남은 실행, 미결 후보, 유지·기각을 구별한다. 선택한 즉시 반영·확인을 마치고 남은 경로를 밝히면 이번 루프를 마치며, 미완료는 부분 완료로 남긴다. Personal의 수집·재조회 구성은 아래 후속 합의를 따른다. prototype 파일·읽기 연결은 작성했고 실제 운영 설치는 아직이다. [직접 요청과 합의 범위](../../records/2026-10-27-ticket05-interview.md#2026-10-28--3번-처리-방향과-4번으로의-연결)를 따른다.
- **Work 연결 정정(2026-10-28):** 선택한 개선은 해당 대상에 수행하고, 진행 중 자연스럽게 생기는 Work 기록은 기존 방식을 따른다. 루프가 별도 Work 기록·이관을 의무화하지 않는다. 현재 구체화는 Personal의 미반영 후보·경험을 모으고 다음 루프에서 다시 찾는 방법이다. 길잡이·주제별 상세·미분류 기록과 다음 루프 재조회는 후속 수용됐고 prototype 실물은 작성했으며 실제 운영은 아직이다.
- **Personal 수집·재조회(2026-10-28):** 짧은 길잡이에서 주제와 경험·열린 후보·아직 묶지 않은 기록을 찾고, 주제별 상세에서 경험·해석·미결 이유·다시 볼 조건·이후 판단을 연결한다. 다음 루프는 대화 전체와 길잡이를 훑은 뒤 관련 주제의 근거·반례를 대조해 경험·해석·후보를 갱신한다. 새 조건 없이 보류안을 반복 권하지 않으며 반영된 후보는 실제 대상·이유와 연결한다. 경험만 보존할 수 있고 고정 양식·즉시 분류를 요구하지 않는다. [직접 수용과 남은 논의](../../records/2026-10-27-ticket05-interview.md#2026-10-28--personal-수집재조회-방향-수용과-4번의-남은-논의)를 따른다.

[설명·직접 수용](../../records/2026-10-27-ticket05-interview.md#2026-10-28--실제-사용-경험-관찰-방향-수용)을 따른다.
- **효과 불확실성·부작용 판단(2026-10-28):** 미사용·적용 불충분·효과 불명확·실제 문제를 구별하고 기대 이득·근거와 한계·유지 부담으로 유지·수정·적용 범위 축소·철회를 제안한다. 불확실성만으로 유지나 제거를 자동 결정하지 않는다. 명확한 문제는 반복을 기다리지 않고, 선택에 영향을 주며 비용에 맞는 경우에만 한정 비교한다. 확인 사실·공백·추천과 이유를 함께 제시하고 선택한 범위로 반영한다. [직접 수용](../../records/2026-10-27-ticket05-interview.md#2026-10-28--효과-불확실성부작용-판단-수용과-네-묶음-점검)을 따른다.
- **대상:** 관련 Project·Personal 본문 전체의 내용·구성·표현을 목적과 내용 지침에 비춰 살핀다. 협업 방식, Work·스킬·워크플로·검사·도구·환경, 기존 기준과 구조의 더 나은 대안도 포함한다. 새 정보나 명백한 부족만 보는 작업은 아니다.

- **호출·진행:** 사용자 요청으로 실행하고 AI도 시점을 제안한다. 현재 맥락을 잘 아는 기존 세션에서 진행하며 대화가 길어져도 바로 반영하는 목적을 우선한다.
- **선택·반영:** 개선안을 함께 선택한 뒤 현재 가능한 것은 이번 루프에서 반영한다. 모두 후보로 보관하고 미루지 않는다. 선택 없이 직접 반영할 범위는 반복 사용 뒤 정한다. 기존 일상 갱신·이미 허용된 반영에 새 승인 절차를 더하지 않는다.
- **제시:** 추천과 이유를 먼저 보여주고 나머지 후보도 확인할 수 있게 한다. 검토 범위·중요한 유지 판단·남은 공백을 짧게 함께 보여준다.
- **추가 확인:** 외부 조사는 필요시 한다. 기존 대화·자료를 먼저 읽고 답에 따라 개선 방향이 달라지는 중요한 불확실성만 사용자에게 짧게 묻는다.
- **기대 효과:** 반복 설명·정정 부담 감소, Project 내용 개선을 통한 다음 판단의 개선, 새로운 협업 방법 발견을 모두 기대한다. 닫힌 목표 목록이나 우선순위·효과 입증으로 취급하지 않는다.

## 마감 뒤에도 열린 선택

네 묶음 합의의 실행 본문·Personal 실제 파일/읽기와 전체 대화 입력 절차는 [prototype 실행안](../../records/prototypes/development-workflow/skills/improvement-loop/SKILL.md)에 작성했다. 정확한 파일명은 이번 구체화 선택이고 후보 분류·점수·결과 양식을 고정하지 않았다. Main의 대표 경로 열람·정적 대조와 독립 수행·운영 사용은 구별하며, 두 보완까지 반영하고 완료 조건을 대조해 설계 결과를 마감했다.

개별 개선안의 채택은 각 루프에서 판단한다. 별도 역할·고정 검토자 수·자동 반영 범위 확대·정기 실행은 이번 합의로 확정하지 않으며 기타-01은 보류한다. 배포·저장소 간 접근은06, 실제 적용과 전체 효과 관찰은07의 책임과 잇되05 자체의 실행안 설명·대표 장면 확인을 뒤로 넘기지 않는다.

## 조사와 형성 근거

[외부 전반 재조사](../../records/2026-10-27-ticket05-broader-reference-investigation.md)는 기존 컨텍스트·협업·수행 기반·기록·효과 확인의 접근을 넓게 비교한 입력이다. 첫 조사의 부족을 automate-me 하나의 보충으로 축소하지 않는다. [Work 중심 제안](../../records/2026-10-27-ticket05-collaboration-learning-proposal.md)과 [그 제안의 개선 리뷰](../../records/2026-10-27-ticket05-collaboration-learning-review.md)는 이후 Personal 배치 합의 이전의 형성 근거다. 새 배치의 독립 검토·적용·효과 확인으로 읽지 않는다.

04-03이 연결한 context-update는 일상 정정과 채택된 Personal·Project 의미의 한정 반영 방법이다. 05는 무엇을 배우고 유지하거나 바꿀지 판단하는 운영을 맡고, 선택한 코드·스킬·도구 변경은 해당 수행으로 잇는다. 기존 반영 절차가 있다는 사실을 전체 학습·개선 루프가 이미 충분하다는 근거로 쓰지 않는다.

## 04-02에서 이어받은 개선 판단 사례

2026-10-26 [04-02 마감](../../records/2026-10-26-ticket04-02-closeout-and-followups.md)과 [배경·응답의 종합 판단](../../records/experiments/explain-choice-investigation-60medium-revised-2026-10-26/comparison.md#배경과-함께-본-다음-행동의-권고)을 이후 운영안의 사례로 받는다. 기준이 이미 있는데 실제 판단에 충분히 적용되지 않은 경우, 일부 근거 확인은 좋아졌으나 최종 답의 큰 변화는 없는 경우, 지침을 더하지 않고 현재판을 유지한 선택을 함께 다룬다.

07의 실제 적용 관찰에서 중요한 판단 누락이 서로 다른 장면에 반복되거나 지침의 충돌·요구 누락이 확인되면 원요청·근거·실제 응답과 영향을 대조해04-02의 필요한 부분을 다시 연다. 명확한 결함은 반복을 기다리지 않는다. 한 답에 항목을 더 넣을 수 있다는 사실이나 취향 차이만으로 범용 문구·새 역할·반복 시험을 자동 추가하지 않는다. 제품 선택·가능한 조사 누락은 우선 해당 작업의 수행 책임과 대조한다. 이 입력을 받았다는 사실로05 운영안 설계나 효과 확인이 완료된 것은 아니다.

## 맡은 결과와 범위

04-03의 [제안·검토 후 반영 구체화](../../records/2026-10-26-context-proposal-review-apply-design.md)는 담당자의 제안·근거, Main의 판단·실제 반영과 결과를 이후 경험 검토에서 선택할 입력으로 남긴다. 이미 확보한 유효한 근거를 재사용하고, 중요한 공백·충돌·대상 변경에 필요한 부분만 추가 확인한다. 미반영 후보뿐 아니라 이미 반영한 선택의 효과·유지 이유도 대상이 될 수 있다. 일상 사실 정정을 이 티켓까지 미루지 않으며, 이 입력이05의 담당·시점·독립 검토 구성이나 효과 관찰 방법의 확정은 아니다.

검토할 경험의 후보에는 반복 교정, 잘된 경험, 새로 드러난 기준, 도구·자료 접근의 부족 등이 있다. 이는 닫힌 목록이나 자동 발동 규칙이 아니며, 단발 사건도 이후 판단을 바꿀 수 있으면 살필 수 있다.

현재 컨텍스트의 구성·내용·기준과 실제 사용, 사람과 AI가 조사·설명·선택·위임한 방식, 대화에서 생긴 이해·목표의 변화, 현재 기록과 개선 평가의 적절성도 검토 대상이 될 수 있다. 이미 보고된 실패만으로 범위를 제한하지 않으며, 기존 체계의 책임 구분은 채택된 변경을 연결할 때 사용한다. 이 관점들을 매 대화 전수 검사 항목으로 만들지는 않는다.

운영안에는 다음 관계를 담는다.

- 어떤 장면을 검토 후보로 삼고 어느 범위의 원문·결과·후속 변경을 근거로 보존할지.
- 즉시 확인할 일과 경험이 더 쌓여야 판단할 일을 어떻게 나누고, 검토 비용에 맞는 크기·시점·담당을 어떻게 정할지.
- 이미 기대한 기준을 반복해서 적용시키는 교정, 필요한 학습·제품 선택, 새 기준을 찾는 논의를 어떻게 구별할지.
- 코드·구조, 도구, 자동 검사, 문서, 스킬·역할 배치 중 무엇을 바꾸거나 유지할지와 선택 이유.
- 후보 제시·채택·반영·효과 관찰을 구별하고, 미채택·보류·추가 근거 요청도 다음 경로로 남기는 방법.

매 대화의 전체 회고, 세션 종료 고정 호출, 반복 횟수만으로 새 규칙 생성, 모든 후보에 인간 인터뷰를 붙이는 방식은 전제가 아니다. 실제 참여가 필요한 판단을 줄이려 하지 않되, 이미 확인한 사실을 사용자가 계속 다시 설명하게 만들지 않는 대안을 다룬다.

## 실행 맥락과 접근

이미 보존한 사례로 검토 흐름을 구성한다. 예를 들어 재개에서 중심을 다시 잡은 경험과 잘 복구한 경험을 비교하고, 첫 보고의 재작성과 중요한 DB·인증 선택을 위한 질문을 같은 실패로 세지 않는지 확인한다.

경험을 해석할 때 사용자 발화, 실제 산출물·변경, AI의 해석과 미확인을 구별한다. 침묵·진행·커밋 요청만으로 만족이나 개선 효과를 추정하지 않는다. 재설명 부담이 줄었다는 전체 평가는 유지하되 수치나 특정 장치의 인과 효과를 만들어내지 않는다.

AI가 확인할 수 있는 원문·코드·문서·도구 사실은 먼저 확인한다. 개인의 이해·선호·감수할 비용이 보완 선택을 가르는데 기존 근거로 알 수 없다면 구체 장면과 대비안을 제시해 필요한 부분만 묻는 방법을 설계한다. 전체 재수집이나 새 인터뷰를 선행 조건으로 두지 않으며, 설계 중 사용자 판단이 필요한 부분은 해당 사례로 좁혀 논의한다.

자료의 참고 범위는 나누어 사용한다.

전체 접근과 관련성·한계는 [재조사 기록](../../records/2026-10-27-ticket05-broader-reference-investigation.md)을 먼저 읽는다. 아래 첫 조사 자료는 그 일부다. 재조사는 문서의 실제 사용, 현재 지식과 현실의 대조, 작업 방식의 근거별 추출, 기록 감사, 목표·전제의 재검토, 효과 비교를 함께 다룬다.

- 강연의 `retro`는 세션 원자료에서 탐색·검사·표준·도구 비용·정보 접근 등의 환경 개선 후보를 찾는 방법이다. 채택부터 다음 작업의 효과 확인까지 완결한 운영 결과로 보지 않는다.
- pstack `reflect`는 판단·도구·다른 관점을 나눠 보고 기존 기준·실제 수행·구조적 해결을 대조하는 방법이다. 스킬 중심의 수신 대상·단발 사건 제외·고정 검토자 수·외부 backlog 등록은 우리 운영값으로 가져오지 않는다. 실제 원문과 차용/조정 근거는 위 Desktop 조사 기록에서 읽는다.
- Vercel 자료는 수집과 판단을 나누고, 후보·기각·열린 질문을 사람이 검토하며 좁은 위치에 반영하는 방법을 제공한다. 주간 주기나 collector·judge 분리를 그대로 채택하지 않는다.
- Vercel의 공개 eval은 copywriting 범위다. 기대 수정을 숨긴 사례나 skill 없는 실행과의 비교는 참고하되 전체 개발 방식의 효과가 입증됐다고 확대하지 않는다.

대안을 비교할 때 새 지시를 추가하는 방법뿐 아니라 기존 지시의 정리, 코드 구조 개선, 이미 있는 검사의 연결, 자료 진입 경로 보완, 변화 없이 더 관찰하는 방법도 검토한다. 원인을 하나로 닫을 근거가 부족하면 선택을 가를 관찰과 보류 이유를 남긴다.

02는 경험의 근거와 현재 상태를 어디에 남길지, 03은 Project 맥락, 01-01·01-02·01-03는 개발 방식·품질·검증, 04-01~04-03은 스킬 설계를 맡는다. 경험을 공통 기반 개선으로 다룰지 프로젝트 안에서 해결할지도 판단한다. 근거 보존은 02, ai-workspace로 전달하고 대상에 다시 반영하는 방법과 비용은 06과 연결한다. 실제 적용 위치와 전환은 06에 연결하고, 07이 전체 대표 사례 대조와 후속 관찰 계획을 구성할 수 있게 필요한 관찰을 넘긴다.

## 완료 조건과 확인 방법

운영안 문서를 만들었다는 사실만으로 완료하지 않는다. 다음 내용을 기존 사례에 대입해 판단할 수 있어야 한다.

- 반복 교정, 잘된 경험, 필요한 사람의 선택, 도구·자료 부족처럼 성격이 다른 사례에서 검토하거나 지나갈 이유와 범위·시점이 드러난다. 해당 사례에 없는 사실은 만들지 않는다.
- 한 개선 후보에서 근거, 문제 해석, 적절한 반영 대상, 유지·변경 대안, 비용과 사람의 선택을 따라갈 수 있다. 기준 추가만으로 끝나지 않는다.
- 미채택·보류 후보가 사라지거나 확정 규칙으로 바뀌지 않고, 다시 볼 조건 또는 추가 근거의 필요로 연결된다.
- 채택할 경우 무엇이 달라져야 하는지와 다음 유사 작업에서 무엇을 관찰할지 정한다. 규칙 준수, 개발 결과, 사용자 부담의 변화와 미확인을 구별한다.
- 대표 사례를 보완안의 예시로 반복한 확인과 아직 보지 않은 유사 상황에서 확인할 계획을 구별한다. 후속 관찰의 범위·시점·책임과 효과가 없을 때 수정·철회할 판단을 07에 연결한다.

이 티켓의 설계 완료는 운영안을 비교·판단할 수 있는 상태다. 채택, 코드·도구·문서·스킬에 실제 반영, 이후 효과 확인은 별도로 기록한다. 관찰하기 쉬운 결과가 좋아졌다는 이유만으로 전체 작업 경험이 개선됐다고 판정하지 않는다.

## 현재 상태와 실제 결과

전체 구체안·독립 개선 리뷰·Main 보완 뒤 사용자가 네 묶음의 운영 방향을 합의했다. 이번 Main 점검은 합의와 현행 prototype·05 완료 조건을 대조한 문서 점검이며 별도 독립 리뷰나 실제 실행이 아니다. 운영 방향 합의·실행안 구체화·대표 사례 대조까지를05 설계 완료로 마감한다. 실제 설치·새 상황 수행·사용 효과는 후속이다.

설계할 때 필요한 근거는 다음에서 선택한다.

- [외부 접근 전반의 재조사](../../records/2026-10-27-ticket05-broader-reference-investigation.md): 사용자 정정 원문, 자료 선정·추가 관점·기존 사례·한계와 현재 논의의 진입점.

- [평가·인터뷰 연결 기록](../../records/2026-10-12-01-background-and-evaluation.md): 효용과 마찰, 필요한 질문을 구별할 기존 사례.
- [사용자 인터뷰](../../source/noline-evaluation/reviews/interview-20261012.md): 만족·부담·선호의 확인과 회고가 불확실한 부분.
- [기록 시점과 재개 후속 비교](../../source/noline-evaluation/reviews/record-timing-followup.md): 기록 보존·열람·적용을 나누어 봐야 하는 근거.
- [retro 기준판](../../source/lectures/retro.ko.md): 환경 개선 후보를 찾는 관점과 제안 단계의 한계.
- [Vercel 제품 설계 자료](<../../source/lectures/vercel-product-design (1).md>): 근거 수집·판단·미채택 경로와 eval의 범위.
