# 현재 논의의 진입점

**현재 초점:** [113의 적용과 검증](../records/2026-10-20-113-content-policy-worker-application.md)에서 정책과 현재 데모만 받은 워커의 해석·수정, 새 독자의 두 상황과 독립 대조를 읽는다. Personal 세 주제의 README·index·분할 본문과 이름 기준의 background를 실제 구성했다. 이후 상위 README의 공통 본문 선택과 내용 이동 뒤 참조 목적을 보존하는 정책을 보완했다. 원칙은 [CONTENT-POLICY.md](../records/prototypes/development-workflow/noline-demo/context/CONTENT-POLICY.md), 현재 범위와 다음 판단은 [state](state.md)가 소유한다.

88·89에서 프로토타입의 초기 작성과 당시 검토를 수행했다. **96의 품질 유보 뒤97에서 평가하고98에서 빠진 판단과 같은 코드 비교를 반영했다. 같은 폴더에서 계속 발전시키는 단계다.** [정정89](../records/2026-10-19-89-local-context-structure-correction.md)와 [development-workflow](../records/prototypes/development-workflow/README.md)가 현재 구조·실물의 진입점이다. Noline demo는 Main이 구체 적용 대상으로 고른 예시이며 실제 Noline 적용은 아니다.

[보완87](../records/2026-10-19-87-conditional-application-and-provenance.md)의 조건별 적용과 과정 재접근을 이어받는다. 개인 기준의 현재 위치는89의 로컬 context/personal이며, 별도 ai-workspace 호스트로 고정한86의 해석은 대체한다. demo 안에서 Personal·Project의 독립 본문과 Work의 선택·충돌 판단·반환 절차를 구성했다. 실제 운영 저장소의 설치·배포·동기화·skill 연결은 남아 있다.

사용자가 **이름과 실제 책임·완료 범위**를 선택해 만든 [세 본문82](../records/2026-10-19-82-naming-responsibility-completion-draft.md)와 구체 적용83을 바탕으로 수정했다. 일반 의미·조건은 유지하면서 판단 질문, 개명·이름 유지·동작 수정의 대비와 과정 근거에 다시 접근하는 경로를 보완했다. 기준 전체 채택·원본 이동·통합·설치는 없다. [state](state.md)에서 다음 행동, [03](tickets/03-project-context.md)·[04-03](tickets/04-skill-improvements/04-03-context-skills.md)에서 책임별 미완료 범위를 확인한다.

[7쌍 본문 비교](../records/prototypes/criteria-format-comparison-2026-10-19/README.md)는87 보완 전의01·새 구체화 원문과 평가를 보존한 snapshot이다. 87의 [이전 적용 시안](../records/prototypes/personal-project-applied-2026-10-19/README.md)은 원형으로 보존하고, 현재 발전시킬 본문은88의 단일 프로토타입에서 읽는다. 새로 작성하는 질문·사례를 이미 결정된 기준으로 올리지 않는다.66·68·72는 시안 반영 요청이고73은 전체 만족·최종 수용 유보다. [85](../records/2026-10-19-85-personal-location-proposal-and-format-provenance.md)는 이전 글로벌 추천과 형식 근거를 구별한 기록이며 현재 위치는89의 정정을 따른다.

## 문서별 책임

- [memory.md](memory.md): 대상물 경계·범위 안의 완성도, 배경과 평가에서 얻은 경험, Spec·Ticket을 쓰게 된 흐름.
- [spec.md](spec.md): 전체 목표·공통 기준·잠정안·사용자 선택·미정.3절은 전체 체계와 현재 초점을 연결한다.
- [tickets/index.md](tickets/index.md): 상위01~07과 하위 Ticket의 관계. 각 Ticket은 상세 결과·완료 조건·진행을 소유한다.
- [state.md](state.md): 현재 작업 중심, 다음 추천, 미실행 범위와 재진입 경로. 과거의 날짜별 진행은 records에서 찾는다.
- [design-map.md](design-map.md): 전체 분해에서 놓친 관점을 살피는 열린 논의 지도. 확정 아키텍처가 아니다.
