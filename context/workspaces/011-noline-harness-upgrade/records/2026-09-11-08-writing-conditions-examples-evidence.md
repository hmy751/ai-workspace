## 수정본에서 드러난 문제

사용자는 Main이 직접 수정한 Noline 03 Ticket과 테스트 전략 record를 다시 보고, 새 작성 지침에 더 보완할 점을 판단하도록 요청했다. 수정본에서는 선택 이유와 문서 간 역할 분리가 개선됐지만, 일부 압축이 판단 조건이나 이해에 필요한 근거를 약화한 것을 확인했다.

- 원대화는 테스트용 TypeScript 설정을 유지할 회귀 테스트의 타입 검사와 연결했고, 공용 mock은 반복되는 준비 코드와 연결했다. 수정 record의 “실제 typecheck 충돌이 나타나면 추가한다”, “같은 이유로”라는 묶음에서는 서로 다른 도입 이유가 좁아지거나 합쳐졌다.
- 원대화의 `refresh` 검사는 “이전 값에 누적하지 않고 처음부터 다시 계산하는지”를 확인하는 사례였다. Ticket의 “`refresh` 호출 뒤 값 재계산”에는 입력 변경과 누적 여부라는 판별 기준이 충분히 드러나지 않았다.
- 수정 record가 session·hook 운영 설명을 덜어낸 것은 적절했지만, 방향 채택의 근거인 사용자 발화와 원대화 접근점도 빠졌다. 사용자의 “전반적으로 다 좋아 근데 packages 나 이런건 괜찮을까?”와 후속 “그래 좋아 그럼 결정사항들 논의 기록하려면 어디에 남기는게 좋을까?”는 전체 방향의 채택을 지지하며 정확한 버전·설정 값의 개별 확정까지 증명하지 않는다.

## 작성 지침에 반영한 범위

Main은 위 세 관점으로 기존 문단을 보완하자고 제안했고 사용자는 “그래 보완해줘”라고 승인했다. [DOCUMENT-WRITING.md](../../../../reference-project/context/work/workspaces/DOCUMENT-WRITING.md)의 기존 내용 충분성·압축·읽기 흐름 문단에 판단 조건의 구분, 구체 사례의 조건·결과 보존, 결정·정정 범위를 뒷받침하는 최소 원문 보존을 통합했다.

이는 특정 테스트나 record만의 규칙이 아니라 사람용 Workspace 문서 전반의 작성 기준이다. 고정 목차·도식·원문 전체 복제·추가 reviewer를 요구하지 않는다. Tradeoff 비용, 용어의 역할과 문서 간 중복은 기존 기준으로 충분해 유사 규칙을 추가하지 않았다. Maintainer의 읽기·쓰기 권한과 원문 보존 Owner도 변경하지 않았다.

## 확인 결과와 한계

보완된 본문이 기존 bridge의 최초·후속 입력에 각각 한 번 포함됨을 확인했고 Maintain 테스트 67개와 `git diff --check`가 통과했다. 전역 사람용 진입 reference는 이해·판단·근거 접근 경로를 점검하는 기준으로만 읽었으며 수정하지 않았다.

Noline에는 새 작성 지침이 아직 적용되지 않았으므로 이번 대조는 그 지침의 실제 실행 평가가 아니다. 실제 모델을 호출하거나 Noline 문서를 다시 수정하지 않았고 커밋도 만들지 않았다. 앞선 source 변경과 새 보완은 작업 트리에 함께 남아 있다.
