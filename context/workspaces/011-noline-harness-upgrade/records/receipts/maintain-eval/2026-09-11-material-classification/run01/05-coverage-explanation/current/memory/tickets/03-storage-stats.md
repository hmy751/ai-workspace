# 03 — 저장 용량의 집계·부분 실패·표시

## 맡은 결과와 범위

`apps/client/src/features/profile/hooks/useStorageStats.ts`와 프로필 표시 연결을 다룬다. 성공과 바깥 실패 처리에서 같은 stats 표시값을 따로 조립하는 중복을 줄이고 부분 결과가 남는 범위를 읽히게 한다. 병렬 조회·새 실패 상태·새 단위 체계는 도입하지 않는다.

## 실행 맥락과 접근

[보존 계약](../spec/03-concepts-and-contracts.md)과 [품질 기준](../spec/04-quality-and-completion.md)을 적용한다. Main의 [조사 초안](../../../../../../../eval-inputs/noline-002-additional-research-and-ticket-drafts-2026-09-11.md)은 파일 조회 도중 실패하면 앞서 더한 용량을 표시하고 지도 조회까지 진행하지 않는다고 설명한다. 개별 지도 팩 실패는 경고 후 다음 팩을 계속 읽는다. `ProfileScreen.tsx`가 DB·지도 표시값을 사용한다는 Main 보고다.

전체 파일 조회 실패와 개별 팩 실패의 계속 여부를 구별하고 이미 집계한 값을 보존하는 순서를 유지한다. 함수 분리 크기는 실행 때 판단하되 실패 결과를 이해하려고 더 많은 파일을 따라가게 되면 개선 여부를 다시 본다.

## 완료 조건과 확인 방법

변경 전 기존 hook을 통해 FileSystem·Mapbox 의존성을 제어하고 수정 후 동일 조건으로 비교한다.

- 빈 디렉터리, 대상 확장자와 무관 파일 혼합을 확인한다.
- DB 파일 조회 중간 실패, `getPacks` 실패, 개별 `pack.status` 실패 뒤 다음 팩 성공을 구별한다.
- 0·1,024·소수 단위 표시, 최종 DB·지도·합계와 관련 호출 순서를 보존한다.

성공·실패 표시 조립이 한 의미로 관리되고 부분 결과 보존 위치가 명확해졌는지 전후 코드를 비교한다. 실제 기기 파일 접근과 네이티브 지도 팩을 확인하지 않았다면 그 범위는 미확인으로 남긴다.

## 현재 상태와 실제 결과

실행 전 초안이다. Main이 코드와 표시 사용처를 조사했다고 보고했다. 제품 수정·동작 테스트·실기기 검증은 미실행이다. hook 검사 방법은 실행 때 준비하며 위 사례는 계획이다.
