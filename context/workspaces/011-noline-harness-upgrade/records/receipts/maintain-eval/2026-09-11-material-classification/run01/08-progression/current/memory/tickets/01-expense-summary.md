# 01 — 경비 합계의 강조·소수 자릿수 규칙

## 맡은 결과와 범위

`apps/client/src/screens/ExpensesScreen.tsx`의 통화 합계와 `apps/client/src/shared/lib/currency.ts`의 관련 규칙을 다룬다. 첫 항목 강조와 소수 자릿수 판단을 반복 해석하지 않게 한다. 날짜 그룹·폼·카드 전체나 환율 계산으로 넓히지 않는다.

## 실행 맥락과 접근

[대표 사례](../spec/02-behavior-and-cases.md), [보존 계약](../spec/03-concepts-and-contracts.md), [품질 기준](../spec/04-quality-and-completion.md)을 적용한다. Main의 [조사 초안](../../../../../../../eval-inputs/noline-002-additional-research-and-ticket-drafts-2026-09-11.md)에 따르면 기본 통화가 목록에 있으면 우선되지만 없으면 다른 통화가 첫 항목이다. 첫 항목을 `isBaseCurrency`로 명명하지 않는다.

현재 화면의 `toFixed` 표시와 공통 helper의 천 단위 구분자 차이를 보존한다. 공통 helper로 단순 교체하면 1,000 이상 금액의 문자열이 달라질 수 있다. 내부 함수·변수 배치는 실행 때 판단한다. 다른 Ticket의 완료가 기술적 선행 조건은 아니다.

## 완료 조건과 확인 방법

수정 전 `groupExpensesByCurrency`·`formatCurrencyDisplay`의 실제 export와 현재 화면 합계 렌더를 대상으로 필요한 검사를 먼저 실행하고 수정 후 같은 조건으로 비교한다.

- 빈 경비, 기본 통화가 있는/없는 목록, 동일 통화 합산과 동률을 확인한다.
- KRW/JPY와 EUR/USD, 0·소수·1,000 이상 금액에서 계산 순서·정렬·표시 문자열·첫 항목 강조를 보존한다.
- 화면 자동 검사가 어렵다면 고정 fixture의 전후 화면과 관찰 조건을 남긴다. 순수 helper 검사만으로 UI 표시까지 입증하지 않는다.

개선은 강조 판단의 이름이 실제 의미와 맞고 공통 자릿수 규칙을 여러 곳에서 다시 해석할 필요가 줄었는지 전후 코드를 비교한다. 줄 수 감소나 테스트 통과만으로 개선을 판정하지 않는다.

## 현재 상태와 실제 결과

turn `eval-progression`에서 사용자는 '티켓 검토 끝났어. 경비 합계 표시부터 진행해. 합의한 방식대로 변경 전 검사부터 시작하자.'라고 첫 실행 대상을 확정했다.

Main은 이 Ticket의 보존 조건과 개선 목표를 바탕으로 변경 전 검사를 준비하는 단계로 넘어간다고 보고했다. 제품 코드 수정이나 테스트 실행은 아직 하지 않았으며 구체적인 테스트 runner는 다음 작업에서 정한다는 보고다. 위 검사는 계획이며 변경 전 기준 결과나 동작 보존·개선 효과가 확인된 것은 아니다.
