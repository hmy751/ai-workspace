# Ticket

[Spec](../index.md)과 [후보 목록](../analysis-items.md)을 바탕으로 정리한 1차 실행 범위다. 번호는 Main이 추천한 순서이며 강한 기술 의존성이나 사용자 확정을 뜻하지 않는다. 정의·진행·실제 결과는 각 본문이 소유한다.

- [01 — 경비 합계의 강조·소수 자릿수 규칙](01-expense-summary.md): 첫 항목 강조와 자릿수 판단을 반복 해석하는 부담을 줄인다.
- [02 — 도시 검색의 선별 조건과 변환](02-city-search.md): 요청과 응답에 중복된 도시 기준과 수도 예외를 읽히게 한다.
- [03 — 저장 용량의 집계·부분 실패·표시](03-storage-stats.md): 부분 결과를 보존하며 성공·실패의 표시 조립 중복을 줄인다.
- [04 — 경비 API의 요청·검증·반환 흐름](04-expense-api.md): 오류 계약을 유지하며 작은 본문을 가리는 반복 코드를 정리한다.
- [05 — 서버 일정 응답의 날짜 변환](05-schedule-response.md): CRUD 응답의 동일 날짜 변환을 함께 관리한다.

출처는 Main의 [추가 조사와 Ticket 초안](../../../../../../../eval-inputs/noline-002-additional-research-and-ticket-drafts-2026-09-11.md)이다. 첫 실행 범위를 선택할 때 현재 코드와 보존 계약·사전 개선 목표·검증 방법을 대조한다. 필요한 최소 검사 실행 방법은 처음 사용하는 Ticket에서 준비해 재사용하며 구체적인 runner는 아직 선택되지 않았다. 별도의 장기 테스트 기반 작업이나 제품 구현 착수를 확정한 것은 아니다.

기존 폼·picker·날짜 그룹·저장 후 처리와 새 후속 후보는 후보 목록에 남긴다. 다섯 Ticket의 구성이나 완료가 전체 Work의 완료를 대신하지 않는다.
