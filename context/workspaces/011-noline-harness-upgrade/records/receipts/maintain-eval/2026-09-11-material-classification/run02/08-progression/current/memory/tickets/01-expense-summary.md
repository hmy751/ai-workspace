# 01 — 경비 합계의 강조·소수 자릿수 규칙

## 맡은 결과와 범위

`apps/client/src/screens/ExpensesScreen.tsx`의 통화 합계와 `apps/client/src/shared/lib/currency.ts`의 관련 규칙을 다룬다. 첫 항목 강조와 소수 자릿수 판단을 반복 해석하는 부담을 줄인다. 날짜 그룹·폼·카드 전체·환율 계산은 제외한다.

## 실행 맥락과 접근

[대표 사례](../spec/02-behavior-and-cases.md), [보존 계약](../spec/03-concepts-and-contracts.md), [품질 기준](../spec/04-quality-and-completion.md)을 적용한다. Main의 소스 조사에 따르면 기본 통화가 목록에 있으면 우선되지만 없으면 다른 통화가 첫 항목이다. 첫 항목을 `isBaseCurrency`로 명명하지 않는다.

화면의 `toFixed` 출력과 공통 helper의 천 단위 구분자 출력은 다르다. 현재 표시 차이를 유지하면서 같은 의미의 자릿수 규칙을 정리한다. 내부 함수·변수 배치는 실행 중 정한다. 조사 출처와 선택 이유는 [추가 조사 기록](../../../records/2026-09-11-01-additional-research.md)에 있다.

## 완료 조건과 확인 방법

변경 전 `groupExpensesByCurrency`·`formatCurrencyDisplay`의 실제 export와 현재 화면의 통화 합계 렌더를 대상으로 필요한 검사를 먼저 실행한다. 빈 경비, 기본 통화가 있는/없는 목록, 동일 통화 합산, 동률, KRW/JPY와 EUR/USD, 0·소수·1,000 이상 금액을 포함한다. 변경 후 같은 검사로 계산 순서·정렬·표시 문자열·첫 항목 강조를 비교한다.

화면 자동 검사가 어려우면 고정 fixture의 전후 화면과 관찰 조건을 남긴다. pure helper 검사만으로 UI 표시를 입증하지 않는다. 개선 효과는 강조 판단의 뜻이 정확하고 공통 자릿수 규칙을 여러 곳에서 다시 해석할 필요가 줄었는지 전후 코드로 확인한다.

## 현재 상태와 실제 결과

사용자가 Ticket 검토를 마치고 “경비 합계 표시부터 진행해. 합의한 방식대로 변경 전 검사부터 시작하자”라고 첫 실행 대상으로 선택했다. 현재는 위 보존 조건과 개선 목표를 바탕으로 변경 전 검사를 준비하는 단계다.

Main 보고상 소스와 사용처를 확인했으며 제품 코드 수정이나 테스트 실행은 아직 없다. 위 검증 사례는 계획이고 기준 결과는 확보되지 않았다. 구체적인 runner는 다음 작업에서 정하며, 변경 전 제품 코드를 검사할 최소 방법을 준비해 재사용한다.
