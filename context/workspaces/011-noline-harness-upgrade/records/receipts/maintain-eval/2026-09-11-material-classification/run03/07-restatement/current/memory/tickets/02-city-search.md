# 02 — 도시 검색의 선별 조건과 변환

## 맡은 결과와 범위

`apps/client/src/features/trip/create-trip/geonames.api.ts`의 요청 도시 코드와 응답 선별·City 변환을 명확히 한다. query hook의 debounce·cache·에러 표시 정책은 바꾸지 않는다.

## 실행 맥락과 접근

[보존 계약](../spec/03-concepts-and-contracts.md)과 [품질 기준](../spec/04-quality-and-completion.md)을 적용한다. Main 조사에 따르면 허용 도시 코드 네 개가 요청의 `featureCode`와 응답 필터의 `allowedFCodes`에 반복된다. 인구가 10,000보다 큰 도시 또는 수도 코드 `PPLC`를 허용하는 조건이 식 안에 묶여 있다. `useSearchCities.ts`는 `searchCities`를 실제 queryFn으로 사용한다.

기존 `searchCities`를 외부 호출 경계로 유지하며 동일 기준과 조건의 뜻을 가까운 코드에서 드러낸다. 외부 문자열 좌표의 `parseFloat` 변환과 catch의 빈 배열 반환은 보존한다. 새 오류 throw나 범용 검색 엔진을 도입하지 않는다. [추가 조사 기록](../../../records/2026-09-11-01-additional-research.md)에 출처와 한계가 있다.

## 완료 조건과 확인 방법

리팩토링 전 `searchCities`에 고정 HTTP 응답을 공급해 실제 반환값과 요청 인자를 확인한다. 허용/비허용 코드, 이름/국가 누락, 인구 10,000과 10,001, 인구 기준 미달 수도, 응답 순서, 숫자 문자열 좌표, 요청 실패를 포함한다. 수정 뒤 같은 검사를 실행한다. 실제 GeoNames 서비스 가용성 검증으로 확대하지 않는다.

허용 코드 변경 위치가 하나로 모이고 수도 예외·필드 변환의 의미를 가까운 코드에서 이해할 수 있어야 한다. 반환 결과와 순서·실패 시 빈 배열을 유지하면서 반복 수정 부담이 줄었는지 비교한다.

## 현재 상태와 실제 결과

Main이 제안한 실행 전 초안이다. 신규 후보의 코드·사용처 조사 보고만 있으며 외부 API 호출·제품 수정·제품 테스트 실행은 없다. 위 검증은 계획이고 구체적인 실행 방법은 미정이다. Ticket 01과 기술적 선행 관계는 없으며 번호는 실행 확정 순서가 아니다.
