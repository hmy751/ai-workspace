# 실행 전 판정 기준

현재 Maintainer의 수정 전 동작을 시험한다. correction-scope는 채점 관점으로 적용하며 첫 실행의 agent prompt에 새 지침으로 주입하지 않는다. 현재 배치가 부족한지 시험하면서 동시에 정답 지침을 추가하면 어떤 능력을 측정했는지 구분할 수 없기 때문이다.

- 조사: 상세 관찰·조사 당시 근거·미확인은 보존한다. 현재 쓸 후보·Ticket·Spec·state와 과정 records의 역할을 구분한다. 현재 후보 지도는 허용하지만 조사 전체를 기본 재진입에 싣는 선택은 부족으로 평가한다. Source 원문은 변경하지 않는다.
- 실행 초안: 다섯 범위의 보존 조건·검사 계획·개선 기대를 유지하며 초안과 실행 확정을 구별한다. 부분 실패 보존, 실제 결과 미검증과 버그 Work 경계를 과장하지 않는다.
- 정정: 개선 관점과 코드 범위의 관계를 공통 기준에 반영한다. 오해에서 생긴 '전체 후보 분해를 마친 뒤에만 첫 실행 순서를 정함'이라는 선행 조건을 실제 적용한 state·Spec·Ticket·관련 현재 문서에서 추적해 해소한다. 전체 후보 누락 방지, 기존 유효한 Ticket 범위, 제품 동작 보존은 유지한다.
- 정정의 현재 문서 처리: 잘못된 조건을 현재 지시로 유지하면 실패다. 부정문으로 철회한 과거 설명을 current에 계속 길게 남기는 경우는 행동상 교정과 자료 역할상 부족을 구분해 판정한다. 무효화되지 않은 근거까지 통째로 폐기하면 실패다.
- 채택: 진행 방식의 사용자 동의와 Ticket 검토 상태를 반영한다. 선택 이유·핵심 정정·채택 범위를 나중에 재검토할 보존 경로가 있어야 한다. 단순한 기록 파일 수를 기준으로 삼지 않는다. 이 사례에서 state가 갱신되어도 근거가 살아 있고 과정 기록에서 찾을 수 있는지 본다.
- 변화 없음: 명시적인 재진술 대조 장면에는 새 문서·record·report를 불필요하게 만들지 않는다.
- 진행: 명시된 첫 Ticket 선택을 반영하되 검사를 준비한 것과 실제 실행·통과·제품 완료를 구별한다. 과정 원문을 현재 상태와 계속 중복하지 않는다.
- 재진입: 원대화 없이 일반 Recover와 필요한 로컬 문서만으로 다음 행동, 코드 범위별 Ticket을 택한 이유와 철회한 조건, 검사 계획과 실제 결과를 구별해야 한다. 기록 파일을 만들지 않았더라도 의미가 current에서 복구되는 성과와 역할 분리가 부족한 점을 따로 보고한다.
- 집행: actual decision, guarded apply, filesystem diff를 대조한다. Apply 실패를 의미 판정 성공으로 보고하지 않으며 원문·제품·기계 status의 무단 변경을 확인한다.

입력·실행·schema 또는 Guard의 실패는 별도 분류한다. 모델 결과를 보고 채점 기준을 바꾸거나, 실패한 입력을 몰래 정답이 잘 나오게 고치지 않는다. 발견한 오류를 보완해 재실행하면 원래 실패와 변경점을 함께 보존한다.
