# 목표와 기준

## 목표

저장소 이름을 `ai-workspace`로 바꾸고, 실제로 사용하는 AI 개발도구라는 정체성이 처음 방문한 개발자에게 드러나게 한다. 기존 Git 이력을 보존한 채 이후 원격 저장소에 게시할 수 있는 상태를 준비한다.

## 프로젝트 정체성

AI Workspace는 AI 에이전트와 실제 소프트웨어를 개발하면서 반복해 사용하는 작업 방식과 도구의 저장소다. 목표를 실행 가능한 Spec·Ticket으로 만들고, Project와 Work context를 유지하며, 세션을 넘어 판단과 검증 결과를 이어 가는 repo-local skill과 Harness를 제공한다.

이 저장소는 역량 설명을 위해 별도로 만든 전시물이 아니다. 사용자가 자기 개발에 쓰기 위해 만든 재사용 모듈을 공개하며, 실제 적용·실패·개선 기록이 그 개발도구의 근거가 된다.

## 보존 조건

- 기존 커밋 이력과 브랜치를 유지한다.
- `Context Harness`는 내부 책임과 기존 skill 이름으로 계속 사용할 수 있다. 저장소 이름 변경과 내부 개념 이름을 일괄 치환하지 않는다.
- 과거 Workspace, records와 source의 당시 저장소명·경로·적용 사실은 소급해서 바꾸지 않는다.
- 다른 Project snapshot, 대화·prompt·평가 receipt와 절대경로를 공개할지는 게시 전에 현재 Git 이력까지 포함해 별도로 판단한다.
- 원격 저장소 생성·push와 라이선스 선택은 아직 수행하거나 결정하지 않았다.
