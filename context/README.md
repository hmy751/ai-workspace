# context

실제 개발 프로젝트에서 사람과 AI가 프로젝트 공통 맥락과 진행 중인 작업 상태를 복구하고, 필요한 정보만 선택해 행동하며, 검증 결과를 지속 상태에 다시 반영할 수 있게 하는 context+harness 운영 구조를 탐구하는 작업대다.

## 세 층의 역할

- [`active/`](./active/): 지금 유효한 프로젝트 공통 맥락과 진행 중인 작업 상태. 재진입할 때 먼저 읽는 현재 상태다.
- [`history/`](./history/): 작업하면서 생긴 상세 기록, 판단 변화, 시도와 검증 결과. 날짜순으로 쌓지만 그 자체가 현재 상태를 뜻하지는 않는다.
- [`source/`](./source/): 판단을 다시 확인할 수 있는 원본, 사용자 선택 발췌, AI 의견, 기존 작업 관찰 자료와 provenance.

## 작업 중 갱신 흐름

1. 작업 과정과 새로 확인한 사실을 `history/` 문서에 남긴다.
2. 결과를 source·코드·test·사용자 정정 등 적절한 근거로 확인한다.
3. 확인된 결과 중 **지금도 유효하고 다음 작업에 필요한 내용만** `active/`에 반영한다.
4. 이전 history는 남긴다. 이후 판단이 달라지면 과거 문서를 현재형으로 고치지 않고 새 history를 추가한 뒤 active를 갱신한다.

재진입할 때는 `active/index.md`에서 시작한다. 과거 이유나 실패가 필요할 때만 연결된 history를 읽고, 근거를 재확인해야 할 때 source를 연다.

아직 context+harness 운영 구조 자체나 설치 패키지를 설계한 상태는 아니다.
