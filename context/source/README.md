# Source workspace

이 폴더는 이후 설계의 근거가 되는 자료를 원천별 역할에 맞게 보존한다. 자료의 중요도를 깎기 위한 분류가 아니라, 나중에 원문·사용자 선택·AI 판단·과거 작업을 서로 바꿔 쓰지 않기 위한 경계다.

## 구조

- `00-intake/`: 이번 대화에 들어온 붙여넣기 원문과 무결성 기록
- `10-external/`: 원본 링크가 있는 외부 참고 자료의 HTML 스냅샷과 사용자 선택 발췌
- `20-ai-opinion/`: 사용자가 공감해 가져온 AI 의견
- `30-prior-work/`: AX와 cofathon에서 사용자가 실제로 했던 작업 방식의 관찰 자료. 정답 원천으로 취급하지 않는다.
- `manifest.json`: 모든 source ID, 역할, 원본 위치, 스냅샷 상태를 한곳에서 찾는 색인
- `VERIFICATION.md`: 이번 intake에서 실제로 확인한 것과 아직 증명하지 않은 것

## 읽는 순서

1. `manifest.json`에서 자료의 역할과 현재 상태를 확인한다.
2. 각 `source-record.md`에서 원본 URL·접근일·해시를 확인한다.
3. 사용자가 중요하게 고른 부분은 `user-selected-excerpts.md`를 먼저 읽고, 문맥이 더 필요할 때만 `original.html`을 연다.
4. `30-prior-work/`는 현재 구조의 답으로 복제하지 않고, 실제 작업 습관과 실패·검증 방식의 관찰 자료로만 읽는다.

## 보존 원칙

- `original.html`과 `00-intake/*.txt`는 원본 스냅샷이므로 내용 수정 대신 새 스냅샷을 추가한다.
- 사용자 선택 발췌는 붙여넣기 원문의 문구를 요약하거나 바꾸지 않는다. 읽기용 제목·구분선과 Markdown 공백만 더하거나 정규화하며, byte 원본은 `00-intake/`에 둔다.
- 이후 생기는 설계 해석은 이 폴더의 source 파일을 덮어쓰지 않고 별도 작업 계층에 둔다.
- 링크는 재접근 경로이고, 로컬 스냅샷과 SHA-256은 이번 판단에 사용한 시점을 식별한다.
