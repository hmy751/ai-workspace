# Goal 반복과 평가 보정 반복을 다시 구분

날짜: 2026-07-17

## 계기

[기존 Goal·loop 설계 기록](./19-loop-engineering-and-working-principles-redraft.md), 현재 [Goal 중심 작업 루프](../core/loop.md), 결과물과 평가 기준을 함께 올리는 loop engineering 원형을 다시 비교했다.

비교 시점의 기존 `core/loop.md`는 git `8e2b0d1`에 남아 있다. 당시에는 결과물 보정·평가 방법 정밀화·공유 기준 승격·Goal amendment를 네 갱신 종류로 병렬 배치했다. 원형에서 직접 가져온 핵심 문장은 `Goal Setting → 검증 → Eval Refinement → Tuning → Goal Setting Again`과 평가할 때마다 에이전트의 평가 기준을 업데이트한다는 설명이다. 아래 첫 이식안은 commit하지 않은 작업 초안이므로, 그 초안의 핵심 변환과 기각 이유를 이 기록에 함께 보존한다.

첫 이식안은 기존 Goal 계층과 완료 의미를 보존한다는 결론을 먼저 고정하고, 원형의 `Goal Setting → 검증 → Eval Refinement → Tuning → Goal Setting Again`을 `Build → Evaluate → 결함 진단 → 같은 조건 재실행`으로 축소했다. 이 안은 test·fixture 중심의 검증 강화에는 유효했지만 다음을 놓쳤다.

- 기존 Goal Loop 자체의 Goal·상태·문서 복잡성을 검토하지 않았다.
- 평가 뒤 다음 반복의 목표와 품질 수준을 다시 설정하는 동작을 제거했다.
- 사람과 에이전트의 평가 차이를 결과물·평가 시스템 결함 분류로 바꿨다.
- 비통과 결과만 기준 보정의 출발점으로 삼아, 에이전트가 통과시킨 약한 결과와 좋은 결과에서 배우는 경로를 놓쳤다.
- 보정된 평가 기준과 `같은 수락 기준`을 동시에 요구해 무엇을 유지하고 무엇을 바꿀지 흐렸다.

따라서 기존 구조의 빈칸에 기능을 추가하는 방식이 아니라, 양쪽의 장단점을 함께 적용해 반복 구조를 다시 정리했다.

## 비교에서 유지한 것

현재 Goal Loop에서 유지한다.

- Mission·Campaign Goal·엔지니어링 최상위 Goal·loop Goal의 소유권
- 활성 loop Goal이 있으면 그 Goal이 현재 구현을 직접 지배하고, 없으면 다음 loop 선택 판단점을 가리키는 구조
- 최신 증거에서 다음 판별 질문이나 구현 loop를 고르는 방식
- 실입력·원근거·독립 판별과 관찰 가능한 완료 증거
- Goal amendment, 안전한 경로 부재, 전체 마감·예산 경계
- 구현 기록과 평가 증거는 loop 폴더, 바깥 결정은 process가 소유하는 경계

평가 기준을 갱신하는 원형에서 유지한다.

- 결과물만 고치지 않고 무엇을 좋은 결과로 판단하는지도 고친다.
- 평가에서 배운 품질 수준을 다음 반복의 목표와 평가 축에 반영한다.
- 사람의 품질·임팩트 판단을 에이전트 평가와 대조한다.
- 갱신한 기준을 다음 실행이 실제로 읽는 위치에 남긴다.
- 최종 결과뿐 아니라 검증 가능한 결과물과 짧은 판정 기록을 남긴다.

## 수정하거나 가져오지 않은 것

- `만족할 때까지`, `1등 품질까지` 같은 무제한 반복은 완료 조건으로 쓰지 않는다.
- 사람의 취향이나 한 reviewer의 판정을 자동 정답으로 승격하지 않는다.
- 새 세션이나 다른 agent라는 사실만으로 독립 판별이라고 하지 않는다.
- 평가할 때마다 기준을 자동 추가하지 않는다. 다음 유사 판단에서도 재사용할 수 있을 때만 보정한다.
- `Goal Setting Again`을 상위 Goal의 매번 변경으로 읽지 않는다. 같은 완료 의미 안에서는 이번 반복의 목표와 평가 축을 다시 설정한다.
- 구현 loop의 반복 기록을 process나 current에 모두 복제하지 않는다.

## 승격한 운용 기준

### 바깥 Goal 반복

활성 Goal과 최신 증거에서 가장 중요한 미충족 상태를 고르고, 제한된 판별 실행이나 독립 계약이 필요한 번호 구현 loop를 연다. 결과 뒤 `ACHIEVED / CONTINUE / REPLAN / BLOCKED` 중 하나로 활성 Goal을 다시 판정한다. course correction과 한 실행의 보류는 별도 최상위 상태가 아니라 `CONTINUE` 아래의 다음 행동 선택으로 다룬다.

### 구현 loop 안의 평가 보정 반복

`이번 반복의 목표·평가 축 설정 → Build 또는 Tuning → 검증 → 사람·원근거·에이전트 평가의 차이 확인 → Eval Refinement → 실제 실행 기준에 반영 → 다음 반복의 목표·평가 축 다시 설정`을 반복한다.

- 비통과, 에이전트의 잘못된 통과, 사람 판단과 원근거의 충돌, 통과 결과에서 발견한 재사용 가능한 높은 품질 기준을 모두 보정 후보로 본다.
- 사람의 판단·실제 사용자 조건과 원근거·에이전트와 독립 판별자의 평가를 대조한다.
- 일회성 결과물 수정과 다음 판단에도 쓸 평가 기준을 구분한다.
- 보정 기준은 loop Goal, skill, rubric, validator, test, fixture 가운데 다음 실행이 읽는 위치에 반영한다.
- 같은 시나리오·입력과 Goal의 안정된 제약은 유지하되 보정 기준으로 이전 약한 결과, 새 결과, 정상 또는 대비 사례를 함께 다시 판정한다.
- `관찰 → 이전 평가 → 사람·원근거와의 차이 → 이전 기준 → 보정 기준 → 실제 반영 위치 → 재실행 결과`와 다음 반복 목표를 해당 loop 폴더에 보존한다.
- 필수 완료 상태·증거·제약이 바뀌면 안쪽 반복을 멈추고 Goal amendment로 올린다.

## 기존 Loop 01의 증거 상한

Loop 01은 최초 test 뒤 상태 계약·provenance·판단 우선순위·reload 검증을 고친 기술 사례다. 그러나 이 기준을 세운 뒤 수행한 prospective 반복은 아니다. 구현 중 실제 입력 가치 gate의 소유 경계도 Loop 01에서 최상위 Goal로 이동했으므로, 완료 의미를 유지한 평가 보정의 성공 증거로 소급 사용하지 않는다.

완료된 Loop 01 기록은 고쳐 쓰지 않는다. 새 기준의 실제 작동은 다음 번호 loop에서 처음 검증하며, 그때 사람·원근거·에이전트 평가 차이와 다음 반복 목표 재설정이 실제 기록으로 남아야 한다.

## 현재 상태에 미치는 영향

- Mission, Campaign Goal, 최상위 구현 Goal의 현재 완료 의미를 바꾸지 않는다.
- 현재 leaf Goal의 유무와 커서는 이 문서가 임의로 바꾸지 않는다.
- 새 번호 loop나 빈 평가 기록 파일을 미리 만들지 않는다.
- 이번 변경은 공통 운용 계약이며, 아직 작동 검증을 통과했다는 뜻이 아니다.
