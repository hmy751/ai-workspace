# 2026-07-14 — current를 상태 보고서에서 지도 우선 구조로 교정

## 사용자 정정

사용자는 기존 `current.md`가 설명이 많아 한 번에 파악되지 않고, AX 작업본에 명시된 `지도 우선` 감각을 놓쳤다고 지적했다.

## 어긋났던 점

직전 current는 지도보다 다음 내용을 먼저 길게 설명했다.

- 프로젝트 목표와 확정 결정
- 출처 정책과 완료 상태
- 두 독립 검사 결과
- SessionStart·hook·commit 검증
- 현재 후보 설명과 선택 gate

전체 지도는 이 설명 뒤에 축약된 단계 목록으로 놓였다. 그래서 사람은 전체 구조와 현재 위치를 보기 전에 상태 보고서를 읽어야 했고, AI도 지도를 따라 세부 문서로 내려가기보다 요약문을 현재 맥락으로 받게 됐다.

## AX 원본에서 다시 확인한 기준

- `current.md`의 본체는 지도 트리다.
- 첫 뎁스는 요구사항·리서치·문제·솔루션·엔지니어링·제출 같은 큰 흐름만 둔다.
- 완료된 가지도 남겨 전체 생애주기를 보존한다.
- 현재 위치에는 커서 하나만 두고 그 판단점에서만 깊어진다.
- 상세 판단과 이력은 원천 문서로 내리고 지도에는 현재 해석 한 줄과 경로만 둔다.
- hook은 current 내용을 해석하거나 복제하지 않는다. 단순히 시작 계약을 주입해 current/core를 다시 읽고 프로젝트·커서·다음 일을 복기하게 한다.

AX의 재진입 교차검증에서는 전체 지도가 최근 구현에 과적합된 제출 답변을 프로젝트 전체 관점으로 복구하는 데 실제로 쓰였다. 동시에 최종 current가 136줄까지 커져 재진입 카드와 백과사전을 함께 맡았다는 한계도 확인됐다.

## 교정한 것

- `current.md`를 147줄 상태 보고서에서 46줄 지도 트리로 다시 작성했다.
- 지도 앞에는 역할과 갱신 규칙만 남기고 바로 전체 지도가 나오게 했다.
- 지원 목표·요구사항 → 트랙 → 문제 정의 및 리서치 → 솔루션 → 엔지니어링 → 지원 제출의 전체 흐름을 첫 층에 놓았다.
- 완료된 조사와 후보 판별은 해당 가지의 현재 해석과 상세 링크로 남겼다.
- 커서는 `과제 방향 선택` 하나에 두고, 지금 비교할 후보 3·1·2와 판단할 정보만 그 아래에서 깊어지게 했다.
- hook·commit·검증 절차 설명은 지도에서 제거했다.

## 바꾸지 않은 것

- `.codex/hooks.json`
- `tools/codex-session-start.py`
- `CLAUDE.md`의 단순 read·recap·stop 계약
- 후보 판정과 우선 논의군 자체

지도 우선의 의미는 `current.md`가 소유하고, hook은 최신 current를 다시 읽게 하는 역할만 유지한다.
