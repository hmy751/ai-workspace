# 제출 문항 교정과 업로드 실패

작성일: 2026-07-10~11

## 한 것

- `submission-answers.md`의 다섯 답변을 과제 원문, README, 코드, 테스트, process와 교차 검증했다.
- Q1~Q4는 근거·구현·글자 수와 일치해 유지했다.
- Q5는 ZIP 생성 전 작성된 문장 때문에 `최종 ZIP 검증은 남았다`고 적혀 있었으나, 실제로는 ZIP 생성·해제·구조·테스트 검증이 끝난 상태라 교정했다.
- 교정 뒤 글자 수는 Q1 552/800, Q2 568/800, Q3 838/1000, Q4 611/800, Q5 793/800이다.
- 최종 ZIP은 `src/`, `README.md`, `logs/`만 포함하며 설문 답변은 웹 폼에 별도로 입력하는 문서임을 확인했다.
- 2026-07-10 23:59:20 KST에 웹 폼에서 ZIP 업로드를 시도했으나 `업로드에 실패했습니다. 다시 시도해 주세요.` 오류가 표시됐다.
- 기존 ZIP은 로컬 무결성 검사를 통과했다. 서버 호환 변수를 줄이기 위해 같은 내용을 표준 Deflate 방식과 정확한 `submission.zip` 이름으로 다시 만들고 재검증했다.
- 마감 전 시도 화면과 ZIP을 첨부해 제출 인정 또는 대체 제출 경로를 요청하는 운영자 문의문을 작성했다.

## 펼친 후보

- Q5의 이전 미검증 문장을 그대로 유지하기.
- 완료된 ZIP 검증과 실제 남은 한계를 분리해 교정하기.
- 업로드 실패 뒤 plugin 내용을 다시 바꾸기.
- 동일 내용을 더 보편적인 Deflate ZIP으로 다시 묶고 운영자에게 증거를 전달하기.

두 번째와 네 번째를 선택했다.

## 기각한 후보와 이유

- `context/`와 `.git/`을 ZIP 최상위에 추가하기: 과제 원문이 제시한 최상위 `src/ + README.md + logs/` 구조에서 벗어나며 실행에 필요하지 않다.
- 업로드 오류를 plugin 또는 ZIP 내용 결함으로 단정하기: 원본과 호환 ZIP 모두 로컬 무결성·구조 검증을 통과해 원인이 확인되지 않았다.
- 설문 검수 뒤의 대화를 사용자의 의사와 달리 ZIP 로그에 다시 넣기: 사용자가 직전 로그는 추가하지 말라고 명시해 기존 ZIP을 유지했다.

## 막힌 지점과 해결

- **막힘**: 마감 직전 웹 업로드가 실패했고 마감 뒤에는 같은 폼에서 재시도 결과를 확정할 수 없었다.
- **해결**: 23:59:20 오류 화면을 보존하고, 검증된 ZIP의 크기·구조·해시와 함께 운영자에게 대체 제출을 요청하도록 했다.

## 검증 안 된 것

- 실제 업로드 실패가 서버 마감 처리, 네트워크, 브라우저, 저장소 업로드 endpoint 중 어디에서 발생했는지.
- 운영자가 마감 전 제출 시도 증거를 인정하거나 대체 제출을 허용하는지.
