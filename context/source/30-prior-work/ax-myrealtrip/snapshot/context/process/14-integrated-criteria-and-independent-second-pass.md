## 기준이 바뀐 과정

1. 처음에는 `문제 존재 → 좁은 관점 → 크기 → 과제 적합성`의 순차 게이트를 제안했다.
2. 사용자는 이 방식이 구체성·현재 근거·구현 가능성을 너무 일찍 높여, 출제자와 회사가 중요하게 보는 문제나 더 큰 가능성을 줄일 수 있다고 지적했다.
3. `ai-self-check`의 독립 감사에서도 `가장 좁은 표현`과 조기 통과·보류 판정이 현재 탐색 단계에는 이르며, 회사 중요도를 마지막 가중치로 미룬 점도 맞지 않는다고 확인했다.
4. 이에 따라 아래 기준을 순차 탈락 조건이 아니라 같은 후보를 여러 면에서 보는 종합 기준으로 바꿨다.
   - 문제의 구체성: 작게 만드는 것이 아니라 누가·어느 상황·행동·마찰·결과인지 식별한다.
   - 출제자·회사 중요도: 공식 해커톤 영상의 직접 발화를 이 항목의 최우선 근거로 본다.
   - 실제 사용자 행동과 결과
   - 회사 중요도 근거와 사용자 문제 근거가 각각 공개 자료로 재확인 가능한지
   - 현재 해결 상태와 원인 주체
   - 손실 강도·반복 구조·상황의 폭·비즈니스 연결로 보는 잠재적 크기와 임팩트
   - Codex plugin 개입 가능성은 초기 탈락 기준이 아니라 낮은 우선순위의 보조 확인
5. 명확히 해결된 주제만 제외하고, 불확실한 빈칸은 후보를 없애는 대신 그대로 표시했다. 문제의 크기와 실제 구현 범위도 분리했다.

## 펼친 후보

독립 2차 추출에서는 다섯 후보가 나왔다. 번호는 여행 여정의 대략적인 순서일 뿐 순위가 아니다.

1. AI에서 얻은 여행안을 실제 예약으로 넘길 때 다시 시작되는 검증
2. 복합 투어·액티비티의 개인별 객관적 이용 가능성 판단
3. 상세·후기로 실제 경험의 시간·강도·운영 방식을 예상하는 판단
4. 특수 취향·동행·신체 조건에 맞는 상품 발견
5. 예약 뒤 변경·취소·부분 인원 예외 대응

후보 2~4는 새로운 사용자 사례를 각각 확보한 것이 아니다. 기존 사용자 후기 세 건을 서로 다른 문제 경계에서 재사용했으며, 02에 그 중복 관계를 명시했다.

## 01과 02의 대조

두 판의 차이는 새 증거의 추가보다 같은 증거를 어디까지 하나의 문제로 묶는지에서 생겼다.

| 독립 2차 추출 | 첫 후보판과의 관계 | 대조에서 확인된 점 |
|---|---|---|
| 1. AI 여행안 뒤 재검증 | 01에서는 `많은 탭·외부 검증`을 아직 내용이 특정되지 않은 상위 행동으로 둠 | 회사 직접 발화와 잠재적 문제 크기를 높게 보면 독립 후보로 보이지만, 실제 검증 항목·채널·구매 결과는 여전히 비어 있음 |
| 2. 개인별 객관적 이용 가능성 | 01의 A와 A1에 거의 대응 | 서로 독립된 추출에서 반복된 가장 구체적인 구매 직전 문제 경계 |
| 3. 실제 경험 예상 | 01에서는 A2라는 인접 하위 구간으로 둠 | 한 손실 사례뿐이라 근거는 얇지만, 객관적 가능성과 다른 판단·결과를 만들 수 있어 별도 비교 가치가 생김 |
| 4. 특수 조건 상품 발견 | 01의 C에 대응 | 회사 중요도는 강하고 사용자 발견 실패·미충족 규모는 약하다는 경계가 두 판에서 반복됨 |
| 5. 예약 뒤 예외 대응 | 01의 B에 대응 | 현재 지원 이후 남는 실패와 플랫폼 통제 범위가 약하다는 경계가 두 판에서 반복됨 |

따라서 02가 01을 뒤집은 것은 아니다. 두 판에서 세 갈래가 안정적으로 반복됐고, 첫 판이 상위 행동 또는 하위 구간으로 둔 두 갈래를 02가 독립 후보로 다시 드러냈다. 어느 묶는 단위가 최종 Problem Statement에 맞는지는 아직 선택하지 않았다.

## 기각하거나 보류한 것과 이유

- 항공 최저가 반복 탐색, 예약 뒤 운항 정보 분산, 취소 뒤 대안 공백, 자유여행과 패키지 사이의 선택은 현재 출시된 직접 대응이 있어 독립 후보로 다시 올리지 않았다.
- 환불 불가 숙소·티켓 재판매는 리셀마켓이 일부 대응하지만 남은 적용 범위를 특정하지 못해 후보화하지 않았다.
- 사용자 행동이 약한 후보 1·3·4를 이번 단계에서 기각하지 않았다. 약한 근거와 모르는 결과를 해당 후보 안에 그대로 남겼다.

## 막힌 지점과 해결

- **막힘**: 새 기준을 01에 바로 적용하면 기존 A·B·C 안에서만 판단하게 되고, 기준이 새 후보를 발견하는 대신 기존 후보를 정당화하는 장치가 될 수 있었다.
- **해결**: 새 작업 주체에게 기존 후보판·process·비교 목표를 주지 않고 원자료와 종합 기준만 전달했다. 프로젝트 시작 규칙상 `current.md`는 읽었지만, 그 안의 기존 후보 정보는 추출 입력에서 제외하게 했다.
- **막힘**: 첫 02 초안에서 회사 관찰과 집계 자료가 구체 사용자 여정처럼 이어지거나, 같은 후기 세 건이 후보별 새 사례처럼 읽힐 수 있었다.
- **해결**: 후보군을 바꾸지 않고 검증 채널·검색 실패·항공사 경로 같은 단정을 약화하고, 사례 재사용 관계와 자료 시점·적용 범위를 명시했다.

## 문제를 닫는 순서에 대한 추가 논의

- 사용자는 이 작업이 해커톤 과제이므로 문제의 근거·구체성뿐 아니라 독창성, 비즈니스성, 심사자에게 잘 보이는 데모 가능성도 최종 선택을 바꿀 수 있다고 지적했다.
- 하나의 문제를 완전히 닫은 뒤 처음 솔루션을 펼치면, 다른 유효한 문제에서 더 매력적인 문제–솔루션 조합이 나올 가능성을 너무 일찍 없앨 수 있다.
- 현재의 잠정 절차는 최종 문제 게이트 전에 유력 문제 후보들의 솔루션 가능성을 짧게 확인하는 것이다. 각 후보에서 Codex가 개입할 순간, 입력과 출력, 기존 기능과 다른 독창성, 짧은 데모의 임팩트, 가장 큰 미확인 가정만 본다.
- 이 확인은 근거 없는 문제를 화려한 솔루션으로 구제하는 단계가 아니다. 사용자 문제가 성립하는 후보들 사이에서 어느 조합을 더 깊게 팔지 판단하는 자료다. 본격적인 솔루션 후보 확장은 하나의 문제를 선택한 뒤 진행한다.

## 검증하지 않은 것

- 다섯 후보 모두 구매 보류·포기, 반복률, 전환 손실, 문의 비용, 시장 규모를 공개 근거로 확정하지 못했다.
- 후보 1에서 사용자가 실제로 검증하는 항목·채널과 구매 결과
- 후보 2의 문의 빈도·왕복 시간·구매 포기, 공식 상품 데이터 접근 범위
- 후보 3의 반복 사용자 사례와 사전 공개 가능 정보·당일 운영 변수의 경계
- 후보 4의 실제 검색 실패와 공급 부족·조건 표현 실패의 구분
- 후보 5의 현재 상담 이후 남는 실제 손실과 예약 내부 상태 접근 범위
- 어떤 후보가 독창성·비즈니스성·데모 가능성까지 포함한 가장 강한 조합인지는 아직 보지 않았다.
